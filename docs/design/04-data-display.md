# 金额、百分比、日期时间的显示

全站只有一套格式化函数（前端一个模块），页面不各自拼字符串。下面的数字只是说明格式，不是业务数据。

## 1. 金额

**数据从哪来**：金额在系统里是「最小货币单位的整数 + 币种」（日元 1 = 1，人民币 1 = 100 分，见 ADR 0004）。每种币种有几位小数由 `packages/domain/src/money.ts` 的 `CURRENCIES` 决定，整数和十进制字符串之间的转换用同一文件里的 `formatMajor` / `parseMajor`。前端**不得**用浮点数做金额的乘除和小数位处理（不写 `amount / 100`、`toFixed`、`parseFloat`）。

**显示格式**：`币种代码 + 空格 + 带千分位的数字`

| 币种 | 小数位 | 格式示意 |
| --- | --- | --- |
| JPY、KRW | 0 | `JPY 98,000` |
| CNY、USD 等 | 2 | `CNY 4,600.50` |

- **一律显示三位字母的币种代码，不用符号。**「¥」同时代表日元和人民币，这个平台两种都有，用符号一定会看错。
- 小数位数固定为该币种的位数：日元永远没有小数点；人民币永远两位（`CNY 4,600.00`，不省略成 `4,600`）。
- 千分位用半角逗号，小数点用半角句点，不随界面语言变化。
- 币种代码和数字之间用不换行空格，金额不在中间折行。
- 负数（退款、扣款、冲减）：负号写在数字前，`JPY -1,200`。同时用文字说明性质（列名或标签写「退款」「扣款」），不只靠负号或红色。
- 零显示为 `JPY 0` / `CNY 0.00`。**没有金额**（未产生、不适用）显示「—」，不能显示成 0。
- 价格配置里填 0 表示免费提供的项目，列表里显示「免费」。
- 不做「万」「k」这类缩写；看板上的大数字也显示完整数值。

**在表格里**

- 金额列右对齐，`font-variant-numeric: tabular-nums`。
- 币种代码用 `text-secondary`，数字用 `text-primary`。
- 一列里只有一种币种时，把币种写进表头（「结算价（JPY）」），单元格只显示数字。
- 一列里有多种币种时，每个单元格都带币种代码。

**多币种**

- 平台不设本位币。不同币种的金额**不能相加**：合计行按币种各出一行（「合计 JPY …」「合计 CNY …」）。
- 需要换算成同一币种展示时（报表选了展示币种）：换算值前加「约」，旁边或气泡里写明原币金额、所用汇率和汇率时间。原币金额始终可以看到。
- 汇率显示 6 位有效数字，写成「1 JPY = 0.0… CNY」的形式，并标注汇率时间。

**输入金额**

- 输入框右侧（或左侧）固定显示币种代码作为前后缀；币种由所属的子品牌决定，用户不能在这里改。
- `inputmode="decimal"`（日元、韩元用 `"numeric"`）；不用 `type="number"`。
- 输入时不自动插入千分位；失去焦点后格式化显示，再次聚焦恢复成纯数字。
- 校验：只允许数字和一个小数点；小数位超过该币种位数时报错「{币种} 最多 {N} 位小数」（日元：「日元金额不能有小数」）；不能为负的字段填了负数时报错。
- 粘贴带逗号或空格的数字时自动去掉。

**供应商后台**：只显示「结算价」。不显示对外价、加价比例，相关页面和组件不为这两项留位置。

## 2. 百分比

- 数据是基点整数（1% = 100）。显示时换成百分数，最多两位小数，去掉末尾的 0：1250 → `12.5%`，1000 → `10%`，25 → `0.25%`。换算用整数的整除和取余，不用浮点除法。
- 输入框后缀固定显示「%」，最多输入两位小数。
- 可以为负的调价显示正负号：`+10%`、`-5%`。

## 3. 日期和时间

**格式**（不随界面语言变化，中日英通用）

| 内容 | 格式 | 示意 |
| --- | --- | --- |
| 日期 | `YYYY-MM-DD` | `2026-03-01` |
| 日期 + 时间 | `YYYY-MM-DD HH:mm`，24 小时制 | `2026-03-01 14:30` |
| 带星期（用车时间） | `YYYY-MM-DD 周X HH:mm` | `2026-03-01 周日 14:30` |
| 只有时间 | `HH:mm` | `14:30` |
| 需要到秒（审计日志、调用日志） | `YYYY-MM-DD HH:mm:ss` | — |
| 日期范围 | 用「至」连接 | `2026-03-01 至 2026-03-31` |
| 每日时段 | 用「–」连接 | `08:00–20:00` |
| 跨天时段 | 结束时间前加「次日」 | `22:00–次日 06:00` |
| 时长 | 「X 小时 Y 分钟」，不满 1 小时只写分钟 | `1 小时 30 分钟`、`45 分钟` |

- 不用 12 小时制，不用「上午 / 下午」。不用两位数年份。
- 月、日、时、分都补零到两位。
- 日期时间不折行；用等宽数字。
- 在页面上用 `<time datetime="带时区偏移的 ISO 8601">` 包住，便于读屏和复制。
- 没有时间时显示「—」。

**相对时间**

- 只用于「刚发生的事」和「快到的期限」，并且旁边或气泡里必须有绝对时间。
- 过去：1 分钟内「刚刚」；1 小时内「N 分钟前」；24 小时内「N 小时前」；更早直接显示绝对时间。
- 期限倒计时（派车截止、接单截止）：「还剩 2 小时 15 分钟」；已过期：「已超时 40 分钟」，并用 `danger` 状态徽标。倒计时每分钟更新一次。
- 用车时间、账单日期、审计日志永远显示绝对时间。

## 4. 时区

系统里所有时间规则（服务时间、夜间时段、提前预订时长、派车截止）都按**服务城市的当地时间**计算。看的人可能在另一个时区，所以每个时间都要让人知道它是哪里的时间。

| 时间类型 | 按哪个时区显示 | 怎么标注 |
| --- | --- | --- |
| 与用车有关的时间：用车时间、航班落地时间、派车截止时间、司机出发 / 到达 / 完成时间、服务时间段、库存和价格日历上的日期 | 服务城市当地时间 | 时间后面跟城市时区：`2026-03-01 周日 14:30 东京时间`。同一个卡片或表格里都是同一个城市时，在卡片标题或表头标一次即可（「用车时间（东京时间）」） |
| 与操作有关的时间：创建时间、修改时间、审计日志、登录记录、工单回复 | 查看者浏览器的时区 | 页面底部或表头注明「时间按你的本地时区（UTC+8）显示」；气泡里给出 UTC 时间 |

- 「XX 时间」里的城市名来自主数据的城市名称；没有合适名称时写 UTC 偏移（`UTC+9`）。偏移量按该日期实际生效的值计算（考虑夏令时），不写死。
- 查看者的时区与服务城市不同时，用车时间旁边用 `text-tertiary` 再给一行本地时间：「你的时间 03-01 13:30」。两个时区相同时不显示这一行。
- **填写**与用车有关的时间时，输入框的标签或帮助说明写明「按{城市}当地时间填写」，输入值按该城市时区解释，不按浏览器时区。
- 时区换算一律用 `Intl.DateTimeFormat` 加 `timeZone` 参数（IANA 名称，如 `Asia/Tokyo`），不手工加减小时。
- 列表按「用车日期」筛选时，「今天」「明天」指的是服务城市的今天、明天；列表里混有多个城市时，筛选条上注明按哪个时区算。

## 5. 其他数字和编号

- 数量、公里数、分钟数：千分位逗号，单位写在数字后面并隔一个空格（`1,200 公里`、`90 分钟`）。
- 地图上的距离和半径：统一用公里，最多 3 位小数、去掉末尾的 0（`3 公里`、`2.5 公里`、`0.35 公里`）；拖动时实时显示的数值保留 1 位小数（`3.2 公里`）。面积：不小于 1 平方公里的写「约 12.4 平方公里」（1 位小数），更小的写「约 8,500 平方米」（取整到百）。接口里半径是整数米，换算用字符串或整数运算，不用浮点乘除。
- 订单号、商品 ID、主数据编码：等宽字体，原样显示，不截断中间；旁边提供「复制」图标按钮。放不下时允许在任意位置折行（`overflow-wrap: anywhere`）。
- 电话：带国家区号（`+81 …`），用 `<a href="tel:…">`，在手机上点了能直接拨号。
- 打码的个人信息（列表里的乘客姓名、电话）：保留首尾，中间用「*」代替；旁边的「查看」按钮点了才显示全文。
- 密钥：只在生成时完整显示一次；之后只显示后 4 位（`••••1a2b` 的形式）。

## 6. 主数据的显示

- **状态**：只有两种，全站同一套写法（放进前端的状态对照表）：

  | 状态 | 徽标颜色 | 文字 |
  | --- | --- | --- |
  | 启用 | `success` | 启用 |
  | 停用 | `neutral` | 已停用 |

  「待指定城市」不是状态，是导入的机场缺了一项内容；它用 `warning` 徽标显示在「所属城市」那一格，和状态徽标同时出现。
- **多语言名称**：列表和只读处显示「显示名」，取法见 `02-components.md` 第 16 节。需要让人认出原文时，在显示名下面用 `font-size-xs` + `text-tertiary` 再给一行其余语言的名称（用「 / 」连接，单行，超出省略，各带 `lang`）。
- **国家**：`中文国名（两位代码）`，如「日本（JP）」。国名用 `Intl.DisplayNames("zh-Hans", { type: "region" })` 取，不在前端另存一张国名表；取不到名字的（如 XK）只显示代码。
- **时区**：`IANA 名称（当前偏移）`，如「Asia/Tokyo（UTC+9）」。名称用等宽字体；偏移按今天实际生效的值算（考虑夏令时），用 `Intl.DateTimeFormat` 取，不写死。
- **坐标**：`纬度, 经度`，各 6 位小数，等宽字体，如 `35.552258, 139.779694`。**界面上永远是纬度在前**（和地图软件里复制出来的顺序一致）；接口字段里经度在前（`lng`、`lat`），前端在收发时对好，不要照着字段顺序摆控件。不显示度分秒，不显示「N / E」。
- **枚举值**一律显示中文，不显示接口里的英文值：

  | 内容 | 显示 |
  | --- | --- |
  | 地点类型 | 机场、车站、地标、航站楼、出口 |
  | 车站类型 | 新干线、铁路、地铁 |
  | 地标类型 | 酒店、景点、港口、商场 |
  | 国际 / 国内 | 国际、国内、国际和国内；没填显示「—」 |
  | 车型等级 | 经济、舒适、商务、豪华 |
  | 动力 | 燃油、电动 |
  | 品类 | 接送机、点对点、包车 |
  | 计费方式 | 按次、按个、按人、按时长 |

- **「人数 / 行李数」组合**：写成「6 人 4 件」，用标签样式（`02-components.md` 第 7 节）；一格里最多显示 3 个，其余写「+N」，完整内容在编辑页看。
- **数据来源**：导入的记录显示「OurAirports」，手工录入的显示「手工录入」。
- **最近修改时间**：属于「与操作有关的时间」，按查看者本地时区显示（第 4 节）。

## 7. 区域的显示

- **状态**：启用（`success`）/ 已停用（`neutral`），和主数据同一套写法。
- **业务类型**（标签样式，不是状态）：通用、接送机、点对点、包车。不显示接口里的英文值。
- **图形的名字**：类型 + 序号，中间一个空格——「营运 1」「禁行 2」；有备注名时写「禁行 2 · 皇居周边」。序号删除后不重排。
- **图形的说明**：多边形写「多边形 · 6 个点」，圆写「圆 · 半径 3 公里」。
- **顶点的坐标**：同第 6 节的坐标写法（纬度在前，6 位小数，等宽字体）。接口里的 GeoJSON 是经度在前，前端在收发时对好。
- 颜色、线型、图例的文字见 `pages/tenant-areas.md` 第 6 节。

## 8. 商品的显示

- **状态**：三种，全站同一套写法（放进前端的状态对照表；枚举和中文名取自 `@nozomi/domain` 的 `PRODUCT_STATUS_NAMES`）。两种中性色的状态靠文字区分，不另配颜色：

  | 状态 | 徽标颜色 | 文字 |
  | --- | --- | --- |
  | 草稿 | `neutral` | 草稿 |
  | 已上架 | `success` | 已上架 |
  | 已下架 | `neutral` | 已下架 |

- **品类**（标签样式，不是状态）：接送机、点对点、包车。
- **商品编号**（接口的 `code`，需求文档说的「商品 ID」）：等宽字体，原样显示，旁边提供「复制」（第 5 节）。列表里放在显示名下面一行。
- **显示名**：商品详情里的标题，按「中文 → 英语 → 日语 → 韩语」取第一个有内容的；一种语言都没填的显示「未命名的{品类}商品」（`text-secondary`）。
- **子品牌**：「{子品牌名}（{币种代码}）」。
- **接送点**：「{显示名}（{编码}）」，编码用等宽字体；车站同样写法。
- **配到哪一步了**（步骤导航、检查清单、列表的「上架准备」）：一律「图标 + 文字」，文字只用这几种——已完成 / 已满足、还差 {N} 项、功能即将开放（步骤导航里简写成「即将开放」）、等待开放 {M} 步、不是必须、可以上架；M1-04 起另有两种**不影响上架的提醒**，都用警告色的三角图标：「{N} 个组合没有价格」（跟在「已完成 / 已满足」下面一行）、「有 {N} 处要留意」（不是必须的项有问题时）。M1-05 起，库存这一步的「已完成」后面带上模式（「已完成 · 不限量」「已完成 · 限量」），限量而从今天起没有库存时写「从今天起没有库存」（三角，警告色，不拦上架）。**不写「失败」「未通过」「错误」**：没配完不是出错。
- **时段**：按第 3 节，跨午夜的写「22:00–次日 06:00」；全天写「全天 24 小时」。服务规则里的时间都是城市当地时间，在页面顶部标一次（第 4 节）。
- **提前预订时长**：「{N} 小时」；不小于 24 小时的后面用 `text-tertiary` 补一个换算「（{D} 天 {H} 小时）」，整天的写「（{D} 天）」。
- **免费等待**：「{N} 分钟」；不限的写「不限时」，不写「无限」「∞」。平台规定的下限写「平台规定最少 {N} 分钟」。
- **取消规则的档位**：「用车前 {A} 小时及以上」「用车前 {B} 到 {A} 小时」「用车前不足 {B} 小时」；扣款写「免费取消」「扣 50%」「扣 100%」。
- **附加服务的单价**：金额按第 1 节；填 0 的显示「免费提供」；按个、按人、按时长的在金额后面加「/ 个」「/ 人」「/ 小时」。

## 9. 价格的显示

供应商后台的价格都是**结算价**，用子品牌的结算币种（第 1 节）。页面细则见 `pages/tenant-prices.md`。

- **计价方式**：固定一口价、里程 + 时长、包车套餐（名字取自 `@nozomi/domain` 的 `PRICING_MODEL_NAMES`；说明文字里「固定一口价」可以简称「一口价」）。不显示接口里的英文值。
- **方向**（标签样式）：接机、送机、接送通用；接送点是车站时写接站、送站、接送通用。
- **套餐**：「{N} 小时」；连公里一起写时「10 小时 / 300 公里」。
- **组合**：「{区域} · {车型组} · {方向或套餐}」，中间用「 · 」。
- **一条价格读成一句话**（金额带币种代码）：

  | 计价方式 | 写法 |
  | --- | --- |
  | 固定一口价 | 每单 JPY 20,000，不看里程和时长。 |
  | 里程 + 时长 | 10 公里、30 分钟以内 JPY 8,000；超出的部分每公里 JPY 300（不足 1 公里按比例）、每分钟 JPY 50｛；最少收 JPY 9,000｝。 |
  | 包车套餐 | 10 小时、300 公里以内 JPY 98,000；超时每小时 JPY 5,000，超公里每公里 JPY 400。 |

  填 0 的写成人话：「超出里程不另收」「超时不另收」，不写「JPY 0」。
- **起步里程**：接口里是整数米，界面上是公里，最多 1 位小数、去掉末尾的 0（`10 公里`、`2.5 公里`）；换算用字符串或整数运算。
- **生效日期**：「2026-10-10 至 2027-03-31」；没有结束的写「2026-10-10 起一直有效」，**不写「长期」「永久」「—」**。说的是用车日期，按城市当地时间（第 4 节）。
- **一条价格现在怎么样**（图标 + 文字）：生效中（对勾，`success-text`）、{YYYY-MM-DD} 起生效（时钟，`info-text`）、{YYYY-MM-DD} 到期，之后没有价格（三角，`warning-text`）、已停用 / 已过期（短横线，`text-secondary`）、没有价格（三角，`warning-text`）。「今天」用接口给的城市当地的今天，不用浏览器的日期。
- **没有价格**：一律写「没有价格」（一个组合）或「还没有设价格」（整个商品），用警告色，不用危险色；第一次出现的地方要带上后果「客人询价时报不出价」。**不写「缺价」「未配置」**，不显示成 0 或「—」（对比表里因为格子窄用「—」，表下必须有图例）。
- **调价步骤**：方向用词「上调 / 下调」，**不用「加价 / 减价」、不用单独的正负号表达方向**。按比例：「上调 20%」「下调 5%」（百分比按第 2 节，最多两位小数）；按金额：「上调 JPY 500」「下调 JPY 1,000」。一条规则有几步时，第一步照写，之后的前面加「再」：「上调 20%，再下调 JPY 1,000」。
- **变化量**（试算、日历明细里的一列）：带正负号的数，`+4,000`、`−1,000`（负号用「−」U+2212，和数字等宽对齐）；旁边一定另有「上调 / 下调」的文字。
- **没取整的中间结果**：照实显示（最多 6 位小数，用 `@nozomi/domain` 的 `formatExact`），后面小字「（还没取整）」；只有最后一行是取整后的数。
- **取整**：只有四舍五入时写「四舍五入」；另设了取整单位时写「取整到 JPY 100」。取整单位在接口里是最小货币单位的整数，显示时按第 1 节换成金额。
- **调价规则的「什么时候」**：
  - 出行日期：同生效日期的写法；两头都没填的写「不限日期」。
  - 周期：「每天」「每周六、周日」（按周一到周日的顺序；连续三天以上写「每周一至周五」）「指定的 {N} 天」（不多于 3 天时直接列出日期）「{国名}的节假日」。
  - 时段：「全天」或第 3 节的时段写法（`22:00–次日 06:00`）。要说清跨午夜落在哪天时写「周五 22:00–周六 06:00」。
- **调价规则的「对哪些」**：「全部区域」「全部车型组」「接机和送机」「全部套餐」；指定的写名字，多于 1 个时写「{第一个}等 {N} 个」。
- **调价规则的状态**：已启用（`success`）、已停用（`neutral`）；出行日期全部过去的另加 `neutral` 徽标「已结束」。
- **日历格子里的金额**不带币种（币种在页面的说明行里写一次）；被调过的用朝上 / 朝下的箭头图标 + 规则名，**箭头旁边必须有文字**（规则名），读屏读「上调」「下调」。
- **供应商后台任何地方都不出现对外价和加价比例**，也不写会让人联想到「平台在这个价上再加多少」的话。


## 10. 库存的显示

页面细则见 `pages/tenant-inventory.md`。

- **模式**：不限量、限量（`@nozomi/domain` 的 `INVENTORY_MODE_NAMES`）。不写「无限 / 有限」。
- **数量**：单位是「单」，整数，千分位（`1,200 单`）。可售单数（一共）、还剩、已售、待付款（下了单还没付款、先占着的）；已售 + 待付款 = 已占用。
- **一天的情况**（图标 + 文字；全站同一套）：

  | 情况 | 写法 | 颜色 |
  | --- | --- | --- |
  | 不限量 | 不限量 | `text-secondary` |
  | 有库存 | 剩 {N}（完整的写「还剩 {N} 单」），后面「共 {N}｛ · 已售 {N}｝｛ · 待付款 {N}｝」 | `text-primary` |
  | 设了，占满了 | 圆圈对勾 + 已订满 | `info-text` |
  | 设成了 0 | 短横线 + 停售 | `text-secondary` |
  | 限量，这一天没设过 | 三角 + 没设；第一次出现的地方带上后果「卖不出去」 | `warning-text`（成片出现时底 `warning-bg`） |

- **「没设」不显示成 0、「—」或空白**：0 是停售，是另一回事。
- 不限量时预先设好的数：「已设 {N}，限量时生效」。
- 日期是城市当地的用车日期（第 4 节）；「今天」用接口给的。
- **Excel 里的位置**：单元格写成 `F7`（列字母 + 行号，等宽）；行写「第 7 行」，指的是表格软件里看到的行号（表头是第 1 行）。
- **文件大小**：`48 KB`、`1.2 MB`（`02-components.md` 第 35 节）。
