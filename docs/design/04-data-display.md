# 金额、百分比、日期时间的显示

全站只有一套格式化函数（前端一个模块），页面不各自拼字符串。下面的数字只是说明格式，不是业务数据。

## 1. 金额

**数据从哪来**：金额在系统里是「最小货币单位的整数 + 币种」（日元 1 = 1，人民币 1 = 100 分，见 ADR 0004）。每种币种有几位小数由 `packages/domain/src/money.ts` 的 `CURRENCIES` 决定，整数和十进制字符串之间的转换用同一文件里的 `formatMajor` / `parseMajor`。前端**不得**用浮点数做金额的乘除和小数位处理（不写 `amount / 100`、`toFixed`、`parseFloat`）。

**显示格式**：`币种代码 + 空格 + 带千分位的数字`

| 币种 | 小数位 | 格式示意 |
| --- | --- | --- |
| JPY、KRW | 0 | `JPY 98,000` |
| CNY、USD 等 | 2 | `CNY 4,600.50` |

- **一律显示三位字母的币种代码，不用符号。**「¥」同时代表日元和人民币，这个平台两种都有，用符号一定会看错。
- 小数位数固定为该币种的位数：日元永远没有小数点；人民币永远两位（`CNY 4,600.00`，不省略成 `4,600`）。
- 千分位用半角逗号，小数点用半角句点，不随界面语言变化。
- 币种代码和数字之间用不换行空格，金额不在中间折行。
- 负数（退款、扣款、冲减）：负号写在数字前，`JPY -1,200`。同时用文字说明性质（列名或标签写「退款」「扣款」），不只靠负号或红色。
- 零显示为 `JPY 0` / `CNY 0.00`。**没有金额**（未产生、不适用）显示「—」，不能显示成 0。
- 价格配置里填 0 表示免费提供的项目，列表里显示「免费」。
- 不做「万」「k」这类缩写；看板上的大数字也显示完整数值。

**在表格里**

- 金额列右对齐，`font-variant-numeric: tabular-nums`。
- 币种代码用 `text-secondary`，数字用 `text-primary`。
- 一列里只有一种币种时，把币种写进表头（「结算价（JPY）」），单元格只显示数字。
- 一列里有多种币种时，每个单元格都带币种代码。

**多币种**

- 平台不设本位币。不同币种的金额**不能相加**：合计行按币种各出一行（「合计 JPY …」「合计 CNY …」）。
- 需要换算成同一币种展示时（报表选了展示币种）：换算值前加「约」，旁边或气泡里写明原币金额、所用汇率和汇率时间。原币金额始终可以看到。
- 汇率显示 6 位有效数字，写成「1 JPY = 0.0… CNY」的形式，并标注汇率时间。

**输入金额**

- 输入框右侧（或左侧）固定显示币种代码作为前后缀；币种由所属的子品牌决定，用户不能在这里改。
- `inputmode="decimal"`（日元、韩元用 `"numeric"`）；不用 `type="number"`。
- 输入时不自动插入千分位；失去焦点后格式化显示，再次聚焦恢复成纯数字。
- 校验：只允许数字和一个小数点；小数位超过该币种位数时报错「{币种} 最多 {N} 位小数」（日元：「日元金额不能有小数」）；不能为负的字段填了负数时报错。
- 粘贴带逗号或空格的数字时自动去掉。

**供应商后台**：只显示「结算价」。不显示对外价、加价比例，相关页面和组件不为这两项留位置。

## 2. 百分比

- 数据是基点整数（1% = 100）。显示时换成百分数，最多两位小数，去掉末尾的 0：1250 → `12.5%`，1000 → `10%`，25 → `0.25%`。换算用整数的整除和取余，不用浮点除法。
- 输入框后缀固定显示「%」，最多输入两位小数。
- 可以为负的调价显示正负号：`+10%`、`-5%`。

## 3. 日期和时间

**格式**（不随界面语言变化，中日英通用）

| 内容 | 格式 | 示意 |
| --- | --- | --- |
| 日期 | `YYYY-MM-DD` | `2026-03-01` |
| 日期 + 时间 | `YYYY-MM-DD HH:mm`，24 小时制 | `2026-03-01 14:30` |
| 带星期（用车时间） | `YYYY-MM-DD 周X HH:mm` | `2026-03-01 周日 14:30` |
| 只有时间 | `HH:mm` | `14:30` |
| 需要到秒（审计日志、调用日志） | `YYYY-MM-DD HH:mm:ss` | — |
| 日期范围 | 用「至」连接 | `2026-03-01 至 2026-03-31` |
| 每日时段 | 用「–」连接 | `08:00–20:00` |
| 跨天时段 | 结束时间前加「次日」 | `22:00–次日 06:00` |
| 时长 | 「X 小时 Y 分钟」，不满 1 小时只写分钟 | `1 小时 30 分钟`、`45 分钟` |

- 不用 12 小时制，不用「上午 / 下午」。不用两位数年份。
- 月、日、时、分都补零到两位。
- 日期时间不折行；用等宽数字。
- 在页面上用 `<time datetime="带时区偏移的 ISO 8601">` 包住，便于读屏和复制。
- 没有时间时显示「—」。

**相对时间**

- 只用于「刚发生的事」和「快到的期限」，并且旁边或气泡里必须有绝对时间。
- 过去：1 分钟内「刚刚」；1 小时内「N 分钟前」；24 小时内「N 小时前」；更早直接显示绝对时间。
- 期限倒计时（派车截止、接单截止）：「还剩 2 小时 15 分钟」；已过期：「已超时 40 分钟」，并用 `danger` 状态徽标。倒计时每分钟更新一次。
- 用车时间、账单日期、审计日志永远显示绝对时间。

## 4. 时区

系统里所有时间规则（服务时间、夜间时段、提前预订时长、派车截止）都按**服务城市的当地时间**计算。看的人可能在另一个时区，所以每个时间都要让人知道它是哪里的时间。

| 时间类型 | 按哪个时区显示 | 怎么标注 |
| --- | --- | --- |
| 与用车有关的时间：用车时间、航班落地时间、派车截止时间、司机出发 / 到达 / 完成时间、服务时间段、库存和价格日历上的日期 | 服务城市当地时间 | 时间后面跟城市时区：`2026-03-01 周日 14:30 东京时间`。同一个卡片或表格里都是同一个城市时，在卡片标题或表头标一次即可（「用车时间（东京时间）」） |
| 与操作有关的时间：创建时间、修改时间、审计日志、登录记录、工单回复 | 查看者浏览器的时区 | 页面底部或表头注明「时间按你的本地时区（UTC+8）显示」；气泡里给出 UTC 时间 |

- 「XX 时间」里的城市名来自主数据的城市名称；没有合适名称时写 UTC 偏移（`UTC+9`）。偏移量按该日期实际生效的值计算（考虑夏令时），不写死。
- 查看者的时区与服务城市不同时，用车时间旁边用 `text-tertiary` 再给一行本地时间：「你的时间 03-01 13:30」。两个时区相同时不显示这一行。
- **填写**与用车有关的时间时，输入框的标签或帮助说明写明「按{城市}当地时间填写」，输入值按该城市时区解释，不按浏览器时区。
- 时区换算一律用 `Intl.DateTimeFormat` 加 `timeZone` 参数（IANA 名称，如 `Asia/Tokyo`），不手工加减小时。
- 列表按「用车日期」筛选时，「今天」「明天」指的是服务城市的今天、明天；列表里混有多个城市时，筛选条上注明按哪个时区算。

## 5. 其他数字和编号

- 数量、公里数、分钟数：千分位逗号，单位写在数字后面并隔一个空格（`1,200 公里`、`90 分钟`）。
- 订单号、商品 ID、主数据编码：等宽字体，原样显示，不截断中间；旁边提供「复制」图标按钮。放不下时允许在任意位置折行（`overflow-wrap: anywhere`）。
- 电话：带国家区号（`+81 …`），用 `<a href="tel:…">`，在手机上点了能直接拨号。
- 打码的个人信息（列表里的乘客姓名、电话）：保留首尾，中间用「*」代替；旁边的「查看」按钮点了才显示全文。
- 密钥：只在生成时完整显示一次；之后只显示后 4 位（`••••1a2b` 的形式）。
