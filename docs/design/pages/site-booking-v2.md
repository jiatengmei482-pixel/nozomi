# 官网：新预订页（`/book/new`，M8-03）

ADR 0069（预订页重新设计）A3 和「修正版 v2」的页面规范。新页面先放在 `/book/new`，旧的 `/book`、下单页、订单页不动，M8-05 验收后切换。
通则（外观框架、字号、控件、语气与信任、文案用词、时间金额、键盘、亮暗）全部沿用 [`site-booking.md`](./site-booking.md) 第 2、8、9、10 节；本文只写新页面不同的地方。
这一批（M8-03）只有「你的行程」「选择车型」两块；「怎么联系你」、右侧栏的路线图 / 合计 / 取消规则 / 去付款、手机第 3 步是 M8-04。

## 1. 给谁用

第一次来订接送机、市内用车或包车的客人，多数在手机上，可能刚下飞机或在国内准备行程，可能用的是第二语言。
他们不懂我们后台的城市、区域、接机 / 送机这些分类，只知道「从哪里到哪里、几点、几个人几件行李」。客服、广告、合作方会直接发带参数的链接给他们。

## 2. 要完成什么

只填出发地、目的地两个地址 + 日期时间 + 人数（行李选填），就看到所有坐得下的车型和一口价，选一个。
城市、机场、接机还是送机、落在哪个报价区域都由系统判断（`POST /site/v1/quotes/by-points`）；包车是「上车地点 + 套餐时长」（沿用现有包车询价，城市按上车地点找最近的可订城市）。

### 3.1 布局

| 宽度 | 排法 |
| --- | --- |
| < 1024px（手机、平板） | **分步**：第 1 步「你的行程」+ 吸底「查看车型和价格」；第 2 步「选择车型」，顶部行程条（行程类型加粗、两端、时间、`2 人 · 2 件`、次要按钮「修改」回第 1 步），选了车型后底部**固定**条「车型 · 一口价 [下一步]」。换步时焦点移到那一步的区块标题（`tabindex="-1"`）。 |
| ≥ 1024px | **单页**：正文仍最宽 `layout-reading-max-width`（和顶栏对齐），分两栏 `2fr / 1fr`：左列「你的行程」「选择车型」，右侧栏「行程摘要」`position: sticky`（`top: space-4`）。没有「查看车型和价格」按钮（填齐就自动报价）。 |

- 页面标题「预订接送车」，下面一句「输入出发地和目的地，马上看到所有车型的一口价」（设计稿原文）。
- 手机底部固定条：`bg-surface`、上边框 `border-default`、`shadow-md`，`z-sticky`，留 `env(safe-area-inset-bottom)`；页面底部留出同样高度，不挡最后一张车型卡。「下一步」在 M8-04 接；这一批点了在条里显示一句 `role="status"`：「填写乘客信息并付款的一步还没有开放，敬请稍候。」

### 3.3 地址框：输入即提示（ADR 0069 B1）

- 无障碍和组合框（`02-components.md` 第 3 节，`Combobox`）同一套：`role="combobox"`、`aria-expanded`、`aria-controls`、`aria-activedescendant`；↓↑ 移动高亮，回车选中，Esc 收起。候选面板用组合框的样式（< 480px 从底部升起）。
- 至少 2 个字（和后端同一条 `placeQueryIssue`）才查，停顿 300 毫秒再查；一次「输入 → 选中」用同一个会话令牌，选中后换新的。
- 候选：平台的机场、车站在前（第二行写「机场」「车站」），谷歌的地点在后（第二行是地址，`text-secondary`、`font-size-sm`，任意位置可折行）。选中谷歌的候选后再取坐标和类型。
- 状态行在输入框下面（`role="status"`，空时不占位，不放进候选列表）：「请至少输入 2 个字，如酒店名、地址或机场」/「正在查找…」/「找到 N 个地点，用 ↑↓ 选择、回车确认。」/「没有找到。请换个说法（如酒店的英文名、地址）。」；谷歌用不了、太频繁、取不到坐标时用 warning 样式（同 `site-booking.md` 3.6），**一定指到别的方式**（「下面只有平台的机场和车站」「也可以在地图上选点」）。
- 后备「在地图上选点」：有底图时在地址框下面（次要按钮，`aria-expanded`），用现有的地图选点组件（`site-booking.md` 3.6 的全部规则：键盘选点、署名、准星）；地图从另一端（或第一个城市的中心）打开；选点后查这个位置的地址当名称，查不到写「地图上选的位置（纬度, 经度）」。

## 4. 「选择车型」

### 4.1 列表

- 一句说明：「按价格从低到高 · 坐不下的已隐藏。报价 30 分钟内有效（到当地时间 HH:mm），过了请重新查询。」
- 顺序按一口价从低到高（接口已排好）；坐不下的接口不返回。
- 默认显示：**电脑 4 个、手机 3 个**；多出来时下面次要按钮（`lg`、撑满）「显示全部 N 个车型 ▾」，点了全部显示、按钮消失，焦点落到第一个新露出来的车型的「选择」。已选的车型总是显示。
- 改了行程里任何一项，旧结果立刻收起（显示骨架「正在查询价格」），停顿 400 毫秒后重新报价。

### 4.2 车型卡

`.book-vehicle`：同 `.site-quote` 的卡片（`radius-lg`、`border-default`、`shadow-card`，≥ 768px 内边距 `space-6`）。从上到下：车型名（`<h3>`，`font-size-xl`）和一口价（`.price`，靠右，放不下换行）→ 细线 → M7 车型标识（`VehicleLabelItems`：代表车型、同级车型、最多乘客、最多行李「4 件（行李按 28 寸行李箱计）」；包车多一行「包车套餐」）→ 主按钮「选择」（撑满，读屏名「选择 {车型}」）。
选中：卡片描边换成 `primary` 双线，按钮变次要按钮「已选择」（`aria-pressed="true"`），卡片下面展开车内示意图。

### 4.3 车内俯视示意图

按车型的**最多乘客 N、最多行李 M**（车型标识）自动画的 SVG，不用照片（`pages/book/new/SeatMap.tsx`，排布规则 `lib/book-new.ts` 的 `seatPlan`）：

- 车身：圆角矩形，`bg-surface` 填充 + `border-strong` 描边；前面一条挡风玻璃线。
- 前排：右边司机位（`neutral-bg` + `border-strong`，写「司机」`neutral-text`），左边 1 号座位。后面 N − 1 个座位一排排往后，每排 2 或 3 个（轿车后排 3 个，7 座车 3 + 2）。
- 乘客座位：`primary` 实底，编号 1–N 用 `on-primary`（主按钮同一组搭配，亮 8.15 / 暗 4.97；座位对车身 `primary` / `bg-surface` 亮 8.15 / 暗 3.47）。
- 行李位：在座位后面的行李区（虚线隔开），`warning-bg` 底 + `warning-text` 描边和编号 1–M，顶上带提手（和座位形状不同）。`warning-text` / `warning-bg` 亮 5.97 / 暗 8.15。
- 图下（`figcaption`，`text-secondary`）：图例色块 +「乘客座位 N 个 · 行李 M 件（行李按 28 寸行李箱计）· 人数少时空座位也可以放行李」，下一行小字「示意图」（`text-tertiary`）。
- 读屏：SVG 是 `role="img"`，名称「{车型}的车内示意图：乘客座位 N 个，行李 M 件（行李按 28 寸行李箱计）」。不只靠颜色：形状不同、有编号、有文字。
- 宽度按排数算，最宽不超过 320px，手机上 `max-width: 100%`。

### 4.4 一口价包含

列表下面，小标题「一口价包含」，每条前面一个 `success-text` 的对勾。条目只用 `@nozomi/domain` 的 `fixedPriceIncludes`（ADR 0069 三语清单，中文界面用中文）：

| 条目 | 什么时候写 |
| --- | --- |
| 一口价已含所有费用（高速费、停车费等），无需另付 | 接送机、点对点。**包车先不写**：包车现在仍可事后加收高速费、停车费，说法要和规则同一天切换（ADR 0069 第二批确认 ①；开关 `FIXED_PRICE_RULES.charterAllInclusive`）；包车下面照旧写现有的说明「按车计价的套餐价。超出套餐的时长和公里、高速费、停车费服务后按实际收取…」 |
| 专车专用，不拼车 | 全部 |
| 举牌接机 | 中标商品的「包含」清单里有才写——报价接口现在不给商品的包含清单，**这一批不写** |
| 航班落地后免费等待 N 分钟 / 免费等待 N 分钟 | N 取报价，0 或不限时不写 |

**绝不写「跟踪航班」**（B14 决定不做）。

### 4.5 右侧栏（电脑）

「行程摘要」区块：行程（接机 / 送机 / 点对点 / 包车 N 小时）、出发地、目的地、航班落地 / 用车时间（「11月20日（周三）14:30」）、乘客 / 行李、航班号（填了才有）；下面所选车型的「{车型} · 一口价」+ `.price--lg`（`site-facts__item--total` 浅底），没选时「还没有选择车型」。路线图、车费、合计、取消规则、去付款是 M8-04。

## 5. 链接参数

`/book/new?from=…&to=…&date=YYYY-MM-DD&time=HH:mm&pax=N&bags=N`：`from` / `to` 是平台地点编码（如 `NRT`，用输入即提示找平台的地点）或「纬度,经度」（可带 `from_name` / `to_name`）。打开就预填并报价；手机上两端和时间都齐了直接到第 2 步。**每一项单独判断，不合法的只是不预填，不报错**。

## 6. 空状态和出错

| 状态 | 显示 |
| --- | --- |
| 加载中（配置、城市） | 骨架，`aria-label`「正在打开预订页」 |
| 官网没开 / 没有可订城市 / 配置、城市读不出来 | 同 `site-booking.md` 3.4（「暂未开放预订」要给已下单的客人指路；出错给「重试」） |
| 还没填齐 | 「选择车型」里一句「填好出发地、目的地、日期和时间后，这里会列出能坐下的车型和一口价。」（包车：「选好上车地点、包车时长…」） |
| 正在报价 | 骨架「正在查询价格」 |
| 报不出价 | warning 小框，小标题「没有可预订的车」，逐条写原因（不显示内部代码）：时间太近「时间太近，请选更晚的时间或联系客服」；人数太多「人数或行李超过所有车型，可以分两辆车预订或联系客服」；不在服务范围 / 没有商品「这个地址暂时没有在线报价，请联系客服」；其余沿用 `UNAVAILABLE_REASON_TEXT`。提到客服时下面给客服电话（`tel:` 链接，登记了才有） |
| 渠道不卖这里（`CHANNEL_SCOPE_DENIED`） | 小号空状态「没有在线报价」/「这个地址暂时没有在线报价，请联系客服」+ 客服电话 |
| 报价出错（网络、限速） | 小号错误状态「价格没有查出来」+ 原因（限速说等多久）+「重试」 |
| 地址提示用不了 | 见 3.3，只是状态行，不挡填写 |

## 7. 断点、键盘、亮暗

- 320 / 360 / 400px 不横向滚动（含候选展开、示意图展开、底部固定条）；≥ 1024px 两栏。
- 只用键盘能走完：两段式单选（方向键）→ 地址框（输入、↓↑、回车）→ 日期时间 → 乘客 / 行李（回车展开、Tab 到 − +）→ 航班号 → 车型「选择」→「显示全部」。
- 亮暗两套都只用 `01-tokens.md` 允许的搭配；每一步过 axe（`e2e/site-booking-new.spec.ts`）。
