## 1. 给谁用

第一次来订接送机、市内用车或包车的客人，多数在手机上，可能刚下飞机或在国内准备行程，可能用的是第二语言。
他们不懂我们后台的城市、区域、接机 / 送机这些分类，只知道「从哪里到哪里、几点、几个人几件行李」。客服、广告、合作方会直接发带参数的链接给他们。

## 2. 要完成什么

只填出发地、目的地两个地址 + 日期时间 + 人数（行李选填），就看到所有坐得下的车型和一口价，选一个。
城市、机场、接机还是送机、落在哪个报价区域都由系统判断（`POST /site/v1/quotes/by-points`）；包车是「上车地点 + 套餐时长」（沿用现有包车询价，城市按上车地点找最近的可订城市）。

### 3.3 地址框：输入即提示（ADR 0069 B1）

- 无障碍和组合框（`02-components.md` 第 3 节，`Combobox`）同一套：`role="combobox"`、`aria-expanded`、`aria-controls`、`aria-activedescendant`；↓↑ 移动高亮，回车选中，Esc 收起。候选面板用组合框的样式（< 480px 从底部升起）。
- 至少 2 个字（和后端同一条 `placeQueryIssue`）才查，停顿 300 毫秒再查；一次「输入 → 选中」用同一个会话令牌，选中后换新的。
- 候选：平台的机场、车站在前（第二行写「机场」「车站」），谷歌的地点在后（第二行是地址，`text-secondary`、`font-size-sm`，任意位置可折行）。选中谷歌的候选后再取坐标和类型。
- 状态行在输入框下面（`role="status"`，空时不占位，不放进候选列表）：「请至少输入 2 个字，如酒店名、地址或机场」/「正在查找…」/「找到 N 个地点，用 ↑↓ 选择、回车确认。」/「没有找到。请换个说法（如酒店的英文名、地址）。」；谷歌用不了、太频繁、取不到坐标时用 warning 样式（同 `site-booking.md` 3.6），**一定指到别的方式**（「下面只有平台的机场和车站」「也可以在地图上选点」）。
- 后备「在地图上选点」：有底图时在地址框下面（次要按钮，`aria-expanded`），用现有的地图选点组件（`site-booking.md` 3.6 的全部规则：键盘选点、署名、准星）；地图从另一端（或第一个城市的中心）打开；选点后查这个位置的地址当名称，查不到写「地图上选的位置（纬度, 经度）」。

## 4. 「选择车型」

### 4.1 列表

- 一句说明：「按价格从低到高 · 坐不下的已隐藏。报价 30 分钟内有效（到当地时间 HH:mm），过了请重新查询。」
- 顺序按一口价从低到高（接口已排好）；坐不下的接口不返回。
- 默认显示：**电脑 4 个、手机 3 个**；多出来时下面次要按钮（`lg`、撑满）「显示全部 N 个车型 ▾」，点了全部显示、按钮消失，焦点落到第一个新露出来的车型的「选择」。已选的车型总是显示。
- 改了行程里任何一项，旧结果立刻收起（显示骨架「正在查询价格」），停顿 400 毫秒后重新报价。

### 4.2 车型卡

`.book-vehicle`：同 `.site-quote` 的卡片（`radius-lg`、`border-default`、`shadow-card`，≥ 768px 内边距 `space-6`）。从上到下：车型名（`<h3>`，`font-size-xl`）和一口价（`.price`，靠右，放不下换行）→ 细线 → M7 车型标识（`VehicleLabelItems`：代表车型、同级车型、最多乘客、最多行李「4 件（行李按 28 寸行李箱计）」；包车多一行「包车套餐」）→ 主按钮「选择」（撑满，读屏名「选择 {车型}」）。
选中：卡片描边换成 `primary` 双线，按钮变次要按钮「已选择」（`aria-pressed="true"`），卡片下面展开车内示意图。

### 4.3 车内俯视示意图

## 5. 链接参数

`/book/new?from=…&to=…&date=YYYY-MM-DD&time=HH:mm&pax=N&bags=N`：`from` / `to` 是平台地点编码（如 `NRT`，用输入即提示找平台的地点）或「纬度,经度」（可带 `from_name` / `to_name`）。打开就预填并报价；手机上两端和时间都齐了直接到第 2 步。**每一项单独判断，不合法的只是不预填，不报错**。

- 编码（M8-04 验收问题 1 起）：每个编码只调一次 `GET /site/v1/places/by-code?code=`（只在渠道授权的城市里、只给启用的，不调谷歌），不逐城市扫描。找不到时在「你的行程」顶部 warning 提示「链接里的地点「NRT」没有找到，请在下面重新选择出发地和目的地。」；被限速或出错时「链接里的地点「NRT」暂时没有读出来，请稍后刷新页面，或在下面直接选择。」，都不自动报价。

## 10. 区域价的显示（M8-13，ADR 0073 第三部分第 4 节、第四部分）

后端是 M8-15（包车下车地点、区域加价）和 M8-11（点对点线路价、含公里数）。**这一节按 ADR 写，写的时候接口还没定稿**：字段名以 `openapi.yaml` 为准，页面行为以本节为准；需要后端给的列在 10.7。

两条总规矩：

1. **价格仍然只有一个数**。线路价、超出的公里、区域加价都是报价时就算进一口价的；下面的说明行只是告诉客人「这个价里有什么」，**不是另一笔费用，也不写成算式**（不写「基础价 + 超出 = 合计」：客人看到的每公里对外价是单独取整的，和总价可能差一个取整单位，ADR 0073 第四部分）。
2. **没设含公里数、没设区域加价的价格，和已经下了的订单，显示一个字都不变**（M8-13 验收第 3 条）。说明行只在报价或订单里有对应的数时才出现。

### 10.1 包车：下车地点必填

```
360px（手机第 1 步，选了「按小时包车」）
┌ 你的行程 ───────────────┐
│ [ 接送 | 按小时包车 ]     │
│ 上车地点 [京王广场酒店   ]  │
│ 下车地点 [河口湖站       ]  │  ← M8-13 新增，必填
│ 包车结束时在哪里下车，价格按 │
│ 上车和下车地点算。          │
│ 包车时长 [8 小时       ▾]  │
│ 日期 / 上车时间（当地）     │
│ 乘客 / 行李 [2 人 · 2 件▾] │
│ [  查看车型和价格  ] 吸底   │
└────────────────────────┘
```

- 字段顺序：服务 → 上车地点 → **下车地点** → 包车时长 → 日期、时间 → 乘客 / 行李。下车地点和上车地点是**同一个地址框**（3.3：输入即提示、地图选点、同样的状态行和出错），标签「下车地点」，帮助文字「包车结束时在哪里下车，价格按上车和下车地点算。」
- 地图选点从上车地点那里打开（3.3「从另一端打开」）。
- **没选下车地点不报价**：「选择车型」里的提示改成「选好上车地点、下车地点、包车时长、日期和时间后，这里会列出能坐下的车型和价格。」；手机上点「查看车型和价格」时，下车地点框标红「请选择下车地点」，焦点移过去（同其他必填项的写法）。
- 包车时长下拉仍按**上车地点**所在城市读（不变）。
- **链接参数**（第 5 节）：包车也用 `to` 当下车地点。旧链接只有 `from`（包车）没有 `to` 时：预填上车地点，下车地点空着并在框下面写信息提示「请选择下车地点，包车现在按上车和下车地点报价。」，不报错。旧预订页 `/book` 的包车跳到这里时带着它填过的东西（M8-15）。
- 手机第 2 步顶部的行程条：「包车 8 小时 · {上车} → {下车}」（地点名单行省略，完整的在读屏名里）。右侧栏「行程摘要」（4.5）：行程「包车 8 小时」、上车地点、**下车地点**、上车时间。
- 「怎么联系你」（第 7 节）里「按行程类型只带要的那一端」改为：包车两端都带（上车点、下车点）。

### 10.2 包车：「含区域加价」

报价里这一辆车的价格含了区域加价（上车或下车地点在供应商的加价区域里）时：

| 在哪 | 写什么 | 样式 |
| --- | --- | --- |
| 车型卡（4.2），价格下面 | 含区域加价，已算在这个价格里 | `font-size-sm`，`text-secondary`，靠右对着价格；放不下时折行 |
| 右侧栏 / 手机第 3 步的「车费」（第 8 节第 4 项）下面 | 同上 | 同上 |
| 订单页「行程」的「总价」下面（`site-booking.md` 5.4） | 含区域加价 | 同上 |
| 确认邮件（10.5） | 已付金额那一行后面「（含区域加价）」 | 纯文本 |

- **不写金额、不写是哪个区域**（ADR：不单列金额）。没有加价（两端都在商品的服务区域里，或加价是 0）不写。
- 不写「附加费」「另收」这类会让人以为要多付钱的话。

### 10.3 点对点：含公里数那一行

报价用的价格设了含公里数（10.7 的字段不为空）时，写一句：

| 情况 | 文字 |
| --- | --- |
| 超出了，超出单价大于 0 | 含 30 公里，本次路线约 34.2 公里，超出 5 公里 × 300 JPY（已含在一口价里） |
| 没超出 | 含 30 公里，本次路线约 28.4 公里，在含的公里数以内 |
| 超出了，超出单价是 0 | 含 30 公里，本次路线约 34.2 公里，超出的公里不另收 |

- X = 含公里数；D = 报价时的路线距离（`route_meters`），**向上取整到 0.1 公里**，整数不带 .0（`04-data-display.md` 第 9 节：避免「约 30.0 公里，超出 1 公里」这种看起来对不上的写法）；Z = 超出公里数（后端算好的整数，页面不重算）；Y = **每公里的对外价**（客人币种就是订单币种，按 `site-booking.md` 2.6 的写法「300 JPY」）。
- 放在哪：车型卡里车型标识下面一行（`.site-facts__item`，标签「公里数」）；右侧栏「车费」下面；订单页「行程」里「总价」后面一项「公里数」；确认邮件（10.5）。四处是同一句话，用同一个格式化函数。
- 右侧栏的路线一行（第 8 节第 2 项「约 X 分钟 · Y 公里」）在选了这种车型时也用同一个 D（向上取整到 0.1 公里），两处数字不能不一样。
- 这一行是**报价时锁定的**：订单页、邮件用订单上存的数，不按现在的路线重算；客人改了地址、改单生效后显示改单后订单上的数。
- 线路价本身（「东京 23 区 → 成田周边」这种）**客人看不到**：对客人只有一个价，用的是线路价还是区域价不写。

### 10.4 不在任何区域：转人工

- 包车上车地点或下车地点不在供应商的任何报价区域里（ADR 0073 第三部分第 1 节）：不报价，沿用现有的人工报价说法，**一个字不改**——「这个地址暂时没有在线报价，请联系客服」+ 客服电话（`tel:` 链接，登记了才有），warning 小框，同第 6 节「报不出价」。不管是上车还是下车那一端出的问题，都是这一句（客人不需要知道区域是什么）。
- 只是一部分车型报不出（某些车型组在这个区域没设加价）：那些车型不出现在列表里，不另外说明（和「坐不下的已隐藏」同一个做法）。
- 点对点设了含公里数的价格**拿不到路线距离**时这条价格不报价：同样只是那些车型不出现；全都报不出时按第 6 节「报不出价」，原因文字用同一句「这个地址暂时没有在线报价，请联系客服」（见 10.8 第 2 条）。

### 10.5 确认邮件（`order.confirmed`，发给客人）

ADR 0049 的模板，变量白名单里加两项**可选行变量**（同 `fee_note`：没有值时整行不出现）：

```
订单号：NZ2026…
用车时间：2026-11-20 09:00（当地时间）
行程：东京：京王广场酒店 → 河口湖站：包车 8 小时      ← 包车的 route 带上下车点（订单存了下车点后自然就有）
车型：…
已付金额：99,000 JPY（含区域加价）                   ← area_surcharge_note：「（含区域加价）」接在金额后面
公里数：含 30 公里，本次路线约 34.2 公里，超出 5 公里 × 300 JPY（已含在一口价里）   ← distance_note，只有点对点设了含公里数的单
费用说明：…
```

- 文字和 10.2、10.3 完全相同（同一个函数生成）。
- **发给供应商的邮件不加这两项**：ADR 0049 规定供应商邮件不写任何金额；行程里的下车点照常出现（route 是共用的）。
- 用车前提醒、改单等其他邮件不加（只在确认邮件里说一次价格构成）。

| 5 | 邮件模板变量 `area_surcharge_note`、`distance_note`（客人白名单，可选行） | 10.5 |
| 6 | `@nozomi/domain` 里生成 10.3 那句话和 D 的格式（向上取整到 0.1 公里）的函数，页面、邮件共用 | 10.3、10.5 |

> **M8-19 落地（2026-11-10）**：本分支落实 10.1、10.2（车型卡、右侧栏 / 手机第 3 步的「车费」）、10.4 和 10.6 第 2 条的包车下车地点（订单页「下车地点」、修改订单的「下车地址」；旧单没有下车点时都不显示）；10.3、10.5、10.6 第 1 条、订单页「总价」下面的「含区域加价」由 M8-13 做（官网订单应答还没有这一项）。10.5 见 m8-12 分支的规范。
> **M8-13 落地（2026-11-10）**：10.3（车型卡、右侧栏车费下面、订单页「公里数」，路线一行同一个 D）、10.5（确认邮件）、10.6 第 1 条（旧预订页卡片）、订单页「总价」下面的「含区域加价，已算在这个价格里」（按任务要求用和车型卡同一句全称，不用表里的短写）。官网订单应答的字段是 `includes_area_surcharge`、`distance`（ADR 0073「M8-13 落地时定下的细节」）；邮件里的「（含区域加价）」接在现有的「已付金额：JPY 99,000」后面（已付金额的写法不改）。
> 字段名以 `openapi.yaml` 为准：10.7 第 1 条的 `area_surcharge_included` 实际是 M8-15 给的 `includes_area_surcharge`；第 2 条 M8-19 已落实（`/site/v1` 包车询价不给 `dropoff` 是 400 `REQUIRED`，路径 `/dropoff`）；第 4 条用现有的 `OUT_OF_SERVICE_AREA`。

### 10.8 ADR 没写清的地方（按推荐的做法设计）

1. **路线距离 D 怎么取整显示**：推荐向上取整到 0.1 公里（10.3）。四舍五入会出现「约 30.0 公里，超出 1 公里」（实际 30.04 公里，按 ADR 向上取整到 1 公里是超出 1 公里），客人会以为算错了。
2. **含公里数的价格拿不到路线时，客人看到什么**：推荐沿用「这个地址暂时没有在线报价，请联系客服」（客人改不了地图服务，只能找客服），不另写一句。
3. **「含区域加价」写不写是哪一端**：推荐不写（ADR：不单列金额，客人不需要知道区域是什么）。
4. **没超出时要不要写这一行**：推荐写（「在含的公里数以内」），让客人知道这个价含多少公里，以后改目的地时不意外。

## 11. 报不出价：留下联系方式、人工报价（M8-21，ADR 0076）

一家供应商都报不出价时，客人除了看到「这个地址暂时没有在线报价，请联系客服」和客服电话（**原样保留，一个字不改**），还能留下联系方式请客服人工报价，或者直接用 WhatsApp 联系客服。

### 11.1 出现在哪

| 情况 | 位置 |
| --- | --- |
| 接送（接送机、点对点）报价列表为空（任何原因，含不在服务范围、没有商品、时间太近、坐不下） | 「选择车型」里「没有可预订的车」小框下面 |
| 渠道不卖这一段（`CHANNEL_SCOPE_DENIED`） | 「选择车型」里「没有在线报价」下面 |
| 包车报价列表为空 | 同第 1 行 |
| 包车上车地点不在任何能订包车的城市里、或那个城市没有包车套餐 | 「你的行程」最下面（乘客 / 行李下面）；同时「包车时长」换成通用的 1–12 小时下拉（帮助文字「没有在线报价时，选一个大概的时长，客服报价时会和您确认」），选了才能提交 |
| 旧预订页 `/book` 询价结果「没有可预订的车」 | 原因列表、客服电话下面 |

还没填齐行程、或有报价时不出现。

**报不出价时只有这一块（M8-21b，业主 2026-11-10 定）**：上表任何一种情况（新预订页的接送报价为空、渠道不卖这一段、包车报价为空、包车上车地点没有在线报价）都**不出现**第 7 节下单用的「怎么联系你」（姓名、邮箱、手机号、即时通讯、备注、同意保存银行卡）和「去付款」：电脑单页左列只有「你的行程」「选择车型」（警告小框 + 本节的表单和 WhatsApp 按钮），右侧栏照旧是行程摘要（「还没有选择车型」）；手机本来就到不了第 3 步。改了行程、报出价以后「怎么联系你」照旧出现（之前填的内容还在）。有报价时第 7、8 节一点不变。旧预订页 `/book` 的「怎么联系你」本来就在选车以后的下单页里，报不出价时页面上只有本节的表单，不用改。

### 11.2 表单

- 小节标题「请客服人工报价」（`h3`，旧预订页里同样 `h3`），白底卡片（`color-bg-surface`、`border-default`、`radius-md`），放在 warning 小框下面，不放在里面。
- 说明一句：「留下邮箱或 WhatsApp（至少一项），客服核对行程后联系您报价。行程会自动带上，不用再填。」
- **只有两个框**（业主 2026-11-10 定）：「邮箱」（`type=email`、`autocomplete=email`）、「WhatsApp」（`type=tel`、`autocomplete=tel`，帮助文字「以 + 和国家码开头，如日本 +81、中国 +86；可以有空格」）。≥ 768px 并排，更窄上下排。没有姓名、备注、勾选框。
- 提交按钮「提交」（主按钮、lg）；**按钮右边**一行小字「提交即同意客服通过您留下的方式联系您」（`font-size-sm`、`text-secondary`），窄屏折到按钮下面。点提交就是同意，不另加勾选框。
- 陷阱字段 `website`：人看不到（裁成 1px，不用 `display: none`）、键盘到不了（`tabindex=-1`）、读屏读不到（`aria-hidden`）。
- 行程由页面自动带上：用车类型（接送按报价识别的接机 / 送机 / 点对点；认不出时两端有机场算接送机）、城市（认得出时）、两端名称和坐标、当地日期时间、人数、行李、包车时长。

### 11.3 校验和提交结果

| 情况 | 显示 |
| --- | --- |
| 两项都没填 | 邮箱框下面「请至少填一项：邮箱或 WhatsApp」，焦点到邮箱；填了任何一项这句收起 |
| 邮箱格式不对 | 邮箱框下面「邮箱的格式不对，请写完整，如 name@example.com」 |
| WhatsApp 不以 + 开头、位数不对 | WhatsApp 框下面「WhatsApp 号码请以 + 和国家码开头（如日本 +81、中国 +86），共 8 到 15 位数字」 |
| 行程不齐（包车没选时长、没选日期时间） | 表单顶部 danger 提示「请先在上面选好…，再提交。」，不提交 |
| 接口 400 点名 `/email`、`/whatsapp` | 落在对应的框下面 |
| 429 | 「操作太频繁了，请 N 分钟后再试。」（有 WhatsApp 按钮时接「也可以点下面的「通过 WhatsApp 联系我们」。」）；填的内容还在 |
| 断网、5xx | 通用说法 + 同上；填的内容还在 |
| 成功（接口一律 202） | 表单换成一行 `role=status`：「已收到。客服会通过您留下的邮箱或 WhatsApp 联系您报价，请留意消息。」（success 图标）。重复提交也是这一句，不说明有没有记上 |

改了行程（任何一项）表单重新出现（清空）。

### 11.4 「通过 WhatsApp 联系我们」

- 在表单（或「已收到」那一行）下面，次按钮样式的链接（lg、对话气泡图标），新标签页打开（`rel="noopener noreferrer"`，读屏多读「（在新标签页打开）」）。
- 号码来自 `GET /site/v1/config` 的 `support_whatsapp`（运营后台「系统设置 → 官网设置」的「客服 WhatsApp 号码」）；**为 null 时整个按钮不显示**。
- 链接 `https://wa.me/<号码>?text=<编码后的一句话>`，这句话由 `@nozomi/domain` 的 `manualQuoteWhatsappText` 生成：「您好，我想咨询用车报价：点对点，新宿站 → 成田机场，2026-12-01 09:30，2 人。」（包车加「N 小时」）。只有行程要点，没有客人的任何个人信息。行程不齐时只写「您好，我想咨询用车报价。」

### 11.5 断点、亮暗

- 320 / 390 宽不横向滚动；按钮文字可以折行（`white-space: normal`）。
- 亮暗两色只用令牌；axe 无问题（e2e `manual-quote.spec.ts`）。
