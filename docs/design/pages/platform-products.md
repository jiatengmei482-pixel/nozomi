# 供应商的商品、报价试算（运营后台）

M1-12 的页面：运营后台的「商品」（所有供应商的商品，只读）——列表、详情；供应商详情页里的「商品」一栏；首页的「商品」卡片；「报价试算」。
接口见 ADR 0021（`GET /platform/v1/products`、`/products/{id}`）和 ADR 0020「两个试算接口」（`POST /platform/v1/quotes/preview`），字段以 `apps/api/openapi.yaml` 为准。
**本任务没有新增令牌和组件**：列表沿用表格、筛选条、游标分页（`02-components.md` 第 5、6 节）；详情沿用供应商后台商品页的步骤导航和各步骤的**只读模式**（`tenant-products.md` 3.7），不另画一套；试算用坐标输入、单选组、组合框、时间与日期输入（第 3、27 节）。新加一个线性图标「计算器」（报价试算的菜单项）。

界面上一律叫「供应商」「商品」「结算价」「对外价」「加价比例」，不写 tenant、product、settlement、markup。

## 1. 概览

| 页面 | 给谁用 | 要完成什么 |
| --- | --- | --- |
| 商品列表 | 运营、招商、渠道经理、客服、风控、只读、超级管理员 | 找到某家供应商的某个商品；看它上没上架、有没有可以卖的价格；回答「供应商说已经上架了，平台看得到吗」 |

| 供应商详情里的「商品」 | 同上（还要能看供应商：`tenant.read`） | 在供应商详情里直接看到这家有哪些商品 |

### 3.1 首屏看到什么

```
┌ 配置步骤  已完成 5 / 5 ┐ ┌ ① 基础信息 ……（供应商后台同一个组件，只读）┐
│ ① 基础信息 ✓ 已完成   │ │                                            │
│ ……                   │ │                                            │
│ 上架检查   ✓ 已上架   │ │                                            │
└──────────────────────┘ └────────────────────────────────────────────┘
```

- 页面类型「分步编辑」的版式（`03-layout.md` 第 2 节），但**全部只读**：用的是供应商后台商品页的步骤导航和各步骤组件，带只读参数（`tenant-products.md` 3.7 的样子）——字段是只读样式、没有操作区、没有「更多」菜单、上架检查没有「上架」「下架」，「去修改」「去填」都换成「去查看」，每一步底部「回到列表」。**页面上没有任何修改的入口**，不会发出任何写请求。
- 标题行下一行比供应商后台多三项：**供应商**（有 `tenant.read` 的是链接）、**子品牌**、**版本 {N}**（商品只有一个版本号，任何一步保存都会变；供应商说「我刚改了」时对得上）、**上架时间**。
- 「回到列表」回到来的地方：从商品列表来的回列表（带着筛选和翻页），从供应商详情来的回供应商详情，直接打开地址的回商品列表。
- 和供应商后台的差别（接口只给了这些）：
  - **③ 价格规则**只有「价格规则」「调价规则」两个页签，没有「价格日历」（平台侧没有日历接口，ADR 0021「本期不做」）；没有「导入 / 导出」。
  - **④ 库存**不是库存日历，是一张卡片：库存模式（不限量 / 限量）；限量时「从今天起有库存的日子：{N} 天」，0 天写三角 +「从今天起没有库存，卖不出去」（`warning-text`）；说明「每一天设了多少、卖了多少在供应商后台的「库存」里看，运营后台现在只看得到模式和还有几天有库存。」
- 页面级提示条（都不能关闭）：信息「这是供应商「{名称}」的商品……」；供应商已暂停时警告「**这家供应商已暂停。** 暂停期间它的商品不参与比价、不接新订单。」；城市 / 接送点 / 子品牌被停用时警告「**这个商品的{城市}「{名称}」已停用。** 商品不能上架、不会参与报价。」

## 5. 报价试算

### 5.1 首屏看到什么

```
报价试算
填一次用车请求，看所有供应商一起比价的结果……只是试算，不会生成可以下单的报价，也不占库存。
┌ 用车请求 ───────────────────────────────────────────────┐
│ 城市 * [组合框]                品类 * ( )接送机 ( )点对点 ( )包车 │
│ 机场或车站 * [组合框]           方向 * ( )接机 ( )送机          │   ← 接送机才有；车站写接站 / 送站
│ 上车点 / 下车点：纬度 [ ] 经度 [ ]（可以粘贴「纬度, 经度」）        │   ← 按品类和方向只出现要填的
│ 套餐时长（小时）                                              │   ← 包车才有
│ 用车时间：日期 [2026-10-08] 时刻 [08:00]  按{城市}当地时间（{时区}）填写 │
│ 人数 [ ]   行李数（选填）[ ]                                    │
│ 客人支付的币种 [请选择 ▾]                                      │
│ 假定的里程和时长（选填）：里程（公里）[ ] 时长（分钟）[ ]           │
│ [试算]  清空重填                                              │
└────────────────────────────────────────────────────────────┘
试算结果（有结果后出现，焦点移到这个标题）
```

- 页面类型「列表、看板」的宽度；表单卡片限制在 `layout-form-max-width`，结果用满宽度。
- **要填哪几个点和后端是同一个规则**（`@nozomi/domain` 的 `quoteCheckPoints`）：接机只要下车点、送机只要上车点（机场那一端用接送点），点对点两端，包车只要上车点。方向没选时先不出坐标。
- 坐标先用输入框（纬度在前，`02-components.md` 坐标输入）；以后有了地图选点再加「在地图上选」。
- 用车时间按城市当地时间解释；日期、时刻用普通输入框，失去焦点时整理写法（第 27 节）。
- 假定的里程和时长：不填就按谷歌地图预估的路程算（M2-02，ADR 0042）；填了就按假定值算，用来试「如果路程是这么多」；要么都填、要么都不填。
- 校验：点「试算」时全部校验，有错的在字段下方，表单顶部「有 N 处需要修改」并可点跳过去，焦点到第一处。后端 400 指出的字段落到对应的地方；409 `MASTER_DATA_NOT_READY` 落在城市（或机场 / 车站）下面：「这个城市已被平台停用，现在不报价。请换一个，或先到主数据里启用它。」；网络不通、服务器出错：表单顶部「试算没有成功。……你填写的内容还在。」

### 5.2 结果

- 第一行概况：「找到 {N} 个已上架的商品，{K} 个车型组报出了价。{M} 个商品有没报出价的，原因见最下面。」用了路程时加「用的路程：{X} 公里、{Y}」；最后「加价比例不低于 {下限}%」。
- **每个车型组一张卡片**（`<h3>` 车型组名，包车加「· {N} 小时套餐」）：
  - 第一行（对勾，`success-text`）：「中标：**{供应商}**（{商品编号}） · 对外价 **{金额}** · 结算价 {金额}」。
  - 全部候选的表（按名次）：名次（第一名后面 `success` 徽标「中标」）、供应商 / 商品、结算价（结算币种）、对外价（表头写客人支付的币种）、加价比例、排序价、在同价区间（在 / 不在）、明细。观察期的供应商在名字下面加标签「观察期（排序价按对外价加 5%）」。
  - 「看明细」（文字按钮，`aria-expanded`）在这一行下面展开结算价是怎么来的：基础价、调价（每条规则「上调 20%（+JPY 4,000）」和合计，含取整尾差）、加急费、夜间费、附加服务、司机语言（有才写）、取整前、取整（「取整到 JPY 100」/「四舍五入」）、结算价、按多少路程算、换算成客人支付的币种（汇率、汇率时间、汇率缓冲；同币种写「不用换算」）、对外价、免费等待。
  - 卡片底部一句规则说明：同价区间、谁中标、客人付的是中标者自己的对外价。
- 用了路程时，概况里「用的路程」后面写明来源：「来自缓存」/「刚调用谷歌地图」/「起终点几乎重合，按 0 计算」/「你填写的假定值」。
- **没取到路线时**（接口的 `route_status` 为 `unavailable`）：结果上方一条 `warning` 提示条，写出原因码（等宽）、中文说明和怎么办，并说明「一口价和包车不受影响；可以填假定的里程和时长再试算」。
- **没报出价的**：一张表——供应商 / 商品、车型组（整个商品报不出时写「整个商品」）、原因（后端写好的中文原因，原样显示）。
- 一个候选商品都没有：「没有可以比价的商品」「「{城市}」的{品类}还没有已上架的商品。」+ 链接「去商品列表看看」（带着城市、品类、已上架）。有候选但一个车型组都没报出价：警告提示条「一个车型组都没有报出价。」「原因见下面「没报出价的」。」

## 9. 未覆盖需求（M8-20，ADR 0075 第四部分）

客人询价时一家供应商都报不出价，平台自动记的一条。运营据此联系供应商补报价区域（原因多是「在运营区域里，但没有报价区域」的地方），招商据此找新供应商（「不在任何运营区域里」多的地方）。

**菜单与权限**：运营后台菜单「未覆盖需求」（图标 target，排在「报价试算」后面，和商品、区域地图、报价试算同属「商品与报价」这一段），`demand.read`（超级管理员、运营、招商、渠道经理；客服、财务、风控、主数据运营、技术、只读没有）。地址 `/platform/uncovered-demands`，面包屑 `商品 / 未覆盖需求`。没有权限时「你没有权限查看这里」「需要的话，请联系管理员开通「未覆盖需求 · 查看」。」，不取数据。
