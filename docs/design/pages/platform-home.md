# 运营后台首页、运营后台菜单

M1-08 的页面。组件和令牌见上一级目录的规范；首页用到的「入口卡片」在 `02-components.md` 第 18 节。

本文只管运营后台（`/platform`）。供应商后台的首页暂时保持 M0-07 的样子（一张「当前登录」卡片），等供应商后台有了第一批模块再单独写。

## 1. 首页

### 1.1 给谁用、要完成什么

| 给谁用 | 要完成什么 |
| --- | --- |
| 所有平台员工，登录后的第一个页面，每天打开很多次 | ① 一眼看到有没有等着自己处理的事；② 一步进入要去的模块；③ 顺带知道各模块里大概有多少东西 |

首页不是报表：只放「数量」和「需要处理的提醒」，不放趋势图、金额、排行。订单量、GMV 这些等订单模块上线后做成单独的「总览」内容再加进来。

（图里的数字只是示意排版，页面上的数字全部来自接口。）

首屏（1280×720，不滚动）必须看到：全部分区标题、全部卡片、卡片上的提醒行。目前一共五张卡片，一屏放得下。

- 页面类型「列表、看板」，最大宽度 `layout-content-max-width`。
- 页面标题 `<h1>`「首页」，标题行没有主操作按钮。浏览器标签页标题「首页 · NOZOMI 运营后台」。
- **去掉现在的「当前登录」卡片**：姓名、角色、邮箱在顶栏的账号菜单里已经有了，首屏留给入口和提醒。
- 分区：每个分区一个 `<section>`，标题是 `<h2>`（`font-size-lg`，`font-weight-bold`），标题与卡片间距 `space-3`，分区之间 `space-8`。分区里是入口卡片的栅格（`repeat(auto-fill, minmax(min(240px, 100%), 1fr))`，间距 `space-4`）。
- 卡片宽度跟着栅格走，不固定；一行放几张由宽度决定（1280px 宽、侧边栏常驻时一行 4 张）。

### 1.3 分区和卡片

分区、卡片的顺序与侧边栏菜单一致（第 2 节）。**只显示当前角色有权限看的模块的卡片**；一个分区里一张卡片都没有时，整个分区（连标题）不显示。

| 分区 | 卡片 | 点了去哪 | 数量行 | 提醒行 | 谁能看到 |
| --- | --- | --- | --- | --- | --- |
| 运营 | 供应商 | 供应商列表页还没做：**卡片只显示数量，不是链接**（见下） | 「{N} 正常 · {N} 已暂停」 | 无 | 能看供应商的角色（超级管理员、运营、招商、只读） |
| 主数据 | 城市 | 城市列表 | 「{N} 启用 · {N} 已停用」 | 条件见下 | 全部角色 |
| 主数据 | 地点 | 地点列表（机场页签） | 「{N} 启用 · {N} 已停用」 | 「{N} 个机场待指定城市」→ 处理导入的机场 | 全部角色 |
| 主数据 | 车型组 | 车型组列表 | 「{N} 启用 · {N} 已停用」 | 无 | 全部角色 |
| 主数据 | 附加服务 | 附加服务列表 | 「{N} 启用 · {N} 已停用」 | 无 | 全部角色 |

**数量行的写法**

- 每组是「数字 + 说明」：「12 启用」「3 已停用」。说明用的词和列表页的状态徽标完全一样（主数据：启用 / 已停用；供应商：正常 / 已暂停），用户在首页看到的词和点进去看到的词对得上。
- 两组都显示，即使其中一个是 0（「8 启用 · 0 已停用」）。不把 0 的那组藏起来，否则卡片高度和内容会随数据跳。
- 「地点」的数量是机场、车站、地标三类合计，**不含航站楼和出口**（它们是机场、车站的下级，不在地点列表里单独成行）。

**提醒行的规则**

| 卡片 | 什么时候显示 | 文字 | 点了去哪 |
| --- | --- | --- | --- |
| 地点 | 待指定城市的导入机场数量 > 0 | **{N} 个机场待指定城市** | 「处理导入的机场」页（`master-data.md` 第 4 节）。没有修改主数据权限的角色：去地点列表并筛好「待指定城市」，只能看 |
| 城市 | 启用的城市数量是 0，**并且**待指定城市的机场数量 > 0 | **先新增城市，才能给机场指定城市** | 新增城市页。没有修改权限的角色不显示这一条 |

- 提醒只放「有人不处理就会一直卡在那里」的事。「已停用 3 个」这种只是数量，不是提醒。
- 提醒行用警告色（黄色）+ 三角图标 + 文字，三者同时出现；不用红色，红色留给超时和失败。
- 以后别的模块的提醒（待审核的供应商、超时未派车的订单）也按这个格式写在各自的卡片上。

**还没有页面的模块（现在只有「供应商」）**：卡片上模块名是普通文字，没有箭头，不可点，不可聚焦；数量照常显示。供应商列表页做出来以后，把它换成链接即可，位置不变。不放点了没用的入口。

### 1.4 数据从哪来

一次请求：`GET /platform/v1/dashboard/summary`（后端在 M1-08 里同时在做；下表按写本文时分支上的 `apps/api/openapi.yaml`，合并时字段有变以合并后的为准）。

| 卡片 | 数量取自 |
| --- | --- |
| 供应商 | `tenants.active`（正常）、`tenants.suspended`（已暂停） |
| 城市 | `master_data.cities.active`、`.disabled` |
| 地点 | **机场 + 车站 + 地标三类相加**：`master_data.places.by_type.airport` / `.station` / `.poi` 各自的 `active`、`disabled`。**不要直接用 `places.active` / `places.disabled`**，那是连航站楼、出口一起算的 |
| 地点的提醒行 | `master_data.places.airports_without_city` |
| 车型组 | `master_data.vehicle_groups.active`、`.disabled` |
| 附加服务 | `master_data.addons.active`、`.disabled` |

- 当前角色没有权限的模块，接口返回 null（`tenants` 为 null → 没有供应商卡片；`master_data` 为 null → 没有主数据分区）。前端**不**自己再按角色判断一遍「该不该有数量」，以接口返回为准；「卡片是不是链接、提醒行去哪」按第 1.3 节用角色的操作权限判断（`@nozomi/domain` 的 `platformRoleCan`）。
- 各个 `total` 字段首页不用。
- 进入首页时请求一次；从别的页面回到首页时重新请求；窗口重新获得焦点且距上次请求超过 60 秒时重新请求。不做定时轮询。
- 重新请求期间保留旧数字（按 `02-components.md` 第 12 节「已有内容，正在刷新」的做法，但首页不显示进度条、不降低不透明度——数字只是参考，没必要闪）。

### 1.5 各种状态

| 状态 | 显示什么 |
| --- | --- |
| **加载中**（第一次） | 分区标题和卡片**立即显示**，标题链接马上可以点（入口不等数量）；每张卡片的数量行是一条骨架灰块，没有提醒行。显示哪些卡片：此时还不知道接口会返回哪些模块，先按角色的操作权限决定（能看主数据的显示四张主数据卡片，能看供应商的显示供应商卡片）。请求 300ms 内返回则不显示骨架 |
| **加载成功** | 数量和提醒行填进去。卡片高度变化只允许来自提醒行的出现 |
| **加载失败**（网络不通、服务器出错） | 页面标题下方一条危险提示条：标题「数量没有加载出来」，正文「入口可以照常使用。请检查网络后重试。」，带文字按钮「重试」。所有卡片照常显示、照常可点，数量行显示「—」，没有提醒行。点「重试」后提示条消失、数量行回到骨架，再按结果显示 |
| **刷新失败**（之前成功过，这次重新请求失败） | 保留上一次的数字，不显示提示条，不打扰（下次进入首页会再请求） |
| **数量为 0** | 照常显示「0 启用 · 0 已停用」。卡片不隐藏、不换成「还没有数据」之类的话——点进去以后，列表页的空状态会说明下一步做什么 |
| **没有权限** | 没有权限的模块没有卡片，不显示成灰掉的卡片，也不显示「你没有权限」。目前每个平台角色都能看主数据，所以首页不会一张卡片都没有；如果将来出现这种情况，内容区显示空状态：标题「这里暂时没有你可以使用的模块」，说明「需要的话，请联系管理员开通。」，没有按钮 |
| **加载时间过长**（超过 10 秒） | 按失败处理 |
| **登录已过期**（401） | 跳到登录页（全局行为） |

首页上的一处失败不影响别处：侧边栏、顶栏、其他卡片都照常可用。

### 1.6 手机宽度

- 页面边距 `space-4`。栅格的 `min(240px, 100%)` 保证 < 512px 时一行一张卡片、撑满宽度；512–767px 一行两张。
- 卡片内三行都允许折行：数量行的两组在放不下时折成两行；提醒行的文字折行，箭头留在第一行右侧。
- 卡片在触屏上整张可点，高度自然 ≥ 72px，够大，不需要另外放大。
- 分区之间 `space-6`（比桌面的 `space-8` 小一档）。
- 在 320、360、400 三个宽度下，对「加载中、加载成功（有提醒行）、加载失败、侧边栏滑出」四个状态各检查一次横向溢出。

### 1.7 键盘与无障碍

- Tab 顺序：跳到正文 → 顶栏 → （失败时的「重试」）→ 各分区的卡片，从左到右、从上到下；每张卡片先标题链接，再提醒链接。
- 卡片的标题链接读作「城市，12 启用，3 已停用」：给链接加 `aria-describedby` 指向数量行。提醒链接读作它自己的文字。
- 数量加载完成不抢焦点，也不逐个播报；页面里放一个只给读屏的 `role="status"`，加载完成后内容是「数量已更新」，加载失败由提示条的 `role="alert"` 读出。
- 亮色、暗色各看一遍：卡片（`bg-surface`）和页面底色（`bg-page`）分得开；提醒行（`warning-bg` 上的 `text-primary` 文字、`warning-text` 图标）读得清；悬停时的 `border-strong` 边框看得见。

### 1.8 模块多了以后怎么排

现在 5 张卡片。以后每做出一个有列表页的模块，就按下面的规则加，不用重新设计首页：

1. **一个菜单项一张卡片**，卡片顺序 = 菜单顺序，分区 = 下面第 2 节菜单的分组（一级菜单里没有子项的那些，统一放在第一个分区「运营」里）。
2. 分区顺序固定：运营 → 主数据 → 系统设置。日常要处理的在上面，偶尔才配置的在下面。
3. 每张卡片最多 3 组数量、2 条提醒；想放更多说明这个模块需要自己的总览页。
4. 卡片总数超过 12 张、或者同时出现的提醒经常超过 3 条时，在页面标题下面加一个「待处理」分区，把所有卡片的提醒行集中列在最上面（每条一行，格式同提醒行，前面加模块名），卡片上的提醒行保留。在此之前不加，避免同一条提醒在首屏出现两次。
5. 订单模块上线后，「运营」分区上方加一个「今日」分区放订单数量和异常待办（需求文档里「总览」菜单的内容），届时另写规范。

## 2. 运营后台菜单的分组与顺序

顺序依据需求文档《平台运营端与渠道对接》「运营后台菜单与角色」的 13 个一级菜单；文字改成用户的说法（界面上叫「供应商」，不叫「租户」）。

**菜单只列已经做出来的页面**，没做的不占位置；做出来一个加一个，位置按下表。只显示当前角色有权限的项。

| 顺序 | 一级菜单 | 子项 | 图标 | 谁能看到 | 现状 |
| --- | --- | --- | --- | --- | --- |
| 1 | 首页 | — | 房子 | 全部 | 已有 |
| 2 | 供应商 | — | 楼房 | 超级管理员、运营、招商、只读 | 页面未做，暂不显示 |
| 3 | 渠道 | — | 分叉箭头 | 渠道经理 | 未做 |
| 4 | 连接器 | — | 插头 | 技术、渠道经理 | 未做 |
| 5 | 订单 | — | 单据 | 客服、运营 | 未做 |
| 6 | 工单 | — | 对话气泡 | 客服 | 未做 |
| 7 | 比价监控 | — | 柱状图 | 运营、招商 | 未做 |
| 8 | 财务结算 | — | 钱包 | 财务 | 未做 |
| 9 | 风控 | — | 盾牌 | 风控 | 未做 |
| 10 | **主数据** | **城市、地点、车型组、附加服务**（按这个顺序） | 数据库（圆柱） | 全部角色（都能看；只有主数据运营、超级管理员能改） | **M1-08 新增** |
| 11 | 通知中心 | — | 铃铛 | 运营 | 未做 |
| 12 | 报表 | — | 折线图 | 运营 | 未做 |
| 13 | 系统设置 | 平台账号、审计日志、集成状态 | 齿轮 | 各子项按权限 | 页面未做，暂不显示 |

所以 M1-08 做完后，侧边栏是这样：

```
NOZOMI  运营后台
─────────────────
⌂ 首页
▾ 主数据
     城市
     地点
     车型组
     附加服务
```

- 「主数据」是分组项，点它只展开 / 收起（样式和行为见 `02-components.md` 第 10 节）。默认展开；用户收起后记住。
- 主数据子项的顺序是「先有城市，才能有地点」的依赖顺序，其后是车型组、附加服务。以后加的汇率、节假日、详情模版排在附加服务后面。
- 「地点」一个菜单项管机场、车站、地标（页面里用页签切换），不拆成三个菜单项：三者的字段和操作几乎一样，需求文档里也是同一套「接送点」。
- 地址（供前端对照，可按路由实现调整，但要保持「列表 / new / :id」的结构）：

| 页面 | 地址 |
| --- | --- |
| 首页 | `/platform` |
| 城市列表 / 新增 / 编辑 | `/platform/master/cities`、`…/cities/new`、`…/cities/{id}` |
| 地点列表 / 新增 / 编辑 | `/platform/master/places`、`…/places/new`、`…/places/{id}` |
| 处理导入的机场 | `/platform/master/places/pending` |
| 车型组列表 / 新增 / 编辑 | `/platform/master/vehicle-groups`、`…/new`、`…/{id}` |
| 附加服务列表 / 新增 / 编辑 | `/platform/master/addons`、`…/new`、`…/{id}` |

- 面包屑：`主数据 / 城市`、`主数据 / 城市 / 新增城市`、`主数据 / 城市 / {显示名}`。「主数据」这一级不是页面，是普通文字不是链接。< 768px 只显示最后一级。
- 需要新增的图标（线性、16px，和现有图标同一套画法）：数据库、楼房、向右箭头、向左箭头、加号、放大镜、叉号、复制、筛选（漏斗）、更多（三个点）、外链。其余菜单的图标等对应页面做的时候再加。
