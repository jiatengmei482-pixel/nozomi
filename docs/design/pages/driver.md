# 司机页（司机 H5）

对应实现：`apps/web/src/pages/driver/DriverTripPage.tsx`；样式：`apps/web/src/styles/driver.css`（版式）和 `dispatch.css` 里 `.driver-` 开头的区块规则。业务规则见 ADR 0027、0064；M6 视觉改版见 ADR 0066（M6-04）。

## 1. 给谁用

接了这一单的司机。没有账号，从调度发的链接（`/driver#<令牌>`）打开。只在手机上用，人在车上或路边，常常单手、强光、赶时间。

## 2. 要完成什么

- 看清这一单：什么时候、在哪儿接、接谁（人数、行李、航班）、送到哪儿；一键打电话给客人和调度、一键导航到上车点。
- 按顺序回传履约：我出发了 → 已到达上车点 → 接到客人了 → 完成（包车完成时先填实际分钟、公里）。
- 接机：拍到达屏、填实际落地时间。
- 客人没出现：记联系、拍举牌照片、申请离开、提交「客人未出现」。

页面上没有任何价格。

## 3. 从上到下看到什么

360px 宽的手机上，首屏能看到标题、状态、客人和行程，屏幕底部是吸底的「下一步」按钮条（第 3b 节，M6-08，业主 2026-11-13 决定）：信息顺序不变，不用往下滑就能点。

从上到下（320–400px 宽都一样，不横向滚动）：

1. **品牌色带**：比登录页矮（9rem），只放「NOZOMI」标识；右上角是主题切换（垫 `bg-surface` 底板）。告诉司机这是 NOZOMI 的单。
2. **卡片**（手机上几乎占满屏宽，两边各留 `space-2`）：正文 16px（`font-size-lg`），比后台大一号。
   - 标题：方向 · 用车时间（`font-size-3xl`），最重要的一行。
   - 订单状态徽标：比后台大一号、加粗，仍是颜色 + 圆点 + 文字；旁边是订单号（等宽、次要文字色）。
   - 「客人」「行程」两块：区块标题用次要文字色做小标签；**客人和人数行李、航班、上车、下车**四行是关键信息，`font-size-xl` 加粗；电话号码大号、至少 44px（触屏）高，点了就拨号。坐标、免费等待、车辆是次要信息，用正文或提示字号。
3. **下一步**面板：主色描边的框，留在行程之后的原位置，里面是区块标题「下一步」、包车完成时的「实际用了多少分钟」「实际跑了多少公里」两个输入框、「点按钮时会带上手机的定位…」一行提示。页面上**唯一的主按钮**（整宽，比普通大按钮再高 `space-4`，`font-size-xl` 加粗）在吸底按钮条里（第 3b 节）。还没到可以点的时间时，按钮下面是一条警告色提示条，写明「还没到时间：最早几点（当地时间）」，用 `aria-describedby` 关联到按钮，和按钮一起在吸底按钮条里。
4. 后面按需要出现「航班落地」「客人没出现时」「已记录」，都是整宽的次要按钮（描边），至少 48px（触屏）高，字长时换行；「提交『客人未出现』」是危险按钮，证据不齐时禁用。证据清单每项一条：齐了的成功色底 + ✓，还差的灰底 + ✗。
5. 最后一行：链接有效期，分隔线隔开，提示字号。

## 3a. 包车的下车地点（M8-13，ADR 0073 第三部分第 4 节）

M8-15 起官网包车必须填下车地点，订单上存着下车点（坐标 + 地址）。司机页「行程」一块：

- 「下车：{地址}」照现在的写法，是关键信息（`font-size-xl` 加粗）；包车单现在也有真实的下车地址了。
- 有下车点坐标时，下面加一个文字链接「导航到下车点」（不是按钮：页面上的大按钮只给「导航到上车点」和「下一步」；链接的可点区域至少 44px 高）和一行提示字号的「下车点坐标：…」，写法同上车点。
- **旧的包车单没有下车点**：写「下车：没有指定（包车，按客人安排）」，不写「—」（司机会以为是漏了）。
- **页面上仍然没有任何价格**：不显示区域加价、含公里数、超出公里数，也不显示「区域」这个说法。
- 320–400px 不横向滚动；长地址任意位置折行。

## 3b. 吸底按钮条（M6-08；来源：业主 2026-11-13 决定）

司机在车上、路边单手操作，任何滚动位置都要按得到「下一步」，同时不打乱司机已经熟悉的信息顺序。做法和新预订页手机的底部固定条（`site-booking-v2.md` 第 2 节）相同：

- **内容**：主按钮（「我出发了」「已到达上车点」「接到客人了」「服务完成」），有「还没到时间」提示时提示条在按钮下面，同在条里。不放别的东西（包车的两个输入框和定位说明留在「下一步」面板里）。
- **包车「服务完成」缺分钟或公里**：按钮禁用，按钮下面一行提示字号、`text-secondary` 的「先填实际用了多少分钟和公里数」，在按钮条里，用 `aria-describedby` 关联到按钮；两项都填了数字后提示去掉、按钮可点。同时有「还没到时间」时两条都关联。
- **样式**：固定在视口底部，左右贴边；底 `bg-surface`，上边线 `border-default`，`shadow-md`，层级 `z-sticky`；内边距上下 `space-3`，底部再加 `env(safe-area-inset-bottom)`。左右内边距让按钮和卡片里的内容对齐：手机上是页面边距加卡片内边距（`space-2` + `space-4`），更宽时按卡片宽（`layout-auth-card-width`）居中、内缩 `space-6`。按钮和提示条之间 `space-3`。
- **所有宽度都吸底，有意统一**：司机页只在手机上用；平板、电脑上同样吸底，不另做一套版式（少一种状态要测、要维护），按钮条的内容跟卡片对齐。
- **不挡内容**：按钮条的实际高度由页面用 ResizeObserver 量出来（字号放大、更窄、提示出现或消失都会变），写在 `<html>` 的 `--driver-bar-height` 上。这是量出来的长度，不是设计令牌，样式检查只放行这一个变量和这一处写法。页面底部留出这个高度再加 `space-6`，滚到底时最后一行（链接有效期）完整显示在按钮条上面；滚动容器（`<html>`）的 `scroll-padding-bottom` 是这个高度再加 `space-4`，用 Tab 或输入时滚到的链接、按钮、输入框停在按钮条上面。量到之前（不支持 ResizeObserver 的浏览器）按「上下内边距 + 主按钮 + 上边线 + 安全区」估。
- **无障碍**：只是视觉上固定，DOM 位置不变——仍在「下一步」区块里、调度电话之后、「航班落地」之前，Tab 顺序、读屏顺序、按钮的读屏名都照旧。亮、暗两套对比照 `01-tokens.md`；320 / 360 / 390px 不横向滚动；axe 零违规。
- **没有下一步**（已完成、已取消、客人未出现等）时没有按钮条，页面底部照旧。
- 出错提示条仍在卡片顶部（焦点移过去），不放进按钮条。

## 4. 空状态和出错

- **链接不完整**（`#` 后面不是合法令牌）：标题「链接不完整」，下面一句「请从调度发给你的消息里重新打开完整的链接。」
- **加载中**：标题「这一单」，下面「加载中…」。
- **链接无效或已过期 / 网络失败**：标题「这一单」，下面红色提示条（`role="alert"`），写明怎么办（联系调度重新发送、检查网络后重试）。
- **操作失败**（太早、状态已变、照片太大等）：卡片顶部的红色提示条，焦点移过去，读屏读出；页面同时刷新到最新状态。
- 没有「空」的情况：链接对应的就是一张单；没有下一步（已完成、已取消）时不显示「下一步」面板。

## 5. 检查清单

- 亮、暗两套；320px、360px 不横向滚动；Tab 能到每个按钮和链接，聚焦环清楚；axe 零违规。
- 320 / 360 / 390px 打开链接不滚动就看得到「下一步」按钮和「还没到时间」提示；滚到底最后一行不被吸底按钮条挡住（第 3b 节）。
- 颜色只用 `01-tokens.md` 允许的搭配：提示条 `text-primary` / `warning-bg`，清单 `success-text` / `success-bg`、`text-secondary` / `bg-subtle`，提示文字 `text-secondary`（户外比 `text-tertiary` 更清楚）。
