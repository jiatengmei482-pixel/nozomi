# 系统设置：平台员工、审计日志、系统状态（运营后台）

M1-10 的页面，都在运营后台菜单的「系统设置」分组下。同一个任务里的供应商管理见 [`platform-tenants.md`](./platform-tenants.md)；**新增员工、发密码重置时「一次性链接」怎么交付，规则全部在那篇的第 2 节，本文不重复**。本文用到的新组件：一次性链接、改前改后对照（`02-components.md` 第 37、38 节）。**本任务没有新增令牌。**

依据：《平台运营端与渠道对接》「运营后台菜单与角色」；ADR 0008、ADR 0013、ADR 0041（第三方密钥，4.1 节）；`apps/api/openapi.yaml` 的 `/platform/v1/staff*`、`/audit-logs`、`/integrations`；`packages/domain/src/access.ts`。接口从 M0-06 起就有，本文按接口现在的样子写；缺的列在第 6 节。

标了 **［需负责人确认］** 的汇总在第 7 节。

目录：1 概览 · 2 平台员工 · 3 审计日志 · 4 系统状态（4.1 第三方密钥） · 5 手机宽度、键盘、文案 · 6 需要后端补的 · 7 需要负责人定的 · 8 本期不做

### 2.2 新增员工

单独的页面（十个角色加说明超过一屏，不用对话框）。`<h1>`「新增员工」；从「重新邀请」进来时标题是「重新邀请 {姓名}」，邮箱是只读的。

| 字段 | 控件 | 规则与提示 |
| --- | --- | --- |
| 邮箱 * | 输入框，`type="email"`，`autocomplete="off"` | 以后用它登录运营后台。没填：「请填写邮箱」；格式不对：「这不是一个邮箱地址」。帮助说明：「平台员工和供应商的账号是两套，同一个邮箱可以两边各有一个。」 |
| 姓名 * | 输入框 | 没填：「请填写姓名」 |
| 角色 * | 单选组，十个选项，没有默认值；每个选项下面一行小字说明「能做什么」（见下表） | 没选：「请选择角色」。字段的帮助说明：「角色决定他能看到哪些菜单、能做哪些操作。**账号启用以后角色暂时不能改**，选错了只能停用后重新建。不确定时先给「只读」。」 |

**角色说明**（定稿。第二列的小字由两部分拼成：固定的一句「负责什么」+ 按 `@nozomi/domain` 的 `platformPermissions(角色)` **现算出来**的「现在能做的」，这样以后给角色加了权限，页面不用改）

| 角色 | 固定的一句 |
| --- | --- |
| 超级管理员 | 什么都能做，包括管理平台员工、看审计日志。人数越少越好，但至少要有两个人，免得一个人忘了密码就没人能处理。 |
| 运营 | 日常运营：管理供应商，处理订单和异常。 |
| 招商 | 负责供应商入驻：新建供应商、邀请管理员、暂停和恢复。 |
| 渠道经理 | 负责销售渠道和加价规则。 |
| 客服 | 处理订单、工单和投诉。 |
| 财务 | 负责对账、结算和付款。 |
| 风控 | 负责价格和下单的风险规则。 |
| 主数据运营 | 维护城市、机场、车站、车型组、附加服务。 |
| 技术 | 负责连接器和系统配置，可以看系统状态。 |
| 只读 | 只能看，不能改。 |

「现在能做的」的写法：把这个角色有的操作换成人话，用顿号连接——

| 操作 | 人话 |
| --- | --- |
| `tenant.read`（没有 create） | 看供应商 |
| `tenant.read` + `tenant.create` + `tenant.change_status` | 管理供应商（新建、邀请管理员、暂停和恢复） |
| `master_data.read`（没有 manage） | 看主数据 |
| `master_data.manage` | 维护主数据 |
| `staff.manage` | 管理平台员工 |
| `audit_log.read` | 看审计日志 |
| `integration.read` | 看系统状态 |

- 例：运营——「现在能做的：管理供应商（新建、邀请管理员、暂停和恢复）、看主数据。」
- **角色对应的模块还没上线时**（渠道经理、客服、财务、风控现在只有「看主数据」）：后面加一句 `text-tertiary` 的「他负责的模块还没有上线，现在登录后只能看主数据。」判断方法：这个角色的操作只有 `master_data.read`。
- 选「超级管理员」时，单选组下方多一条警告提示条：「**超级管理员可以管理所有平台员工、看到全部审计日志。** 请只给确实需要的人。」

页面底部的信息提示条和操作区同新建供应商（`platform-tenants.md` 4.1）：「系统不会给对方发邮件。点「新增」后会显示一条邀请链接，只显示一次。」按钮「取消」「新增」（重新邀请时写「重新邀请」）。

| 后端返回 | 显示在哪 | 文字 |
| --- | --- | --- |
| 409 `EMAIL_TAKEN` | 邮箱字段下方 | 这个邮箱已经有一个设过密码的平台员工账号了。他忘了密码的话，请在列表里给他「发密码重置链接」；账号被停用了的话，请在列表里「启用」。 |
| 400、403、网络、5xx | 同 `platform-tenants.md` 4.2、2.4 | 网络不明时的说法用 2.4 的通用那一条（对同一个没激活的邮箱再点一次只是重发邀请，不会多出一个人） |

成功：留在这一页弹出一次性链接对话框（「给 {姓名}（{邮箱}）· 平台员工，{角色名}」；链接是 `/platform/accept-invite#token=…`）；关闭后回到列表，Toast「已邀请「{姓名}」」，那一行短暂标出。

### 2.3 重新邀请

「更多 → 重新邀请」去新增页，带着这个人的邮箱（只读）、姓名、角色（可改）。说明：「会发出一条新的邀请链接，之前那条作废。姓名和角色按这次填的更新。」其余同 2.2。

### 2.4 发密码重置链接

确认对话框（不是危险操作）：

- 标题：给「{姓名}」发密码重置链接？
- 正文：会生成一条重置链接（24 小时有效，只显示一次），由你发给他本人。**发出链接不会改掉他现在的密码**，也不会让他退出登录；他用链接设了新密码以后，旧密码才失效。请先确认提出要求的就是他本人。
- 按钮：「取消」、「发出」（主按钮；等待时「发出中…」）。成功：同一个对话框里换成一次性链接的内容（`/platform/reset-password#token=…`）。
- 被拒绝 409 `ACCOUNT_NOT_ACTIVE`（页面上的状态过时了）：对话框里危险提示条「这个账号现在不是在用的状态。待激活的请用「重新邀请」，已停用的请先「启用」。」，去掉「发出」，「取消」改成「知道了」；关闭后列表重新取。

说明里固定的一句（`text-tertiary`）：「最后一个超级管理员自己忘了密码，页面上处理不了，要请技术在服务器上重设。」

### 2.5 停用和启用

**停用**（危险操作的确认）：

- 标题：停用「{姓名}」？
- 正文：停用以后，他**马上不能登录**，已经登录着的也会立刻退出。｛待激活的：｝他还没有设过密码，之前发给他的邀请链接会作废。之后可以重新启用｛待激活的：重新邀请｝。
- 按钮：「取消」（默认焦点）、「停用」（危险按钮；等待时「停用中…」）。成功：Toast「已停用「{姓名}」」。
- 被拒绝 409 `LAST_ADMIN_REQUIRED`：对话框里危险提示条「**现在不能停用。** 他是最后一个在用的超级管理员。请先给另一个人开一个超级管理员账号，等对方设好密码以后再停用他。」，去掉「停用」，「取消」改成「知道了」。
- **自己那一行没有「停用」**（页面不给；接口现在不拦，6.3）。

**启用**（普通确认）：

- 标题：启用「{姓名}」？ 正文：启用以后，他可以用原来的密码登录，角色不变（{角色名}）。按钮「取消」「启用」。成功：Toast「已启用「{姓名}」」。
- 被拒绝 409 `ACCOUNT_NOT_ACTIVATED`（这个账号从没设过密码就被停用了）：对话框里危险提示条「这个账号还没有设过密码，不能直接启用。请重新邀请他。」+ 链接「去重新邀请」（去 2.3），去掉「启用」。

## 3. 审计日志

### 3.1 这一页回答什么

「谁，在什么时候，对什么，做了什么，改之前和改之后各是什么。」日志只能看：**不能改、不能删**（接口没有，数据库也拦着），这句话写在页面标题下面（`text-secondary`）：

> 平台和供应商后台里的每一次登录、新建、修改、停用都记在这里，只能查看，不能修改或删除。密码、链接里的令牌不会被记录。

| 操作人 | 第一行邮箱（没有的写「—」）；第二行是谁（`font-size-xs`，`text-tertiary`）：平台员工 / 供应商的账号 / 系统（服务器上的命令）/ 没有登录的访问者。邮箱是一个按钮，点开小菜单「只看这个人」（操作人没有编号时没有这个菜单） |
| 操作 | 中文名，标签样式。「登录失败」「停用」「暂停」「删除」不另外用红色（这里是记录，不是警报） |
| 对象 | 第一行「{类型} {名称}」——名称从这条记录的改后值、改前值里找（依次看 `name`、`email`、`code`、`title`；名称是多语言的取显示名），找不到就没有名称；第二行对象编号的前 8 位 +「…」（等宽，`text-tertiary`，`title` 放完整编号）。点了有小菜单「只看这个对象」 |
| 来源 | 后台 / 接口 / 命令行（`console` / `api` / `cli`） |
| （详情） | 文字按钮「详情」，`aria-label="第 {编号} 条记录的详情"` |

- IP 地址不放在表格里（列太多），在详情里。
- 行不可点；只有「详情」和两个小菜单。
- < 768px 用**方式 B**：第一行操作（标签）+ 时间；第二行操作人；第三行对象；最下面「详情」。

### 3.4 一条记录的详情

对话框（表单尺寸，`min(640px, 100% - 32px)`；内容多时正文滚动）。标题：「{操作} · {对象类型} {名称}」。

- 上半部分 `<dl>`（两栏；< 768px 单栏）：时间（到秒，本地时区；下面一行 UTC）、操作人（邮箱 + 是谁）、操作、对象（类型、名称、完整的对象编号 +「复制」）、所属供应商（名称；平台级的记录写「—」）、来源、来源地址（IP；命令行的写「—」）、记录编号。
- 下半部分「**改了什么**」：组件「改前改后对照」（`02-components.md` 第 38 节）。

  | 这条记录有什么 | 显示 |
  | --- | --- |
  | 改前、改后都有 | 三列的表：项目 / 改前 / 改后。**只列变了的项**；下面一行「另有 {N} 项没有变」+ 文字按钮「全部显示」 |
  | 只有改后（新建、邀请、登录失败的原因等） | 两列：项目 / 内容。小标题换成「记下的内容」 |
  | 只有改前（删除） | 两列：项目 / 删除前的内容 |
  | 都没有 | 「这次操作没有记下更多内容。」 |

  - **项目名**：接口给的是字段的英文名。常见的换成中文（`name` 名称、`email` 邮箱、`role` 角色、`status` 状态、`reason` 原因、`temporary_password` 用了临时密码……对照表放前端，逐步补），后面用 `text-tertiary` 的等宽小字带上原名；不认识的只显示原名。**审计日志是这个后台里唯一允许出现字段原名的地方**——排查问题时要拿它去对接口和数据库。
  - **值**：文字原样；是 / 否；状态、角色等认识的枚举换成中文并在后面带原值；金额、日期不做换算（照记录的原样）；空的写「（空）」。值是一组东西（对象、数组）时显示成缩进好的文本块（等宽，底 `bg-subtle`）。
  - **长内容折叠**：一个值超过 6 行或 300 个字，先显示前 6 行 +「展开（共 {N} 行）」；展开后可以「收起」。区域的多边形坐标、商品的服务规则常常很长。
  - 每个值可以选中复制；右上角「复制这条记录」把整条（接口返回的原样）复制成文本。
- 最下面固定一行（`text-tertiary`）：「密码、密码的哈希、邀请和重置链接里的令牌不会被记录，所以这里看不到，不是被隐藏了。」
- 按钮只有「关闭」。Esc、点遮罩都可以关（没有表单）。

| --- | --- |

## 4. 系统状态

只读的一页。接口 `GET /platform/v1/integrations`。

```
系统设置 / 系统状态
系统状态                                                                    [重新检查]
这里只显示各项配好了没有，以及打过码的信息；看不到密钥原文。每次打开这一页都会记入审计日志。
┌──────────────┬────────────┬──────────────────────────────────────────────┐
│ 项目          │ 状态        │ 说明                                          │
│ 数据库        │ ● 已配置    │ postgres://nozomi_app:••••@db:5432/nozomi     │
│ Stripe       │ ● 未配置    │ —                                            │
└──────────────┴────────────┴──────────────────────────────────────────────┘
```

- 页面类型「列表」，最大宽度 `layout-reading-max-width`。`<h1>`「系统状态」；标题下一句说明如图（`text-secondary`）。
- 表格三列：项目（接口的 `label`，`<th scope="row">`）、状态（徽标：已配置 `success` / 未配置 `warning`）、说明（接口的 `detail`，等宽，`overflow-wrap: anywhere`；空的写「—」）。顺序按接口返回的。不分页、不筛选。
- 有未配置的项时，表格上方一条警告提示条：「**有 {N} 项还没有配置**：{项目名，用「、」连接}。用到它们的功能现在不能用。配置要由技术在服务器上做；谷歌地图和 Stripe 支付也可以由超级管理员在下面的「第三方密钥」里直接填写。」（M4-09 起按页面实际；密钥不要发在聊天里的提醒见 4.1 和 `docs/secrets.md`。）全部已配置时不显示提示条。
- **汇率数据**（M1-14；接口的 `fx_center`，ADR 0022）：表格下面一张卡片，标题「汇率数据」+ 状态徽标（正常 `success` / 已过期 `danger` / 还没有汇率 `warning`，同汇率页）。`<dl>` 四项：是否过期（「没有过期，跨币种报价照常」/「已过期（超过 48 小时没有更新），跨币种报价已暂停」/「还没有汇率，跨币种报价都报不出」）、这批汇率的时间（数据源给的，`YYYY-MM-DD HH:mm` 本地时区；没有写「—」）、最近一次拉取（时间 + 拉取结果徽标，同汇率页；失败 / 内容不对时后面一句人话的原因，错误码不显示原文；没拉过写「还没有拉过」）、定时拉取（「已打开（每天自动拉取）」/「没有打开，只能在汇率页手动拉取」）。卡片底部链接「看汇率和拉取记录」去汇率页。**过期时**表格上方再加一条危险提示条（同首页）：「**汇率超过 48 小时没有更新，跨币种报价已暂停** 现在这批汇率是 {时间} 的。请到汇率页检查数据源，或立即拉取一次。」+ 链接「去汇率页处理」。
- **「重新检查」**（次要按钮，带刷新图标）：重新请求一次。**这一页不自动刷新**——不定时轮询、窗口重新获得焦点时也不重取（每次请求都会写一条审计日志，不能刷出一堆）。
- 状态：加载中——表头 + 5 行骨架；加载失败——「加载失败」「请检查网络后重试。」+「重试」；没有权限——第 1 节。
- < 768px：每一项一张卡片（项目名 + 徽标一行，说明一行）。

### 4.1 第三方密钥（M4-09，依据 ADR 0041）

负责人要求在后台直接填谷歌地图、Stripe 的密钥，不用登服务器改 `.env`。规则全部在 ADR 0041；接口 `GET /platform/v1/integration-secrets`，`PUT` / `DELETE /platform/v1/integration-secrets/{google-maps|stripe}`，`POST …/{key}/test`。实现在 `apps/web/src/pages/platform/IntegrationSecretsSection.tsx`。

放在系统状态页的汇率卡片下面，`<h2>`「第三方密钥」，下面一句说明：「**哪一份生效：运营后台填写的优先；后台没填（或清空后）才用服务器配置文件里的值。** 谷歌地图和 Stripe 支付的密钥可以在这里直接填写，保存后马上生效，不用重启。页面上只显示末 4 位。」（加粗的一句是接口的 `precedence_note`。）

```
第三方密钥
哪一份生效：运营后台填写的优先；……  谷歌地图和 Stripe 支付的密钥可以在这里直接填写……
┌ 谷歌地图                                     ● 已配置 ┐
│ 现在用的          后台设置（••••1234）               │
│ 后台填写的        ••••1234 · 2026-10-26 10:20 · 张三 │
│ 服务器配置文件里  有                                 │
│ [更换]  [测试一下]  [清空]                           │
│ 「测试一下」会真的调用一次谷歌地图……                 │
└──────────────────────────────────────────────────────┘
┌ Stripe 支付                                  ● 未配置 ┐ …
```

- **每项一张卡片**（`card`）：标题是接口的 `label`（`<h3>`）+ 状态徽标（已配置 `success` / 未配置 `warning`）。`<dl>` 三行：
  - **现在用的**：「后台设置（••••1234）」/「服务器配置文件（••••5678）」/「未配置」；Stripe 后面再写「· 测试密钥 / 正式密钥」（`mode`）。只读角色没有打码值，只写来源。
  - **后台填写的**（只有超级管理员看得到）：没填写写「没有填写」；填了写末 4 位、时间、谁改的；后台那一份没生效时加一句原因（解不开：「后台填写的那一份读不出来（服务器的数据加密密钥可能换过），现在没有用它。请重新填写一次。」；不适用于这个环境：「……例如测试密钥到了正式环境……请换成这个环境能用的密钥。」）。
  - **服务器配置文件里**：「有」/「没有」。
- **按钮**（只有 `can_manage` 为真时才有；只读角色一个都没有）：「填写」（后台没填时）/「更换」（后台填了时）、「测试一下」（这一项有生效的值时）、「清空」（后台填了时）。按钮下一行小字说明测试的代价：谷歌地图「『测试一下』会真的调用一次谷歌地图（查一条东京站到新宿站的路线），每次产生极少量费用，通常在谷歌每月的免费额度内。」；Stripe「『测试一下』只查一次账户余额，不收钱、不产生费用，也不改任何数据。」
- **填写 / 更换**：对话框，标题「填写「谷歌地图」的密钥」/「更换「Stripe 支付」的密钥」。说明一句（Stripe：「Stripe 的三项要一起填。从 Stripe 控制台复制后粘贴到下面。」；谷歌地图：「从谷歌云控制台复制密钥后粘贴到下面。」）+「保存后马上生效，不用重启。」（更换：「保存后马上改用新的，原来在后台填写的那一份不再使用。」）。
  每项一个密码类型的输入框（标签用接口 `fields[].label`），不受控、粘贴后不回显、提交后清空；后端逐项出错时错误落在对应的输入框下面。按钮「取消」「保存」（保存中「保存中…」）。成功后 toast「已填写「谷歌地图」的密钥」/「已更换……」。
  服务器没配数据加密密钥（`encryption_configured` 为假）时「填写」不可用，旁边说明「服务器还没有配置数据加密密钥，现在不能在后台填写密钥。请联系技术人员在服务器上配置好以后再来填写。」
- **测试一下**：按钮显示「测试中…」；结果显示在卡片里：徽标「可用」（`success`）+「测的是{来源}里的那一份。」，或「不可用」（`danger`）+ 接口给的原因说明（密钥无效、没开通 API、网络不通等）。不回显密钥。
  同一项 5 秒内重复点（接口 429 `INTEGRATION_TEST_RATE_LIMITED`）：显示「刚测过，请过几秒再试」。
- **清空**：确认对话框，标题「清空「{名称}」在后台填写的密钥？」；正文加粗一句「清空后改用服务器配置文件里的值（如果有）。」再接一句后果：配置文件里有——「服务器配置文件里也有这一项，清空后马上改用那里的值。」；没有——Stripe「服务器配置文件里没有这一项，清空后 Stripe 支付就是「未配置」，客人将不能在线付款，直到重新填写。」/ 谷歌地图「……用到它的功能会停下来，直到重新填写。」；最后一行「以后随时可以重新填写。」
  按钮「取消」（默认焦点）和「清空」（`danger`，清空中「清空中…」）。成功后 toast「已清空「{名称}」在后台填写的密钥」。
- 状态：加载中——两张卡片的骨架；失败——「第三方密钥加载失败」「请检查网络后重试。」+「重试」；没有权限——「你没有权限查看第三方密钥」。
- < 768px：卡片单栏，`<dl>` 每项上下两行，按钮折行。亮暗两套主题、320 宽都要看。

## 5. 手机宽度、键盘、文案

**手机宽度**（最窄 320px）：三个列表都用卡片；新增员工页单栏，十个角色各占一行（带两行小字）；审计日志的筛选收进「筛选」面板，时间的三个快捷按钮在面板里排成一行；详情对话框贴底，`<dl>` 单栏，「改了什么」的三列表换成每项一块（项目名一行、「改前」一行、「改后」一行）；长的值在自己的文本块里折行（`overflow-wrap: anywhere`），不横向滚动。在 320、360、400 三个宽度下检查：员工列表（各种状态、每种「更多」菜单）、新增页（选了超级管理员、出错）、四个确认对话框和各自被拒绝的样子、一次性链接对话框；审计日志（加载中、有数据、带着三个小标签、无结果、筛选面板、详情里有很长的值并展开）；系统状态（有未配置的、全部已配置、失败）。

**键盘与读屏**

- 所有操作都能只用键盘完成。角色的单选组用 `<fieldset>` + `<legend>`，每个选项的小字用 `aria-describedby` 关联。
- 审计日志：表格容器可以聚焦和滚动；操作人、对象上的小菜单是菜单按钮（`aria-haspopup="menu"`）；筛选的小标签的「×」读作「移除条件：操作人 kato@example.com」。翻页后焦点移到表格容器。
- 详情对话框：「改了什么」是真正的 `<table>`（`<caption>` 视觉隐藏）；「展开」是 `<button aria-expanded>`；展开后焦点不动。
- 系统状态：徽标有文字；「重新检查」完成后用 `role="status"` 播报「已重新检查，{N} 项未配置」。
- 两套主题各看一遍：三种账号状态的徽标；审计日志详情里 `bg-subtle` 的文本块、变了的项的标记；系统状态里未配置的徽标和警告提示条。

**Toast**：已邀请「{姓名}」· 已给「{姓名}」发出密码重置链接 · 已停用「{姓名}」· 已启用「{姓名}」· 已复制

**按钮、菜单和链接**：新增员工 · 新增 · 重新邀请 · 发密码重置链接 · 发出 · 停用 · 启用 · 看他的操作记录 · 看这个账号的变更记录 · 去重新邀请 · 今天 · 最近 7 天 · 最近 30 天 · 只看这个人 · 只看这个对象 · 详情 · 全部显示 · 展开 · 收起 · 复制这条记录 · 关闭 · 重新检查 · 清空筛选 · 取消 · 知道了 · 重试

**统一的叫法**

| 界面上叫 | 不要写成 |
| --- | --- |
| 平台员工 | platform_user、staff、平台账号、管理员（「管理员」留给供应商的管理员）|
| 待激活 / 在用 / 已停用 | invited / active / disabled、未激活、正常（「正常」是供应商的状态）、禁用 |
| 新增员工、重新邀请 | 创建用户、重发令牌 |
| 角色（十个中文名） | role、权限组 |
| 审计日志（页面）、操作记录（别处的链接） | audit log、日志流水 |
| 操作人、对象、来源（后台 / 接口 / 命令行）、来源地址 | actor、resource、source、IP 段 |
| 改前 / 改后、另有 N 项没有变 | before / after、diff |
| 系统状态、已配置 / 未配置 | integrations、集成、configured / missing、健康检查 |

## 7. 需要负责人定的事

1. **谁能看平台员工和审计日志。** 现在只有超级管理员（需求文档「系统设置：超级管理员」）。运营、招商做了暂停供应商这样的操作以后，自己看不到操作记录。**推荐：先保持只有超级管理员**；要放开的话，告诉我们哪些角色可以看审计日志（只看、不能改）。
2. **在用的员工不能改角色。** 接口现在没有这个功能，选错了也没法另建（邮箱被占着）。**推荐尽快补**（第 6 节第 2 条）；在那之前请在新增时看清角色，不确定先给「只读」——但「只读」之后也改不了，所以**实际建议是这个功能补上之前，只给确定角色的人开账号**。
3. **请至少保留两个超级管理员。** 只剩一个人而他又忘了密码时，页面上处理不了，要技术在服务器上重设。页面在新增员工时写了这个建议。
4. **渠道经理、客服、财务、风控四个角色现在登录后只能看主数据**（他们负责的模块还没做）。页面在选这些角色时会写明。**请知悉。**
5. **系统状态页每打开一次记一条审计日志。** 这是后端现在的做法（看的是打过码的配置信息）。页面因此不自动刷新。**推荐：保持**；觉得日志太吵再改。
