# 供应商管理（运营后台）、一次性链接的交付

M1-10 的页面：运营后台的「供应商」——列表、新建、详情、暂停 / 恢复、邀请管理员、给管理员发密码重置。同一个任务里的平台员工、审计日志、系统状态见 [`platform-settings.md`](./platform-settings.md)。本文用到的新组件：一次性链接（`02-components.md` 第 37 节）。**本任务没有新增令牌。**

依据：《平台运营端与渠道对接》「运营后台菜单与角色」「租户管理」的状态表（只取和现有接口对应的部分：正常、暂停）；ADR 0008（登录、邀请、重置令牌）、ADR 0013；`apps/api/openapi.yaml` 的 `/platform/v1/tenants*`；`packages/domain/src/access.ts`。入驻申请、资质审核、合同、评分、清退是 M4-01，不在本文。

接口从 M0-06 起就有，**本文按接口现在的样子写**；接口缺的东西列在第 9 节，每条都写了没有时页面怎么办。界面上一律叫「**供应商**」，不叫「租户」。文中的名字、邮箱只用来说明格式，页面上不预置任何数据。

标了 **［需负责人确认］** 的汇总在第 10 节。

目录：1 概览 · 2 一次性链接的交付 · 3 列表 · 4 新建 · 5 详情 · 6 暂停和恢复 · 7 邀请管理员、发密码重置 · 8 状态、手机宽度、键盘、文案 · 9 需要后端补的 · 10 需要负责人定的 · 11 本期不做

## 2. 一次性链接的交付

**系统现在没有邮件服务。** 新建供应商、邀请管理员、发密码重置、新增平台员工、给平台员工发密码重置——这五个操作成功时，接口返回一个一次性的令牌，**只在这一次应答里出现**。页面要把它变成一条完整的链接交到操作的人手里，由他自己发给对方。这是本任务最要紧的交互，五处用的是同一个对话框（组件「一次性链接」，`02-components.md` 第 37 节）。

### 2.1 链接是什么

| 操作 | 链接 | 有效期（以接口的 `expires_at` 为准） |
| --- | --- | --- |
| 新建供应商、邀请供应商管理员 | `{供应商后台网址}/accept-invite#token={令牌}` | 7 天 |
| 给供应商管理员发密码重置 | `{供应商后台网址}/reset-password#token={令牌}` | 24 小时 |
| 新增平台员工（`platform-settings.md`） | `{运营后台网址}/platform/accept-invite#token={令牌}` | 7 天 |
| 给平台员工发密码重置 | `{运营后台网址}/platform/reset-password#token={令牌}` | 24 小时 |

- 路径取自前端已有的 `lib/portal.ts`，不另写一份。两个后台现在在同一个网址下，所以 `{…网址}` 都是当前页面的 `window.location.origin`；以后分开部署时改成配置（9.8）。
- 令牌放在 `#` 后面（片段）：浏览器不会把它发给服务器，不进服务器的访问日志。对方打开后的页面见 `login.md`。

### 2.2 对话框

```
┌ 邀请链接（只显示这一次）─────────────────────────────────────┐
│ 给  山田太郎（yamada@example.com）· NOZOMI 自营车队 的管理员     │
│                                                              │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ https://…/accept-invite#token=4f9c…                      │ │
│ └──────────────────────────────────────────────────────────┘ │
│ [复制链接]   [复制链接和说明]                                  │
│                                                              │
│ ! 系统不会发邮件。请你自己把链接发给对方本人。                    │
│ · 有效期到 2026-10-16 14:30（7 天），只能用一次。               │
│ · 拿到链接的人就能给这个账号设密码并登录，不要发到群里。           │
│ · 关闭以后无法再看到这条链接。对方没收到或过期了，可以重新发起，     │
│   旧链接会作废。                                              │
│                                          [我已经发给对方，关闭] │
└──────────────────────────────────────────────────────────────┘
```

| 部分 | 内容 |
| --- | --- |
| 标题 | 「邀请链接（只显示这一次）」/「密码重置链接（只显示这一次）」 |
| 给谁 | 「给 **{姓名}**（{邮箱}）· {供应商名称} 的管理员」；平台员工写「· 平台员工，{角色名}」。让人确认没发错人 |
| 链接 | 只读的多行文本框（3 行，等宽字体，`overflow-wrap: anywhere`，可以选中）；`aria-label="邀请链接"`；`autocomplete="off"`、`spellcheck="false"`。**完整显示，不打码**（这是它唯一出现的地方） |
| 复制链接 | 主按钮。点了以后按钮文字变成「已复制」（带对勾，3 秒后变回），并用 `role="status"` 播报「链接已复制」。**不发 Toast**（Toast 的内容会留在页面的播报区里） |
| 复制链接和说明 | 次要按钮：复制一段可以直接粘贴发出去的话（见下）。可选的方便，不是必须 |
| 说明 | 第一句是警告提示条（`warning`）：「**系统不会发邮件。** 请你自己把链接发给对方本人（邮件、LINE、企业微信等你们平时用的方式）。」下面三条普通文字，如图。有效期写绝对时间（查看者本地时区，`04-data-display.md` 第 4 节）+ 括号里的时长 |
| 密码重置时多两条 | 「发出链接不会改掉对方现在的密码；对方用它设了新密码以后，旧密码才失效，他在所有设备上都要重新登录。」「再发一次会让这条链接作废。」 |
| 关闭 | 只有一个按钮「**我已经发给对方，关闭**」（次要按钮）。**没有右上角的关闭按钮；Esc、点遮罩都不关闭**——这是一条关掉就没有了的内容，不能被误关 |

- **还没复制过就点关闭**：按钮上方出现一行警告色的确认（不另开对话框）：「还没有复制过这条链接。关闭以后无法再看到，只能重新发起。」+「仍然关闭」（文字按钮，`danger-text`）「回去复制」（次要按钮，焦点落在它上面）。复制过（任意一个复制按钮，或在文本框里手动选中复制过）就直接关闭。
- **复制不成功**（浏览器不让写剪贴板）：自动选中文本框里的全部内容，按钮下方出错文字「没有复制成功。链接已经选中，请按 Ctrl + C（Mac 上是 ⌘ + C）复制。」
- 「复制链接和说明」复制的内容（定稿；中文一份，不带任何令牌以外的敏感信息）：

  > {姓名}，你好：
  > 这是 NOZOMI {供应商后台 / 运营后台}的{账号开通 / 密码重置}链接，请在 {有效期的绝对时间} 前打开，设置你自己的密码：
  > {链接}
  > 链接只能用一次，请不要转发给别人。登录邮箱：{邮箱}

- 打开时焦点落在「复制链接」上。对话框宽 `min(640px, 100% - 32px)`；< 480px 贴底，两个复制按钮各占一行。
- 关闭后：焦点回到发起操作的按钮（新建供应商是换到详情页，4.3）；这时发一条 Toast「已邀请「{姓名}」」/「已给「{姓名}」发出密码重置链接」（**Toast 里没有链接**）。

### 2.3 令牌不能去的地方（前端实现的硬性要求）

1. 令牌和拼好的链接**只放在这个对话框组件的内存状态里**，对话框关闭时清掉。
2. **不进地址栏**：不放进网址参数、片段；不放进路由的 `state`（它会留在浏览记录里）。所以「新建成功后换到详情页」是在对话框**关闭以后**才换（4.3）。
3. **不进任何存储**：`localStorage`、`sessionStorage`、IndexedDB、Cookie、接口客户端的缓存都不放。刷新页面后链接就没有了——这是有意的。
4. **不进日志**：不 `console.log`；不进错误上报；页面出错时（错误边界）显示的内容里不能带应答的原文。
5. 不放进 Toast、提示条、`title`、`aria-label` 的值里。
6. 发起这些操作的请求**不自动重试**：重复一次就多发一个令牌、让上一个作废。网络不明时由人决定再点一次（2.4）。
7. 端到端测试：发起后断言 `location.href`、`history.state`、两种 Storage 里都搜不到令牌；关闭对话框后页面上也搜不到。

### 2.4 发起时出问题

| 情况 | 显示什么 |
| --- | --- |
| 请求还没回来 | 发起的按钮进入加载态（「邀请中…」「发出中…」「新建中…」），表单只读 |
| 网络不通、超时、5xx | 在发起的表单或对话框里：危险提示条「**不确定有没有成功。** 请检查网络后再试一次。如果其实已经成功了，再试一次会发出一条新的链接，之前那条作废——没有影响，因为它还没有交到任何人手里。」按钮恢复可点 |
| 业务上被拒绝 | 各页面自己的说明（第 4、7 节） |
| 链接拿到了，但接口没给 `expires_at`（不应出现） | 有效期那一条写「有效期：邀请 7 天 / 重置 24 小时」 |

### 3.1 首屏看到什么

```
供应商
供应商                                                                    [+ 新建供应商]
[搜索：按名称搜索 ] [状态：全部 ▾]                                              清空筛选

```

首屏（1280×720）必须看到：标题和「新建供应商」、筛选条、表头和至少 8 行。

- 页面类型「列表」。`<h1>`「供应商」；主按钮「新建供应商」（`<a>`，去 `/platform/tenants/new`；没有 `tenant.create` 的不显示）。
- **接口现在只能翻页，不能按状态、关键字筛，顺序是创建时间从早到晚**（9.1）。所以页面进来时把全部供应商取完（每次 200 条，取到没有下一页为止；首期按 100 家设计），**筛选、搜索、排序都在浏览器里做**：
  - 排序：最近修改的在前。
  - 关键字（`q`）：按名称，不分大小写，包含即可。状态（`status`）：全部 / 正常 / 已暂停。都写进网址（`replace`）。首页卡片的两个数字以后可以带着 `status` 过来。
  - 每页 50 行，在浏览器里分页；左下角「共 {N} 家」。
  - 取到 2,000 家还没取完时停下，表格上方警告提示条：「供应商太多，只载入了最早建的 2,000 家。请联系技术处理。」（到那时接口必须已经支持筛选。）

| 列 | 内容 |
| --- | --- |
| 供应商 | 名称，是去详情页的 `<a>`（`<th scope="row">`）；最多两行，超出省略，`title` 放全文 |
| 状态 | 徽标：正常 / 已暂停 |
| 创建时间、最近修改 | `YYYY-MM-DD HH:mm`，查看者本地时区，`text-secondary` |
| 操作 | 「查看」（同名称的链接，`aria-label="查看 {名称}"`）+「更多」菜单：正常的——邀请管理员、暂停（`danger-text`）；已暂停的——邀请管理员、恢复。只读角色只有「查看」，没有「更多」 |

- 「更多」里的操作和详情页是同一套对话框（第 6、7 节）；做完后这一行留在原地，焦点回到「更多」。
- < 768px 用**方式 B**（卡片）：第一行名称 + 状态徽标；第二行「创建于 {日期}」；最下面「查看」和「更多」。供应商的数量少、字段少，卡片比横向滚动的表好用。

## 4. 新建供应商

单独的页面，页面类型「表单」。`<h1>`「新建供应商」。两张卡片。

### 4.1 字段

**供应商**

| 字段 | 控件 | 规则与提示 |
| --- | --- | --- |
| 名称 * | 输入框 | 1 到 100 个字；只有空格的等于没填。帮助说明：「车队或公司的名字。它的员工登录供应商后台时会看到这个名字。」没填：「请填写名称」；超长：「名称最多 100 个字」。**和已有的供应商同名**（页面用列表里已经取到的名字比，不分大小写、去掉首尾空格）：不拦，字段下方警告色提示「已经有一家叫「{名称}」的供应商了。确定要再建一家同名的吗？」 |

**第一个管理员**（卡片说明：「这家供应商的第一个账号，角色是管理员：他可以给自己的同事开账号。新建成功后你会得到一条邀请链接，由你发给他。」）

| 字段 | 控件 | 规则与提示 |
| --- | --- | --- |
| 邮箱 * | 输入框，`type="email"`，`autocomplete="off"` | 以后用它登录。格式规则同登录页（`@nozomi/domain` 的校验）。没填：「请填写邮箱」；格式不对：「这不是一个邮箱地址」。帮助说明：「对方用这个邮箱登录。请填他本人在用的邮箱。」 |
| 姓名 * | 输入框，`autocomplete="off"` | 1 到 100 个字（上限以 `openapi.yaml` 的 `PersonName` 为准）。没填：「请填写姓名」 |

- 卡片底部一条信息提示条（不能关闭）：「**系统不会给对方发邮件。** 点「新建」后，这里会显示一条邀请链接，只显示一次，请当场复制并发给对方。」——让人在点之前就知道接下来要做什么。
- 操作区：「取消」（回列表；有修改先问）、「新建」（主按钮；等待时「新建中…」）。

### 4.2 被拒绝

| 后端返回 | 显示在哪 | 文字 |
| --- | --- | --- |
| 409 `EMAIL_TAKEN` | 邮箱字段下方 | 这个邮箱已经是某家供应商的账号了，一个邮箱只能属于一家供应商。请换一个邮箱；如果他就是那家供应商的人，请到那家供应商的详情页处理。 |
| 400（字段不合规） | 对应字段下方 | 按字段的出错文字；对不上字段的放页面级危险提示条「提交的内容不符合要求，请检查后重试。」 |
| 403 | 页面级危险提示条 | 你没有权限新建供应商。需要的话，请联系管理员开通。 |
| 网络不通、5xx | 页面级危险提示条 | **不确定有没有建成。** 请先回到供应商列表看一眼有没有「{名称}」：有的话不要再建一次，到它的详情页点「邀请管理员」重新拿链接；没有再回来重试。 |

最后一条和 2.4 的通用说法不同：这个接口没有幂等键（9.4），重试可能建出两家同名的供应商，所以要先请人看一眼。

### 4.3 成功以后

1. 留在新建页，立即弹出一次性链接对话框（2.2），「给谁」那一行写「{姓名}（{邮箱}）· {供应商名称} 的管理员」。对话框后面的表单已经是只读的。
2. 对话框关闭后，换到（`replace`）这家供应商的详情页，Toast「已新建供应商「{名称}」」。浏览器「后退」不会回到填好的表单。
3. 这时刷新页面或关掉标签页：浏览器自带的离开确认会拦一次（对话框开着时页面算「有没处理完的事」）。真的离开了，供应商已经建好，链接没有了——到详情页点「邀请管理员」用同一个邮箱重新发起即可（接口对没激活过的账号会重发）。这句话也写在详情页（5.3）。

- **暂停原因**接口现在不在供应商上返回，只记在审计日志里（9.2）。所以：有 `audit_log.read` 的角色（超级管理员），页面另取一次这家供应商最近的一条暂停记录（审计日志按对象 = 这家供应商、操作 = 暂停筛，取最新的一条），把原因、操作人、时间显示出来；原因是空的写「没有填原因」。其他角色看不到审计日志，这一行写「暂停原因记在审计日志里，需要的话请问超级管理员。」

## 6. 暂停和恢复

### 6.1 暂停（危险操作的确认，带一个必填的原因）

- 标题：暂停「{名称}」？
- 正文：暂停以后——
  - 它的**商品不参与比价，不会再接到新订单**；
  - **已经接下的订单不受影响**，仍然要照常派车、履约；
  - 它的账号**仍然可以登录**供应商后台，页面上会看到「已暂停」；
  - 可以随时恢复。
- 字段「暂停原因 *」：多行文本框，3 行，最多 500 个字，右下角实时字数「{n} / 500」。帮助说明：「写给同事和以后的自己看的：为什么暂停、谁要求的。会记入审计日志，供应商看不到。」没填（或只有空格）：「请填写暂停原因」；超长：「原因最多 500 个字」。**接口允许不填，页面要求必填**（9.6）。
- 按钮：「取消」（默认焦点）、「暂停」（危险按钮；等待时「暂停中…」）。有表单的对话框，点遮罩不关闭。
- 成功：对话框关闭，Toast「已暂停「{名称}」」；详情页重新取（徽标、提示条、按钮跟着变），列表里这一行的徽标变成「已暂停」。别人已经先暂停了，接口照常返回成功，页面同样处理（**这次填的原因是否记下以接口为准**）。
- 失败按 `02-components.md` 第 9 节；404：「找不到这家供应商，它可能已被删除。」

需求文档把「停用租户」列在「敏感操作双人复核」里；现在的接口是一个人点了就生效 **［需负责人确认］**（10.1）。

### 6.2 恢复（普通确认）

- 标题：恢复「{名称}」？
- 正文：恢复以后，它的商品重新参与比价、可以接新订单。｛看得到暂停原因时再加一段：｝当初暂停的原因：{原因}。请确认问题已经解决。
- 按钮：「取消」、「恢复」（主按钮；等待时「恢复中…」）。成功：Toast「已恢复「{名称}」」。
- 恢复不要求填原因（接口不收）。

## 7. 邀请管理员、发密码重置

两个都是有表单的对话框；成功后**原对话框换成**一次性链接对话框（同一个 `<dialog>` 里换内容，不叠两层）。

### 7.1 邀请管理员

- 标题：邀请管理员
- 说明：给「{供应商名称}」开一个管理员账号。｛已暂停：｝这家供应商已暂停，仍然可以邀请。
- 字段：邮箱 *、姓名 *（规则和出错文字同 4.1）。邮箱的帮助说明：「之前邀请过、但对方还没设密码的邮箱也可以填：会发出一条新的链接，旧的作废。」
- 对话框底部一条信息提示条：「系统不会发邮件。点「邀请」后会显示一条邀请链接，只显示一次。」
- 按钮：「取消」、「邀请」（主按钮；等待时「邀请中…」）。

| 后端返回 | 文字（邮箱字段下方） |
| --- | --- |
| 409 `EMAIL_TAKEN` | 这个邮箱已经有账号了（在这家或别的供应商，并且已经设过密码）。如果他是这家供应商的管理员、只是忘了密码，请用「发密码重置链接」。 |
| 404 | 找不到这家供应商。（对话框里危险提示条，去掉「邀请」，「取消」改成「知道了」） |

### 7.2 发密码重置链接

- 标题：给管理员发密码重置链接
- 说明：只能发给「{供应商名称}」里**在用的管理员**。别的角色（调度、财务等）忘了密码，请让他们自己的管理员在供应商后台里处理。
- 字段：管理员的邮箱 *（接口现在要靠邮箱指定是谁；账号列表有了以后从行上发起，不用再填）。
- 说明的第二段（`text-secondary`）：「发出链接不会改掉他现在的密码。请先确认提出要求的人就是他本人——例如打他留在合同上的电话。」
- 按钮：「取消」、「发出」（主按钮；等待时「发出中…」）。

| 后端返回 | 文字 |
| --- | --- |
| 404（供应商不存在，或这个邮箱不是它的管理员——接口不区分） | 邮箱字段下方：「这家供应商没有用这个邮箱的管理员。请核对邮箱；如果他不是管理员，请让他们的管理员处理。」 |
| 409 `ACCOUNT_NOT_ACTIVE` | 邮箱字段下方：「这个账号现在不是在用的状态。还没设过密码的，请用「邀请管理员」重新发邀请；已经被停用的，要先由他们的管理员启用。」 |

## 8. 状态、手机宽度、键盘、文案

**手机宽度**（最窄 320px）：列表用卡片（3.1）；新建页单栏；详情页 `<dl>` 单栏，标题行的按钮换到标题下一行、撑满，供应商编号可在任意位置折行；对话框贴底、按钮各占一行。**一次性链接对话框里的链接文本框高度随内容长到 5 行**，保证不用横向滚动就能看全；说明的几条可折行。在 320、360、400 三个宽度下检查：列表（加载中、有数据、两种空状态、失败、「更多」菜单打开）、新建页（含出错、同名提示）、一次性链接对话框（邀请、重置、没复制就关闭的确认、复制失败）、详情（正常、已暂停带原因、加载失败、404）、暂停 / 恢复 / 邀请 / 重置四个对话框和各自被拒绝的样子。

**键盘与读屏**

- 所有操作都能只用键盘完成；对话框的焦点规则按 `02-components.md` 第 9 节。
- 一次性链接对话框：`aria-labelledby` 指向标题，`aria-describedby` 指向「系统不会发邮件」那一条；打开时焦点在「复制链接」；Tab 顺序：链接文本框 → 复制链接 → 复制链接和说明 → 关闭。Esc 不关闭，但读屏用户要知道为什么：对话框里有一句只给读屏的话「这个对话框只能用最下面的按钮关闭」。
- 暂停原因的字数用 `aria-live="polite"`，只在剩 50 个字以内时播报。
- 状态徽标都有文字；已暂停的提示条 `role="status"`（它是持续状态，不是刚发生的错）。
- 两套主题各看一遍：徽标、已暂停的提示条、一次性链接对话框里的警告条和只读文本框（`bg-subtle` 上的等宽字）。

**Toast**：已新建供应商「{名称}」· 已暂停「{名称}」· 已恢复「{名称}」· 已邀请「{姓名}」· 已给「{姓名}」发出密码重置链接 · 已复制（供应商编号）

**按钮、菜单和链接**：新建供应商 · 查看 · 更多 · 邀请管理员 · 发密码重置链接 · 暂停 · 恢复 · 新建 · 邀请 · 发出 · 复制链接 · 复制链接和说明 · 已复制 · 我已经发给对方，关闭 · 仍然关闭 · 回去复制 · 看这家供应商的操作记录 · 回到供应商列表 · 取消 · 知道了 · 重试 · 清空筛选

## 10. 需要负责人定的事

1. **暂停供应商要不要两个人确认。** 需求文档把「停用租户」列为「敏感操作双人复核」（发起人和审核人不能是同一人）。现在是有权限的一个人填了原因就生效。**推荐：现在先一个人**（平台只有几个人，暂停可以随时恢复，每次都记入审计日志）；双人复核等审批流程统一做的时候一起加。
2. **「暂停」现在只是改了状态。** 页面按需求文档写了「商品不参与比价、已有订单继续履约、仍可登录」，其中「不参与比价」要等报价和比价功能上线才真正起作用（后端说明里写的是 M4-01）。**请知悉**；在那之前暂停一家供应商，实际效果只有它自己的后台上显示「已暂停」。
3. **邀请和重置链接由你们自己发给对方。** 系统没有邮件服务，页面把链接显示一次，由操作的人复制后用邮件、LINE 等发出去。**请确认这是可以接受的做法**；要系统自动发邮件的话，需要一个新任务（选邮件服务、你在服务商那里开账号并把密钥填进设置页）。
4. **供应商详情页暂时看不到管理员是谁。** 接口没有这项查询，所以页面上只能「填邮箱来邀请 / 重置」。**推荐尽快补**（第 9 节第 3 条）：这是运营最常问的问题——「他们的管理员是谁、接受邀请了没有」。
5. **运营和招商看不到暂停原因**（第 9 节第 2 条），只有超级管理员看得到。**推荐补。**
