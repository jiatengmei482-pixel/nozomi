# 主数据：城市、地点、车型组、附加服务

M1-08 的页面，都在运营后台「主数据」分组下（菜单和地址见 [`platform-home.md`](./platform-home.md) 第 2 节）。组件和令牌见上一级目录的规范；本文用到的新组件：多语言输入组、可增减的行、编码字段（`02-components.md` 第 16、17、19 节），主数据各种值的显示写法（`04-data-display.md` 第 6 节）。

接口是 `apps/api/openapi.yaml` 的 `/platform/v1/master/*`，规则见 ADR 0012。文中的「东京」「HND」等只用来说明格式，页面上不预置任何数据。

目录：1 概览 · 2 列表页的共同规则 · 3 四个列表各自的列和筛选 · 4 处理导入的机场 · 5 新增 / 编辑页的共同规则 · 6 四个表单各自的字段 · 7 导入来源的显示 · 8 保存出错的处理 · 9 文案汇总 · 10 手机宽度 · 11 键盘与无障碍 · 12 需要其他角色配合、待定的事

## 1. 概览

| 页面 | 给谁用 | 要完成什么 |
| --- | --- | --- |
| 四个列表页（城市、地点、车型组、附加服务） | 主数据运营、超级管理员维护；其他所有平台角色来查 | 找到一条记录；看它是不是启用的；停用 / 启用；进入新增或编辑 |
| 处理导入的机场 | 主数据运营、超级管理员。**负责人最先会用到的页面** | 把导入进来、还没有城市的机场一个接一个地指定城市并启用，中途不用回列表 |
| 新增 / 编辑页 | 主数据运营、超级管理员；其他角色打开是只读的 | 录入或修改一条记录 |

**权限**（用 `@nozomi/domain` 的 `platformRoleCan(角色, 操作)` 判断，不在页面里写角色名）

| 能做什么 | 需要的操作 | 现在有它的角色 |
| --- | --- | --- |
| 看列表、看详情 | `master_data.read` | 所有平台角色 |
| 新增、修改、停用、启用 | `master_data.manage` | 主数据运营、超级管理员 |

只能看的角色：列表页没有「新增」按钮、没有操作列；编辑页所有字段只读、没有保存按钮（细则见 5.7）；「处理导入的机场」页进不去（显示「没有权限」状态）。

**主数据没有删除，只有停用。** 页面上任何地方都不出现「删除」二字。

## 2. 列表页的共同规则

### 2.1 首屏看到什么

```
主数据 / 城市
城市                                                    [+ 新增城市]
（页面级提示条：有才显示）
[🔍 按编码或名称搜索      ] [状态：全部 ▾] [国家：全部 ▾]      清空筛选
┌──────────────────────────────────────────────────────────────────┐
│ 编码        │ 名称         │ 国家      │ 时区              │ 状态   │ 操作        │
├──────────────────────────────────────────────────────────────────┤
│ CTY-JP-TYO │ 东京          │ 日本（JP） │ Asia/Tokyo（UTC+9）│ ● 启用 │ 编辑  停用   │
│            │ 東京 / Tokyo  │           │                   │        │            │
│ …                                                                               │
└──────────────────────────────────────────────────────────────────┘
共 62 条                                每页 [50 ▾]  [上一页] [下一页]
```

首屏（1280×720，不滚动）必须看到：页面标题和「新增」按钮、筛选条、表头和至少 10 行。

- 页面类型「列表」，最大宽度 `layout-content-max-width`。
- 标题行：`<h1>` 是模块名（「城市」「地点」「车型组」「附加服务」）；右侧主按钮「新增{对象}」（带加号图标，是一个 `<a>`，去新增页）。标签页标题「{模块名} · NOZOMI 运营后台」。
- 从上到下：标题行 → 页面级提示条 → （地点才有的页签）→ 筛选条 → 表格 → 分页。

### 2.2 筛选

按 `02-components.md` 第 5 节「筛选条」。四个列表共有的两项：

| 条件 | 控件 | 选项 / 行为 | 网址参数 | 默认 |
| --- | --- | --- | --- | --- |
| 关键字 | 搜索框，`aria-label="按编码或名称搜索"`，占位文字「按编码或名称搜索」 | 匹配编码和任意一种语言的名称，不分大小写 | `q` | 空 |
| 状态 | 原生下拉，标签「状态」 | 全部 / 启用 / 已停用 | `status`（`active` / `disabled`） | 全部 |

- 默认看「全部」而不是只看启用的：运营来这里常常就是为了找被停用的那一条。
- 关键字对应接口的 `q` 参数（后端在 M1-08 里新增：编码或任意一种语言的名称里包含它，不分大小写）。最多 100 个字；提交前去掉首尾空格，去掉后是空的就不带这个参数。不用接口里按编码精确查找的 `code` 参数。
- 各列表自己的筛选条件见第 3 节。
- 每页条数：20 / 50 / 100，**默认 50**（主数据行短、要一屏多看，和接口默认值一致）。网址参数 `size`。

### 2.3 表格

- 按 `02-components.md` 第 5 节。行高 `table-row-height`；名称列允许两行（显示名一行 + 其余语言一行），其余列单行。
- **第一列是编码**：等宽字体；是一个去编辑页的 `<a>`（只读角色去的是同一个页面的只读态）。编码不截断，放不下时在任意位置折行（`overflow-wrap: anywhere`），列宽上限 160px。
- **名称列**：第一行显示名（`text-primary`，带 `lang`）；第二行其余语言的名称，「 / 」连接，`font-size-xs`、`text-tertiary`，单行省略，完整内容放 `title`。只有一种语言时没有第二行。
- **状态列**：状态徽标，「启用」（`success`）/「已停用」（`neutral`）。
- **操作列**（最右，只有能修改的角色才有这一列）：最多两个文字按钮。

  | 记录的情况 | 第一个 | 第二个 |
  | --- | --- | --- |
  | 启用 | 编辑（`<a>`） | 停用（`<button>`，字色 `danger-text`） |
  | 已停用 | 编辑 | 启用（`<button>`） |
  | 已停用、而且是还没有城市的导入机场 | **指定城市**（`<a>`，去「处理导入的机场」并从这一个开始） | 编辑 |

  每个按钮带读屏用的对象名：`aria-label="停用 CTY-JP-TYO 东京"`。
- 排序：接口固定按创建时间从早到晚，表头不提供排序。
- 没有多选和批量操作（本期不做批量停用 / 启用）。

### 2.4 分页

接口是游标分页：按 `02-components.md` 第 6 节「后端用游标分页的列表」。只有「上一页」「下一页」，没有页码。接口返回了符合条件的总数（`total`），左侧显示「共 {N} 条」（带千分位）。

### 2.5 停用

点行内的「停用」→ 确认对话框（`02-components.md` 第 9 节「危险操作的确认」）。

| 对象 | 标题 | 正文 |
| --- | --- | --- |
| 城市 | 停用城市「{显示名}」？ | 停用后，供应商的选项里不再出现这个城市；已经引用它的内容仍然查得到。之后可以重新启用。 |
| 机场 / 车站 / 地标 / 航站楼 / 出口 | 停用{类型}「{显示名}」？ | 停用后，供应商的选项里不再出现这个{类型}；已经引用它的内容仍然查得到。之后可以重新启用。 |
| 车型组 | 停用车型组「{显示名}」？ | 停用后，供应商的选项里不再出现这个车型组；已经引用它的内容仍然查得到。之后可以重新启用。 |
| 附加服务 | 停用附加服务「{显示名}」？ | 停用后，供应商的选项里不再出现这项附加服务；已经引用它的内容仍然查得到。之后可以重新启用。 |

- 标题下面用一行等宽小字显示编码，避免同名时停错。
- 按钮：「取消」（默认焦点）、「停用」（危险按钮；等待时「停用中…」）。
- 成功：关闭对话框，Toast「已停用「{显示名}」」，这一行的徽标变成「已停用」、操作变成「启用」，焦点落到这一行的「启用」按钮上。**这一行留在原地**，即使当前筛选是「状态：启用」也不立刻消失（下次查询时自然不再出现），避免列表在手底下跳。
- **被保护规则拒绝**（409 `MASTER_DATA_IN_USE`）：对话框不关，按 `02-components.md` 第 9 节「确认后被业务规则拒绝」处理。提示条的文字（`{N}` 取 `details.active_count`）：

  | 对象 | 提示条文字 | 提示条里的链接 |
  | --- | --- | --- |
  | 城市 | **现在不能停用。** 这个城市下还有 {N} 个启用中的地点，请先停用它们，再回来停用城市。 | 「查看这些地点」→ 地点列表，筛好「所属城市 = 这个城市、状态 = 启用」 |
  | 机场 | **现在不能停用。** 这个机场下还有 {N} 个启用中的航站楼，请先停用它们。 | 「去看航站楼」→ 这个机场的编辑页的「航站楼」一节 |
  | 车站 | **现在不能停用。** 这个车站下还有 {N} 个启用中的出口，请先停用它们。 | 「去看出口」→ 这个车站的编辑页的「出口」一节 |

  城市下的启用中的地点分属机场、车站、地标三个页签，「查看这些地点」先去数量最多的那个页签不现实（前端不知道分布）：统一去「机场」页签，并在该页面顶部的信息提示条里写「正在查看城市「{显示名}」下启用中的地点。车站、地标请切换页签查看。」
- 网络不通、服务器出错：对话框不关，按同一节「确认后网络不通或服务器出错」。
- 403：对话框不关，提示条「你没有权限修改主数据。需要的话，请联系管理员开通。」，去掉「停用」按钮。

### 2.6 启用

启用不需要确认（可以随时再停用），点了直接执行：按钮进入加载态「启用中…」。

- 成功：Toast「已启用「{显示名}」」，徽标变「启用」，操作变「停用」，焦点落到「停用」按钮。行留在原地。
- **还不能启用**（409 `MASTER_DATA_NOT_READY`，只有地点会遇到）：在筛选条和表格之间显示一条危险提示条（可以关闭；`role="alert"`），按 `details.reason`：

  | 原因 | 文字 | 提示条里的按钮 |
  | --- | --- | --- |
  | `CITY_MISSING` | 「{编码} {显示名}」还没有指定所属城市，不能启用。 | 「去指定城市」→ 处理导入的机场，从这一个开始 |
  | `CITY_DISABLED` | 「{编码} {显示名}」所属的城市「{城市显示名}」已停用，不能启用。请先启用这个城市。 | 「去看这个城市」→ 该城市的编辑页 |
  | `PARENT_DISABLED` | 「{编码} {显示名}」的上级「{上级编码} {上级显示名}」已停用，不能启用。请先启用上级。 | 「去看上级」→ 上级的编辑页 |

  前端已经知道没有城市的机场不能启用，所以这种行直接不给「启用」按钮（见 2.3），`CITY_MISSING` 只在数据刚好被别人改了时才会遇到。
- 网络不通、服务器出错：同一个位置的危险提示条，「启用「{显示名}」没有成功。网络连接失败，请检查网络后重试。」/「…系统暂时无法启用，请稍后再试。」
- 同一时间只显示最近一次操作的提示条。

### 2.7 各种状态

| 状态 | 显示什么 |
| --- | --- |
| 首次加载 | 筛选条照常显示并可用；表格画表头 + 5 行骨架灰条 |
| 改筛选、翻页 | 保留旧内容并降到 60% 不透明度 + 表格容器顶部 2px 进度条 |
| 加载失败 | 表格容器内（表头保留）错误状态：「加载失败」「请检查网络后重试。」+「重试」。筛选条件保留 |
| 还没有任何数据（没有任何筛选条件、第一页就是空的） | 表格容器内空状态，文案见第 3 节各列表；能修改的角色有主按钮「新增{对象}」，只读角色没有按钮 |
| 筛选后没有结果 | 「没有符合条件的{对象}」「换个条件试试，或清空筛选。」+ 次要按钮「清空筛选」 |
| 没有权限（403） | 内容区：「你没有权限查看这里」「需要的话，请联系管理员开通。」（目前所有角色都能看，这是兜底） |
| 登录已过期（401） | 跳到登录页，登录后回到这个列表（带着筛选条件） |

### 2.8 手机宽度（< 768px）

- **表格用方式 A**（`02-components.md` 第 5 节）：表格保持原样，在自己的容器里横向滚动，第一列（编码）固定在左侧。主数据是列多、主要在桌面维护的表；手机上是偶尔来查一下或改一个状态。真正要在手机上连续操作的「处理导入的机场」是单栏表单，不是表格。
- 固定的编码列最宽 120px（< 480px），编码在里面折行；它右边至少露出一列半，让人看得出可以横向滑。
- 筛选条：只留搜索框和「筛选」按钮，其余条件进底部面板（「筛选 · N」显示已生效的条件数）。
- 标题行：「新增{对象}」按钮放不下时换到标题下一行，撑满宽度。
- 分页：「上一页」「下一页」并排各占一半；「共 N 条」和每页条数在上一行。
- 停用确认对话框贴底显示，按钮各占一行。

### 3.2 地点

地点在数据里是一张表、五种类型（机场、车站、地标、航站楼、出口）。界面上这样分：

- **机场、车站、地标**是三个平级的**页签**，各是一张列表。页签在标题行下面、筛选条上面；默认「机场」；网址参数 `type`（`airport` / `station` / `poi`）。切换页签时保留「状态」和「关键字」，清掉该页签没有的条件，回到第一页。
- **航站楼、出口**是机场、车站的下级，**不出现在这三张列表里**，在所属机场 / 车站的编辑页里的「航站楼」/「出口」一节维护（见 6.3）。理由：它们离开上级没有意义，放进同一张表会让「97 个机场」和它们的航站楼混在一起。
- 页签按 `02-components.md` 第 10 节「页签」；页签上不显示数量。
- 标题行的主按钮跟着页签变：「新增机场」「新增车站」「新增地标」。

## 4. 处理导入的机场

地址 `/platform/master/places/pending`。入口有四个：首页「地点」卡片的提醒行、机场页签的警告提示条、机场列表行内的「指定城市」、启用被拒时提示条里的「去指定城市」。从后两个进来时带上 `?start={机场编号}`，从那一个机场开始。

### 4.1 为什么单独做一个页面

导入的机场是停用的、没有城市（ADR 0012）。现在有 97 个，以后导入更多国家会更多。如果每个都要「进编辑页 → 选城市 → 保存 → 回列表 → 点启用 → 找下一个」，就是几百次来回。这个页面把它变成一条流水线：**同一个位置，选城市，按 Enter，自动换下一个。**

首屏（1280×720）必须看到：说明、还剩多少个、当前机场的编码 / 名称 / 国家 / 坐标、「所属城市」输入框、三个按钮。

- 页面类型「表单」：内容最大宽度 `layout-form-max-width`，居左。
- 标题行右侧是次要按钮「回到地点列表」（`<a>`，去机场页签）。
- 说明文字：`font-size-md`，`text-secondary`，在标题行下方。
- 国家筛选（组合框，默认「全部」，网址参数 `country`）和「还剩 {N} 个」在同一行，两端对齐；放不下时「还剩」折到下一行。
- **当前机场是一张卡片**，上半部分是这个机场的资料（只读），分隔线下面是要填的内容。
- 「本次已处理」在卡片下方，记录这次打开页面以来处理过的机场（只在内存里，刷新就没有了），最新的在最上面，最多显示 10 条：编码、显示名、「→ 城市显示名」、状态徽标、去编辑页的「编辑」链接（万一选错了城市，从这里去改）。一条都没有时这一节不显示。

**卡片上半部分（机场资料）**

| 内容 | 样式 |
| --- | --- |
| 编码 | 等宽，`font-size-xl`，`font-weight-bold`。右侧是状态徽标「已停用」 |
| 名称 | 显示名，`font-size-lg`；`<h2>` |
| 国家 · 坐标 · 来源 | 一行，`font-size-sm`，`text-secondary`，用「·」分隔，可折行。坐标等宽，后面有「复制」图标按钮（`aria-label="复制坐标"`，复制的内容是 `纬度, 经度`，方便贴进地图软件核对位置） |

本任务不做地图。让人核对「这个机场在哪」靠的是英文名、国家和可以复制的坐标。

**卡片下半部分（要填的内容）**

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 所属城市（必填） | 组合框。选项只有**和这个机场同一个国家、启用中**的城市；每个选项显示「显示名 + 编码」；这次打开页面以来选过的城市排在最前（上面加一个小标题「最近用过」）。占位文字「输入城市名称或编码查找」。右边是次要按钮「新增城市」（见 4.4） | 不预选任何城市：数据源里的城市名是自由填写的文字，和平台的城市划分对不上，猜错比不猜更糟（ADR 0012）。没选就提交：「请选择所属城市」 |
| 名称（必填） | 多语言输入组，已有的语言都填好（导入的机场只有英语） | 至少一种。可以顺手补上中文、日语名，也可以不补 |
| 国际 / 国内（选填） | 单选组：不填 / 国际 / 国内 / 国际和国内，默认是这个机场现有的值（导入的是「不填」） | |

坐标不在这里改（要改坐标去编辑页）。

**这个国家一个启用中的城市都没有时**：组合框的面板里显示「还没有{国名}的城市」，输入框下方的帮助说明换成警告色的一行（图标 + 文字）：「还没有{国名}（{代码}）的启用中的城市。请先新增城市。」此时「新增城市」按钮换成主按钮样式，「保存并启用」「只保存，先不启用」禁用，旁边写「请先选择所属城市」。

### 4.3 三个按钮和连续操作

| 按钮 | 做什么 |
| --- | --- |
| **保存并启用**（主按钮，表单的默认提交；等待时「保存中…」） | 先保存（所属城市，以及改过的名称、国际 / 国内），成功后启用这个机场。两步都成功：Toast「已启用「{编码} {显示名}」」，记入「本次已处理」，**卡片换成下一个机场**，「还剩」减一 |
| 只保存，先不启用（次要按钮） | 只保存。成功：Toast「已保存「{编码} {显示名}」，还没有启用」，记入「本次已处理」（徽标是「已停用」），换下一个。这个机场有了城市，不再是「待指定城市」，以后在机场列表里筛「状态：已停用」找到它再启用 |
| 跳过（文字按钮，在最左） | 不保存，把这个机场排到队尾，换下一个。填了一半的内容丢弃，不弹确认（重新填只是再选一次城市）。被跳过的机场再轮到时，编码旁边加一个标签「跳过过」 |

**换下一个时**

- 卡片内容直接替换，不做翻页动画，页面不跳动；卡片滚回可见位置。
- 焦点落到「所属城市」输入框（桌面和手机都是——这一页就是用来连续输入的）。
- 只给读屏的 `role="status"` 播报：「下一个：{编码} {显示名}，还剩 {N} 个」。
- 所属城市清空，不沿用上一个机场选的城市。

**只用键盘的走法**：输入城市名的几个字 → ↓ 选中 → Enter 选定 → Enter 提交（组合框面板关着的时候，Enter 提交表单）→ 自动到下一个机场、焦点回到输入框。全程不用碰鼠标。

**队列怎么取**：按地点列表接口取「机场、还没有所属城市」的记录（需要后端加筛选条件，见第 12 节），加上国家条件，一次取 200 条，按接口的顺序（导入的先后）排队；队列里剩下不到 20 个且后面还有时，在后台取下一批。「还剩 {N} 个」用接口返回的总数（`total`）起算，每处理掉一个减一（跳过的不减）；每取一批新的就按新的总数校正一次。带 `start` 进来时，把那一个机场排到队首（它不在第一批里就单独取一次）。

### 4.4 新增城市（不离开这个页面）

点「新增城市」打开表单对话框（宽 640px；点遮罩不关闭）。标题「新增城市」。字段和校验与城市新增页完全相同（6.1），只有这几处不同：

- **国家**已经填好这个机场的国家，只读。
- **编码**已经填好前缀「CTY-{国家码}-」，光标在后面。
- **时区**：这个国家已有城市时，预填最近新增的那个城市的时区（同一个国家多数情况下时区相同，可以改）；没有则空着。
- **中心坐标**下面有一个文字按钮「填入这个机场的坐标」：点了把机场的纬度、经度填进去。是用户自己点的，不是默认值——机场往往离市中心几十公里，要不要拿它当城市中心由人决定。
- 按钮：「取消」「新增城市」（等待时「新增中…」）。
- 成功：对话框关闭，Toast「已新增城市「{显示名}」」，新城市**已经选在「所属城市」里**，焦点回到「保存并启用」按钮。用户再按一次 Enter 就完成这个机场。
- 出错处理同第 8 节，错误显示在对话框里。
- 对话框里填了内容后点「取消」或按 Esc：直接关闭，内容丢弃，不再弹「有未保存的修改」的确认（规范不允许对话框里再开对话框；这个表单短，重填代价小）。

### 4.5 出错和特殊情况

| 情况 | 显示什么 |
| --- | --- |
| 首次加载 | 说明文字照常；卡片是骨架屏（资料区三条灰块 + 三个输入框形状的灰块）；「还剩」位置是灰块 |
| 加载失败 | 卡片位置显示错误状态：「加载失败」「请检查网络后重试。」+「重试」 |
| **没有待处理的机场**（进来时就没有，或刚处理完最后一个） | 卡片位置显示空状态（图标用对勾，`success-text`）：标题「没有待指定城市的机场了」；说明：这次处理过至少一个时写「这一批都处理完了。」，否则写「导入新的机场后，会出现在这里。」；主按钮「回到地点列表」。选了国家而该国没有时：标题「{国名}没有待指定城市的机场」，次要按钮「看全部国家」 |
| 保存被拒：字段问题 | 显示在对应字段下（第 8 节） |
| 保存成功、**启用没成功** | 卡片顶部警告提示条：「城市已经指定好了，但还没有启用：{原因}」。原因：城市刚被停用 →「所属城市已停用，请先启用城市」；网络 / 服务器 →「网络连接失败」/「系统暂时无法启用」。提示条里两个按钮：「再试一次启用」「先处理下一个」。此时表单字段只读（已经保存过了） |
| 别人刚改过这个机场（409 `VERSION_CONFLICT`） | 重新取这个机场。它已经有城市了 → 从队列里去掉、换下一个，卡片顶部信息提示条：「「{编码} {显示名}」刚被别人处理过了，已为你换到下一个。」（可关闭）。它仍然没有城市 → 把最新内容填进表单（保留用户选的城市），卡片顶部警告提示条：「这个机场刚被别人修改过，已载入最新内容，请再确认一次。」 |
| 同时修改冲突（409 `CONCURRENT_UPDATE`） | 卡片顶部警告提示条：「同时有其他人在修改相关数据，这次没有保存成功。请再点一次。」内容保留 |
| 选的城市刚被停用（409 `MASTER_DATA_NOT_READY` / `CITY_DISABLED`，只在「保存并启用」的启用一步出现）| 见上面「启用没成功」 |
| 网络不通、服务器出错（保存一步） | 卡片顶部危险提示条：「网络连接失败，请检查网络后重试。你填写的内容还在。」/「系统暂时无法保存，请稍后再试。你填写的内容还在。」 |
| 没有修改权限的人打开这个地址 | 内容区「你没有权限查看这里」「需要的话，请联系管理员开通。」 |
| 离开页面时当前卡片填了一半 | 不弹「有未保存的修改」：这里每一个都很短，弹了反而打断 |

### 4.6 手机宽度

- 单栏；卡片内边距 `space-4`；所有输入框撑满。
- 「所属城市」和「新增城市」：< 480px 时按钮换到输入框下一行，撑满宽度。
- 单选组的四个选项折成两行两列。
- 三个按钮各占一行，从上到下：保存并启用、只保存先不启用、跳过。操作区不吸底（卡片不长，吸底会挡住键盘弹出后的内容）。
- 组合框的面板从底部升起（`02-components.md` 第 3 节）。
- 资料区的「国家 · 坐标 · 来源」折成多行；坐标整体不拆开（`white-space: nowrap` 只加在坐标这一小段上）。
- 「本次已处理」每条折成两行：第一行编码 + 状态徽标，第二行名称 → 城市 + 「编辑」。

## 5. 新增 / 编辑页的共同规则

四类主数据的新增、编辑都是**单独的页面**，不用对话框（字段超过一屏；要能用网址直接打开某一条）。新增和编辑是同一个表单组件。

### 5.1 首屏看到什么

```
主数据 / 城市 / 东京
东京                                                         [停用]
CTY-JP-TYO   ● 启用   最近修改 2026-10-07 14:30
（提示条：有才显示）
┌─────────────────────────────────────────┐
│ 基本信息                                  │
│ 国家            编码                       │
│ [日本（JP）]     [CTY-JP-TYO      ] [复制]  │
│ 创建后不能修改。   编码创建后不能修改。        │
│ 名称 *                                    │
│  中文 [东京                             ]  │
│  …                                       │
│ 位置与时区                                 │
│ …                                        │
├─────────────────────────────────────────┤
│                          [取消]  [保存]    │  ← 吸在视口底部
└─────────────────────────────────────────┘
```

- 页面类型「表单」，最大宽度 `layout-form-max-width`，居左。表单放在一张卡片里，按分组排（分组标题 `<h2>`，`font-size-lg`、`font-weight-bold`，分组之间 `space-8`）。
- ≥ 768px 两栏；多语言输入组、可增减的行、单选 / 复选组、地址、说明占整行。
- **标题行**

  | | 新增页 | 编辑页 |
  | --- | --- | --- |
  | `<h1>` | 新增{对象}（新增城市、新增机场、新增航站楼…） | 这条记录的显示名 |
  | 标题下一行 | 无 | 编码（等宽）+ 状态徽标 +「最近修改 {时间}」（`font-size-sm`，`text-tertiary`，本地时区），用间距 `space-3` 隔开，可折行 |
  | 标题行右侧 | 无 | 次要按钮「停用」（字色 `danger-text`）或「启用」，行为同 2.5、2.6（提示条显示在页面级提示条的位置） |
  | 标签页标题 | 新增{对象} · NOZOMI 运营后台 | {显示名} · {模块名} · NOZOMI 运营后台 |

- 新增的记录直接是启用状态：新增页的操作区上方写一行帮助说明「保存后直接是启用状态，供应商马上可以选到。」
- 不显示版本号、内部编号、创建时间。

### 5.2 操作区

吸在视口底部（`02-components.md` 第 4 节）。

| 页面 | 按钮（桌面从左到右；主按钮在最右） |
| --- | --- |
| 新增页 | 取消 · 保存并继续新增（次要） · **保存**（主按钮） |
| 编辑页 | 取消 · **保存**（主按钮） |

- 「取消」是文字按钮，回到来的地方（见 5.3）；表单有改动时先按 `02-components.md` 第 4 节弹确认「有未保存的修改，确定离开吗？」（按钮「继续编辑」「离开」）。
- 提交中：被点的那个按钮进入加载态「保存中…」，其他按钮不可用，字段只读。
- < 480px：按钮各占一行，主按钮在最上。

### 5.3 保存之后

| 操作 | 之后 |
| --- | --- |
| 新增页点「保存」 | 回到来的地方；Toast「已新增{对象}「{显示名}」」 |
| 新增页点「保存并继续新增」 | 留在新增页，Toast 同上；表单清空，**但保留那些连续录入时通常不变的字段**（见第 6 节各表「继续新增时保留」一列）；焦点回到第一个要填的字段；页面滚回顶部 |
| 编辑页点「保存」，有改动 | 回到来的地方；Toast「已保存「{显示名}」」 |
| 编辑页点「保存」，什么都没改 | 不发请求，直接回到来的地方，不显示 Toast |

「来的地方」：从哪个列表（带着它的筛选条件和页码）或哪个上级的编辑页进来的，就回哪里；直接用网址打开的，回这类主数据的列表第一页。

### 5.4 提交什么（前端必须照做）

- **新增**：提交全部字段。
- **修改：只提交用户改过的字段**，没碰过的字段不放进请求体。这不只是为了省流量：
  - 导入的机场一旦提交了和原来不同的英语名或坐标，就会被标成「平台改过」，以后不再随导入更新（第 7 节）。把没改的坐标原样带回去，本来不应该触发这个标记；只提交改过的字段就不用担心小数位取整造成的「看起来没改、其实变了」。
  - 城市的边界本期不在界面上编辑（6.1），任何时候都不提交它，才不会被误清掉。
- **「整体替换」的字段**：名称、说明（多语言）、坐标（纬度 + 经度一起）、人数 / 行李数组合、代表车型、适用品类。这些字段只要其中任何一部分改了，就要把整个字段的当前内容完整提交（改了日语名 → 提交四种语言当前的全部内容；改了纬度 → 经度一起提交）。
- **创建后不能改的字段**（编码、国家、地点的类型和上级、车型组的等级和座位数）在编辑页是只读的，修改时不提交。
- 请求头 `If-Match` 带打开页面时拿到的版本号。
- 判断「改没改」：和打开页面时的值比较（文字去掉首尾空格后比较；坐标按 6 位小数的写法比较；列表类按顺序和内容比较）。改了又改回去算没改。

### 5.5 校验

- 时机按 `02-components.md` 第 4 节：失去焦点时校验，出过错的字段实时重新校验，提交时全部校验。
- 编码、组合等规则直接调用 `@nozomi/domain` 的函数（`cityCodeIssue`、`placeCodeIssue`、`vehicleGroupCodeIssue`、`vehicleComboIssues`、`addonCodeIssue`、`hasVisibleText`、`isLongitude`、`isLatitude`、`isIanaTimeZone`），和后端用的是同一份，不另写一套正则。出错文字用本文第 6 节给出的定稿；domain 函数返回的说明如果和定稿不同，以定稿为准（原因见第 12 节第 5 条）。
- 提交时有错：焦点到第一个出错的字段；这些表单都超过一屏，按规范在表单顶部另放危险提示条「有 N 处需要修改」+ 字段名列表（点了跳到字段）。

### 5.8 坐标输入（城市、地点共用）

```
纬度 *                 经度 *
[35.552258          ]  [139.779694         ]
```

- 两个输入框并排（< 480px 上下排），**纬度在左、经度在右**。各有自己的标签；外层 `<fieldset>`，`<legend>` 是「中心坐标」或「坐标」。提交给接口时字段是 `lng`、`lat`，不要按界面顺序对错。
- `type="text"`，`inputmode="text"`（不用 `decimal`：iPhone 的小数键盘没有负号，西半球和南半球的坐标输不了），`autocomplete="off"`，等宽字体，占位文字不放。
- **粘贴**：在任一个框里粘贴「35.552258, 139.779694」「35.552258 139.779694」这种一对数字（逗号、空格、制表符分隔，全角逗号也认）时，自动拆开填进两个框，按「纬度, 经度」的顺序。如果第一个数的绝对值大于 90、第二个不大于 90（一看就是经度在前），就反过来填，并在下方用信息色的一行提示「看起来是经度在前，已自动对调。请核对。」
- 失去焦点时整理成 6 位小数的写法（多的四舍五入，少的补 0）：`35.5523` → `35.552300`。
- 出错文字：

  | 情况 | 文字 |
  | --- | --- |
  | 没填 | 请输入纬度 / 请输入经度 |
  | 不是数字 | 纬度要填数字，例如 35.552258 / 经度要填数字，例如 139.779694 |
  | 超出范围 | 纬度必须在 -90 到 90 之间 / 经度必须在 -180 到 180 之间 |

- 本任务不做地图，没有「在地图上选点」。

## 8. 保存出错的处理

适用于四类主数据的新增 / 编辑页、「处理导入的机场」页、新增城市对话框。所有情况下**用户已经填的内容都保留**。「表单顶部」指卡片内最上方的提示条位置；出错和警告是 `role="alert"`。

| 400 `VALIDATION_FAILED`，位置对不上任何字段；或 400 `BAD_REQUEST` | 表单顶部危险提示条 | 提交的内容不符合要求，请检查后重试。 | — |
| 409 `CODE_TAKEN` | 「编码」字段下方 | 这个编码已经被使用，请换一个 | 焦点到编码并全选 |

## 11. 键盘与无障碍

- 所有操作都能只用键盘完成；Tab 顺序与视觉顺序一致。
- 列表页的顺序：跳到正文 → 顶栏 → 「新增」→（提示条里的按钮）→（页签，←→ 切换）→ 搜索框 → 各筛选条件 → 清空筛选 → 表格容器（方向键横向滚动）→ 每行的编码链接、操作按钮 → 分页。
- 表格用真正的 `<table>`，表头 `<th scope="col">`，编码所在的单元格是 `<th scope="row">`，这样读屏在读操作按钮时会带上编码。
- 行内操作执行后的焦点见 2.5、2.6（留在这一行的新按钮上，不丢到页面顶部）。
- 状态变化（启用 / 停用成功）由 Toast 的 `role="status"` 读出；被拒绝和出错由提示条的 `role="alert"` 读出。
- 组合框（所属城市、国家、时区）按 `02-components.md` 第 3 节的键盘和 ARIA 规则。
- 单选组、复选框组用 `<fieldset>` + `<legend>`；多语言输入组、坐标输入、可增减的行同样是 `<fieldset>`。
- 「处理导入的机场」换下一个时用 `role="status"` 播报（4.3）；卡片是 `<section>`，`aria-labelledby` 指向机场名称的 `<h2>`。
- 只读字段可以聚焦、可以被读到（`readonly`，不是 `disabled`）。
- 亮色、暗色各看一遍，重点看：`success` 和 `neutral` 两种状态徽标在表格悬停行（`bg-hover`）上；「待指定城市」警告徽标；警告提示条和信息提示条；只读字段（`bg-subtle` + `text-primary`）；固定的编码列与右侧列的分隔线；吸底操作区的上边线。
