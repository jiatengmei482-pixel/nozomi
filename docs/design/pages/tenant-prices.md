| 页面 | 给谁用 | 要完成什么 |

**界面上的说法**（全站统一，第 12 节有完整对照）

- **结算价**：供应商报给平台的价格。这几页上所有金额都是结算价，用子品牌的结算币种。**任何地方都不出现对外价和加价比例，也不写「平台会在此基础上……」这类暗示的话**（CLAUDE.md 规则 4）。
- **价格规则**（一条也叫「一条价格」）：一个组合在一段用车日期里的基础价。
- **组合**：一个区域 + 一个车型组 +（接送机）方向 /（包车）套餐。
- **方向**：接机、送机、接送通用（接送点是车站时：接站、送站、接送通用）。
- **套餐**：包车卖的「几小时 / 多少公里」。
- **计价方式**：固定一口价（本文和页面的说明文字里简称「一口价」）、里程 + 时长（接送机、点对点）；包车套餐（包车）。下拉选项里的名字取自 `@nozomi/domain` 的 `PRICING_MODEL_NAMES`。
- **生效日期**：这条价格对哪些**用车日期**有效（不是下单日期）。
- **调价规则**：在基础价上再调一次的规则；每条规则里有一到几个**调价步骤**，写成「上调 20%」「下调 JPY 1,000」——**界面上用「上调 / 下调」，不用「加价 / 减价」**。
- **基础价**：价格规则直接算出来的价。**调价后的结算价** = 基础价按命中的调价规则依次算完、再取整的结果。

**权限**（用 `@nozomi/domain` 的 `tenantRoleCan` 判断）

| 能做什么 | 需要的操作 | 有它的角色 |
| --- | --- | --- |
| 看三个页签、看菜单里的「价格规则」 | `product.read` | 管理员、商品价格、只读 |
| 改价格规则、调价规则 | `product.manage` | 管理员、商品价格 |
| 改子品牌的取整单位（第 7 节） | `brand.manage` | 只有管理员 |

后端如果给价格另设操作（如 `price.manage`），以它为准，本文的「能修改的角色」跟着换。

## 3. 价格规则

### 3.1 一条价格是什么

**一条价格 = 一个组合 + 一段生效日期 + 计价方式和它的几个数 + 启用 / 停用。**

| 品类 | 组合里有什么 | 可用的计价方式 |
| --- | --- | --- |
| 接送机 | 区域 + 车型组 + **方向**（接机 / 送机 / 接送通用） | 一口价、里程 + 时长 |
| 点对点 | 区域 + 车型组 | 一口价、里程 + 时长 |
| 包车 | 区域 + 车型组 + **套餐时长** | 包车套餐（只有这一种，不显示「计价方式」这一列） |

- 区域、车型组只能是这个商品在第 ① 步选的那些。
- **接送通用**：接机、送机用同一个价。同一个区域和车型组既有「接送通用」又有「接机」时，接机的询价用「接机」那一条（需求文档：更具体的优先），送机的仍用「接送通用」。
- 可用的计价方式以接口给的清单为准（价格规则应答里的 `available_models`）；清单里只有一种时不显示「计价方式」这一列。
- **「里程 + 时长」现在就可以填**（已定）。它报价时要用预估的里程和时长，而路线预估功能还没有上线（M2-02）。所以只要表里有这种价格，价格表上方就有一条信息提示条（不能关闭）：「**按里程和时长计价的价格现在可以先设好。** 按客人实际路线的里程和时长报价，要等路线预估功能上线；在那之前，价格日历上显示的是不超出起步里程和起步时长时的价。」

### 3.2 「该有价格的组合」怎么数

覆盖表、页签上的「缺 {N}」、操作区的概况、上架检查里的提醒，数的是同一件事（用 `@nozomi/domain` 的同一个函数算，14.2）：

| 品类 | 一共有多少个组合 | 一个组合什么时候算「有价格」 |
| --- | --- | --- |
| 接送机 | 区域数 × 车型组数 × 2（接机、送机） | 有一条**启用、还没过期**的价格，方向是它自己或「接送通用」 |
| 点对点 | 区域数 × 车型组数 | 有一条启用、还没过期的价格 |
| 包车 | 区域数 × 车型组数 × 套餐数（套餐 = 这个商品现有价格里出现过的套餐时长，加上本页刚新增、还没填价的，3.8；后者接口不知道，由页面自己加进去） | 这个套餐时长有一条启用、还没过期的价格 |

- 「还没过期」= 结束日期留空，或结束日期不早于城市当地的今天。**以后才开始生效的也算有价格**，覆盖表里会写明哪天起（3.3）。
- 「今天」一律用价格规则应答里的 `today`（城市当地的今天），**不用浏览器的日期**。页面上没保存的修改也要算进去，所以页面用 `@nozomi/domain` 的 `priceCoverage` 对「页面上现在的内容」现算；接口应答里的 `coverage`（`total` / `priced` / `missing`）只在刚加载完、还没改任何东西时和它相同。
- 已停用的区域、平台已停用的车型组照常计入（它们由第 ① 步和上架检查提醒），名字后面加 `neutral` 徽标。
- 没有价格的组合**不是出错**：供应商可以有意不做某个组合。所以它用警告色、不拦保存、不拦上架；但文字要说清后果——「没有价格的组合，客人询价时报不出价」。

### 3.3 覆盖表

  | 情况 | 总结 | 颜色 |
  | --- | --- | --- |
  | 有缺的 | **{M} 个组合里 {K} 个有价格，{N} 个没有价格**（后面一行小字：没有价格的组合，客人询价时报不出价。） | 「{N} 个没有价格」连同三角图标用 `warning-text` |
  | 都有 | {M} 个组合都有价格 | 对勾图标 + `success-text` |
  | 一条都没有 | 还没有设价格（后面一行小字：在下面的表格里填。每一行是一个组合，填上价格、点保存就行。） | `text-secondary` |

- 表格：行 = 区域（按第 ① 步的顺序），列 = 车型组（按等级 → 座位数 → 编码）。行头是区域显示名，列头是车型组显示名（第二行编码，等宽，`font-size-xs`，`text-tertiary`）。
- 右上角一个单选组「**看：**」决定每一格显示哪个方向 / 套餐：接送机是「接机」「送机」（车站：接站、送站）；包车是各套餐「5 小时」「10 小时」…（多于 4 个时换成原生下拉）；点对点没有这一项。每个选项后面带它自己缺的个数：「送机（缺 4）」。
- **每一格**（是一个按钮，点了把下面的价格表筛到这个区域和车型组，并把焦点放到对应那一行的第一个输入格）：

  | 情况 | 显示 | 样式 |
  | --- | --- | --- |
  | 现在有价格 | 金额（不带币种；币种在表的标题里写一次） | `text-primary`，右对齐，等宽数字 |
  | 里程 + 时长 | 「{起步价} 起」 | 同上 |
  | 接机 / 送机用的是「接送通用」那一条 | 金额下面一行小字「通用价」 | `font-size-xs`，`text-tertiary` |
  | 以后才开始 | 金额 + 下面一行「{YYYY-MM-DD} 起」 | 小字用 `info-text` + 时钟图标 |
  | 30 天内到期、后面没有接着的价格 | 金额 + 下面一行「{MM-DD} 到期」 | 小字用 `warning-text` + 三角图标 |
  | **没有价格** | 三角图标 +「没有价格」 | 底 `warning-bg`，字和图标 `warning-text` |
  | 只有停用的 / 只有过期的 | 三角图标 +「没有价格」，下面一行小字「有 1 条已停用」/「已过期」 | 同上；小字 `text-primary` |
  | 这一格有未保存的修改 | 按上面的规则显示**修改后**的样子，最下面多一行小字「未保存」 | `font-size-xs`，`text-primary` |

  每一格的 `aria-label`：「{区域}，{车型组}，{方向 / 套餐}：{JPY 15,000 / 没有价格 / …}。到价格表里看这一行」。
- 覆盖表跟着页面上**现在的内容**实时变（不等保存），让人边填边看到缺口在变小。
- 组合很多时：容器最高 `min(60dvh, 480px)`，自己纵横滚动，表头和第一列吸住。区域 > 12 个时默认收起，只显示总结那句话和「展开」。
- < 768px 的排法见第 10 节。

### 3.4 价格表

组件「可编辑表格」见 `02-components.md` 第 30 节。**表格里的每一行是一条价格；每个还没有价格的组合也占一行，空着等填**——不用点「新增」，看到空行直接填就是新增。

**筛选**（表格上方一行，控件 `sm`；都只筛显示，不影响保存）

| 条件 | 控件 | 默认 |
| --- | --- | --- |
| 区域 | 原生下拉（> 10 个用组合框）：全部 + 各区域 | 行数（含空行）≤ 150 时「全部」；更多时默认第一个有缺口的区域，下拉上方一行小字「组合很多，一次看一个区域。」 |
| 车型组 | 同上 | 全部 |
| 方向 / 套餐 | 原生下拉：全部 + 各方向 / 各套餐（点对点没有） | 全部 |
| 只看没有价格的 | 复选框 | 不勾 |
| 显示已过期的 | 复选框 | 不勾（已过期的价格默认不显示；有 {N} 条被藏着时，复选框后面写「（{N} 条）」） |

有未保存修改的行即使不符合筛选条件也**一直留在表里**，不会因为改筛选而看不见。

**排序固定**：区域（第 ① 步的顺序）→ 车型组（等级 → 座位数 → 编码）→ 方向（接送通用 → 接机 → 送机）/ 套餐时长（从短到长）→ 生效日期（从早到晚）。同一个区域的行，区域那一格只在第一行显示名字（其余行读屏照常读得到）；区域之间用 `border-strong` 的横线隔开。

**列**

| 列 | 内容与控件 | 备注 |
| --- | --- | --- |
| （多选） | 复选框；表头的复选框 = 全选现在显示的行 | 只读角色没有 |
| 区域 | 区域显示名（`<th scope="row">` 的一部分）；已停用的加徽标 | 不能在行里改：要给另一个区域设价，填那个区域的行 |
| 车型组 | 显示名 + 第二行「6 人 4 件」（`font-size-xs`，`text-tertiary`）；平台已停用的加徽标 | 同上 |
| 方向（只有接送机） | 原生下拉：接送通用 / 接机 / 送机 | 空行的默认值见下 |
| 套餐（只有包车） | 文字「10 小时」；后面跟输入格「套餐公里」[   ] 公里 | 套餐时长不能在行里改（它是组合的一部分，3.8） |
| 计价方式（接送机、点对点；可用的只有一种时不显示） | 原生下拉：一口价 / 里程 + 时长 | 改了以后这一行的价格格子跟着换（3.5）；原来填的数先留着，保存时只提交当前计价方式用得到的 |
| 价格的各个数 | 见 3.5。每个数一列，表头带单位和币种 | 金额输入见 3.6 |
| 生效日期 · 从 | 日期输入（`02-components.md` 第 27 节） | 必填。空行预先填好城市当地的今天 |
| 生效日期 · 到 | 日期输入，占位文字「一直有效」 | 留空 = 一直有效 |
| 启用 | 复选框（随保存生效，所以不用开关）；`aria-label="启用这条价格"` | 空行默认勾着 |
| （这一行现在怎么样） | 图标 + 文字，见 3.7 | 不可编辑 |
| （操作） | 「更多」菜单：再加一段日期 · 复制到其他区域或车型组 · 清空这一行 / 删除 / 撤销删除 | 只读角色没有这一列 |

- **空行的方向**（接送机）：一个区域和车型组两个方向都没有价格时，给一行，方向预先选「接送通用」；只有一个方向没有价格时，给一行，方向预先选缺的那个。
- 表格在自己的容器里横向滚动；多选、区域、车型组三列吸在左边。纵向滚动时表头吸顶。
- **表格下方固定一条「这一行的意思」**（读回来的话，3.10）：焦点在哪一行，就读那一行。
- 表格右上角（筛选那一行的右侧）是工具区：选中行以后出现批量操作（3.9）。**这一区的最右边是「导入 / 导出」菜单按钮**（M1-05）：下载空白模版、导出现有的价格、导入价格——入口、下载、导入页（选文件 → 看检查结果 → 确认导入）都写在 [`tenant-inventory.md`](./tenant-inventory.md) 第 7、8 节。导入成功回到这一页时，价格表按服务器的内容重新取。

### 3.5 三种计价方式各填什么

**一口价**（接送机、点对点）

| 列 | 单位 | 规则 | 帮助（表头的说明，见下） |
| --- | --- | --- | --- |
| 基础价 * | 结算币种 | 大于 0 | 每单收多少，不看里程和时长 |

**里程 + 时长**（接送机、点对点）

| 列 | 单位 | 规则 | 帮助 |
| --- | --- | --- | --- |
| 起步价 * | 结算币种 | 不小于 0；**填 0 时必须填最低消费**（否则零里程的行程算出来是 0）：「起步价是 0 时，请填最低消费」 | 起步里程和起步时长以内收这个价 |
| 起步里程 * | 公里，最多 1 位小数（接口里是整数米 `start_meters`，100 的倍数；页面用字符串换算，不用浮点数） | 0 到 1,000 | 起步价里包含多少公里 |
| 起步时长 * | 分钟，整数 | 0 到 1,440 | 起步价里包含多少分钟 |
| 超出每公里 * | 结算币种 / 公里 | 不小于 0；0 = 超出里程不另收 | 超过起步里程后，每公里加多少；不足 1 公里的按比例算 |
| 超出每分钟 * | 结算币种 / 分钟 | 不小于 0；0 = 超出时长不另收 | 超过起步时长后，每分钟加多少 |
| 最低消费（选填） | 结算币种 | 留空 = 不设；填的话大于 0 | 算出来不到这个数时，按这个数收 |

- 表头的「基础价」这一列和「起步价」是同一列（表里两种计价方式的行都有时，表头写「基础价 / 起步价（{币种}）」）。**里程 + 时长的另外五列只在表里有这种行时才出现**；一口价的行在这五列里显示「—」（不是输入格，Tab 跳过）。
- 最低消费填得比起步价还低：不拦，那一格下面的行提示（3.7）写「最低消费比起步价低，不会起作用」。
- 这种价格**按预估的里程和时长报价，不按实际跑的结算**（需求文档）。这句话写在「这一行的意思」里（3.10）。

**包车套餐**（包车）

| 列 | 单位 | 规则 | 帮助 |
| --- | --- | --- | --- |
| 套餐时长 | 小时，整数 | 1 到 72；是组合的一部分，在「套餐」里管（3.8），行里不能改 | — |
| 套餐公里 * | 公里，整数 | 1 到 5,000 | 套餐价里包含多少公里 |
| 套餐价 * | 结算币种 | 大于 0 | 这个套餐收多少 |
| 超时每小时 * | 结算币种 / 小时 | 不小于 0；0 = 超时不另收 | 超过套餐时长后每小时收多少，服务结束后按实际结算；不足 1 小时的按比例算 |
| 超公里每公里 * | 结算币种 / 公里 | 不小于 0；0 = 超公里不另收 | 超过套餐公里后每公里收多少，服务结束后按实际结算；不足 1 公里的按比例算 |

- 包车的超时费、超公里费**只在这里设**（需求文档）；第 ② 步的附加服务里没有。
- 范围的上下限取自 `@nozomi/domain` 的 `PRICE_LIMITS`（上表是它现在的值；任何一个金额最多 1,000,000,000 个最小货币单位），页面不写死。
- **超出的部分不凑整**（ADR 0018：超出 500 米收 0.5 公里的钱，超时 30 分钟收半小时的钱）。需求文档没有写超出部分按什么粒度算 **［需负责人确认］**（15.8）。

**表头的帮助**：每个价格列的表头名字后面有一个「说明」图标按钮（圆圈问号，`aria-label="{列名}的说明"`），点开是一个小面板（下拉面板样式，不是悬停气泡——触屏上也要能看到），内容是上表「帮助」那一句。同一句话也会出现在「这一行的意思」里，所以不看帮助也能填对。

**出错文字**（显示在哪见 3.7）

| 情况 | 文字 |
| --- | --- |
| 必填的没填（这一行已经填了别的格） | 请填{列名}｛可以是 0 的列再加：｝，不另收请填 0 |
| 该大于 0 的填了 0 | {列名}要大于 0（基础价、套餐价、最低消费） |
| 不是数字 | 请填数字 |
| 负数 | {列名}不能是负数 |
| 小数位超了 | 日元金额不能有小数 / {币种} 最多 {N} 位小数（`04-data-display.md` 第 1 节） |
| 太大 | {列名}最多 {上限} |
| 起步里程、起步时长、套餐公里超范围 | 请填 {下限} 到 {上限} 之间的数｛整数的列：整数｝ |
| 生效日期 | 「请填开始日期」；「这不是一个日期，请按 2026-10-08 的格式填写」；「结束日期不能早于开始日期」 |

### 3.6 金额怎么输入、怎么显示

组件见 `02-components.md` 第 29 节；规则沿用 `04-data-display.md` 第 1 节「输入金额」，这里写清这一页的做法。

- **币种不在每一格里重复**：表头写一次「基础价（JPY）」，格子里只有数字，右对齐，等宽数字。表格以外的金额输入框（调价步骤、手机上的表单）仍然把币种代码放在输入框的后缀里。
- **小数位**按结算币种（`@nozomi/domain` 的 `CURRENCIES`）：
  - 没有小数的币种（JPY、KRW）：`inputmode="numeric"`，只收数字；敲了小数点或粘贴了带小数的数，失去焦点时报「日元金额不能有小数」（韩元同理），**不自动四舍五入、不自动去掉小数**。
  - 两位小数的币种：`inputmode="decimal"`，最多两位；只填整数的，失去焦点后补成两位（`4600` → `4,600.00`）。
- **千分位**：输入时不插逗号；失去焦点后显示带千分位的写法（`20,000`）；再聚焦时变回纯数字（`20000`）并全选，方便直接重填。
- 容错（失去焦点或粘贴时整理）：去掉逗号、空格、币种代码和符号（`JPY`、`¥`、`円`、`元`）；**全角数字、全角小数点换成半角**（日语、中文输入法下常见）。整理不出数字的不动它并报「请填数字」。
- 不能为负；不用 `type="number"`。
- 字符串和金额之间的转换只用 `@nozomi/domain` 的 `parseMajor` / `formatMajor`，**不用浮点数**。
- 上限以 `@nozomi/domain` 导出的为准；输入框的 `maxlength` 按上限的位数加上千分位和小数留够。

### 3.7 每一行现在怎么样

倒数第二列，图标 + 文字（`font-size-sm`），一行只显示一种，从上往下取第一个符合的：

| 情况 | 图标 | 文字 | 颜色 |
| --- | --- | --- | --- |
| 有写错的 | 圆形叹号 | 第一条出错文字（其余的在「这一行的意思」里列全） | `danger-text` |
| 和别的价格日期重叠（第 4 节） | 圆形叹号 | 和 {N} 条价格的日期重叠 | `danger-text` |
| 将删除（点保存后才真的删） | 短横线 | 将删除 + 文字按钮「撤销」 | `text-secondary`；这一行的输入格变成只读、文字加删除线 |
| 新填的，还没保存 | 实心圆点 | 新的，未保存 | `info-text` |
| 改过，还没保存 | 实心圆点 | 改过，未保存 | `info-text` |
| 空行（这个组合没有价格） | 三角警示 | 没有价格 | `warning-text` |
| 已停用（没勾「启用」） | 短横线 | 已停用 | `text-secondary` |
| 已过期 | 短横线 | 已过期 | `text-secondary` |
| 以后才开始 | 时钟 | {YYYY-MM-DD} 起生效 | `info-text` |
| 30 天内到期、同一个组合后面没有接着的价格 | 三角警示 | {YYYY-MM-DD} 到期，之后没有价格 | `warning-text` |
| 生效中 | 对勾 | 生效中 | `success-text` |

- 「生效中 / 以后才开始 / 已过期」按城市当地的今天算。
- 「30 天内到期」由页面判断：结束日期不晚于 `addDays(today, 30)`（`@nozomi/domain`），并且同一个组合没有从结束日期的后一天接上的启用的价格。不算「还有几天」，只写到期的日期。
- 有未保存修改的行，行首另有 3px `primary` 竖条（`02-components.md` 第 30 节）；出错和重叠的行，行首是 3px `danger-solid` 竖条。竖条只是辅助，文字是这一列。
- 出错的那一格用输入框的出错样式（`02-components.md` 第 2 节）；出错文字不在格子下面展开（表格行高不跟着跳），显示在这一列和「这一行的意思」里。

### 3.8 包车的套餐

包车的组合里有「套餐时长」，而商品本身没有「卖哪些套餐」的清单——**套餐就是价格里出现过的那些时长**。所以包车商品在覆盖表上方多一行「套餐」：

```
套餐：  [5 小时 ×]  [10 小时 ×]   [+ 新增套餐]
```

- 每个套餐是一个标签（`02-components.md` 第 7 节），按时长从短到长；能修改的角色看到标签上的「×」（`aria-label="删除 {N} 小时套餐"`）。
- **「新增套餐」**（次要按钮，`sm`）打开一个小对话框：

  | 字段 | 控件 | 规则与提示 |
  | --- | --- | --- |
  | 套餐时长 * | 输入框，后缀「小时」，`inputmode="numeric"` | 整数，1 到 72。和已有的重复：「已经有 {N} 小时的套餐了」 |
  | 套餐公里 * | 输入框，后缀「公里」 | 整数，1 到 5,000。帮助说明：「先给这个套餐的每一行都填上这个公里数，之后可以在表格里一行一行改。」 |

  按钮「取消」「新增」。确定后：价格表里给每个「区域 × 车型组」多出一行这个套餐的空行（套餐公里已经填好），覆盖表的「看」里多一个选项并切到它，焦点落到第一行新空行的「套餐价」。**新增套餐本身不发请求**：一行价格都没填就离开的话，这个套餐不会留下。
- 「×」删除一个套餐：这个套餐下有已保存的价格时先确认——标题「删除 {N} 小时套餐？」，正文「这个套餐下的 {K} 条价格会标成「将删除」，点保存后才真的删除。」，按钮「取消」「标成将删除」（次要按钮，字色 `danger-text`）。只有空行时不用确认，直接去掉。
- 一个套餐都没有（新商品）：覆盖表和价格表的位置是一个空状态——标题「**先加一个套餐**」；说明「包车卖的是套餐，例如「10 小时 / 300 公里」。加了套餐，下面会列出每个区域和车型组，等你填套餐价。」；主按钮「新增套餐」。

### 3.9 快一点录：多选、批量、复制、粘贴

组合多的时候（5 个区域 × 6 个车型组 × 2 个方向 = 60 行），一格一格敲太慢。四种办法，都**只改页面上的内容，点保存才生效**：

**① 键盘像表格软件一样走**（`02-components.md` 第 30 节）：Tab / Shift+Tab 横着走，Enter / Shift+Enter 竖着走到下一行 / 上一行的同一列。填完一列基础价只用数字键和 Enter。

**② 粘贴一片**：在任何一个输入格里粘贴从表格软件复制来的多行多列内容（换行分行、Tab 分列），从这一格起**向右、向下**依次填进现在显示的行；超出表格的部分丢掉。粘贴后用 `role="status"` 播报并在表格上方显示一条信息提示条：「已填 {N} 格｛，有 {K} 格的内容不是数字，没有填｝。还没有保存。」+ 文字按钮「撤销这次粘贴」。只粘贴一个值时就是普通粘贴。

**③ 批量改**：勾选若干行后，工具区显示「已选 {N} 条」和下面的按钮（放不下时收进「批量操作」菜单）：

| 按钮 | 打开的对话框 | 做什么 |
| --- | --- | --- |
| **设生效日期** | 「从」「到」两个日期输入（都可以留空 = 不改这一头）；「到」下面一个复选框「改成一直有效」 | 把选中行的生效日期改成一样的。会造成日期重叠时，对话框里先用警告色写出「改完以后有 {K} 条会和别的价格日期重叠」，仍然可以应用（到表格里再处理，第 4 节） |
| **填同一个数** | 列出这些行共有的价格列，各一个输入框（都可以留空 = 不改这一列） | 把填了的那几列写进所有选中行（空行也写，等于给它们新增价格） |
| **调整价格** | 单选「上调 / 下调」+ 单选「按比例 / 按金额」+ 数值；下面一张预览表列出前 5 行的「现在 → 调整后」和一句「共 {N} 条」 | 把选中行里已经有数的**主价格**（基础价 / 起步价 / 套餐价）一起调。按比例的结果四舍五入到币种的最小单位（用 `@nozomi/domain` 的 `applyBasisPoints`）；调完不大于 0 的行不动，并在预览里标出来。空行不受影响 |
| **启用** / **停用** | 无 | 勾上 / 取消选中行的「启用」 |
| **删除** | 无（点保存前随时可以撤销） | 已保存的行标成「将删除」；新填的行清空，变回空行 |

**④ 复制到其他区域或车型组**（选中行的批量按钮，也在每一行的「更多」菜单里）——对话框：

| 字段 | 控件 | 规则与提示 |
| --- | --- | --- |
| 复制到哪些区域 | 多选复选框组：这个商品的全部区域；默认只勾选中行自己所在的区域 | 至少勾一个 |
| 复制到哪些车型组 | 多选复选框组；默认都不勾 | 区域和车型组合起来至少要有一个不是自己的组合 |
| 价格 | 单选：「原样复制」（默认）/「复制时上调」/「复制时下调」；选后两种时出现「按比例 / 按金额」和数值 | 只调主价格（基础价 / 起步价 / 套餐价）；其余的数原样 |
| 目标组合已经有价格时 | 单选：「跳过」（默认）/「换成复制过去的」 | 「换成」= 把目标组合里日期有重叠的那几条标成「将删除」，再填进新的 |

- 方向 / 套餐、计价方式、生效日期、启用状态原样带过去。
- 对话框底部实时写出结果：「会填 {N} 个组合｛，跳过 {K} 个已经有价格的｝」。N 是 0 时「复制」按钮禁用，旁边写「没有可以填的组合」。
- 按钮「取消」「复制」。确定后：目标行填上内容，状态是「新的，未保存」；Toast 不发（还没保存），用 `role="status"` 播报「已填 {N} 个组合，还没有保存」；焦点落到第一条被填的行。

**再加一段日期**（行的「更多」菜单）：在这一行下面插入同一个组合的新行，价格的数照抄，「从」预先填成上一段结束日期的后一天（上一段是「一直有效」时留空，并触发 4.2 的提示），焦点落到新行的「从」。用来做「明年 4 月 1 日起换新价」。

- 批量操作、粘贴、复制都可以用页面上方信息提示条里的「撤销」退回一步（只退最近的一次）；点保存以后不能撤销。
- 一次保存最多 500 条（`PRICE_LIMITS.maxBatchChanges`）；一个商品最多 2,000 条价格（超了保存时接口会拒绝，页面在到 2,000 条时就不再让新增，提示「一个商品最多 2,000 条价格，请先删掉用不到的（例如已过期的）。」）。未保存的修改到 400 条时，操作区左侧的概况换成警告色：「未保存的修改已经有 {N} 条，一次最多保存 500 条，请先保存。」到 500 条后再改别的行会被拦住，提示同一句话。

### 3.10 读回来的话：「这一行的意思」

表格下方固定的一条（`02-components.md` 第 30 节「当前行说明」）：底 `bg-subtle`，`font-size-sm`，`text-primary`，`aria-live="polite"`（焦点换行或输入停下 500ms 后更新）。焦点不在表格里时显示最后停留的那一行；从没进过表格时写「点表格里的任何一行，这里会用一句话说明这一行的价格。」

格式：**「{区域} · {车型组} · {方向 / 套餐}——{价格的话}{生效日期的话}」**，后面跟这一行的全部出错文字和提醒。金额带币种代码（`04-data-display.md` 第 1 节）。

| 计价方式 | 价格的话（示意数字） |
| --- | --- |
| 一口价 | 每单 JPY 20,000，不看里程和时长。 |
| 里程 + 时长 | 10 公里、30 分钟以内 JPY 8,000；超出的部分每公里 JPY 300（不足 1 公里按比例）、每分钟 JPY 50｛；最少收 JPY 9,000｝。按预估的里程和时长报价，不按实际跑的结算。例：预估 20 公里、50 分钟 = JPY 12,000。 |
| 包车套餐 | 10 小时、300 公里以内 JPY 98,000；超时每小时 JPY 5,000，超公里每公里 JPY 400（超出的部分服务结束后按实际结算，不足 1 小时、1 公里的按比例算）。 |

- 填 0 的写成人话：「超出里程不另收」「超出时长不另收」「超时不另收」「超公里不另收」；起步里程是 0 写「起步价里不含里程」，起步时长是 0 写「起步价里不含时长」。
- 里程 + 时长的「例」：里程取「起步里程 + 10 公里」，时长取「起步时长 + 20 分钟」，结果用 `@nozomi/domain` 的 `basePrice(pricing, { meters, minutes })` 算、再四舍五入到币种的最小单位，**页面不自己写公式**。五个必填的数没填齐时不显示「例」。
- 生效日期的话：「2026-10-10 起一直有效。」/「2026-10-10 至 2027-03-31 有效。」/ 没勾启用时再加「**现在是停用的，不会用来报价。**」
- 这一行还没填价格时：「{区域} · {车型组} · {方向}——还没有价格。客人询价这个组合时报不出价。」
- 这句话是**基础价**，不含调价规则。句子最后固定跟一个链接「在价格日历里看每天的结算价」（带上这一行的组合去 6.2 的地址；这一行有未保存的修改时不显示这个链接）。

### 3.11 各种状态

| 状态 | 显示什么 |
| --- | --- |
| 加载中 | 覆盖表：总结那句话是骨架，表格画行头列头（区域、车型组的名字从商品里已经有了）+ 骨架格。价格表：表头 + 5 行骨架。操作区不显示 |

| 筛选后一行都没有 | 表格容器里：「没有符合条件的价格」「换个条件试试。」+「清空筛选」 |

### 3.12 只读角色

- 覆盖表照常（格子仍然可以点，用来筛选和定位）。
- 价格表没有多选列、「启用」复选框和操作列；输入格全部显示成文字（金额带千分位、右对齐）；「启用」一列显示「启用」/「已停用」；没有价格的组合照常列出空行，写「没有价格」。
- 「这一行的意思」照常。没有保存按钮，操作区只有「下一步」。

## 4. 生效日期重叠

### 4.1 规则

**同一个商品里，同一个「区域 + 车型组 + 方向 / 套餐时长」的价格，生效日期不能重叠**（需求文档）。

- 日期两头都算在内：「到 2027-03-31」和「从 2027-03-31」是重叠的，下一段要从 2027-04-01 起。
- 「一直有效」= 没有结束日期，和它开始以后的任何一段都重叠。
- 方向不同就不是同一个组合：「接送通用」和「接机」可以同时有（接机的询价用接机那一条）。包车的套餐时长不同也不是同一个组合。
- 计价方式不在组合里：同一个组合同一天只能有一条价格，不管是哪种计价方式。
- 已停用的价格**也算**（否则一启用就撞上）；标了「将删除」的不算。
- 判断只用 `@nozomi/domain` 的 `findPriceRuleOverlaps`，页面和后端是同一份规则。

### 4.2 填的时候就提示

每次改了生效日期、方向，或做了批量操作、粘贴、复制，页面都对**这个商品的全部价格**（包括被筛选藏起来的）重新算一遍重叠。

- 重叠的每一条：行首 3px `danger-solid` 竖条；「从」「到」两格用出错样式；状态列写「和 {N} 条价格的日期重叠」。
- 「这一行的意思」里逐条写出和谁重叠，并给出最可能的改法：

  > **和这个组合的另一条价格日期重叠：**「2026-10-10 起一直有效，JPY 20,000」。
  > ［把那一条的结束日期改成 2027-03-31］ ［到那一行］

  - 「把那一条的结束日期改成 {这一条开始日期的前一天}」：只在「那一条开始得更早、这一条开始得更晚」时给（最常见的情况：旧价一直有效，现在加一段新价）。点了以后那一行的「到」被改掉、标成「改过，未保存」，重叠消失；用 `role="status"` 播报「已把「{那一条的日期}」那一条的结束日期改成 {日期}」。
  - 其余情况只给「到那一行」（把筛选放开到能看见它，焦点落到它的「从」）。
- 页面级提示条的位置出现一条危险提示条（`role="alert"`，重叠第一次出现时播报一次，之后数量变化不重复打断）：

  > **有 {N} 条价格的生效日期重叠，保存前要改。**
  > · 东京 23 区 · 商务 7 座 · 接机：2027-04-01 起一直有效 ↔ 2026-10-10 起一直有效
  > · ……（最多列 5 组，其余写「还有 {K} 组」）

  每一组是一个按钮，点了跳到其中靠后的那一条。
- **有重叠时不能保存**：点保存不发请求，焦点移到这条提示条。（它属于「写错了」，不是「没填完」。）
- 批量「设生效日期」、「复制到…」的对话框里，应用前就写出会新造成几条重叠（3.9），让人在对话框里就能换个日期。

### 4.3 保存被拒绝（409 `PRICE_RULE_CONFLICT`）

页面已经先查过，所以真的被拒绝时，多半是**别人刚加了一条**，或页面上的内容过时了。

- **这次保存一条都没有存进去**（批量保存是全部成功或全部失败）；页面上填的内容全部保留。
- 用应答里的明细（`details.conflicts[]`：每条 `{ id 或 ref, valid_from, valid_to, with: [{ id 或 ref, valid_from, valid_to }] }`——已经在库里的用 `id`，这次新增的用页面提交时起的 `ref`）把这些行标成 4.2 的重叠样式。
- 和它重叠的那一条不在页面上时：重新取一次这个商品的价格，把新出现的行并进表格（未保存的修改不动），这些行的状态列在这一次会话里写「别人刚加的」（`info-text`，实心圆点）。
- 页面级危险提示条（焦点移到它）：

  > **没有保存。** 有 {N} 条价格的生效日期和已有的价格重叠，所以这一批都没有保存。改好以后再点保存。
  > · {组合}：{这一条的日期} ↔ {已有那一条的日期}｛（别人刚加的）｝

  每一条是按钮，点了跳到那一行。
- 应答里没有明细、或对不上页面上的行：提示条只写第一句，加一句「请点「重新读取价格」后再检查。」和按钮「重新读取价格」（重新取，保留未保存的修改，再按 4.2 重新算）。
- 接口是按**保存之后**的样子判断重叠的：同一批里把旧的删掉、加上同一个组合的新的，不算重叠。页面的即时检查同样不把「将删除」的算进去（4.1）。
- 调价规则没有这种冲突（它们可以重叠，重叠了就依次算）。

### 5.2 顺序就是先后

- **只靠「上移」「下移」按钮，不要求拖动**（做法同 `02-components.md` 第 26 节：焦点跟着这一行走，`Alt` + `↑` / `↓` 是快捷键，每次移动用 `role="status"` 播报「{规则名} 现在排第 {i}，共 {N} 条」）。
- 动过顺序以后**不立即保存**：表格上方出现一条信息提示条「顺序改了，还没有保存。」，操作区变成「还原顺序」（次要按钮）、「保存顺序」（主按钮；等待时「保存中…」）。保存成功 Toast「已保存顺序」。有未保存的顺序时离开，按未保存的修改处理。
- 保存顺序被拒绝，原因是规则的编号和库里的对不上（400，原因 `IDS_MISMATCH`：别人刚新增或删除了一条）：页面级警告提示条「**调价规则刚被别人改过，顺序没有保存。** 已经载入最新的列表，请重新排一下。」，列表重新取。
- 顺序没保存时，启用 / 停用、删除、「编辑」照常可点：点「编辑」等会离开列表的，先问未保存的顺序；启用 / 停用、删除不问（它们不影响顺序），做完后未保存的顺序还在。
- 新建的规则排在**最后**（最后算）。
- 停用的规则留在原来的位置，计算时跳过。
- 顺序什么时候有影响，写在说明里就够了；想知道某一天具体怎么算，去价格日历点那一天（6.4）。

### 5.3 新建 / 编辑：首屏看到什么

单独的页面（表单超过一屏），仍然在第 ③ 步里：步骤导航、说明行、三个页签都在，「调价规则」页签显示为当前。`<h3>` 是「新建调价规则」/ 规则名；它左边一个文字按钮「‹ 回到调价规则」。

表单最大宽度 `layout-form-max-width`，从上到下五张卡片：**名称 → 什么时候 → 对哪些 → 怎么调 → 这条规则的意思（读回来的话和试算）**。首屏（1280×720）必须看到名称、「什么时候」整张卡片、操作区。

**名称**

| 字段 | 控件 | 规则与提示 |
| --- | --- | --- |
| 出行日期 | 日期范围输入：「从」「到」都可以留空。新建时「从」预先填城市当地的今天 | 看的是**用车日期**，两头都算在内。「从」留空 = 不限开始；「到」留空 = 一直有效；读回来的话按 `02-components.md` 第 27 节（都空着写「不限日期」）。出错文字同 3.5 的生效日期。周期选了「指定日期」时这一项不显示，提交时两头都留空（日期就是下面选的那些） |

周期的四个选项（每个选项下面一行小字；选中的那一个展开自己的字段）：

| 选项 | 小字 | 展开的字段 |
| --- | --- | --- |
| 每天 | 出行日期里的每一天。 | 无 |
| 每周的某几天 | 出行日期里的每个周几。 | 星期选择（`02-components.md` 第 34 节）：周一到周日七个可以多选的按钮。至少选一个：「请至少选一天」。旁边两个文字按钮「工作日」「周末」（一次选好周一到周五 / 周六周日） |

  - 商品所在的国家不在清单里：复选框组上方一行警告色的提示（三角图标 + `warning-text`）：「平台还没有登记{国名}的节假日，暂时不能按{国名}的节假日调价。可以先用「指定日期」，或联系平台运营。」

  - 已有的规则里选着一个现在没有数据的国家（平台后来删了，或是经接口建的）：那个国家照常列出并保持勾选，名字后面加 `neutral` 徽标「没有数据」，下面警告色的一行：「{国名}现在没有登记节假日，这一部分不会生效。」
  - 预览只列平台**已经登记**的日子。预览下面固定一行小字（`text-tertiary`）：「节假日以平台登记的为准；平台之后补登或改动，这条规则会跟着变。」
- **时段两头怎么算，和第 ② 步的服务时间不一样**（时段输入下方固定一行帮助说明，`text-tertiary`）：「从开始的时间起算，到结束的时间之前为止：填 22:00 到 06:00，06:00 整用车的不算在内。（第 ② 步的服务时间是两头都算。）」这样相邻的两条规则（06:00–22:00 和 22:00–06:00）在交界的那一分钟不会同时生效。
- 时段的读回来的话（时段输入自带的那一行）要结合周期写清跨午夜落在哪一天：

  | 周期 + 时段 | 读回来的话 |
  | --- | --- |
  | 每天，22:00–06:00 | 每天 22:00–次日 06:00，共 8 小时（跨午夜） |
  | 每周五、周六，22:00–06:00 | 周五 22:00–周六 06:00、周六 22:00–周日 06:00 |
  | 指定日期 2026-12-31，22:00–06:00 | 2026-12-31 22:00–2027-01-01 06:00 |

**对哪些**（卡片说明：「不选就是全部。以后这个商品新加的区域、车型组也算在「全部」里。」）

每一项都是「**全部 / 指定**」的单选组——不用「留空 = 全部」的多选框，免得把「还没选」看成「全部」：

| 字段 | 选项 | 选「指定」时 |
| --- | --- | --- |
| 区域 | 全部区域（默认）/ 指定区域 | 复选框组：这个商品在第 ① 步选的区域（> 12 个时换成带搜索的多选面板）。至少勾一个：「请至少选一个区域，或改成「全部区域」」 |
| 车型组 | 全部车型组（默认）/ 指定车型组 | 同上 |
| 方向（只有接送机） | 接机和送机（默认）/ 只接机 / 只送机（车站：接站、送站） | 看的是**客人这一单是接还是送**，和价格规则里用的是「接送通用」还是「接机」那一条无关 |
| 套餐（只有包车） | 全部套餐（默认）/ 指定套餐 | 复选框组：这个商品现有的套餐（「5 小时」「10 小时」） |

- 指定的区域、车型组后来从第 ① 步去掉了：编辑页里照常列出并保持勾选，名字后面加 `neutral` 徽标「已不在这个商品里」，下面一行警告色提示「有 {N} 个已经不在这个商品里，保存时会一起去掉。」

**怎么调**：策略步骤编辑器，见 5.4。

### 5.4 调价步骤和试算

组件见 `02-components.md` 第 33 节。

```
怎么调 *
第 1 步   [上调 ▾]  [按比例 ▾]  [     20 ] %              [↑] [↓] [×]
第 2 步   [下调 ▾]  [按金额 ▾]  [  1,000 ] JPY            [↑] [↓] [×]
[+ 加一步]
几步从上到下依次算：后一步在前一步算完的结果上接着算。
```

| 每一步的格子 | 控件 | 规则 |
| --- | --- | --- |
| 方向 | 原生下拉：上调 / 下调 | 新的一步默认「上调」。**正负号不让人手敲**：提交时由页面换成带正负号的数 |
| 方式 | 原生下拉：按比例 / 按金额 | 默认「按比例」 |
| 数值 | 按比例：输入框，后缀「%」，最多两位小数。按金额：金额输入（3.6），后缀币种代码 | 都要大于 0（「请填大于 0 的数。不想调，请删掉这一步」）。上调按比例最多 1,000%（「上调最多 1,000%」）；下调按比例最多 99.99%（「下调要小于 100%」）——即 `PRICE_LIMITS.minPercentBp` 到 `maxPercentBp`。金额的上限同价格 |

- 至少 1 步、最多 10 步（`PRICE_LIMITS.maxAdjustSteps`）；到上限时「加一步」禁用，旁边写「最多 10 步」。只剩一步时删除按钮禁用，`title`「至少保留一步」。
- 「上移」「下移」换步骤的先后（做法同 5.2，立即体现在试算里）。
- 百分比在接口里是基点整数（20% = 2000），金额是最小货币单位整数；换算用字符串和整数，不用浮点数（`04-data-display.md` 第 2 节）。

**这条规则的意思**（最后一张卡片；只读的内容，`aria-live="polite"`，输入停下 500ms 后更新）

第一段是**一句话读回**：

> 2027-10-01 至 2027-10-07，每天、全天；全部区域、全部车型组、接机和送机：在基础价上**上调 20%**，再**下调 JPY 1,000**。

（各部分的写法见 `04-data-display.md` 第 9 节。必填的没填齐时，没填的那一段用 `text-tertiary` 写「（还没有填{什么}）」。）

第二段是**试算**——拿一个基础价一步一步算给人看：

```
用哪个价来算： [东京 23 区 · 商务 7 座 · 接机　JPY 20,000 ▾]

                            变化          算完是
基础价                                    JPY 20,000
第 1 步  上调 20%            +4,000       JPY 24,000
第 2 步  下调 JPY 1,000      −1,000       JPY 23,000
取整到 JPY 100                            JPY 23,000
────────────────────────────────────────────────
这条规则单独生效时：JPY 20,000 → JPY 23,000，比基础价高 JPY 3,000。
同一天还命中别的调价规则的话，会接着往下算，最后才取整；每天实际是多少，看价格日历。
```

- **用哪个价来算**（原生下拉）：选项是这个商品里**这条规则碰得到的**（`adjustRuleCoversPrice`）、启用且没过期的价格，写成「{区域} · {车型组} · {方向 / 套餐}　{金额}」，最多列 20 条；最后一项是「自己填一个数」（选了以后旁边出现一个金额输入框）。默认第一条。金额用这条价格**能报出的最低数**（价格规则应答里每条的 `base`，等于 `basePrice(pricing, {}, packageHours)`：一口价的基础价、里程 + 时长的起步价或最低消费、包车的套餐价）；里程 + 时长的后面标「（不超出起步时）」。一条都碰不到时，只有「自己填一个数」，输入框是空的，表格的位置写「填一个基础价，这里会一步一步算给你看。」——**页面不预先放一个示例数字**。
- 每一行的数**全部来自 `@nozomi/domain` 的 `applyAdjustRules(基础价, [这条规则], 取整单位)`**：它返回每一步的 `delta`、`after`（没取整的精确值）、`unrounded` 和取整后的 `finalMinor`。后端的价格日历和以后的报价用的是同一个函数（经 `tripPrice`）；页面不自己做乘除。
- **四舍五入和后端一致**：中间每一步不取整（需求文档：每一步用高精度计算，只在最后取整一次）。中间结果不是整数时照实显示（用 `formatExact` 给出的十进制写法，最多 6 位小数），后面加小字「（还没取整）」；最后一行才是「四舍五入｛、取整到 {币种} {取整单位}｝」的结果。四舍五入的规则是正好一半时远离零（`money.ts` 的 `roundFractionToUnit`）。
- 变化那一列带正负号；上调、下调另有文字（第二列），不只靠正负号和颜色。
- 算下来最后的结果**不大于 0**（`finalMinor` 为 `null`）：那一行用危险色 + 圆形叹号，下面写「按这个价算下来不大于 0，这样的规则保存不了。请把下调改小。」（保存时拦，5.5。）
- 窄屏的排法见第 10 节。

### 5.5 校验、异常确认、保存

- 校验时机按 `02-components.md` 第 4 节；点保存时有错，焦点到第一处，顺序：名称 → 出行日期 → 周期 → 时段 → 区域 → 车型组 → 套餐 → 各步骤。页面级提示条的位置放「有 {N} 处需要修改」。
- 调价规则**必须填完整才能保存**（它没有「草稿」：存下来启用了就会影响报价；想先存着就不勾「启用」）。
- **调完不大于 0 的规则存不了**（只查启用的规则；不勾「启用」可以先存着）。点保存时页面先用 `adjustRuleNonPositivePrices(这条规则, 启用且没过期的价格)` 查一遍，有的话不发请求，页面级危险提示条：「**不能保存。** 按「{组合}」的价格 {金额} 算，调完不大于 0｛；另有 {K} 条价格也是这样｝。请把下调改小、缩小适用范围，或先不勾「启用」。」后端拒绝时（400，原因 `ADJUST_RESULT_NOT_POSITIVE`，只告诉有几条：`detail.count`）用同一句话；页面自己找不出是哪一条时写成「按适用范围内的 {count} 条价格算，调完不大于 0。」
- **调得很多时再问一次**（平台的风控要求：单条调价超过 +300% 或低于 −50%，保存时二次确认）。判断用 `@nozomi/domain` 的 `adjustRuleIsUnusual(规则, 基础价们)`：这条规则单独生效时，对它碰得到的任何一条价格（或试算里自己填的那个数）的结果高于基础价的 4 倍、或低于基础价的一半。后端不拦，只由页面确认。确认对话框（不是危险操作，但默认焦点在「回去检查」）：
  - 标题：这条规则调得很多，确认保存？
  - 正文：按「{组合}」的价格算，{金额} 会变成 **{金额}**（{上调 / 下调}了 {金额}）。如果是多敲了一个 0，请回去改。
  - 按钮：「回去检查」「确认保存」（主按钮；等待时「保存中…」）。
- 保存成功：回到「调价规则」页签（从价格日历来的回价格日历，6.5），Toast「已新建调价规则「{名称}」」/「已保存「{名称}」」；列表里这一行短暂用 `bg-selected` 标出（2 秒，设置了「减少动态效果」时不做），焦点落到它的名称链接。
- 新建请求带 `Idempotency-Key`。保存被拒绝、别人先改了、离开时的确认：同 `tenant-products.md` 第 8 节。这条规则已经被别人删了（404）：页面级危险提示条「找不到这条调价规则，它可能已被别人删除。」+ 链接「回到调价规则」，保存按钮禁用。
- 操作区：「取消」（回列表，有修改先问）、「保存」（主按钮）。已上架的商品，操作区左侧写「已上架，保存后约 1 分钟生效」。

### 5.6 这条规则碰得到价格吗

一条规则存得下来，不等于它会生效。「这条规则的意思」卡片最下面、以及列表里那一行的名称下面，出现下面的情况时用警告色（三角图标 + `warning-text`）写一行；都不拦保存：

| 情况 | 文字 |
| --- | --- |
| 适用范围内没有任何启用且没过期的价格 | 适用范围里现在没有价格，这条规则暂时调不到任何东西。 |
| 出行日期和适用范围内所有价格的生效日期都不重合 | 这段出行日期里，适用范围内没有生效的价格。 |
| 「每周的某几天」在出行日期里一次都不出现（例如日期只有周一到周三，选的却是周六） | 出行日期里没有{周几}，这条规则不会生效。 |
| 节假日：出行日期里没有假日 | 5.3 预览里的那一句 |

### 5.7 启用、停用、删除

**启用 / 停用**（列表里的开关）

- 草稿、已下架的商品：点了立即保存，开关旁边的文字跟着变，Toast「已启用「{名称}」」/「已停用「{名称}」」。失败时开关弹回去，页面级危险提示条说明原因。启用、停用不带版本号（接口不要求），但成功后商品的版本号会变，页面要用应答里的新版本号。启用时接口会再查一遍「调完不大于 0」：被拒绝（400，`ADJUST_RESULT_NOT_POSITIVE`）时提示条写「**没有启用。** 按现在的价格算，这条规则有 {count} 条价格调完不大于 0。请先改这条规则。」+ 链接「去修改」。
- **已上架的商品先确认**（它马上会改变正在卖的价格）：标题「启用「{名称}」？」/「停用「{名称}」？」；正文「这个商品已上架，{启用 / 停用}后大约 1 分钟生效，之后的报价就会{按这条规则调价 / 不再按这条规则调价}。已经下的订单不受影响。」；按钮「取消」（默认焦点）、「启用」/「停用」（主按钮）。
- 启用一条「调得很多」的规则（5.5）：不管商品是什么状态，都用 5.5 的那个确认。

**删除**——确认对话框（危险操作）：

- 标题：删除调价规则「{名称}」？
- 正文：删除后不能恢复。｛已上架：｝这个商品已上架，删除后大约 1 分钟生效。只是暂时不用的话，可以停用。
- 按钮：「取消」（默认焦点）、「删除」（危险按钮；等待时「删除中…」）。成功：这一行消失，Toast「已删除调价规则「{名称}」」，焦点到下一行的名称链接（没有就到「新建调价规则」）。

### 5.8 只读角色

列表没有「新建调价规则」、上移 / 下移、开关、「更多」；「编辑」写「查看」。打开一条规则：字段全部是只读样式（单选组显示成一行文字，步骤显示成「第 1 步：上调 20%」），「这条规则的意思」和试算照常（「用哪个价来算」可以换，它不改数据）；没有保存按钮，只有「回到调价规则」。只读角色打开 `…/adjust/new`：「你没有权限查看这里」。

## 6. 价格日历

### 6.1 这一页回答什么

选一个组合，看这个月**每一天客人用车时的结算价**是多少、是哪条价格、被哪几条调价规则调过。它**只看不改**：要改，点过去改价格规则或调价规则；想对一段日期调价，在日历上选日期新建调价规则（6.5）。

日历上的结算价 = **基础价 → 依次过命中的调价规则 → 取整**。**不含**加急费、夜间加价、附加服务（它们跟下单时间、用车时刻、客人选了什么有关，在第 ② 步设）。这句话固定写在日历下方（`font-size-sm`，`text-tertiary`）：

> 日历上是按价格规则和调价规则算出来的结算价，不含加急费、夜间加价和附加服务。日期是{城市显示名}当地的用车日期。

### 6.3 月历的每一格

组件见 `02-components.md` 第 32 节。一周从周一开始；只画这个月的日子，月初月末的空位是空白格（不显示相邻月的日子，免得把别的月的价当成这个月的）。

每一格从上到下：

| 行 | 内容 | 样式 |
| --- | --- | --- |
| 第一行 | 日期的「日」（等宽数字）；今天后面跟文字「今天」；是假日的后面跟假日名（单行省略；接口给的是**商品所在国家**、平台登记过的假日） | 日 `font-size-sm` + `text-secondary`；今天的「日」和「今天」用 `font-weight-bold` + `text-primary`；假日名 `font-size-xs` + `text-tertiary` |
| 第二行 | **结算价**（不带币种；币种在说明行里已经写了） | `font-size-md`，`font-weight-medium`，`text-primary`，等宽数字 |
| 第三行 | 命中的调价规则：朝上 / 朝下的箭头图标 + 第一条规则的名字（单行省略）；多于一条时后面跟「+{N}」 | `font-size-xs`，`text-secondary`。箭头的方向是「比基础价高 / 低」；调完和基础价一样时用短横线 |

特殊的格子（**文字 + 图标，不只靠颜色**）：

| 情况 | 第二行显示 | 第三行显示 | 样式 |
| --- | --- | --- | --- |
| 没有调价规则命中 | 结算价 | 空 | — |
| **这一天没有价格**（没有价格规则覆盖这一天，或那一条停用了） | 三角图标 +「没有价格」 | 「已停用」/ 空 | 底 `bg-subtle`；图标和字 `warning-text` |
| 里程 + 时长的价格 | 「{金额} 起」 | 同普通格 | 月历下方多一行说明：「这个组合按里程和时长计价，日历上是不超出起步里程和起步时长时的价（起步价或最低消费）调完以后的数。按客人实际路线报价要等路线预估功能上线。」 |
| 这一天里不同时段的价不一样 | 「用车时间」那个时刻的价 | 规则名后面跟标签「分时段」 | 标签样式（`02-components.md` 第 7 节） |
| 调完不大于 0（正常保存时已经拦住，别的修改造成时才会出现） | 圆形叹号 +「算不出价」 | 第一条规则名 | 图标和字 `danger-text` |
| 已经过去的日子 | 照常 | 照常 | 「日」用 `text-tertiary`；其余不变（过去的价仍然看得清） |

- 每一格是一个可以聚焦的单元格（`role="gridcell"`），读作「10 月 1 日周五，｛国庆节，｝结算价 JPY 24,000，上调，命中国庆旺季｛等 2 条规则｝」/「10 月 9 日周六，没有价格」。
- 格子的高度是 `table-row-height` 的两倍；≥ 768px 七列等分容器宽度（`repeat(7, minmax(0, 1fr))`）。更窄时不画格子，见第 10 节。

### 6.4 某一天的明细

点一格（或聚焦后按 Enter）= 选中这一天，明细面板显示它。面板的位置：≥ 1280px 在月历右侧（宽 320px，吸在视口里）；768–1279px 在月历下面；< 768px 从底部升起（第 10 节）。没有选中任何一天时，面板显示今天（今天不在这个月里就显示这个月的 1 日）。

```
2027-10-01 周五 · 国庆节                       （<h4>；日期用 <time>）
结算价  JPY 24,000                             （font-size-xl，font-weight-bold）
10:00 用车 · 东京 23 区 · 商务 7 座 · 接机

基础价                          JPY 20,000
  一口价 · 2026-10-10 起一直有效   [改这条价格]

   上调 20%          +4,000      JPY 24,000
取整到 JPY 100                   JPY 24,000
────────────────────────────────────────

  00:00–22:00   JPY 24,000
  22:00–24:00   JPY 26,400   还命中「周末夜间」
```

- 规则按执行的先后编号；每条规则下面逐步列出「怎么调 / 变化 / 算完是」（写法同 5.4 的试算；数字来自接口，页面不重算）。
- 「取整」一行：只有四舍五入时写「四舍五入」，另设了取整单位时写「取整到 {币种} {单位}」。取整前后一样也照常列出（让人知道有这一步）。
- 「这一天不同时段的价」只在这一天有不止一段时显示；当前「用车时间」所在的那一段前面加文字「现在看的」。
- **没有价格的日子**：结算价的位置写「**这一天没有价格**」，下面说明原因和去处：

  | 原因 | 文字 | 按钮 |
  | --- | --- | --- |
  | 这个组合一条价格都没有 | 这个组合还没有价格，客人询价时报不出价。 | 去填价格（去「价格规则」页签，筛到这个组合） |
  | 有价格，但生效日期不包括这一天 | 这个组合的价格在这一天不生效：｛列出最近的前后两段日期｝。 | 去改生效日期 |
  | 覆盖这一天的那条价格是停用的 | 这一天的价格现在是停用的。 | 去启用 |
- 「改这条价格」去「价格规则」页签并定位到那一行；「改这条规则」去那条调价规则的编辑页。只读角色的按钮写「看这条价格」「看这条规则」。
- 面板是 `<section aria-labelledby>`，内容更新时用 `aria-live="polite"` 只播报第一行和结算价。

### 6.5 在日历上选一段日期，新建调价规则

**选的是连续的一段日期**（按日期的先后，不是矩形）：从 9 月 28 日选到 10 月 3 日，中间的每一天都选上。只能在显示着的这一个月里选（跨月的规则，选完到表单里再改「到」）。

| 用什么 | 怎么选 |
| --- | --- |
| 鼠标 | 在一格上按下、拖到另一格、松开；或点一格再按住 Shift 点另一格。只点一下 = 只选中这一天（并显示它的明细） |
| 键盘 | 焦点在月历里时：方向键在日子之间走（←→ 前后一天，↑↓ 前后一周）；`Home` / `End` 到这一周的周一 / 周日；`PageUp` / `PageDown` 上个月 / 下个月（焦点留在同一个「日」）。**`Shift` + 方向键**从当前这一天起扩大或缩小选中的范围；或者在起点按**空格**、走到终点再按一次**空格**。`Enter` 看这一天的明细。`Esc` 取消选择 |
| 触屏 | ≥ 768px：点起点那一格，再点终点那一格（第一次点后，选择条上写「再点一天作为结束」）。< 768px 见第 10 节 |

- 选中的格子：底 `bg-selected`；起点、终点两格的第一行另有文字「起」「止」（`text-link`，`font-weight-medium`；只选了一天时写「起止」）——不只靠底色。
- 选好以后，月历上方出现**选择条**（吸在月历容器顶部，底 `bg-surface`，下边线 `border-default`）：

  > 已选 **2027-10-01 至 2027-10-07**，共 7 天　　［新建调价规则］ ［取消选择］

  - 选择条用 `role="status"` 播报；键盘选完后按 `Tab` 的下一个停靠点就是「新建调价规则」。
  - 只读角色没有「新建调价规则」，选择条只写已选的日期（月历上方那句「可以直接新建调价规则」也不显示）。
- **「新建调价规则」**（主按钮）去 `…/adjust/new`，带着已选的内容，表单预先填好：

  | 表单里的 | 预先填成 |
  | --- | --- |
  | 出行日期 | 选的那一段 |
  | 周期 | 每天 |
  | 时段 | 全天 |
  | 区域、车型组、方向 / 套餐 | **日历上现在看的这一个组合**（「指定区域」勾这一个，等等） |
  | 名称、步骤 | 空着 |

  表单最上面一条信息提示条（可关闭）：「已按你在日历上选的填好了日期和适用范围（{区域} · {车型组} · {方向 / 套餐}）。想对全部区域或车型组都调，把下面的「对哪些」改成「全部」。」

  适用范围预先填成当前组合而不是「全部」：在日历上看着一个组合选日期，人想的多半是「这个价要调」；填窄了最多是少调，填宽了会悄悄改掉别的组合的价。
- 保存成功或点「取消」都回到价格日历（原来的组合和月份），日历重新取数；保存成功时那一段日期保持选中，明细面板显示起点那一天，让人马上看到调完的结果。

### 6.7 数据怎么取（一个月 × 很多组合）

- **月历**：一次请求取「一个组合 × 一个月」（`from` = 这个月 1 日，`to` = 最后一日）。换月份、换组合各发一次。
- **对比表**：一行一次请求（一个组合 × 一个月）。**同时最多 4 个请求**；先取看得见的行，滚动到的行再取（行进入视口才排队）；一个区域最多 30 个车型组 × 几个方向或套餐，全部取完也就几十次。还没取到的行，行头照常显示，格子是骨架；某一行失败只影响这一行（格子的位置写「没有加载出来」+ 文字按钮「重试」）。
- **缓存**：取过的「组合 × 月」留在内存里，来回翻月份、在月历和对比表之间切换不重新取。**这个商品的价格规则、调价规则、取整单位有任何保存成功，就把缓存全部清掉**；这个标签页回到前台时，超过 1 分钟的缓存也清掉。
- 换组合、换月份时：旧的格子留着降到 60% 不透明度 + 容器顶部 2px 进度条（同列表的做法），不整块闪成骨架；晚到的旧请求结果丢弃。
- 「用车时间」换了不用重新取（接口按天返回了各时段的价，14.1）。
- 日历显示的是**已经保存**的规则算出来的结果。「价格规则」页签里没保存的修改不会出现在这里（换页签前已经问过保存）。

| 首次加载 | 选组合的控件照常；月历画出星期表头和这个月的格子（日期是算得出来的），第二、三行是骨架；明细面板是骨架 |
| 加载失败 | 月历的位置：「加载失败」「请检查网络后重试。」+「重试」；选组合的控件保留 |
| **这个商品还没有任何价格** | 月历不画。空状态：标题「**还没有价格，日历上没有东西可看**」；说明「先到「价格规则」页签把价格填上，这里就会显示每一天的结算价。」；主按钮「去填价格」 |
| 选的这个组合整个月都没有价格 | 月历照常画，每一格都是「没有价格」；月历上方一条警告提示条：「**「{区域} · {车型组} · {方向 / 套餐}」这个月没有价格。**」+ 文字按钮「去填价格」 |
| 网址里的组合不认识（区域或车型组已经不在商品里） | 换成（`replace`）默认的组合，页面级信息提示条：「原来看的那个组合已经不在这个商品里了，现在显示的是「{新的组合}」。」 |

| 只读角色 | 一切照常，只是不能新建调价规则（6.5），明细里的按钮写「看」 |

## 7. 取整单位

需求文档：金额每一步用高精度计算，只在最后按币种的小数位四舍五入；供应商可以另设取整单位（例如日元取整到 100）。取整单位存在**子品牌**上，这个子品牌下的所有商品共用。

- 它出现在说明行里（2.2），所有能看的角色都看得到。
- **取整管的是「基础价 → 调价」算完的那个数，而且只取整这一次**；加急费、夜间加价、附加服务各自是填好的整数，直接相加，不再取整（ADR 0018）**［需负责人确认］**（15.3）。
- 没有调价规则命中时也取整。所以**基础价本身不是取整单位的整数倍时，报价会和填的数不一样**——「这一行的意思」里（3.10）在价格的话后面加一句，用警告色的三角图标开头：「取整单位是 JPY 100，报价时会取整成 JPY 20,100。」（只在取整前后不一样时出现；数字用 `@nozomi/domain` 的 `applyAdjustRules(基础价, [], 取整单位)` 算——和报价是同一个函数。里程 + 时长的不加这句，它的结果本来就不固定。）
- 有 `brand.manage` 的角色（管理员）点说明行里的「修改」，打开对话框：

  | 字段 | 控件 | 规则与提示 |
  | --- | --- | --- |
  | 取整到 * | 原生下拉，选项来自 `@nozomi/domain` 的 `roundingUnitOptions(币种)`（值是最小货币单位：没有小数的币种 1 / 10 / 100 / 1,000；两位小数的币种 0.01 / 0.1 / 1 / 10 / 100）。写成「不另外取整（JPY 1）」「JPY 10」「JPY 100」「JPY 1,000」；两位小数的币种「不另外取整（CNY 0.01）」「CNY 0.10」「CNY 1.00」… | 帮助说明下面实时给两个例子（用 `roundToUnit` 算，不写死）：「例：JPY 23,150 → JPY 23,200；JPY 23,149 → JPY 23,100。四舍五入，正好一半时往大的取。」 |

  - 对话框里一条警告提示条：「**这是子品牌「{子品牌名}」的设置。** 这个子品牌下的所有商品都会跟着变，已上架的商品也一样。」
  - 标题「修改取整单位」；按钮「取消」「保存」（主按钮；等待时「保存中…」）。保存用 `PUT /brands/{子品牌编号}/rounding-unit`，带**子品牌**的版本号（`If-Match`；版本号从 `GET /brands` 取，打开对话框时取一次）。成功：Toast「已保存取整单位」，说明行、「这一行的意思」、试算、价格日历都按新的重算（日历的缓存清掉）。
  - 没有改就点保存：直接关闭，不发请求。
  - 子品牌刚被别人改过（409 `VERSION_CONFLICT`）：对话框里危险提示条「这个子品牌刚被别人修改过。已经载入最新的设置，请确认后再保存。」，下拉换成最新的值，「保存」恢复可点。其余失败按 `02-components.md` 第 9 节。
- 商品价格角色看到的说明行没有「修改」。后面不加「请联系管理员」这种话（说明行要短）；它点不了，也不需要知道谁能点。

## 8. 菜单里的「价格规则」

### 8.1 为什么有它、它是什么

价格在数据上属于某一个商品，页面在商品的第 ③ 步。但负责人和运营想的是「我要去设价格」，不是「我要去某个商品的第 3 步」。所以侧边栏「商品配置」分组里，「商品」下面加一项「**价格规则**」（`/price-rules`）：**一张按价格情况列出所有商品的表，点一个就进它的第 ③ 步**。它不是另一套设价格的页面。

**「调价规则」不另占一个菜单项**（`tenant-home.md` 第 2 节原来的规划是两项）：调价规则和价格日历是第 ③ 步里的页签，这张表的每一行都有直接去它们的链接。两个菜单项进去是同一张表，只会让人不知道该点哪个 **［需负责人确认］**（15.7）。

给谁用：管理员、商品价格、只读（`product.read`）。要完成什么：找到要设价格的商品；一眼看出哪些商品还没有价格。

## 10. 手机宽度

最窄按 320px 验证（内容宽 288px，卡片里 256px）。价格主要在桌面上配；手机上要保证：**能看缺了哪些价格、能改一条价格的数、能启用或停用一条调价规则、能看某一天的价**，页面不横向滚动。批量操作、粘贴、对比表只在 ≥ 768px 提供。

**价格规则（< 768px）**

| 新增套餐、复制到…、取整单位的对话框 | 贴底；复选框组纵向排，一行一个；超过一屏时只有正文滚动 |

**价格日历（< 768px）**

- 选组合的控件各占一行或两个等分一行；月份那一行和「选一段日期」放不下时折成两行。
- 列表按周分组（组标题「{M} 月 {D} 日 – {D} 日」，不用周数）。每一天一行（`table-row-height` 的 1.5 倍以上）：第一行左边「{日} {周几}」+ 假日名（省略），右边结算价（带币种，不折行）；第二行调价规则（箭头 + 第一条的名字 +「+{N}」，单行省略）。今天那一行的日期后面有文字「今天」。打开这个月时自动滚到今天。
- 每一行是按钮：点了从底部升起这一天的明细（6.4 的内容；按钮各占一行）。
- **选一段日期**：点「选一段日期」（次要按钮，`aria-pressed`）进入选择状态——每一行左边出现复选的样子，提示换成「点开始的那一天」；点一天后换成「再点结束的那一天」；点了第二天后，两天之间的都选上（底 `bg-selected`，起止两行有文字「起」「止」）。选择条吸在屏幕底部（操作区的上方）：「已选 10-01 至 10-07，共 7 天」+「新建调价规则」「取消」。再点一次「选一段日期」或「取消」退出选择状态。选择状态下点某一行不打开明细。
- 「对比表」没有（6.6）。

**特别容易溢出的地方**：带币种和小数的大金额（`CNY 1,234,567.00`，不折行，所在的行要允许它单独占一行）；「这一行的意思」和一句话读回里连着的区域名、车型组名；50 个字的调价规则名（列表、日历格子、确认对话框标题里都要能折行或省略）；几百个指定日期的标签（标签区自己纵向滚动）；节假日预览里的一长串；选择条里的日期范围；覆盖表的列头（车型组名最多两行，超出省略）；金额输入框的后缀「JPY / 公里」「JPY / 小时」；带「次日」前缀的时刻输入框。

## 11. 键盘与读屏

- 所有操作都能只用键盘完成（批量操作、复制、排序、在日历上选日期都有不靠鼠标的办法）。Tab 顺序与视觉顺序一致：说明行里的「修改」→ 三个页签 → 页签内容 → 操作区。
- **覆盖表**：真正的 `<table>`，行头列头是 `<th>`；每一格里是一个 `<button>`（Tab 逐格到达；表格容器 `tabindex="0"`、`role="region"`、`aria-label="哪些组合有价格"`）。「看」单选组在表格前面。
- **价格表**：真正的 `<table>`，格子里是普通的输入框、下拉、复选框（不做成 `role="grid"`：每个输入框本来就是 Tab 停靠点，读屏用表格导航能读到行头列头）。
  - 每个输入框的 `aria-label`：「{区域}，{车型组}，{方向 / 套餐}，{列名}」；出错时 `aria-invalid` + `aria-describedby` 指向「这一行的意思」里的出错文字。
  - `Enter` 到下一行的同一列，`Shift` + `Enter` 到上一行（输入法正在组字时不触发）；到最后一行时 `Enter` 不动。下拉和复选框上的 `Enter` 不拦截。
  - `Esc`：把这一格还原成聚焦前的值。
  - 行尾「更多」菜单按下拉菜单的规则；菜单里的操作做完后焦点回到这一行。
  - 多选：行首复选框用空格勾选；`Shift` + 点击 / 空格 连选一段。选中数量用 `role="status"` 播报「已选 {N} 条」。
- **粘贴、批量操作、复制的结果**都用 `role="status"` 播报一句话（3.9），焦点落到第一条被改的行。
- **日期重叠**的危险提示条第一次出现时 `role="alert"`；之后数量变化用 `role="status"`，不反复打断。
- **调价规则的顺序**：5.2。**调价步骤**的上移 / 下移同理，播报「第 2 步现在是第 1 步」。
- **「全部 / 指定」**是 `<fieldset>` + `<legend>` 的单选组；选「指定」后焦点留在单选上，下面的复选框组用 `aria-controls` 关联。
- **星期选择**：`role="group"` + `aria-label="每周的哪几天"`；每个按钮 `aria-pressed`，读作「周六，已选」。
- **读回来的话和试算**：`aria-live="polite"`，输入停下 500ms 后才更新。试算是 `<table>`（有 `<caption class="sr-only">`「按 {金额} 试算」）。
- **月历**：`role="grid"`，`aria-label="{YYYY} 年 {M} 月的结算价，{区域}，{车型组}，{方向 / 套餐}"`；表头 `role="columnheader"`（「周一」…）；整个月历只有一个 Tab 停靠点（当前聚焦的那一天，其余 `tabindex="-1"`），方向键等见 6.5。选中的格子 `aria-selected="true"`。月历前面有一段读屏可见的说明（`aria-describedby`）：「方向键换日期，Enter 看这一天怎么算，Shift 加方向键选一段日期，或在起点和终点各按一次空格。」选择条用 `role="status"`。
- **换月份**后焦点留在按的那个按钮上，月份标题用 `aria-live` 读出；用 `PageUp` / `PageDown` 换月份时焦点留在月历里同一个「日」（那个月没有这一日就到最后一日）。
- **明细面板**更新不抢焦点；手机上从底部升起时按对话框的规则管理焦点。
- 所有只靠图标的按钮都有 `aria-label` 和气泡提示（说明、上移、下移、删除、上个月、下个月、收起）。禁用但需要被读到的按钮用 `aria-disabled`。
- 状态一律「图标 + 文字」，把屏幕调成灰度后仍然分得清：没有价格、未保存、将删除、重叠、已停用、已过期、调高 / 调低、起 / 止、今天。
- 两套主题下 axe 无严重问题。本文用到的颜色搭配都在 `01-tokens.md` 1.6 的表里：`warning-text` 配 `warning-bg`（覆盖表的缺口）、`text-primary` 配 `warning-bg`、状态文字配五种通用背景、`text-link` 配 `bg-selected`（月历选中格里的「起」「止」）。

## 15. 需要负责人定的事

**已经定了的（协调人代定，供知悉）**

- **「里程 + 时长」现在就开放给供应商填。** 页面在有这种价格时固定写明：按客人实际路线的里程和时长报价，要等路线预估功能上线；在那之前价格日历显示的是不超出起步时的价（3.1）。
- **有的组合没有价格，不拦上架。** 上架条件仍然是「至少 1 条启用且未过期的价格」；没有价格的组合在覆盖表、页签、价格表、上架检查、菜单里的表上都用警告色标出，并写明「客人询价时报不出价」。

**还需要你定的**

1. **价格的生效日期怎么填。** 需求文档只写了「生效日期」。现在的做法：开始日期必填（默认今天），结束日期可以不填 = 一直有效；看的是**用车日期**，不是下单日期；两头的日期都算。**推荐：按现在的做法。**
2. **调价规则的时段怎么算。** 两件事：① 跨午夜的时段算在开始的那一天头上——「每周五 22:00–06:00」是周五 22:00 到周六 06:00（另一种理解是「周五当天的 00:00–06:00 和 22:00–24:00」）。② 结束的那一刻不算在内——22:00–06:00 的规则，06:00 整用车不调价；这样相邻的两条规则不会在交界的那一分钟同时生效。它和服务时间「两头都算」不一样，页面上已经写了一句说明。**推荐：都按现在的做法。**
3. **取整单位管到哪一步。** 需求文档写「只在最后取整，供应商可另设取整单位（如日元取整到 100）」。现在的做法：取整的是「基础价按调价规则算完」的那个数，只取整这一次；加急费、夜间加价、附加服务是填好的金额，直接加上去，不再取整。没有调价规则时也取整——所以基础价填 20,050、取整单位是 100 时，报出去是 20,100，页面会提醒。取整单位由供应商的管理员自己改，对这个子品牌下的所有商品立即生效。**推荐：按现在的做法。**
4. **节假日日历没有数据，也没有维护它的页面。** 调价规则的周期可以选「节假日」，它按平台登记的节假日生效。平台现在一条都没有登记（不预置数据），登记只能经接口一条一条做，运营后台还没有对应的页面。所以现在供应商看到的是「平台还没有登记节假日，暂时不能选」，可以先用「指定日期」。**请确认是否新开任务**：① 运营后台的节假日维护页面；② 从官方来源批量导入日本、韩国的法定假日（注明来源和许可）；③ 要不要包括客源国的长假（中国国庆、春节）。
5. **调价后算出来不大于 0 的规则存不了。** 例如基础价 5,000、下调 6,000。价格后来降了、让已有的规则变成这样时，价格照样能存，上架检查里会提醒，真到报价时这样的不报价。**推荐：按现在的做法。**
6. **「调得很多」只提醒、不拦。** 平台需求里写的是「单条调价超过 +300% 或低于 −50%，保存时二次确认」。现在的做法：算下来高于基础价的 4 倍或低于一半时，保存前再问一次。**推荐：按现在的做法。**
7. **菜单只加「价格规则」一项。** 原来的规划是「价格规则」「调价规则」各一个菜单项。因为它们都属于某一个商品，两项进去是同一张「选商品」的表，所以现在只加「价格规则」一项，调价规则和价格日历从这张表或商品的第 ③ 步进。**推荐：只加一项**；想要两个入口的话可以再加。
8. **超出的里程、时长不凑整。** 需求文档没有写超出的部分按什么粒度算。现在的做法：按比例——里程 + 时长的价格超出 500 米收半公里的钱；**包车超时 30 分钟收半小时的钱**（不是「不足 1 小时按 1 小时」）。页面上已经写明「不足 1 小时、1 公里的按比例算」。包车超时怎么收是供应商最在意的，**请确认**；要改成按整小时（或半小时）进位的话，是计价规则的改动。
9. **在日历上选日期新建调价规则时，适用范围默认只填当前看的那一个组合**（不是全部区域和车型组）。理由：填窄了最多是少调，填宽了会悄悄改掉别的组合的价。**推荐：按现在的做法**，表单顶部有一句话提醒可以改成「全部」。
