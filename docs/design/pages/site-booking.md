# 官网：预订接送机、填写订单、订单页、查订单

M3-05 做出的官网页面（ADR 0032），本文是它们的页面规范（M3-09）。令牌、组件见上一级目录；「官网下单页」的通则见 `03-layout.md` 第 4 节最后一段，本文把它展开。后台页面的规则（信息密度、表格）**不适用**于这里，凡是本文和后台规范说法不同的，官网以本文为准。

目录：1 概览 · 2 通则（外观、字号、控件、语气与信任、文案、时间和金额、状态徽标）· 3 预订接送机 · 4 填写订单 · 5 订单页 · 6 查订单与链接失效 · 7 整页状态 · 8 断点 · 9 键盘、读屏 · 10 亮色、暗色 · 11 与当前实现的差异

## 1. 概览

| 页面 | 地址 | 给谁用 | 要完成什么 |
| --- | --- | --- | --- |
| 预订接送机 | `/book` | 第一次来、要订接送机的客人，多数在手机上，可能刚下飞机或还在国内准备行程 | 填行程 → 看到每种车的**总价、免费等待、取消政策** → 选一种去下单 |
| 填写订单 | `/book/checkout` | 选好车的客人 | 核对行程和总价 → 填乘车人、联系方式、航班号 → 同意保存付款方式 → 提交 |
| 订单页 | `/book/order#<链接>` | 下过单的客人：下单后马上看、用车当天在机场看、事后看费用 | 一眼知道**订单现在怎么样、我现在要做什么**；付款、点「我已落地」、改单、取消、对事后的费用提异议 |
| 查订单 | `/book/order`（没有链接或链接失效时） | 链接丢了、换了手机、链接过期的客人 | 用订单号 + 下单时的邮箱或手机号找回订单 |

使用者是**客人，不是后台用户**：不熟悉我们的说法、可能第一次来、用的是手机、网络不稳定、可能用的是第二语言。所有页面都不需要登录。

## 2. 通则

### 2.1 外观框架

```
┌──────────────────────────────────────────┐
│ NOZOMI 用车        [主题] 预订接送机 查订单 │  顶栏：bg-surface，下边框 border-default
├──────────────────────────────────────────┤
│                                          │
│   <h1>                                   │  内容：单栏，最宽 layout-reading-max-width（960px），居中
│   一句说明（text-secondary）               │  边距：< 768px 为 space-4，≥ 768px 为 space-6
│                                          │
│   ┌ 区块 ───────────────────────────┐     │  区块（.site-section）= 卡片：bg-surface、border-default、
│   │ 区块标题                         │     │  radius-lg，内边距 space-4 / ≥ 768px space-6
│   │ …                               │     │  区块之间 space-6
│   └─────────────────────────────────┘     │
│                                          │
│   [        主操作按钮（吸底）        ]     │
├──────────────────────────────────────────┤
│ 数据来源署名（GeoNames、OurAirports）       │  页脚：只在页面上出现城市、机场名称时显示
└──────────────────────────────────────────┘
```

- 不用后台的侧边栏、账号菜单；顶栏只有品牌、主题切换和两个入口（「预订接送机」「查订单」）。
- 顶栏的 DOM 顺序是品牌 → 主题切换 → 入口，各宽度下看到的顺序都和它一致（Tab 顺序和视觉一致）：≥ 480px 一行，品牌在左，主题切换和入口一起靠右（主题切换在入口左边）；< 480px 品牌和主题切换在第一行两端，入口在第二行（第 8 节、第 11 节 F10）。
- 每页一个 `<h1>`；区块标题是 `<h2>`，区块用 `<section aria-labelledby>`。
- 页脚署名：询价、下单、订单页有城市和机场名称，必须显示；查订单页没有，不显示。
- 不用插图、照片、渐变、外部字体。信任感来自**写清楚的价格和规则**，不是装饰（见 2.4）。

### 2.2 字号与层级

官网比后台大一号（`01-tokens.md` 第 3 节「官网和司机 H5 的正文」）：

| 元素 | 令牌 |
| --- | --- |
| 页面标题 `<h1>` | `font-size-2xl`，≥ 768px `font-size-3xl`；`font-weight-bold` |
| 区块标题 `<h2>` | `font-size-xl`，`font-weight-bold` |
| 正文、字段的值、控件文字 | `font-size-lg`（16px）；控件文字通过在 `.site` 上把 `--control-font-size` 设成 `font-size-lg` 实现，桌面和触屏一致，iOS 聚焦时不放大页面 |
| 字段标签、帮助文字、校验提示、说明文字、时间线的时间 | `font-size-md`（14px），标签和说明用 `text-secondary` |
| 报价卡片上的价格 | `font-size-2xl`，`font-weight-bold`，`tabular-nums` |
| 下单页、订单页的总价 | `font-size-xl`，`font-weight-bold`，`tabular-nums` |
| 订单页的状态徽标 | 徽标样式不变，字号放大到 `font-size-md`、最小高 28px |

### 2.3 控件

- 输入框、下拉框、坐标输入框、按钮一律 `lg` 高度（桌面 40px，触屏 48px）；多行文本框按行数撑高。
- **不用星号标必填**。官网的字段几乎都要填，选填的在标签末尾写「（选填）」。客人只需要找少数几个「（选填）」，比在一屏星号里找没星号的容易。（星号由组件统一输出，官网在 `.site` 下隐藏；`required` 属性照常写在输入框上，读屏仍然读「必填」。）
- **不用占位文字当示例**。示例写在字段下方的帮助文字里（「如 +81 90-1234-5678」「如 NH211」「NZ 开头的 18 位」）：占位文字颜色浅、一输入就消失，在手机上还常被当成已经填好的值。
- 校验：提交时整体校验，表单顶部一条危险提示条「有几项没有填好，请看标红的地方。」，每个出错字段下方写具体原因和正确写法；出错后该字段实时重新校验。复选框出错时，提示同样有图标，并经 `aria-describedby` 关联到复选框。
- **主操作按钮**（查询价格、提交订单、付款、我已落地）撑满宽度，用 `.site-actions` 吸在屏幕底部（`position: sticky`，留 `env(safe-area-inset-bottom)`），底色与所在区域相同，避免内容从按钮后面透出来。吸底只在**它所在的表单或区块**范围内生效，滚出这个区块就跟着走，不会一直盖在别的区块上。一屏里同时最多一个吸底按钮。
- 页面内确认（付款、取消、我已落地）和次要操作（返回、不取消了、提交异议）用并排按钮（`.site-actions--inline`），不吸底、底色透明，可换行。

### 2.4 语气与信任感

客人要把钱和行程交给一个第一次见的网站。页面要让他放心，靠的是这几条，**每一条都是硬性要求**：

1. **价格透明**：只给一个数——这辆车这一趟的**总价**，并紧跟着写清含什么（「按车计价，已含高速费和停车费」）。询价、下单、订单页三处的数字完全一致。不出现「起」「约」「另计」；会在服务后另收的费用（超时等候等）在下单页的同意条款里写明，并说明「先通知、48 小时内可以提异议、没有异议才扣款」。
2. **规则先说**：取消政策在**报价卡片上就显示**，下单页再显示一次，订单页的取消区块第三次显示；点「取消订单」后，先显示**按政策这次会扣多少、退多少、退到哪里**，再让客人确认。免费等待写明从什么时候起算（接机从航班落地起算）。
3. **时间说清是哪里的时间**：所有日期时间都标「当地时间」，表单里用车时间的帮助文字写「{城市}的当地时间」。客人跨时区订车，最怕把时间弄错。
4. **不让客人以为自己做错了**：报不出价时说原因和怎么改（「这个地址不在服务范围内，请换一个更靠近市区的地址」），不说「失败」「错误」；系统出错时说「系统暂时无法…，请稍后再试」并给「重试」。
5. **订单一定找得回**：下单成功后立刻告诉客人「请收藏这个页面」，给出链接和复制按钮，并说明还可以用订单号 + 邮箱在「查订单」找回。
6. **客服**：订单页始终显示客服联系方式（需求「客人通知」）。号码登记前（ADR 0032 待定事项 6），页面上的「联系客服」只作为文字说法，不放不能用的链接或按钮；登记后在订单页底部固定放「需要帮助」区块（见 5.10）。
7. **付款**：付款前不显示服务方（第二轮决策）；付款区块写明「付款信息由 Stripe 处理，本站不保存卡号」；付款暂未开放时如实说，**不伪造付款成功**。
8. **不出现后台的东西**：没有供应商、结算价、加价比例、内部编号（报价编号、订单 ID），也不出现「管理员」。

语气：用「您」；短句；先说结论再说原因；动作写成按钮上的动词（「查询价格」「提交订单」「我已落地」「取消订单」）。不用感叹号，不用「亲」「哦」等口语。

### 2.5 文案用词

| 用这个 | 不用 |
| --- | --- |
| 接机、送机 | pickup、dropoff、方向 |
| 用车时间；航班计划到达时间（接机） | service_time、服务时间 |
| 总价 | 售价、对外价、price.total |
| 免费等待 | free_wait |
| 取消政策、取消费、退款 | cancel_policy、tier、基点 |
| 服务方（只在付款后出现） | 供应商、租户、中标 |
| 订单号 | 订单 ID、order_no |
| 订单链接 | 令牌、token |
| 服务后的费用 | 事后加收、extra charge |
| 提异议 | 争议、dispute |
| 修改订单 | 改单、change |

### 2.6 时间、金额

- 日期时间：`YYYY-MM-DD HH:mm`，后面或前面写「当地时间」。（更易读的写法见第 11 节 F8。）
- 金额：`22,000 JPY`（`04-data-display.md` 的格式，千分位 + 币种代码），`tabular-nums`。
- 订单号、订单链接：等宽字体只用于链接；订单号在标题里用正文字体，任意位置可折行。

### 2.7 客人看到的状态

状态 = 颜色 + 文字（徽标带圆点）。要客人自己去做事的用 `warning`，正常进行的用 `info`，完成和确认用 `success`，结束了的用 `neutral`。对照表在 `apps/web/src/lib/site-display.ts`（`GUEST_STATUS_BADGES` 等），文字以那里为准；改文字时两边一起改。

| 订单状态 | 徽标 | 颜色 |
| --- | --- | --- |
| 待支付 | 待付款 | warning |
| 已确认 | 已确认 | success |
| 已派车 / 司机已出发 / 司机已到达 / 服务中 | 同名 | info |
| 已完成 | 已完成 | success |
| 司机报告未接到 | 司机报告未接到您（审核中） | warning |
| 未接到乘客 | 未接到乘客 | neutral |
| 已取消 | 已取消 | neutral |
| 正在重新安排车辆 | 正在为您重新安排车辆 | warning |

### 3.2 表单

| 字段 | 控件 | 说明 |
| --- | --- | --- |
| 城市 | 下拉框 | 只有一个可订城市时替客人选好 |
| 接机还是送机 | 单选两项，每项带一行说明（「从机场到酒店或地址」） | 默认接机；切换后地址、时间字段的标签跟着变 |
| 机场 | 下拉框，「机场名（代码）」 | 城市里只有一个机场时替客人选好；没选城市时提示「先选城市」 |
| 下车（送机：上车）地址或酒店名 | 文本框 | |
| 下车（上车）地点的坐标 | 坐标输入（纬度、经度两框，可整段粘贴「纬度, 经度」） | 帮助文字说明怎么在手机地图里拿到坐标、为什么要。**临时方案**：接入地点搜索后换成搜索 + 地图选点（ADR 0032「本期不做」） |
| 航班到达日期 / 用车日期（当地） | 日期 | 默认城市当地的明天 |
| 航班计划到达时间 / 上车时间（当地） | 时间 | 帮助文字「{城市}的当地时间」；早于当地现在时提示「这个时间已经过了」 |
| 人数、行李（件） | 数字，`inputmode="numeric"` | ≥ 768px 两两并排 |

### 3.3 结果

查询后在表单下方出现「可预订的车（N 种）」区块：

- 顶部一句：「按车计价的一口价，已含高速费和停车费。报价 30 分钟内有效（到当地时间 HH:mm），过了请重新查询。」
- 每种车一张卡片（`.site-quote`，`radius-md`，`border-default`），从上到下：车型名（`<h3>`）和**总价**（同一行，放不下时价格换到下一行）、座位和可坐人数行李、参考车型（「… 或同级」）、免费等待（含起算点）、**取消政策**、主按钮「预订{车型}」（撑满）。
- 卡片顺序按总价从低到高（第 11 节 F6）。
- 改了表单里任何一项，结果立刻收起（避免客人拿旧价格下单）。

### 3.4 状态

| 状态 | 显示 |
| --- | --- |
| 加载中（读配置、城市） | 骨架：一条长灰块 + 四个控件高的灰块，`aria-label`「正在打开预订页」 |
| 官网没开 | 空状态（neutral）：「暂未开放预订」/「官网的在线预订还没有开放，请稍后再来。已经下过单的客人可以点上方的「查订单」查看订单。」——**一定要给已下单的客人指路** |
| 没有可订城市 | 空状态：「暂时没有可预订的城市」/「…请稍后再来。」 |
| 配置、城市读不出来 | 错误状态：「页面没有打开」/「城市列表没有读出来」+ 原因 +「重试」（`lg`） |
| 机场读不出来 | 在机场字段的位置显示小号错误状态 +「重试」，表单其余部分照常可填 |
| 查询中 | 「查询价格」按钮加载态「正在查询」 |
| 报不出价 | 区块标题「没有可预订的车」，下面逐条列原因，每条都说**怎么改**（`UNAVAILABLE_REASON_TEXT`） |
| 这个城市不开放（渠道没授权） | 表单顶部危险提示「这个城市暂不开放预订，请换一个城市。」 |
| 操作太频繁 | 表单顶部危险提示「操作太频繁了，请 N 秒 / 分钟后再试。」 |

## 4. 填写订单（`/book/checkout`）

### 4.1 首屏看到什么

上面是「行程」区块（核对用），下面是「乘车人和联系方式」表单，吸底按钮「提交订单（22,000 JPY）」——**按钮上带总价**，客人点之前就知道要付多少。

### 4.2 行程区块

`<dl>`：接机 / 送机（「机场（代码） → 地址」）、航班计划到达 / 上车时间（「… （{城市}当地时间）」）、车型、人数 / 行李、**总价（按车计价，已含高速费和停车费）**、取消政策；下面一行说明「报价有效到当地时间 …」；文字按钮「返回修改行程」（带回刚才填的内容）。

### 4.3 表单

| 字段 | 属性 | 帮助文字 |
| --- | --- | --- |
| 乘车人姓名 | `autocomplete="name"` | — |
| 手机号（带国家码） | `type="tel"`、`inputmode="tel"`、`autocomplete="tel"` | 以 + 和国家码开头，如 +81 90-1234-5678。司机和客服用它联系您 |
| 邮箱 | `type="email"`、`inputmode="email"`、`autocapitalize="none"`、`spellcheck=false` | 以后可以用订单号和这个邮箱查找订单 |
| 航班号（接机必填；送机「（选填）」） | `autocapitalize="characters"` | 接机：如 NH211。航班延误时司机按实际落地时间等候；送机：如 NH211 |
| 下车（上车）地址或酒店名 | 带入询价时的地址 | 写给司机看的，酒店名或详细地址 |
| 即时通讯（选填）+ 账号 | 下拉 + 文本框；没选应用时账号框禁用 | — |
| 备注（选填） | 多行，最多 2000 字 | — |
| 同意保存付款用的银行卡 | 复选框，必勾 | 「服务后的费用会先通知您，48 小时内可以在订单页提异议；没有异议才会扣款。」 |

### 4.4 状态

| 状态 | 显示 |
| --- | --- |
| 直接打开（刷新、收藏，没有选好的车） | 空状态「还没有选车」/「请先查询价格、选好车型再来填写订单。」+ 主按钮「去查询价格」（`lg`） |
| 提交中 | 按钮加载态「正在提交」；网络失败再点不会重复下单（同一个幂等键） |
| 报价过期 / 已下过单 / 车刚被订完 | 警告提示条说明原因；吸底按钮换成「重新查询价格」（带回行程），不再能提交 |
| 后端校验不通过 | 能对上字段的标在字段下；对不上的在顶部说「提交的内容不符合要求，请检查后重试。」 |
| 服务器出错 | 顶部危险提示 + 「再点一次「提交订单」不会重复下单。」 |
| 成功 | 跳到订单页（5.2 的「订单已提交」提示） |

## 5. 订单页（`/book/order#<链接>`）

### 5.1 首屏与区块顺序

```
订单 NZ2026…            ● 待付款     ← 标题行：订单号 + 状态徽标（放不下时徽标换行）
（订单已提交 + 链接 + 复制）          ← 只在刚下单跳过来时
┌ 当前要做的事 ──────────────┐      ← 见下表，最多一个
└───────────────────────────┘
┌ 行程 ┐ ┌ 订单进度 ┐ ┌ 司机和车辆 ┐ ┌ 航班落地 ┐ ┌ 服务后的费用 ┐ ┌ 修改订单 ┐ ┌ 取消订单 ┐ ┌ 需要帮助 ┐
```

原则：**客人进来要做的那件事排在状态下面第一位**，其余按「行程 → 进度 → 司机 → 落地 → 费用 → 修改 → 取消 → 帮助」排。

| 订单情况 | 排在第一位的区块 |
| --- | --- |
| 待付款 | 付款 |
| 接机单、已付款、「我已落地」已经能点 | 航班落地 |
| 有还在异议期内的服务后费用 | 服务后的费用 |
| 其他 | 行程 |

没有内容的区块不显示（例如还没派车时没有「司机和车辆」，送机单没有「航班落地」，没有费用时没有「服务后的费用」）。

### 5.2 刚下单

成功提示条：「订单已提交。请收藏这个页面，之后凭这个链接查看订单；也可以随时用订单号和邮箱在「查订单」里找到它。」下面是链接（等宽、`font-size-sm`、任意位置折行）和复制按钮，复制按钮紧跟在链接后面（不能用 `.copy-button` 默认的绝对定位），复制后 Toast「已复制」。这条提示只在刚下单跳过来时出现，刷新后不再出现（链接不在页面上重复显示）。

### 5.3 付款

| 情况 | 显示 |
| --- | --- |
| 付款暂未开放（没配置 Stripe） | 警告提示条：「付款暂未开放：订单已为您保留到当地时间 …，到时没有付款会自动取消。付款开放后可以回到这个页面付款。」不放付款按钮 |
| 付款组件还在接入中 | 警告提示条：「在线付款还在接入中，订单已为您保留到当地时间 …，到时没有付款会自动取消。」 |
| 正常 | 说明「请在当地时间 … 前付款，过时订单会自动取消。付款信息由 Stripe 处理，本站不保存卡号。」→ 付款表单 → 吸底主按钮「付款 22,000 JPY」→ 页面内确认「确认支付 22,000 JPY？」[确认支付] [返回] |
| 付款已提交 | 信息提示「已提交付款，正在确认（通常几秒钟），订单状态会自动更新。」——只认付款通知，不在页面上自行宣布成功 |
| 付款组件没加载出来 | 危险提示 + 次要按钮「重新加载」 |

### 5.4 行程

`<dl>`，≥ 768px 两栏：接机 / 送机、航班计划到达 / 上车时间（当地）、航班号、车型、人数 / 行李、乘车人、备注（有才显示）、**总价**（`font-size-xl` 加粗）、免费等待、服务方（付款后才有）。

### 5.5 订单进度

竖线时间线（`border-strong` 左边线），每步一行：客人说法的步骤名（`TIMELINE_NAMES`；取消时写原因，如「超过付款期限没有付款，系统自动取消」）+ 当地时间（`text-secondary`）。从早到晚。

### 5.6 司机和车辆（派车后）

司机姓名、司机电话（用车前 24 小时才给，之前写「用车前 24 小时显示」）、车辆（车牌 · 车型 · 颜色）。

### 5.7 航班落地（接机单）

| 情况 | 显示 |
| --- | --- |
| 待付款 | 计划到达时间 + 「付款后，航班落地时可以在这里点「我已落地」。」 |
| 离计划到达 3 小时以上 | 「航班落地后请点「我已落地」，司机按这个时间开始免费等待。当地时间 … 起可以点。」 |
| 可以点 | 说明「落地后点一下，司机会按这个时间开始免费等待，并知道您快出来了。」+ 吸底主按钮「我已落地」→ 页面内确认（`warning` 底的确认框）「确认您的航班已经落地？时间按现在记录，提交后不能修改。」[确认已落地] [还没有] |
| 已确认 | 成功提示（刚点完时）+ 加粗一行「您已确认落地：当地时间 …。」，按钮消失 |
| 太早（后端拒绝） | 危险提示「离航班计划到达还早，落地后再点「我已落地」。」 |

### 5.8 服务后的费用

区块说明：「服务结束后，司机报了下面的费用（附凭证）。提交后 48 小时内可以提异议；有异议的先不扣款，由平台审核。」每一项：费用名、金额（加粗）、状态徽标（`GUEST_EXTRA_STATUS_BADGES`）、司机写的说明、异议截止时间和「没有异议到时会从下单时保存的银行卡扣款」；在异议期内有次要按钮「提异议」→ 展开理由输入框（必填）[提交异议] [取消]。提交后成功提示「异议已提交，这一项先不扣款，平台审核后会通知您。」

### 5.9 修改订单、取消订单

**修改订单**：说明哪些能改、什么时候能改、改时间会重新计价（多退少补）、换车型要取消重订；次要按钮「修改订单」→ 展开表单（字段同下单页，预填现值）[提交修改] [不改了]。只提交改了的字段。结果写在区块顶部：已修改 / 改期需要服务方 30 分钟内确认 / 订单刚有变化请刷新 / 补差价没扣成功。修改记录列在区块里，每条带状态徽标和补收 / 退还金额。

**取消订单**：先写取消政策全文；入口是**次要按钮**「取消订单」（不是红色实底——它是正常的服务，不是危险警告；红色留给真正提交的那一下）；点后先算退款，在 `warning` 底的确认框里写「按取消政策，现在取消免费 / 扣 X，退还 Y，原路退回银行卡。取消后不能恢复，要用车需要重新预订。」[确认取消订单]（`danger` 实底）[不取消了]。改期没被确认时多一个次要按钮「改期没有被确认，免费取消」。不能在网上取消时说「请联系客服」。已取消的订单只显示取消原因、取消费、退款及退款进度。

### 5.10 需要帮助（客服热线登记后）

订单页最后一个区块，始终显示：客服电话（`tel:` 链接，`lg` 次要按钮样式）、服务时间、提示「联系时请提供订单号 NZ…」。号码登记前不显示这个区块（第 11 节 F2）。

## 6. 查订单与链接失效

- `<h1>`「查订单」，说明「输入订单号和下单时填的邮箱或手机号，就能查看订单、付款、取消或修改。」
- 字段：订单号（帮助文字「NZ 开头的 18 位，在订单页顶部」，自动转大写比较）、下单时的邮箱或手机号（全角自动转半角）；吸底主按钮「查找订单」。
- 找到后直接换成订单页（地址换成新链接，不留历史记录）。

| 状态 | 显示 |
| --- | --- |
| 打开时没有链接 | 只有表单 |
| 链接失效、过期、格式不对 | 表单上方警告提示「订单链接无效或已过期，请用订单号和下单时的邮箱或手机号重新查找。」——**不说是哪种失效** |
| 找不到 | 危险提示「没有找到这张订单：请核对订单号，以及下单时填的邮箱或手机号。」——**不说是订单号还是联系方式不对**（防止借此确认订单号存在） |
| 尝试次数过多 | 危险提示「尝试次数过多，请 N 秒 / 分钟 / 小时后再试，或联系客服。」 |
| 订单读不出来（网络、服务器） | 错误状态「订单没有读出来」+ 原因 +「重试」（`lg`）；**不能显示成链接失效**，那会让客人白白去找回 |

## 8. 断点（手机优先）

| 元素 | < 480px | 480–767px | ≥ 768px |
| --- | --- | --- | --- |
| 内容宽度 | 撑满，边距 16px | 同左 | 最宽 960px，居中，边距 24px |
| 顶栏 | 第一行品牌、主题切换（两端），第二行入口 | 一行：品牌在左，主题切换 + 入口靠右 | 同左 |
| 表单 | 单栏 | 单栏 | 日期时间、人数行李、即时通讯两两并排 |
| `<dl>`（行程、报价卡片） | 单栏，标签在上 | 单栏 | 两栏 |
| 主操作 | 撑满、吸底 | 同左 | 同左 |
| 页面内确认的按钮 | 并排、可换行 | 并排 | 并排 |
| 页面标题 | 2xl | 2xl | 3xl |

- 320×640、360×740、400×800 都不能横向滚动，每个状态（含确认框展开、改单表单展开、长邮箱、长订单链接）都要测（`03-layout.md` 第 5 节）。
- 订单号、邮箱、地址、链接任意位置可折行。
- 页面放大到 200% 不截断。

## 9. 键盘、读屏

- 每个控件有可见标签；字段出错时 `aria-invalid` + `aria-describedby` 指向错误文字和帮助文字。
- 页面级提示进 `AlertSlot`（出错、警告用 `role="alert"`，信息、成功用 `role="status"`），容器一开始就在页面里。
- 页面内确认框是 `role="group"` + `aria-label`（「确认付款」「确认取消订单」「确认已落地」）。
- 只用键盘能走完「询价 → 下单 → 订单页 → 取消确认 → 不取消」；Tab 顺序和视觉顺序一致。
- 吸底按钮不能挡住正在聚焦的输入框（区块内吸底，滚到表单末尾时按钮回到原位）。
- 中文界面里的日文名称（车型、地址）标 `lang`。
- 每一步在亮暗两色下过 axe（`e2e/site-booking*.spec.ts`）。

## 10. 亮色、暗色

- 只用 `01-tokens.md`「允许的搭配」里的组合；页面 `bg-page`，区块 `bg-surface`，吸底按钮条的底色与所在区域相同。
- 确认框用 `warning-bg` + `warning-border`，里面的文字 `text-primary`；按钮放在确认框里时按钮条透明，不能露出一条 `bg-surface`。
- 状态徽标、提示条在两套主题下都靠图标 / 圆点 + 文字表达，不只靠颜色。
- M3-09 在 400px、320px、1280px 宽下亮暗两色逐页截图核对过（询价空表单、出错、结果、报不出价；下单、出错、直接打开；订单页待付款、已确认、确认落地、确认取消、改单表单、已完成带司机和费用；查订单、找不到、链接失效；暂未开放、配置出错、加载中）。
