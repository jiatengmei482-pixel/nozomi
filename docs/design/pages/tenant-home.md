# 供应商后台首页、供应商后台菜单

M1-02 起的页面。部件和运营后台首页是同一套：入口卡片（`02-components.md` 第 18 节）、分区、提示条、骨架。两边写法不一致时，以 [`platform-home.md`](./platform-home.md) 为准，本文只写供应商后台不同的地方。

本文只管供应商后台（根路径 `/`）。界面上一律叫「供应商」，不叫「租户」。

目录：1 首页 · 2 菜单的分组与顺序 · 3 需要后端配合的事

## 1. 首页

### 1.1 给谁用、要完成什么

| 给谁用 | 要完成什么 |
| --- | --- |
| 供应商的所有账号（管理员、商品价格、调度、财务、只读），登录后的第一个页面 | ① 一步进入要去的模块；② 看到每个模块里大概有多少东西；③ **刚开通的供应商知道下一步该做什么**（先建区域，再建商品，再设价格） |

首页不是报表：只放数量和「不处理就卡住」的提醒。订单量、中标率这些等订单模块上线后另加「今日」分区。

### 1.2 首屏看到什么

```
≥ 1024px
┌────────┬──────────────────────────────────────────────────────┐
│ 侧边栏  │ [≡] 首页                                [主题] [账号]  │
│        ├──────────────────────────────────────────────────────┤
│        │ 首页                                                  │
│        │ {供应商名称}  ● 正常                                    │
│        │ （提示条：数量加载失败时才显示）                          │
│        │                                                      │
│        │ 商品配置                                               │
│        │ ┌──────────────────────────┐                         │
│        │ │ 区域                    › │                         │
│        │ │ 0 启用  ·  0 已停用        │                         │
│        │ │ ! 还没有区域，先建一个   ›  │                         │
│        │ └──────────────────────────┘                         │
└────────┴──────────────────────────────────────────────────────┘
```

（数字只是示意排版，页面上的数字全部来自接口。）

首屏（1280×720，不滚动）必须看到：供应商名称和状态、全部分区标题、全部卡片、卡片上的提醒行。

- 页面类型「列表、看板」，最大宽度 `layout-content-max-width`。
- `<h1>`「首页」，标题行没有主操作按钮。标签页标题「首页 · NOZOMI 供应商后台」。
- **标题下一行**：供应商名称（`font-size-md`，`text-secondary`）+ 供应商状态徽标（沿用前端已有的供应商状态对照表），间距 `space-2`，可折行；名称很长时在任意位置折行（`overflow-wrap: anywhere`）。数据来自 `auth/me`，还没回来时是一条骨架灰块。
- **去掉现在的「当前登录」卡片**：姓名、角色、邮箱在顶栏的账号菜单里已经有了；供应商名称和状态挪到上面这一行。
- 分区、卡片栅格、卡片样式：同 `platform-home.md` 1.2。

### 1.3 分区和卡片

分区和卡片的顺序与侧边栏菜单一致（第 2 节）：**一个菜单项一张卡片，分区 = 菜单的分组**。只显示当前角色有权限看的模块的卡片；一个分区里一张卡片都没有时，整个分区不显示。

M1-02 做完后只有一张卡片：

| 分区 | 卡片 | 点了去哪 | 数量行 | 提醒行 | 谁能看到 |
| --- | --- | --- | --- | --- | --- |
| 商品配置 | 区域 | 区域列表 `/areas` | 「{N} 启用 · {N} 已停用」 | 见下 | 能看区域的角色（`area.read`：管理员、商品价格、只读） |

- 数量行两组都显示，即使是 0（卡片高度不随数据跳）。说明用的词和区域列表的状态徽标一样（启用 / 已停用）。
- 如果后端本期不给区域做「启用 / 停用」（见 `tenant-areas.md` 第 17 节第 1 条），数量行改成一组：「{N} 个区域」。

**提醒行**

| 卡片 | 什么时候显示 | 文字 | 点了去哪 |
| --- | --- | --- | --- |
| 区域 | 区域总数是 0，**并且**当前角色能新增区域（`area.manage`） | **还没有区域，先建一个** | 新增区域页 `/areas/new` |

- 样式是入口卡片的提醒行（警告色 + 三角图标 + 文字 + 箭头）。它符合「不处理就一直卡在那里」：没有区域，商品和价格规则都建不了。
- 只能看、不能改的角色（只读）在区域总数是 0 时不显示这一条（点了也做不了）。
- 「全部停用了」（启用 0、已停用 > 0）不是提醒，不显示。

**以后的卡片怎么接上引导**（各自的任务里实现，这里先定规则，免得到时候各写各的）

| 卡片 | 提醒行什么时候显示 | 文字 |
| --- | --- | --- |
| 商品 | 启用的区域 > 0，且商品总数是 0 | 还没有商品，先建一个 |
| 商品 | 有商品，但没有一个已上架 | {N} 个商品还没有上架 |
| 价格规则 | 有商品还没有任何启用的价格规则 | {N} 个商品还没有设价格 |

前一步没做完时，后一步的引导不出现（没有区域时不提示「先建商品」）。这样首页上任何时候最多只有一条「下一步」的引导，顺序就是 区域 → 商品 → 价格规则 → 库存 → 上架。不另做「新手步骤条」。

### 1.4 数据从哪来

一次请求：`GET /tenant/v1/dashboard/summary`（需要后端新增，见第 3 节）。

| 卡片 | 数量取自 |
| --- | --- |
| 区域 | `areas.active`、`areas.disabled` |
| 区域的提醒行 | 两个数相加是 0 |

- 当前角色没有权限的模块，接口返回 null（`areas` 为 null → 没有区域卡片）。前端不自己再按角色判断「该不该有数量」，以接口为准；「提醒行显不显示」按角色的操作权限判断（`@nozomi/domain` 的 `tenantRoleCan`）。
- 什么时候请求、重新请求期间怎么显示：同 `platform-home.md` 1.4 最后两条。

### 1.5 各种状态

和 `platform-home.md` 1.5 完全相同（加载中先显示卡片和可点的标题、数量是骨架；失败时提示条「数量没有加载出来」+ 卡片上显示「—」；刷新失败不打扰；数量为 0 照常显示 0）。只有这几处是供应商后台自己的：

| 状态 | 显示什么 |
| --- | --- |
| **一张卡片都没有**（现在的调度、财务角色：区域他们看不了，他们的模块还没做） | 内容区显示空状态：标题「这里暂时没有你可以使用的模块」，说明「需要的话，请联系你们的管理员开通。」，没有按钮。供应商名称和状态那一行照常显示 |
| 加载中、还不知道接口返回哪些模块 | 先按角色的操作权限决定显示哪些卡片（有 `area.read` 的显示区域卡片） |
| 供应商名称没取到（`auth/me` 失败） | 那一行不显示；顶栏的账号菜单已有自己的失败处理，首页不再重复提示 |

### 1.6 手机宽度、键盘与无障碍

同 `platform-home.md` 1.6、1.7。另外：

- 标题下一行的供应商名称和徽标在放不下时折成两行，徽标不被挤出屏幕。
- 在 320、360、400 三个宽度下，对「加载中、有提醒行、加载失败、一张卡片都没有、侧边栏滑出」五个状态各检查一次横向溢出。
- 卡片的标题链接读作「区域，0 启用，0 已停用」；提醒链接读作「还没有区域，先建一个」。

## 2. 供应商后台菜单的分组与顺序

依据需求文档《用车报价服务平台》「租户端功能」第 1–14 节和第 11 节的角色表。顺序按「每天要处理的在上，偶尔才配置的在下」；「商品配置」分组内部按依赖顺序（先有区域才能建商品，先有商品才能设价格和库存）。

**菜单只列已经做出来的页面**，没做的不占位置、不置灰、不写「即将上线」；做出来一个加一个，位置按下表。只显示当前角色有权限的项。

| 顺序 | 一级菜单 | 子项（按这个顺序） | 图标 | 谁能看到（需求文档第 11 节） | 现状 |
| --- | --- | --- | --- | --- | --- |
| 1 | 首页 | — | 房子 | 全部 | 已有 |
| 2 | 订单 | —（救援单是订单页里的页签，不单独占菜单） | 单据 | 管理员、调度、财务（只读）、只读 | 未做 |
| 3 | 工单 | — | 对话气泡 | 管理员、调度 | 未做 |
| 4 | **商品配置** | **区域**、商品、价格规则、调价规则、库存 | 图层（两片叠着的菱形） | 管理员、商品价格、只读 | **M1-02 新增「区域」**；商品 M1-03，价格规则、调价规则 M1-04，库存 M1-05 |
| 5 | 运力 | 司机、车辆 | 方向盘 | 管理员、调度、只读 | 未做 |
| 6 | 经营分析 | 评分与中标、线路最低价查询 | 柱状图 | 管理员、商品价格、只读 | 未做 |
| 7 | 财务 | 对账结算、发票 | 钱包 | 管理员、财务 | 二期 |
| 8 | 设置 | 资质认证、账号、API 密钥、调度对接（Webhook）、操作日志 | 齿轮 | 管理员（账号列表只读角色也能看） | 页面未做，暂不显示 |

所以 M1-02 做完后，有 `area.read` 的角色看到的侧边栏是：

```
NOZOMI  供应商后台
─────────────────
⌂ 首页
▾ 商品配置
     区域
```

- 「商品配置」是分组项，点它只展开 / 收起（`02-components.md` 第 10 节）。默认展开。现在分组里只有一个子项，仍然保留分组：下一个任务就会加「商品」，菜单项的位置不应该每做一个任务就变一次。
- 没有 `area.read` 的角色（调度、财务）现在只看到「首页」。
- **价格规则、调价规则、库存**在数据上属于某一个商品（接口是 `/products/{id}/price-rules` 等）。规划：它们既是商品编辑页里的页签，也在菜单里各有一项——菜单项进去是「先选商品，再看这个商品的这一页」的同一个页面。这样负责人说的「建商品、设价格」各有一个看得见的入口。具体做法在 M1-04、M1-05 的页面说明里定，这里只定位置。
- 面包屑：`商品配置 / 区域`、`商品配置 / 区域 / 新增区域`、`商品配置 / 区域 / {区域显示名}`。「商品配置」这一级不是页面，是普通文字。< 768px 只显示最后一级。
- 地址（供前端对照，保持「列表 / new / :id」的结构）：

| 页面 | 地址 |
| --- | --- |
| 首页 | `/` |
| 区域列表 / 新增 / 编辑 | `/areas`、`/areas/new`、`/areas/{id}` |
| 商品（M1-03） | `/products`、`/products/new`、`/products/{id}` |
| 价格规则、调价规则、库存（M1-04、M1-05） | `/price-rules`、`/adjust-rules`、`/inventory`（带 `?product={商品 ID}`） |

  供应商后台的页面地址在根路径下，**不能落在接口前缀里**（`apps/web/src/lib/api-prefixes.ts`：`/health`、`/tenant/v1`、`/platform/v1`、`/sales/v1`、`/webhooks`）。以后「调度对接（Webhook）」的页面地址用 `/settings/webhooks`，不能用 `/webhooks`。
- 需要新增的图标（线性、16px，和现有图标同一套画法）：图层。其余菜单的图标等对应页面做的时候再加。区域页面自己要的图标列在 `tenant-areas.md` 第 16.4 节。

## 3. 需要后端配合的事

1. **`GET /tenant/v1/dashboard/summary`**：任何已登录的供应商账号都能调，按模块裁剪（和运营后台的同名接口同一个思路）。本期只有一组：

   ```json
   { "areas": { "active": 3, "disabled": 1 } }
   ```

   当前角色没有 `area.read` 时 `areas` 为 `null`。以后每个模块加一组，不改已有的字段。数量只算本供应商自己的（`tenant_id` 来自登录令牌）。
2. **两个新的操作** `area.read`、`area.manage` 加进 `@nozomi/domain` 的 `TENANT_ACTIONS`，分配见 `tenant-areas.md` 第 1 节的权限表。前端的菜单、卡片、按钮都用 `tenantRoleCan` 判断，不写角色名。
3. 首页不需要别的接口。供应商名称和状态用现有的 `auth/me`。
