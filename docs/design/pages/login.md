# 登录页、接受邀请并设置密码页

M0-07 要实现的第一批页面。组件和令牌见上一级目录的规范，这里只写这两个页面特有的内容。

## 1. 概览

| 页面 | 给谁用 | 要完成什么 |
| --- | --- | --- |
| 供应商后台登录 | 租户的管理员、商品价格、调度、财务等用户 | 用邮箱 + 密码进入供应商后台 |
| 运营后台登录 | 平台员工 | 用邮箱 + 密码进入运营后台 |
| 接受邀请并设置密码 | 收到邀请邮件的新用户（租户用户或平台员工） | 给自己的账号设置密码，然后去登录 |

两个登录页是**同一个页面组件、两个入口**，区别只有副标题和底部的切换链接。这样两类用户各自收藏自己的入口，平台员工的入口以后可以单独加限制（公司统一登录、IP 白名单）。

三个页面都不使用后台框架（没有侧边栏和顶栏），都不需要登录就能打开。

## 2. 登录页

### 2.1 首屏看到什么

```
┌───────────────────────────────────────────────┐
│                                   [主题切换]    │
│                                               │
│            ┌─────────────────────────┐        │
│            │ NOZOMI                  │        │
│            │ 供应商后台               │        │
│            │                         │        │
│            │ （提示条：有才显示）       │        │
│            │                         │        │
│            │ 邮箱                    │        │
│            │ [                     ] │        │
│            │                         │        │
│            │ 密码                    │        │
│            │ [                 (眼) ] │        │
│            │                         │        │
│            │ [        登录         ]  │        │
│            │                         │        │
│            │ 我是平台员工，去运营后台登录 │        │
│            └─────────────────────────┘        │
│                                               │
└───────────────────────────────────────────────┘
```

首屏（不滚动）必须完整看到：品牌名、这是哪个后台、两个输入框、登录按钮。360×640 的手机上同样如此。

### 2.2 布局

- 页面底色 `bg-page`，最小高度 `100dvh`。
- 卡片：宽 `min(var(--layout-auth-card-width), 100%)`，水平居中；底 `bg-surface`，边框 `border-default`，圆角 `radius-xl`，内边距 `space-8`，无阴影。
- 垂直位置：≥ 768px 时卡片垂直居中（视觉上略偏上，卡片上方留白 : 下方留白约 2 : 3）；< 768px 时靠上，距顶 `space-12`。**手机上不垂直居中**，否则键盘弹出时卡片会跳动、输入框被遮住。
- < 480px：卡片去掉边框和圆角，底色改为与页面相同（`bg-page`），内边距改为 0，由页面边距 `space-4` 控制左右留白。此时输入框的边框对比的是 `bg-page`（已校验，亮色 3.37、暗色 4.71）。
- 卡片内从上到下：

| 元素 | 样式 | 与下一项的间距 |
| --- | --- | --- |
| 品牌名「NOZOMI」 | 纯文字，不用图片。`font-size-3xl`，`font-weight-bold`，`text-primary`，`letter-spacing: 0.08em`。不是标题元素，用 `<p>` | `space-1` |
| 副标题「供应商后台」或「运营后台」 | `<h1>`，`font-size-lg`，`font-weight-medium`，`text-secondary` | `space-6` |
| 提示条（有才显示） | 见 2.5 | `space-4` |
| 邮箱 | 标签 + 输入框，`lg` 尺寸 | `space-4` |
| 密码 | 标签 + 输入框（右侧「显示密码」按钮），`lg` 尺寸 | `space-6` |
| 「登录」按钮 | 主按钮，`lg` 尺寸，宽度撑满 | `space-6` |
| 切换入口的链接 | `font-size-sm`，`text-link`，居中 | — |

- 主题切换：页面右上角，距边 `space-4`，一个图标按钮，点开是三个选项「跟随系统 / 亮色 / 暗色」。和后台顶栏里的是同一个组件。
- 页面标题（浏览器标签页）：「登录 · NOZOMI 供应商后台」/「登录 · NOZOMI 运营后台」。

### 2.3 文案

| 位置 | 供应商后台登录 | 运营后台登录 |
| --- | --- | --- |
| 副标题 | 供应商后台 | 运营后台 |
| 邮箱标签 | 邮箱 | 邮箱 |
| 密码标签 | 密码 | 密码 |
| 按钮 | 登录 | 登录 |
| 切换链接 | 我是平台员工，去运营后台登录 | 我是供应商，去供应商后台登录 |

- 输入框不放占位文字（不编造示例邮箱）。
- 不放「注册」入口：账号只能通过邀请开通。
- 不放「记住我」。登录状态保持多久由后端的会话规则决定。
- **不放「忘记密码」链接**，直到有对应的任务。放一个点了没用的链接比没有更糟。（见第 5 节「待定」。）

### 2.4 字段

| 字段 | 属性 | 前端校验（提交时；出过错后实时） |
| --- | --- | --- |
| 邮箱 | `type="email"`、`name="email"`、`autocomplete="username"`、`inputmode="email"`、`autocapitalize="none"`、`spellcheck="false"`、`required` | 空：「请输入邮箱」；格式不对：「邮箱格式不正确」。提交前去掉首尾空格 |
| 密码 | `type="password"`、`name="password"`、`autocomplete="current-password"`、`required` | 空：「请输入密码」。不在登录页校验密码长度和复杂度；不去空格 |

- 用真正的 `<form>`，按钮 `type="submit"`，在任一输入框里按 Enter 即提交。这样浏览器和密码管理器才能正确填充和保存。
- 页面打开后焦点自动落在邮箱输入框（仅 ≥ 768px；手机上不自动聚焦，避免一打开就弹键盘）。邮箱已预填时（见 2.5 的「登录已过期」和邀请成功），焦点落在密码框。
- 「显示密码」按钮：在密码框内右侧，图标按钮，`aria-label` 在「显示密码」和「隐藏密码」之间切换，`aria-pressed` 同步；点击后焦点留在密码框。提交时自动切回隐藏。
- Tab 顺序：邮箱 → 密码 → 显示密码 → 登录 → 切换链接 → 主题切换。

### 2.5 状态

**提交中**

- 「登录」按钮进入加载态：转圈 +「正在登录…」，`aria-busy="true"`，宽度不变，不响应再次点击和 Enter。
- 两个输入框设为只读（`readonly`，不用 `disabled`，保持焦点和已填内容）；切换链接不可点。
- 清掉上一次的错误提示条。
- 超过 10 秒没有结果：按「网络错误」处理并恢复可操作。

**登录成功**

- 跳转到登录前想去的页面；没有则去该后台的首页。回跳地址只接受本站内的相对路径，其他一律忽略并去首页。
- 不显示「登录成功」的提示，直接进入。

**登录失败**：在卡片内、输入框上方显示危险提示条（`role="alert"`）。输入框本身不标红（不暗示是哪一项错了）。

| 情况 | 提示条文字 | 之后 |
| --- | --- | --- |
| 邮箱不存在、密码错误、账号还没设置密码、账号属于另一个后台 | **邮箱或密码不正确。** | 保留邮箱，清空密码，焦点移到密码框 |
| 邮箱和密码都正确，但账号已停用（后端返回 `ACCOUNT_DISABLED`） | 显示后端给的文字（现为「账号已停用，请联系管理员」） | 保留邮箱，清空密码，焦点移到密码框 |
| 尝试次数过多被限制 | 尝试次数过多，请稍后再试。（后端给出等待时间时：请 N 分钟后再试。） | 保留邮箱，清空密码；等待期间按钮可点，结果仍是这条提示 |
| 网络不通、请求超时 | 网络连接失败，请检查网络后重试。 | 保留邮箱和密码，焦点留在「登录」按钮 |
| 服务器出错 | 系统暂时无法登录，请稍后再试。 | 保留邮箱和密码；后端返回了请求编号时，在提示条里另起一行显示「编号：…」 |

**不暴露邮箱是否存在**——这是硬性要求：

- 第一行的所有情况必须显示**完全相同**的文字和样式，页面行为也相同（都清空密码、都聚焦密码框）。不能出现「该邮箱未注册」「请去运营后台登录」这类区分。
- 前端只根据「登录失败」这一种结果显示这条提示，不解析后端返回里更细的原因；唯一的例外是「账号已停用」。
- 不在邮箱失去焦点时去后端查邮箱是否存在。
- 「账号已停用」可以单独提示：后端只在密码正确时才返回它（ADR 0008），知道密码的人本来就知道这个邮箱存在，所以不泄露信息。

**进入页面时带着原因**：在同一个位置显示提示条。

| 来由 | 类型 | 文字 |
| --- | --- | --- |
| 登录已过期被送回登录页 | 信息 | 登录已过期，请重新登录。 |
| 用户自己点了「退出登录」 | 成功 | 已退出登录。 |
| 刚设置完密码（从邀请页过来） | 成功 | 密码已设置，请登录。 |

这些提示在用户开始提交后消失。

**已经登录的人打开登录页**：直接跳到对应后台的首页，不显示表单。判断登录状态期间显示卡片的骨架屏，不要先闪出表单再跳走。

**空状态**：本页没有空状态。

### 2.6 手机宽度（360px）

- 页面边距 `space-4`，内容宽 328px；输入框和按钮撑满。
- 触屏下输入框和按钮高 48px、输入文字 16px（令牌自动处理），iOS 不会在聚焦时放大页面。
- 切换链接的文字较长，允许折成两行，不截断。
- 键盘弹出时，「登录」按钮应仍可通过滚动到达；不把任何东西固定在屏幕底部。
- 提示条里的长文字正常折行。
- 按 `03-layout.md` 第 5 节的方法，在 360 和 400 宽度下对「默认、字段出错、提交中、登录失败」四个状态各检查一次横向溢出。

### 2.7 以后会加、现在先留位置的

不在 M0-07 范围内，但布局要容得下，届时不必重排：

- **两步验证**：密码通过后，卡片内容换成「输入验证码」一步（同一张卡片，不跳页）。
- **公司统一登录**（运营后台）：「登录」按钮下方加一条「或」分隔线和一个次要按钮。
- **界面语言切换**：放在主题切换的左边。

## 3. 接受邀请并设置密码页

### 3.1 首屏看到什么

用户从邀请邮件里的链接进来。卡片的位置、尺寸、手机下的变化与登录页完全相同。

```
┌─────────────────────────┐
│ NOZOMI                  │
│ 设置密码                 │
│                         │
│ 你正在为下面的账号设置密码  │
│ {邮箱}                   │
│                         │
│ 新密码                   │
│ [                 (眼) ] │
│ {密码规则说明}            │
│                         │
│ 再输入一次                │
│ [                 (眼) ] │
│                         │
│ [    设置密码并继续     ]  │
└─────────────────────────┘
```

- 副标题（`<h1>`）：「设置密码」。
- 账号说明：一行 `font-size-sm` + `text-secondary` 的「你正在为下面的账号设置密码」，下一行是邮箱（`font-size-md`，`font-weight-medium`，`text-primary`，`overflow-wrap: anywhere`）。邮箱是纯文字，不是输入框，不能改。后端同时返回了所属公司名称或后台类型时，在邮箱下面再加一行（`text-secondary`）。
- 为了让密码管理器把新密码存到正确的账号下，表单里放一个隐藏的只读输入框：`type="email"`、`autocomplete="username"`、值为该邮箱。
- 页面标题：「设置密码 · NOZOMI」。
- 页面加 `<meta name="referrer" content="no-referrer">`，页面上不放任何外部链接和外部资源，避免邀请链接泄露出去。

### 3.2 字段

| 字段 | 属性 | 校验 |
| --- | --- | --- |
| 新密码 | `type="password"`、`autocomplete="new-password"`、`required`、`aria-describedby` 指向密码规则说明 | 空：「请输入新密码」；不符合规则：直接写出没满足的那一条 |
| 再输入一次 | `type="password"`、`autocomplete="new-password"`、`required` | 空：「请再输入一次新密码」；不一致：「两次输入的密码不一致」 |

- **密码规则**只有一份，前端不另定：M0-06 正在写的 `packages/domain/src/password-policy.ts`（`checkPasswordStrength` 做检查，`PASSWORD_ISSUE_MESSAGES` 是每条规则的中文提示，前后端共用）。前端在「新密码」失去焦点和提交时调用它，把返回的每一条没满足的规则逐行显示在「新密码」下方。
- 规则说明作为帮助文字一直显示在「新密码」下方（`font-size-sm`，`text-tertiary`），用户不用等报错才知道要求。文字里的数字取自该文件的常量，不手写。按目前的规则是：「至少 {最短长度} 个字符，包含小写字母、大写字母、数字、符号中的至少三类，不能包含邮箱名。」
- 后端拒绝了前端放行的密码时，把后端返回的说明显示在「新密码」下方。
- 不做「密码强度条」。
- 「不一致」的校验在「再输入一次」失去焦点时进行；之后任一框的内容变化都实时重新比较。
- 两个密码框各有「显示密码」按钮，行为同登录页。
- 进入页面后焦点落在「新密码」（仅 ≥ 768px）。

### 3.3 状态

| 状态 | 显示什么 |
| --- | --- |
| 正在核对邀请链接（刚进页面） | 卡片骨架屏：品牌名照常显示，下面是三条灰块。不显示表单 |
| 链接有效 | 上面的表单 |
| 链接无效：过期、已经用过、被撤销、链接不完整、根本不存在 | 卡片里**不显示表单**，显示错误状态：标题「邀请链接已失效」；说明「链接可能已过期或已经使用过。请联系邀请你的管理员重新发送。」；一个次要按钮「去登录」（已经设过密码的人可以直接去登录）。**各种无效原因显示同一段文字**，不区分，也不显示邮箱 |
| 核对链接时网络不通或服务器出错 | 错误状态：标题「加载失败」；说明「请检查网络后重试。」；次要按钮「重试」。不要显示成「链接已失效」，那会让用户白白去找管理员 |
| 提交中 | 按钮加载态「正在设置…」，两个输入框只读 |
| 提交成功 | 跳到对应后台的登录页，显示成功提示条「密码已设置，请登录。」，邮箱已预填，焦点在密码框 |
| 提交时发现链接已失效（页面开了很久） | 整个卡片换成上面的「邀请链接已失效」 |
| 提交时网络不通或服务器出错 | 表单顶部危险提示条，文字同登录页对应情况；保留已填内容 |

「去登录」和成功后的跳转去哪个后台的登录页：按后端返回的账号类型决定；后端不返回类型时去供应商后台登录页（那里有去运营后台的链接）。

**空状态**：本页没有空状态。

### 3.4 手机宽度（360px）

同登录页 2.6。另外：邮箱可能很长，必须能在任意位置折行；密码规则说明正常折行。检查「核对中、表单、字段出错、链接已失效、提交中」五个状态的横向溢出。

## 4. 无障碍检查清单（两个页面都适用）

- 每个输入框都有可见的 `<label>`，用 `for` / `id` 关联。
- 字段出错文字用 `aria-describedby` 关联到输入框，输入框 `aria-invalid="true"`。
- 失败提示条是 `role="alert"`，出现时读屏会读出；提示条的容器一开始就在页面里（空的），之后只往里填内容。
- 只用键盘能走完整个流程；聚焦环在亮色、暗色下都清楚可见。
- 页面放大到 200% 时内容不被截断、不出现横向滚动。
- 亮色、暗色各看一遍：卡片与页面底色分得开；出错提示条、禁用和加载中的按钮都读得清。
- 提交中的转圈在「减少动态效果」设置下不转，文字「正在登录…」仍然显示。

## 5. 待定，需要前端或其他角色判断的地方

1. **入口网址**。建议供应商后台登录用 `/login`，运营后台登录用 `/platform/login`，邀请页的网址格式跟后端生成的邀请链接一致。最终以 M0-06 的登录接口为准：如果后端只有一个登录接口、自己能分清账号类型，两个入口可以合并成一个页面，去掉切换链接，副标题改为「登录」。
2. **忘记密码**。目前没有对应任务，页面不放入口。需要产品角色决定：自助重置（发邮件）还是由管理员重新发邀请。决定后本页加一个链接即可。
3. **密码规则文字**。`packages/domain/src/password-policy.ts` 在 M0-06 里还没合并，规则和导出的名称可能变；前端实现时以合并后的文件为准，帮助文字跟着调整。
4. **限流提示里的等待时间**。后端返回了才显示具体分钟数。
5. **设置密码成功后是否直接进入后台**。本规范按「回登录页再登录一次」设计（实现简单，也让用户确认密码管理器存对了）。后端在设置密码的同时就建立了登录状态的话，改为直接进后台首页并用 Toast 显示「密码已设置」。
