# 修改密码页

两个后台共用同一个页面（运营后台 `/platform/account/password`，供应商后台 `/account/password`）。它有两种情形，表单相同，框架、标题和文案不同：

| 情形 | 什么时候 | 给谁用 | 要完成什么 |
| --- | --- | --- | --- |
| 普通 | 已登录的人从账号菜单点「修改密码」 | 所有后台用户 | 把自己的密码换成新的 |
| 强制 | 用临时密码登录后（后端返回 `must_change_password` 为 true，ADR 0013） | 目前只有用命令行创建 / 重设的平台超级管理员 | 把临时密码换成只有自己知道的密码；换完之前什么都不能用 |

组件和令牌见上一级目录的规范，这里只写本页特有的内容。M0-12 已按本文第 3–5 节的大部分内容实现；与现有实现不同的地方在第 8 节列出。

## 2. 布局与字段

- 页面类型「表单」：最大宽度 `layout-form-max-width`。表单放在一张卡片里，**单栏**（三个密码框不并排）。
- 底部操作区只有一个主按钮，右对齐；< 480px 撑满宽度。没有「取消」：普通情形下用户用侧边栏离开，强制情形下无处可去。
- 输入框用 `md` 尺寸（不是登录页的 `lg`），都有「显示密码」按钮，行为同 `login.md` 2.4。

| 字段 | 标签（普通 / 强制） | 属性 | 帮助说明 |
| --- | --- | --- | --- |
| 当前的密码 | **当前密码** / **临时密码** | `type="password"`、`name="current-password"`、`autocomplete="current-password"`、`required` | 普通：无。强制：「就是创建账号的人交给你的那一串，带连字符，区分大小写。」 |
| 新密码 | 新密码 | `type="password"`、`name="new-password"`、`autocomplete="new-password"`、`required`，`aria-describedby` 指向规则说明 | 密码规则说明（与设置密码页同一份，取自 `packages/domain/src/password-policy.ts`，不手写） |
| 确认 | 再输入一次新密码 | `type="password"`、`name="confirm-password"`、`autocomplete="new-password"`、`required` | 无 |

- 表单里放一个隐藏的只读邮箱框（`autocomplete="username"`），让密码管理器把新密码存到正确的账号下。
- 进入页面后焦点：强制情形落在「临时密码」（仅 ≥ 768px；手机上不自动聚焦）；普通情形不自动聚焦。
- 强制情形下「临时密码」框允许粘贴，不拦截（临时密码有 23 个字符，本来就是复制过来的）。粘贴进来的内容去掉首尾的空格和换行（复制终端里的一行时很容易带上），中间的字符原样保留。

## 3. 强制情形下的后台框架（受限框架）

用户此刻只能做三件事：改密码、换主题、退出登录。框架上不出现任何点了会被拦回来的东西。

| 部位 | 强制情形 |
| --- | --- |
| 侧边栏 | **不显示**（≥ 1024px 也不显示）。框架变成单列：`grid-template-columns: minmax(0, 1fr)` |
| 顶栏左侧 | 没有菜单按钮。显示品牌名「NOZOMI」（`font-size-lg`，`font-weight-bold`，`letter-spacing: 0.08em`，`text-primary`）+ 后台名称「运营后台」/「供应商后台」（`font-size-sm`，`text-secondary`），两者基线对齐，间距 `space-2`。**是纯文字，不是链接**（首页此刻进不去） |
| 顶栏中间 | **不显示面包屑**：只有这一页，页面标题已经说明了 |
| 顶栏右侧 | 主题切换照常。账号菜单照常显示姓名、角色、邮箱，菜单项只有「退出登录」，没有「修改密码」 |
| 内容区 | 表单这一列**水平居中**（最大宽度 `layout-form-max-width`）；没有侧边栏时靠左会显得偏 |
| 「跳到正文」 | 保留 |

- 320px 宽时顶栏放得下：品牌名 + 后台名称约 150px，右侧两个按钮约 100px。后台名称放不下时允许被省略号截断（`min-width: 0` + `text-overflow: ellipsis`），品牌名和右侧按钮不能被挤掉。
- 强制情形下，打开本后台的任何其他地址（首页、不存在的地址、别人发来的链接）都回到本页，不显示 404，也不记住「原来想去哪」——改完统一去首页。
- 判断「要不要强制」期间（刚刷新页面、`auth/me` 还没回来）：显示受限框架 + 卡片骨架屏，不要先闪出带侧边栏的完整框架。

## 4. 文案定稿

| 位置 | 普通情形 | 强制情形 |
| --- | --- | --- |
| 页面标题（`<h1>`） | 修改密码 | **设置新密码** |
| 浏览器标签页标题 | 修改密码 · NOZOMI {后台名称} | **设置新密码 · NOZOMI {后台名称}** |
| 顶栏面包屑 | 修改密码 | （不显示） |
| 页面顶部提示条 | 无 | 警告提示条：**你正在使用临时密码，请先设置新密码。设置完成前不能使用其他功能。** |
| 第一个字段的标签 | 当前密码 | **临时密码** |
| 提交按钮 | 保存新密码 | 保存新密码 |
| 提交中 | 保存中… | 保存中… |

- 强制情形下标题写「设置新密码」而不写「修改密码」：这不是用户自己要来改，页面上的提示条、标题、按钮说的是同一件事。
- 警告提示条：`warning` 类型，放在页面标题下方、表单卡片上方，与卡片间距 `space-4`；**不能关闭**，一直显示到改完；`role="alert"`。提示条只有正文、没有标题行，也不带按钮。
- 整个页面不出现「must_change_password」「一次性密码」「初始密码」等别的叫法，统一叫「临时密码」（和命令行输出的「临时密码：」一致，用户拿到的就是这个词）。

## 5. 校验与出错文字

校验时机按 `02-components.md` 第 4 节。`{当前}` 在普通情形下是「当前密码」，强制情形下是「临时密码」。

| 情况 | 显示在哪 | 文字 | 之后 |
| --- | --- | --- | --- |
| 第一个字段没填 | 该字段下 | 请输入{当前} | 焦点到该字段 |
| 新密码没填 | 「新密码」下 | 请输入新密码 | 焦点到「新密码」 |
| 新密码不符合规则 | 「新密码」下，每条没满足的规则一行 | 取自 `PASSWORD_ISSUE_MESSAGES` | 同上 |
| 确认没填 | 「再输入一次新密码」下 | 请再输入一次新密码 | 焦点到该字段 |
| 两次不一致 | 「再输入一次新密码」下 | 两次输入的密码不一致 | 同上 |
| 后端：`CURRENT_PASSWORD_INCORRECT` | 第一个字段下 | **{当前}不正确，请重新输入** | 保留三个框的内容，焦点到第一个字段并全选 |
| 后端：`PASSWORD_UNCHANGED` | 「新密码」下 | **新密码不能和{当前}相同** | 焦点到「新密码」 |
| 后端：`WEAK_PASSWORD` | 「新密码」下 | 后端 `details.issues` 里的每一条说明；一条都没有时：「密码不符合要求，请换一个再试。」 | 焦点到「新密码」 |
| 尝试次数过多（429） | 表单顶部危险提示条 | 尝试次数过多，请稍后再试。（有等待时间时：请 N 分钟后再试。） | 保留内容 |
| 网络不通、超时 | 表单顶部危险提示条 | 网络连接失败，请检查网络后重试。 | 保留内容，焦点留在按钮 |
| 服务器出错 | 表单顶部危险提示条 | 系统暂时无法修改密码，请稍后再试。 | 保留内容；有请求编号时另起一行「编号：…」 |
| 登录已过期（401） | 跳到登录页 | 登录已过期，请重新登录。 | 强制情形下重新登录后仍回到本页 |

- 强制情形下临时密码填错时，出错文字只说「临时密码不正确，请重新输入」，不提示「是否大小写错了」之类的猜测（帮助说明里已经写了区分大小写）。
- 后端的出错说明里写的是「当前密码」；强制情形下前端按错误码换成上表的文字，不直接显示后端那句话。
- 提交中：按钮加载态，三个输入框只读；提交失败后内容都保留。

## 6. 成功之后

| 情形 | 去哪 | 提示 |
| --- | --- | --- |
| 普通 | 留在本页，三个框清空，校验状态复位 | 表单顶部**成功提示条**：「密码已修改。这个账号在其他设备上的登录已全部退出。」留到用户离开本页或再次提交 |
| 强制 | 直接进本后台首页（替换掉当前这条浏览记录，按「后退」不会回到本页），框架恢复成完整框架，不用重新登录 | **Toast**：「新密码已生效，临时密码已作废。」 |

**决定：强制情形改完后的提示用 Toast，不用首页上的提示条。** 理由：

- 规范里「成功之后用 Toast 还是成功提示条」的规则（`02-components.md` 第 8 节）：成功后跳到了别的页面，用 Toast。
- 首页的首屏要留给模块入口和待处理的提醒；一条不会自己消失的成功提示条会把它们往下推，刷新后是否还在也说不清。
- 这句话只是让人放心（「可以开始用了，那串临时密码不用再管」），不影响下一步操作，4 秒够读完。

Toast 组件的规范在 `02-components.md` 第 8 节，M1-08 一并实现（主数据页面的「已保存」「已启用」也要用它）。Toast 容器挂在框架最外层，所以「在修改密码页发出、在首页显示」是成立的：页面跳转不会清掉它。只在这一次跳转时显示一次，刷新首页不再出现。

普通情形保留成功提示条，是因为「其他设备上的登录已全部退出」是用户需要读到的后果，属于同一条规则的另一行。

## 7. 状态、手机宽度、无障碍

| 状态 | 显示什么 |
| --- | --- |
| 账号信息加载中 | 卡片骨架屏（三条输入框形状的灰块） |
| 账号信息加载失败 | 卡片内错误状态：「加载失败」「请检查网络后重试。」+「重试」。表单仍然显示、可以提交（改密码不依赖账号信息；邮箱取不到时前端跳过「不能包含邮箱名」这条检查，由后端把关） |
| 空状态 | 本页没有空状态 |
| 没有权限 | 本页没有这种情况：登录了就能改自己的密码 |

- 手机宽度：单栏，输入框和按钮撑满；警告提示条正常折行。320、360、400 三个宽度下，对「默认、字段出错、提交中、顶部提示条出现」四个状态、两种情形各检查一次横向溢出。
- 键盘顺序：（跳到正文）→ 顶栏的主题切换、账号 → 第一个字段 → 显示密码 → 新密码 → 显示密码 → 确认 → 显示密码 → 保存新密码。
- 警告提示条和出错提示条是 `role="alert"`，成功提示条是 `role="status"`；容器一开始就在页面里。
- 亮色、暗色各看一遍：警告提示条（`warning-bg` 上的 `text-primary` 正文）、只读态输入框、加载中的按钮都读得清。
