# 工单与赔付表（运营后台、供应商后台）

M4-03 的页面（接口 M4-02，ADR 0034）。组件和令牌见上一级目录的规范。

## 1. 给谁用、要完成什么

| 页面 | 地址 | 给谁用 | 要完成什么 | 权限 |
| --- | --- | --- | --- | --- |
| 工单列表 | `/platform/tickets` | 客服、运营；财务、风控、只读能看 | 看没有结论的、超时的工单 | 看 `ticket.read` |
| 新建工单 | `/platform/tickets/new?order={订单}` | 客服 | 代客人、渠道、供应商登记，绑定一张订单 | `ticket.manage` |
| 工单详情 | `/platform/tickets/{id}` | 同上 | 对话、内部备注、征求供应商意见、判定（试算赔付）、关闭；财务登记另付 | 处理 `ticket.manage`；另付 `payment.manage` |
| 赔付表 | `/platform/compensation-table` | 每个角色能看；运营改 | 看统一赔付表；发起修改（双人复核） | 看 `master_data.read`；改 `compensation_table.manage` |
| 供应商的工单 | `/tickets`、`/tickets/{id}`、`/tickets/new?order={订单}` | 供应商的管理员、调度、财务、只读 | 24 小时内回复平台；看判定和自己承担的款项；7 天内申诉一次；登记失物 | 看 `ticket.read`；回复、申诉、发起 `ticket.manage` |

## 2. 运营后台：列表

- 筛选条：搜索框「按工单号或订单号查找（完整的号）」；状态（没有结论的〔默认〕/ 全部 / 各状态）、类型、处理人（全部 / 我 / 同事）、时效（全部 / 只看已超时）。
- 列：工单（工单号 + 标题）、类型标签、状态（+ 紧急 `danger` / 高 `warning` 徽标、已超时）、订单号、供应商、处理人、结案期限、创建时间。方式 B。
- 状态徽标：待处理 `warning`、等供应商回复 `info`、处理中 `info`、判定待复核 `warning`、已判定 `success`、已关闭 `neutral`（界面上一律叫「供应商」，不叫「租户」）。
- 标题行主按钮「新建工单」（`ticket.manage`）。空状态「现在没有待处理的工单」。

## 3. 运营后台：新建

- 表单页（720px）。没带订单时先「按订单号查找」（平台订单号或渠道订单号，完整的）。
- 字段：类型（单选，五种，每项一行说明）、被投诉的供应商（只有救援改派过的单才出现）、谁提出的、优先级（默认按规则：用车当天为紧急）、标题、经过（多行）、客人语言（选填）。提交后去工单详情，Toast「已新建工单「TK…」」。

## 4. 运营后台：详情

- 详情布局。主栏：工单本身（描述、类型、来源、优先级、订单、供应商、首次响应 / 结案期限、征求意见的期限）；「和供应商的对话」（每条：谁写的 + 时间 + 正文；说明「这里的每一条供应商都看得到」）+ 输入框「发给供应商」；「内部备注」（`warning-bg` 底，说明「只有平台员工看得到」）+「加备注」。
- 侧栏「处理」：处理人；按钮：认领（没人处理时主按钮）/ 改由我处理、交给同事、征求供应商意见、判定（自己在处理时主按钮）、关闭工单。等供应商回复时写明期限内不能判定。
- 判定对话框（表单，点遮罩不关）：结论单选；投诉、履约失败「成立」时：哪种问题（赔付表的 7 种）、责任方（供应商 / 平台，各带一行后果）、车型降级的结算价之差、司机未到的报销（选填）、重大投诉；「试算」后显示赔付表版本和比例、按比例、最低额（补足时写明平台承担）、赔客人合计、报销、退回原卡、财务另付、供应商承担；判定说明必填（供应商看得到）。成立的要先试算才能提交。达到复核阈值时警告提示条，确认按钮写「提交复核」，提交后 Toast「判定已提交复核：另一位同事批准后才执行」，页面顶部警告提示条「判定待复核」+ 去「待审核」。
- 「判定」一块：结论、责任方、判定人、时间、说明、供应商可以申诉到、供应商的申诉（链接）。「赔付」一块（只在运营后台）：情形、对外价、赔客人、报销、退回原卡、财务另付和状态、供应商承担；待另付时 `payment.manage` 有「登记另付已付」（凭证号必填）。「供应商应扣款项」：种类、金额、状态、怎么算的。
- 被规则拒绝（等供应商回复、刚被改过、判过原工单的人判申诉……）：对话框里危险提示条写明原因，去掉确认按钮，「取消」改成「知道了」。

## 5. 赔付表

- 表格：问题、赔客人、供应商承担（结算币种）；下面「每笔至少等值」「替代交通报销上限」「判定要复核的阈值」。标题写现在用的版本（默认表 / 第 N 版）和生效时间。
- 「修改赔付表」（标题行主按钮，`compensation_table.manage`）：每种问题一个百分比输入框（司机未到只读 100%），最低额（日元整数）、报销上限（对外价的 %）、复核阈值（%），为什么改（选填）；有错时顶部「有 N 处需要修改」。提交后成功提示条「已提交复核」+ 去「待审核」。百分比按基点整数提交。

## 6. 供应商后台

- 列表：状态（没有结论的 / 全部 / 各状态），等着它回复的写 `warning` 徽标「等你们回复」；从订单详情进来只看那一单（可删除的小标签）。
- 详情：等回复时顶部警告提示条写期限和「超时视为认可」；对话里平台员工一律写「平台」；「回复平台」（必填）；「判定」一块（责任方在自己时写「你们」）；「你们承担的款项」；对它不利的判定 7 天内有「申诉」（对话框，理由必填，建「供应商申诉」工单并跳过去；已申诉过、过期的写后端原因）。
- 规则 4：不显示对外价、加价比例、客人那边的赔付金额、内部备注、处理人；页面不从别处拼。
- 发起：从订单详情「就这一单发起工单（失物招领、其他）」进来；没带订单时说明从订单详情发起。

## 7. 菜单、首页

- 运营后台菜单：「异常队列」后面「工单」（对话气泡图标，`ticket.read`）；「取消政策」后面「赔付表」（看工单的人和改 / 审赔付表的人）。首页「运营」分区加「工单」（没有结论 · 已超时，有超时的提醒行）和「赔付表」（版本）卡片。
- 供应商后台菜单：「违约金与扣款」后面「工单」；首页「工单和账单」分区「工单」卡片（没有结论 · 等你们回复，有等回复的提醒行）。

## 8. 复核页（待审核）

新接三类：修改客人赔付表（只列改了的项：每种问题的比例、最低额、报销上限、复核阈值）、工单判定（工单号、状态、结论、情形 · 责任方、赔客人、其中退回原卡 / 财务另付；链接去工单）、付款给供应商（链接去账单）。批准的确认框按类别写批准后的效果。
