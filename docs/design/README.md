## 这套界面给谁用

| 界面 | 使用者 | 设备 | 取向 |
| --- | --- | --- | --- |
| 运营后台 | 平台员工（运营、客服、财务、风控等），整天开着 | 桌面为主 | 信息密度高，表格和筛选是主体 |
| 供应商后台 | 租户的管理员、商品价格、调度、财务 | 桌面为主；调度会在手机上看单、派车 | 同上；订单和派车在手机上必须好用 |
| 官网下单页 | 客人 | 手机为主 | 同一套令牌，控件用大尺寸，留白更多 |
| 司机 H5 | 司机，在车上、户外单手操作 | 只有手机 | 同一套令牌，大按钮、大字、强对比，一屏一件事 |

四类界面共用 `tokens.css`，不另起色板。

## 风格

- 稳重的工具感：冷灰中性色 + 一个蓝色主色。大面积只用中性色，主色只出现在「当前最该点的那个按钮」、链接、选中态、聚焦环上。
- 主色选蓝色的理由：红、绿、橙要留给「危险、成功、警告」表达状态，主色不能和它们抢；蓝色在亮暗两套里都容易做到足够对比度。
- 正文 14px、表格行高 40px，一屏放得下更多行；触屏设备自动换成 16px 输入框和 44px 控件（见 `tokens.css` 末尾）。
- 不用渐变、不用装饰插图、不用外部图片和字体。层次靠背景色差和 1px 边框，阴影只给浮层。唯一的例外是地图的底图（一张张来自底图服务的图片），来源和限制见 `pages/tenant-areas.md` 第 13 节。

## 硬性规则

1. **只引用令牌**。组件样式里不出现十六进制颜色、`rgb()`、写死的字号和层级数字。需要的值令牌里没有，就找美工加令牌。
2. **状态 = 颜色 + 文字**。任何状态都必须有文字（或带文字说明的图标），不能只靠颜色区分。
3. **亮、暗两套都要看过**。每个页面在两套主题下各检查一遍；颜色搭配只用 `01-tokens.md`「允许的搭配」里列出的组合。
4. **360px 宽不横向滚动**。做法和自动检查方式见 `03-layout.md`。M1-08 起新做的页面再加严到 320px。
5. **键盘可用**。所有能点的东西都能用 Tab 到达、用 Enter 或空格触发，并有看得见的聚焦环。
6. **文案用业务说法**。写「派车」「结算价」「用车时间」，不写「assignment」「settlement」「pickup_at」。错误提示说人话，并告诉用户下一步怎么办。
7. **没有演示数据**。空就显示空状态，不用假数据占位。
8. **供应商后台不出现对外价和加价比例**。相关组件不为这两项留位置（CLAUDE.md 规则 4）。

## 前端怎么引用令牌

`docs/design/tokens.css` 是源头。`apps/web` 只保留一个入口文件引入它，不复制内容，避免两份不一致：

```css
/* apps/web/src/styles/tokens.css */
@import "../../../../docs/design/tokens.css";
```

主题切换只改 `<html>` 的 `data-theme`：不设 = 跟随系统，`light` / `dark` = 手动指定。用户的选择存在浏览器本地，页面首次绘制前就要设好（放在 `<head>` 的内联脚本里），避免闪一下。

改了颜色令牌后运行：

```bash
node docs/design/contrast-check.mjs
```
