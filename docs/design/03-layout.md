# 布局规范

## 1. 后台框架（运营后台、供应商后台共用）

```
≥ 1024px
┌──────────┬──────────────────────────────────────────┐
│          │ 顶栏（高 48px，吸顶）                      │
│ 侧边栏    ├──────────────────────────────────────────┤
│ 232px    │ <main> 内容区                             │
│ 常驻      │   页面边距 24px                            │
│          │   最大宽度 1440px，超出后居左，不拉伸        │
└──────────┴──────────────────────────────────────────┘

< 1024px
┌──────────────────────────────┐
│ [≡] 当前页名称        [账号]   │  顶栏
├──────────────────────────────┤
│ <main> 内容区，占满宽度         │  边距：< 768px 为 16px，≥ 768px 为 24px
└──────────────────────────────┘
侧边栏点 [≡] 后从左侧滑入，盖在内容上
```

- 框架用 CSS Grid：`grid-template-columns: var(--layout-sidebar-width) minmax(0, 1fr)`。**第二列必须是 `minmax(0, 1fr)`**，不能写 `1fr`，否则内容里一张宽表格就会把整页撑宽。
- 侧边栏和顶栏固定，只有 `<main>` 纵向滚动。
- 页面语义结构：`<header>`（顶栏）、`<nav>`（侧边栏）、`<main>`（内容，每页只有一个），每页有且只有一个 `<h1>`。
- 两个后台结构相同，靠侧边栏顶部的名称（「运营后台」/「供应商后台」）和菜单内容区分，不另做配色。
- **受限框架**（账号必须先修改密码时）：没有侧边栏，没有菜单按钮；顶栏左侧显示品牌名和后台名称；内容区水平居中。只有修改密码页会用到，细则见 [`pages/change-password.md`](./pages/change-password.md) 第 3 节。

## 2. 内容区

每个页面从上到下：

1. **页面标题行**：`<h1>`（`font-size-2xl`，`font-weight-bold`）在左，页面主操作按钮在右；放不下时按钮换到标题下一行。与下方内容间距 `space-4`。
2. **页面级提示条**（有才显示）。
3. **内容**：卡片、表格、表单。区块之间 `space-6`。

页面宽度按类型定：

| 页面类型 | 最大宽度 | 例子 |
| --- | --- | --- |
| 列表、看板 | `layout-content-max-width`（1440px） | 订单列表、价格规则、总览 |
| 表单、设置 | `layout-form-max-width`（720px），居左 | 新建司机、账号设置 |
| 详情（主栏 + 侧栏） | `layout-content-max-width`；≥ 1024px 时主栏 `minmax(0, 1fr)` + 侧栏 320px，栏间距 `space-6`；更窄时侧栏排到主栏下方 | 订单详情 |
| 编辑器（表单栏 + 画布） | `layout-content-max-width`；≥ 1024px 时表单栏 `minmax(0, 380px)` + 画布 `minmax(0, 1fr)`，栏间距 `space-6`，画布吸在视口里、占满余下的高度；更窄时单栏，画布排在基本信息之后。两种布局的 DOM 顺序相同 | 区域的新增 / 编辑（`pages/tenant-areas.md` 第 3 节） |
| 大段文字 | `layout-reading-max-width`（960px） | 条款、帮助说明 |

**卡片**：底 `bg-surface`，边框 `border-default`，圆角 `radius-lg`，内边距 `space-4`（≥ 768px 为 `space-6`），无阴影。卡片标题 `font-size-lg` + `font-weight-bold`。卡片里不再套卡片；需要再分区时用标题加分隔线。

**详情里的「标签：值」**：用 `<dl>`。标签 `font-size-sm` + `text-secondary`，值 `font-size-md` + `text-primary`。≥ 768px 排成 2–3 栏的栅格；< 768px 单栏，标签在上、值在下。没有值时显示「—」。

## 3. 栅格

- 不引入 12 栏栅格类库，直接用 CSS Grid。
- 固定栏数的地方（表单两栏）：`grid-template-columns: repeat(2, minmax(0, 1fr))`，放在 `@media (min-width: 768px)` 里；默认单栏。
- 数量不定的卡片（看板指标卡）：`grid-template-columns: repeat(auto-fill, minmax(min(240px, 100%), 1fr))`。里面的 `min(…, 100%)` 保证容器比 240px 还窄时不溢出。
- 栏间距：`space-4`；卡片之间 `space-6`（< 768px 为 `space-4`）。

## 4. 响应式规则

样式从手机写起，用 `min-width` 逐级加强。断点见 `01-tokens.md` 第 7 节。

| 元素 | < 480px | 480–767px | 768–1023px | ≥ 1024px |
| --- | --- | --- | --- | --- |
| 侧边栏 | 滑出面板 | 滑出面板 | 滑出面板 | 常驻 |
| 页面边距 | 16px | 16px | 24px | 24px |
| 表单 | 单栏 | 单栏 | 两栏 | 两栏 |
| 表格 | 方式 A 或 B（见组件规范第 5 节） | 同左 | 完整表格，容器内滚动 | 完整表格 |
| 筛选条 | 搜索框 +「筛选」按钮 | 同左 | 全部展开，自动换行 | 全部展开 |
| 表单和对话框的按钮 | 各占一行 | 右对齐并排 | 右对齐并排 | 右对齐并排 |
| 对话框 | 贴底、撑满宽度 | 居中 | 居中 | 居中 |
| 下拉面板 | 从底部升起 | 跟随输入框 | 跟随输入框 | 跟随输入框 |
| 详情页侧栏 | 排到主栏下方 | 同左 | 同左 | 在右侧 |

控件高度和输入框字号不按屏幕宽度切换，而是按是否触屏切换（`pointer: coarse`，已写在 `tokens.css` 里）：触屏笔记本得到大控件，用鼠标的窄窗口保持紧凑。

**官网下单页、司机 H5** 不用后台框架：单栏，内容最大宽度 480px（司机 H5）或 `layout-reading-max-width`（官网），居中；控件一律用 `lg` 尺寸；主操作按钮固定在屏幕底部并留出 `env(safe-area-inset-bottom)`。具体布局在各自任务的页面说明里写。

## 5. 手机宽度不横向滚动

要求：视口宽度 **360px**（常见最窄的安卓手机）到 400px 时，页面本身不出现横向滚动条；宽内容只在自己的容器里滚动。

**从 M1-08 起，最窄验证宽度是 320px**（小屏手机、桌面浏览器 400% 缩放）。M1-08 及以后新做的页面，在 320×640、360×740、400×800 三个视口下都不能横向滚动；此前已做的页面（登录、设置密码）在下次改动时一并补上 320 的检查。相应地，下面第 7 条里固定宽度的上限按 **288px**（320 − 两侧各 16px）执行。

**必须做的**

1. `index.html` 里写 `<meta name="viewport" content="width=device-width, initial-scale=1">`。不加 `maximum-scale`、`user-scalable=no`，用户必须能放大。
2. 全局 `*, *::before, *::after { box-sizing: border-box; }`。
3. Flex 和 Grid 的子元素默认不会缩到比内容更窄，这是横向溢出最常见的原因：
   - Grid 的列写 `minmax(0, 1fr)`，不写 `1fr`；
   - 装有长文字、表格、代码的 Flex 子元素加 `min-width: 0`。
4. 表格、代码块、页签条、价格日历等宽内容包在 `overflow-x: auto` 的容器里，容器自身 `max-width: 100%`。
5. 不会自动断行的长字符串——订单号、商品 ID、邮箱、网址、密钥、WKT 文本——所在元素加 `overflow-wrap: anywhere`。
6. 图片、视频、地图、图表：`max-width: 100%; height: auto`。地图画布的高度由页面规定（`02-components.md` 第 20 节），宽度同样不超过容器。
7. 固定宽度一律写成「不超过容器」的形式：`width: min(480px, 100%)`。任何元素的固定宽度不得超过 328px（360 − 两侧各 16px 的页面边距），除非它在可滚动的容器里。
8. 需要占满宽度时用 `100%`，**不用 `100vw`**：`100vw` 包含纵向滚动条的宽度，在有滚动条的系统上必然溢出。
9. 全屏高度用 `100dvh`，不用 `100vh`（手机浏览器的地址栏会让 `100vh` 比可见区域高）。
10. 浮层（下拉面板、气泡、Toast、对话框）定位后要限制在视口内，距屏幕边缘至少 `space-2`。
11. 并排的按钮组、筛选条、标题行加 `flex-wrap: wrap`。
12. 不用负外边距把内容拉出容器；不用 `white-space: nowrap` 包住长度不定的文字（只用于徽标、按钮、表头这类短文字）。

**禁止的做法**：在 `html` 或 `body` 上写 `overflow-x: hidden` 来「解决」横向滚动。这只是把溢出的内容藏起来，用户看不到也点不到，问题还在。

**怎么检查**

每个页面的端到端测试在 360×740 和 400×800 两个视口下各断言一次，亮色、暗色不影响结果，测一套即可：

```ts
const overflow = await page.evaluate(
  () => document.documentElement.scrollWidth - document.documentElement.clientWidth,
);
assert.equal(overflow, 0);
```

页面有多个状态时（空、有数据、出错、对话框打开、侧边栏滑出），每个状态都要测。另外用 200% 的浏览器缩放在 1280px 宽的窗口里看一遍（相当于 640px 宽），内容不应被截断。
