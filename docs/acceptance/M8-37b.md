# M8-37b 手机上地址被压缩 · 测试环境验收记录

- 日期：2026-11-13（UTC 03:00 前后）；部署 42023627（PR #176 合并后）
- 方式：协调者用 Playwright 的 **WebKit**（Safari 内核）加 iPhone 13（390 宽）和 iPhone SE（320 宽）设备模拟，打开测试环境 /book/new，不登录。
  - 本机 WebKit 缺少 https 组件，所以在本机起了一个只读的 http 转发（127.0.0.1 → 测试环境），页面和接口原样转发，用完已关。
  - CI 里 WebKit 用例（`site-booking-mobile-address.spec.ts`，webkit-iphone 项目）已通过。
- 操作：区间标签的「出发地」「目的地」，包车标签的「上车地点」「下车地点」，每个入口都打开全屏选择页、输入地名，等候选出来后量位置并截图。

| 设备 | 入口 | 选择页宽 | 输入框宽 | 候选列表 | 结论 |
|---|---|---|---|---|---|
| iPhone 13 | 出发地 / 目的地 / 上车地点 / 下车地点 | 390 | 358 | 在输入框正下方（输入框底边 158，候选从 166 开始），左边对齐（都在 x=16），宽 358 | 通过 |
| iPhone SE | 同上四个入口 | 320 | 288 | 在输入框正下方，左边对齐，宽 288 | 通过 |

改前（用户真机截图、PR 描述）：iPhone 13 上输入框 205 宽，候选排在右侧另一栏、宽 153。

截图：`docs/acceptance/M8-37b-shots/`（iPhone 13 四个入口、iPhone SE 出发地；只有公开页面，没有个人信息）。

第 1 步地址换行、第 2–4 步摘要条两端各一行：以 CI 的端到端测试（360 / 390 宽、两个标签、亮暗两色、axe）为证据。电脑布局不变，也以端到端测试为证据。

结论：通过。
