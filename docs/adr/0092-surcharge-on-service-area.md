# ADR 0092：同一区域可以既是服务区域又设包车区域加价

- 状态：已采纳（2026-11-14，M8-46；负责人按业主正式需求决定选项 A）。
- 依据：业主需求文档 `docs/requirements/charter-airport-packages-2026-11-14.md`（分支 req-charter-airport-packages）第六节 P1「服务区域含成田，成田同时设区域加价并保存 → 保存成功」；第一节第 3 条「选继承定价时按普通套餐价加机场区域上车或下车加价」。
- 修改 ADR 0073「M8-15 落地时定下的细节」第 3 条（加价区域）里的「不能是商品本身的区域（400 `AREA_IS_PRODUCT_AREA`）」；ADR 0073 其余内容不变。沿用 M8-38（PR #164，业主确认）的报价口径。

## 背景

ADR 0073 定加价区域时，认为「商品本身的区域里上车、下车都不加价，在那里设加价不会起作用」，所以保存时拒绝把服务区域设成加价区域。M8-38 以后报价引擎已经不是这样算：一端落在有可用加价的加价区域里就收这个加价，哪怕这一端也在商品的服务区域里（大运营区不能把小加价区盖成 0，重叠取最高）。引擎找加价区域时按区域加价规则本身找，不排除服务区域。

结果是保存规则和报价口径不一致：先给成田设了加价、后来又把成田加进服务区域的商品，报价已经在收成田的加价，价格页却写「商品的服务区域，不加价」，而且再补空着的组合时整批保存被拒，页面一直显示「有 N 条未保存」（业主报的 Bug，M8-46）。

## 决定

1. **只放开保存规则**：区域加价的区域可以是商品本身的服务区域。后端批量 / 单条保存、价格导入都不再报 `AREA_IS_PRODUCT_AREA`（这个原因码删掉，别处没有用到）；导入模板「填写说明」里可填的加价区域也列出服务区域。别的检查不变：业务类型要是包车或通用、用途要能挂价格、新选的不能是停用的、不能是别的租户的。
2. **报价引擎不改**，按 M8-38 口径：
   - 一端落在某个服务区域、这个区域又有这个车型组 × 套餐 × 日期可用的区域加价：**收这个加价**（几个加价区域都有时取最高）。
   - 基础定价照旧：用上车点所在的服务区域的套餐价（不在服务区域里时用下车点所在的；都不在时商品的每个区域都算、取最低）。所以成田上车 = 成田的套餐价 + 成田的上车加价。
   - 服务区域没设加价（或这个组合没设）：这一端加 0，和以前一样，不会因此报不出。
3. **不改变任何现有报价**：引擎本来就按已存的规则算，放开的只是「能不能存」。现在报得出的价格，在供应商新存服务区域上的加价之前一分不变；已经存在的「既是服务区域又有加价」的数据今天已经在收加价，放开前后一样。
4. **价格页**（`docs/design/pages/tenant-prices.md` 17.2）：「选择区域」下拉里服务区域可选，小字「商品的服务区域」；区域加价表里设了加价的服务区域只列加价那一行（名字后写「· 也是商品的服务区域」），不再同时列一行「0 / 0 不加价」；没设加价的服务区域照旧写 0。说明文字改成「落在加价区域里时加钱；服务区域也可以设加价；没设加价的服务区域不加钱」。

## 不在本篇

- 业主需求一「机场开始 / 结束套餐」里「单独填价时已含机场部分，该机场区域不再重复加价」：属于以后的机场场景套餐，由需求一的任务处理。在那之前，供应商如果在服务区域的套餐价里已经含了机场部分，又给这个区域设了加价，会收两次——这是供应商自己的定价。
- 区域加价在服务区域里没填的组合，汇总里照旧算「没填」（对服务区域来说没填 = 加 0，不会报不出）；要不要区分写法以后再看。
