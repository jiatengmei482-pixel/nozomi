# ADR 0012：平台主数据——表结构、只读共享、停用代替删除、机场数据来源

- 状态：已采纳（2026-10-07，M1-01）
- 补充 ADR 0010：新增「全平台共用、租户只读」这一类平台表的授权方式。不改变 ADR 0010 的其他内容。

## 背景

M1-01 要建城市、地点（机场 / 车站 / 地标）、车型组、附加服务四类主数据。需求文档（《用车报价服务平台》「统一主数据（平台级）」「数据模型」，《平台运营端与渠道对接》「主数据与内容运营」）给了编码规则和关键字段，但有几处要在落地时定下来。

## 决定

### 四张平台表，租户只读

- `cities`、`places`、`vehicle_groups`、`addons`（迁移 0007）。不带 `tenant_id`，不开行级安全。
- 授权：`nozomi_platform` 可以 `select / insert / update`；`nozomi_app`（租户事务）只有 `select`；`nozomi_preauth` 没有任何权限。
  ADR 0010 原来说平台表只授权给平台角色；主数据是例外——它本来就要给所有租户看，而且内容和租户无关，所以直接给租户角色只读权限，不需要策略。**租户改不了主数据，靠的是数据库里没有写权限**，不只是接口没提供（`tenant-isolation.itest.ts` 两层都测）。
- 谁都没有 `delete`：主数据只停用（`status` = `disabled`），不物理删除，历史订单和规则的引用不会失效（需求文档原话）。验收标准里的「删」就是停用。

### 地点用一张表

- 机场、车站、地标，以及航站楼（挂在机场下）、出口（挂在车站下）都在 `places`，用 `type` 区分、`parent_id` 表示上下级——和需求文档「数据模型」的 `place` 一致。这样「羽田机场 T3」有自己稳定的编号，以后商品、订单可以直接引用到航站楼。
- 接口也是一个资源 `/master/places`（用 `type` 筛选），没有拆成需求文档接口表里的 `airports / stations / pois` 三个路径：三者字段和规则几乎相同，拆开只是把同一套接口复制三份。
- 航站楼、出口的城市和国家跟随上级，不能单独指定；上级换城市时它们跟着换。

### 编码由平台录入，创建后不能改

- 城市 `CTY-国家码-序号`、车站 `STN-国家码-序号`、地标 `POI-序号`、车型组 `VG-等级-座位数`、附加服务 `ADD-代码`、机场用 IATA 三字码；航站楼 / 出口是上级编码加后缀（`HND-T3`）。
- 需求文档的例子（`CTY-JP-TYO`、`VG-BIZ-7`）说明「序号」是人起的助记码而不是流水号，所以全部由平台录入、系统校验格式和唯一性，不自动编号。
- 车型组编码的等级段：需求文档只给了「商务 = BIZ」一个例子。这里定下四个保留的缩写——`ECO` 经济、`CMF` 舒适、`BIZ` 商务、`LUX` 豪华。编码的等级段以某个缩写开头时，等级必须就是它（`VG-ECO-4` 不能配豪华）；缩写后面可以加后缀区分变体（`VG-BIZEV-7`）。不以任何保留缩写开头的等级段目前仍然接受（没有强制「等级段必须是缩写」），是否收紧由负责人决定。
- 编码是所有租户和销售端引用主数据的依据，创建后不能改（改了返回 409 `FIELD_LOCKED`）。车型组的等级和座位数同样不能改：它们决定了「这是哪个车型组」，要换就新建一个、停用旧的。
- 表里另有 `id`（uuid）做主键和外键；编码是对外的稳定标识。

### 版本号与并发修改

- 每条记录带 `version`，每改一次加一；修改接口必须用请求头 `If-Match` 带版本号（需求文档「并发修改」），不一致返回 409 `VERSION_CONFLICT`，没带返回 428。
- 内容没有变化的修改不加版本、不写审计日志。
- 加锁顺序统一是「先上级、后下级」（先机场 / 车站，再它的航站楼 / 出口），避免机场换城市和启用航站楼互相等死。
- 数据库主动放弃的事务（死锁、序列化失败）不是服务器故障：主数据的写操作自动重做最多 3 次，仍不成功返回 409 `CONCURRENT_UPDATE`（全局规则，任何接口都不再把这类错误当成 500）。
- 列表支持 `updated_since`，供以后销售端增量同步。

### 启用和停用的保护

- 手工新增的记录直接是启用的。
- 城市下还有启用中的地点时，城市不能停用；机场 / 车站下还有启用中的航站楼 / 出口时不能停用。
- 地点要启用，必须已经归属到一个启用中的城市，上级也必须是启用的。
- 以后区域、商品引用主数据时，在各自的任务里再加「被上架商品引用时不能停用」之类的检查。

### 机场数据来源：OurAirports

- 来源：OurAirports，<https://ourairports.com/data/>。下载地址：<https://davidmegginson.github.io/ourairports-data/airports.csv>（每天更新，约 13MB）。
- 许可：公有领域（Public Domain）。数据页原文：「All data is released to the Public Domain, and comes with no guarantee of accuracy or fitness for use.」（2026-10-07 核对）。可以自由使用、不需要署名；我们仍然在每条记录上记下来源（`places.source` / `source_ref`），接口里也返回。
- 导入命令：`pnpm masterdata:import-airports --country JP,KR`（或 `--all-countries`；`--file` 读本地文件；`--dry-run` 试运行）。
- 范围：所选国家里**有定期航班的大型、中型机场**，且有 IATA 三字码。2026-10-07 的文件里，日本 82 个、韩国 15 个，全世界 3244 个。小型机场、直升机场、水上机场、已关闭的机场不导入。
- 从数据源取的只有：三字码、英文名、坐标、国家。数据源里没有时区、没有我们的城市划分、没有航站楼。
- **导入的机场是停用的、没有所属城市**：数据源明说不保证准确，也不知道平台怎么划分城市。由平台在后台指定城市、补上其他语言的名称后再启用。这也符合需求文档「主数据变更要先复核再发布」的方向。
- 可重复执行：按数据源里的机场编号（对方承诺不变的内部编号）认同一个机场。再次导入时只新增没有的、更新英文名或坐标变了的；内容一样的不动。
- 不覆盖人工的修改：平台在后台改过英文名或坐标的导入机场（`source_overridden`）、手工录入的机场，导入都不碰；数据源里某个机场的三字码或国家变了、或已关闭，只在命令输出里提示，不自动改、不自动停用。
- 每个新增和更新都写审计日志（操作者「系统」，入口「命令行」）。整次导入在一个事务里，失败则什么都不变。
- 同一时间只允许一次导入（数据库咨询锁）；后到的那次立即提示「另一个机场导入正在运行」。
- 导入写入每个机场时核对版本号：导入运行期间平台在后台改过的机场不覆盖，列为「需要人工处理」。
- 文件必须是 UTF-8（严格解码，文件和下载两条路径都是）、LF 或 CRLF 换行；另存成别的编码、只有 CR 换行、带 NUL 字符的文件整份拒绝并说明原因。坐标只认十进制写法（含科学计数），十六进制等写法按不合格跳过。下载时边读边检查大小，超限立即中止。
- 仓库里不提交数据文件；测试用测试代码里现场构造的小样本，不联网。

### 校验

- 国家码：ISO 3166-1 alpha-2 的 249 个正式代码，外加 XK（科索沃，数据源在用）。
- 时区：IANA 时区名，必须是「大洲/城市」的写法；缩写、固定偏移、UTC 不接受。先过应用里的规则，再和数据库的时区名单（`pg_timezone_names`）逐字核对，保证大小写完全正确。
- 坐标：WGS84，经度 ±180、纬度 ±90，统一保留 6 位小数。
- 城市边界：GeoJSON Polygon / MultiPolygon，环闭合，顶点总数不超过 5000。
- 多语言文本：`ja / zh / en / ko` 四种，名称至少填一种；只有空白或零宽空格等不可见字符的等于没填。
- 关键约束在数据库里也有一份（check 约束），应用代码写错时数据库兜底。

### 列表的总数、搜索和首页统计（M1-08 补充）

- 四类主数据的列表（平台和租户）在 `items`、`next_cursor` 之外多返回 `total`：符合筛选条件的总数，和翻到第几页无关。翻页仍然用游标（按创建时间、再按编号，顺序稳定），没有改成页码：游标翻页在翻的过程中有新数据写入也不会漏行或重复；前端用 `total` 显示「共多少条」，用 `next_cursor` 判断有没有下一页。
- 关键字 `q`：编码或任意一种语言的名称里包含它，不区分大小写，`%`、`_` 按字面匹配。地址、类型等属性不在搜索范围内。
- 「包含」匹配用不上普通索引。目前主数据是千到万行的量级，顺序扫描是毫秒级，所以只为筛选和统计加了两个普通索引（迁移 0008），没有引入 `pg_trgm` 扩展。地点超过十万行或搜索明显变慢时再引入，届时新增 ADR。
- 地点列表的 `city_id=none` 表示「还没有所属城市」（导入后等待复核的机场）。
- 地点的应答里带 `city`、`parent`（所属城市、上级地点的编号、编码、名称），是读取时现查的最新值，不是存下来的副本；页面不用再取整份城市清单来对。
- 「指定城市并启用」一次完成：地点的启用接口可以带 `city_id`，城市和状态在同一个事务里写入、审计一条。只能给还没有城市的地点指定——已经有城市的要换城市仍然走带版本号的修改接口，启用接口不带版本号，不能成为绕过并发保护改城市的口子。
- 给人看的校验说明不夹接口里的英文取值（等级写「豪华」不写 luxury，车站类型写「新干线」不写 shinkansen）；国家码、编码这类本来就是代码的照写。字段取值不在清单里时的通用提示（「只能是：active、disabled」）是全部接口共用的，列的是接口取值，没有改。
- 首页统计 `GET /platform/v1/dashboard/summary` 不要求特定操作，任何已登录的平台员工都能调；但按模块裁剪——没有 `tenant.read` 的角色拿到的租户一组是 null。这样首页不会变成绕过权限看数量的口子，以后新模块照此加一组。

## 没有做的（各有后续任务或等负责人决定）

- **草稿 → 复核 → 发布**流程和 `master.changed` 事件：现在是改了立即生效 + 审计日志。双人复核要等平台的审批功能（M2-04 引入「双人复核」）。
- 国家、语言、币种、节假日、详情模版这几类主数据不在 M1-01 的范围里。国家目前只是城市和地点上的一个校验过的代码。
- 车型组的「升级关系」：现在只有等级和座位数，派车校验（M3-02）时再定是按等级顺序推导还是单独维护。
- 机场的「国际 / 国内默认免等时长」数值、集合点说明和照片：字段留给用到它们的任务（M3）。
- 导入 WKT 格式的边界、中国大陆 GCJ-02 坐标转换：目前没有这类数据。
- 新增接口的 `Idempotency-Key`：主数据靠编码唯一防重复（重复提交返回 409 `CODE_TAKEN`）。

## 理由

- **为什么不给租户角色加行级安全策略而是直接只读授权**：主数据没有「属于哪个租户」的概念，策略只能写成「全部放行」，等于没有；只给 `select` 更简单，也能被 `schema-structure.itest.ts` 的权限清单精确核对。
- **为什么导入的机场默认停用**：自动启用意味着没有人看过的数据直接出现在租户的选项里；坐标偏了会影响 300 米到达判定。多一步人工复核换来的是可控。
- **为什么不自动把机场归到城市**：数据源的 `municipality` 是自由文本（「Narita」「Tokyo」），和平台的城市划分（成田机场算东京）不是一回事，自动匹配错了比不匹配更糟。
- **为什么时区要查数据库**：运行环境对时区名不区分大小写，且会把别名换成另一个名字，单靠它保证不了「同一个时区只有一种写法」。
