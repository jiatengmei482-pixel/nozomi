# ADR 0070：包车一口价全含（不再另收高速费、停车费）

- 状态：已采纳（2026-11-09，M8-09）。业主 2026-11-09 最终决定：所有包车都是一口价，包含高速费、停车费，没有地区例外。
- 补充 ADR 0029「服务后加收」：可加收的类型从「按品类」改为「按品类 + 订单的下单时间」；包车的 `toll`、`parking` 只对分界前下的单开放。其余（超时、超公里、付费等待、加停靠点、加附加服务、凭证、异议期、扣款、审核）不变。
- 落实 ADR 0069「业主 2026-11-09 第二批确认 ①」和「B12 冲突清单」第 1、7 项；`FIXED_PRICE_RULES.charterAllInclusive` 改为 true（同一个改动里切换说法和规则，安全方案第 3 条）。
- 不改 ADR 0040（账单）：账单公式不按加收类型区分，分界前的高速、停车加收照常出账。
- 编号：写这篇时 main 上最大是 ADR 0069，这里用 0070。

## 决定

### 分界

- 常量 `CHARTER_ALL_INCLUSIVE_FROM = "2026-11-10T00:00:00+09:00"`（东京时间 2026-11-10 00:00，`packages/domain/src/fixed-price-includes.ts`），判断函数 `charterAllInclusiveFor(placedAt)`；只在这一处定义，后端规则、邮件、官网订单页、供应商后台表单都调它。
- 按**订单的下单时间**（`orders.created_at`；救援改派的单沿用原单的下单时间）判断，不按服务时间、完成时间或提交时间：报价是在下单那一刻按当时的规则报的。
- 正好在分界那一刻下的算「全含」；早 1 毫秒下的按旧规则。

### 规则（`packages/domain/src/extra-charges.ts`）

| 品类 | 分界前下的单 | 分界及以后下的单 |
| --- | --- | --- |
| 包车 | 超时、超公里、付费等待、加停靠点、加附加服务、高速费、停车费（高速、停车必须附票据） | 超时、超公里、付费等待、加停靠点、加附加服务 |
| 接送机、点对点 | 付费等待、加停靠点、加附加服务 | 同左（本来就是一口价，不变） |

- `extraChargeTypeAllowed(type, category, placedAt)`、`extraChargeTypesFor(category, placedAt)`；`ExtraChargeOrderFacts` 多一个必填的 `placedAt`。
- 拒绝仍是 `TYPE_NOT_ALLOWED`（422 `EXTRA_CHARGE_INVALID`），说明改为「这一单不能收这一项：接送机、点对点是一口价，含高速费和停车费；包车一口价已含高速费、停车费（东京时间 2026-11-10 起下的包车单），只能加收超时、超公里、付费等待、加停靠点、加附加服务」。分界后的包车单提交高速、停车时先报 `TYPE_NOT_ALLOWED`，不再报「要附票据」。

### 保留、只停用入口

- 不删数据、不删枚举值：数据库 `order_extra_charges.type` 的 check 约束、`EXTRA_CHARGE_TYPES`、OpenAPI `ExtraChargeType` 枚举都保留 `toll`、`parking`。已提交的这两类加收照原流程走完（异议、审核、扣款、出账），各端照常显示类型名「高速费（凭票实报）」「停车费（凭票实报）」。
- 只停用入口：提交接口按上表拒绝；供应商后台「提交事后加收」的类型下拉框按同一份规则（`extraChargeTypesFor`）只列这一单能收的，分界后的包车单不再出现这两项和「高速费、停车费必须附」的提示。
- 价格规则、报价、结算公式、账单都不改。

### 说法（同一来源：`fixed-price-includes.ts`）

| 位置 | 说法 |
| --- | --- |
| 新预订页「一口价包含」 | 包车也写「一口价已含所有费用（高速费、停车费等），无需另付」；下面一句「超出套餐的时长和公里服务后按实际收取：先通知您，48 小时内可以在订单页提异议。」 |
| 旧 `/book` 包车说明（`site-display.ts` 的 `priceNote`） | 「按车计价的套餐价，一口价已含所有费用（高速费、停车费等），无需另付。超出套餐的时长和公里服务后按实际收取：……」 |
| 填写订单页 | 包车总价写「总价（按车计价的套餐价，已含高速费和停车费）」 |
| 官网订单页 | 多一行「费用说明」：接送机、点对点写含所有费用；分界后下的包车单再接「超出套餐的时长和公里服务后按实际收取」；分界前下的包车单不显示这一行 |
| 客人订单确认邮件 | 「已付金额」下面一行「费用说明：……」，和订单页同一句（`fixedPriceFeeNote`）；分界前下的包车单整行不出现（可省略变量 `fee_note`） |
| 供应商「新订单」邮件 | 分界后下的包车单在「派车截止」下面加一行 `CHARTER_SUPPLIER_PRICE_NOTE`「包车报价须包含高速费、停车费：对客人是一口价全含，服务后不能再另收高速费、停车费；超出套餐的时长和公里仍按商品规则加收。」；别的单整行不出现（可省略变量 `charter_price_note`，不含规则 4 的禁用词） |
| 供应商后台：包车商品的价格规则页、服务规则 | 价格规则页（套餐那一栏上方）一条提示、服务规则「包车的超时费、超公里费在价格规则里设置」后面接同一句 |
| 司机页 | 没有「高速、停车另收」的说法，票据照片的上传入口不变（不用改） |

## 不做 / 遗留

- 生效前通知有包车商品的供应商（ADR 0069 安全方案第 2 条，后台首页提示 + 邮件）：业主这次定的分界是 2026-11-10，没有留出 14 天的通知期；供应商侧只在价格规则页、服务规则和新订单邮件里写清楚。要不要另发一次通知由业主决定。
- 部署在分界之前时，分界前那段时间下的包车单页面已写「含所有费用」、规则仍允许加收高速、停车（按下单时间）。分界是 2026-11-10 00:00（东京），部署在那之后就没有这段时间。
- 供应商账单异议的示例文字（「停车费 JPY 1,500 没有算进来」，ADR 0069 冲突清单第 5 项）不在本次；分界前的包车单仍可能有停车费加收，例子仍成立。
