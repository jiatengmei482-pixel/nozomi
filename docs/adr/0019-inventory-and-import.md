# ADR 0019：库存，以及价格和库存的 Excel 批量导入导出

- 状态：已采纳（2026-10-09，M1-05）
- 接上 ADR 0016 留给本任务的一件事：上架校验的「库存」一项改为真实判断（仍然不是必须项）。
- 补充 ADR 0001「不为读 zip 引入第三方库」：.xlsx 的读写同样自己实现，理由见「Excel 文件」一节。

## 背景

M1-05 做商品的第 ④ 步库存，和价格、库存的批量导入导出。需求见《用车报价服务平台》「5. 商品 · ④ 库存」、「14. 补充功能」里的「价格批量导入导出」、报价引擎第 9 步「库存」、数据模型的 `inventory_day`。价格日历（M1-04）已经有了；roadmap 这一条里的「价格日历、批量设置」剩下属于本任务的是库存日历和库存的批量设置。下单时的预占、扣减、释放是 M3-01，完整的报价是 M2-01，这里只把结构和判断函数留好。

## 决定

### 库存模型

迁移 `0015_inventory.sql`：`products.inventory_mode`（`unlimited` 默认 / `limited`），和租户表 `inventory_days`（商品、日期、可售总数 `total`、已预占 `held`、已售 `sold`；带 `tenant_id`、行级安全、只授权给租户角色，外键带 `tenant_id`）。

| 需求文档 | 落地 |
| --- | --- |
| 模式：无限（默认）/ 有限 | `unlimited` / `limited`。新商品是不限量 |
| 有限时按「商品 × 日期」设每日可售单数 | `inventory_days` 一个商品一天一行。日期是商品所在城市当地的**用车日期** |
| 预留按「商品 × 日期 × 车型组」的字段，二期开放 | 表里有 `vehicle_group_id`，现在恒为空；接口不接受车型组。唯一索引现在是「商品 + 日期（车型组为空）」，二期开放时换成含车型组的 |
| 批量设置：日期范围 + 数量；不填 = 清除 | `POST …/inventory/batch-set`：日期范围（两端都含）+ 可选的星期 + 数量；数量为 null = 清除 |
| 日历视图点日期直接改 | 就是开始和结束是同一天的批量设置，没有另设接口 |
| 切回无限需二次确认 | 确认由页面做；接口不拦。每天的数切来切去都保留 |
| 下单时预占，支付确认后扣减，取消或超时未支付自动释放 | M3-01。这里只定了结构和做法（见「并发预占」） |
| `inventory_day`：total、held、sold；用原子更新防超卖 | 同名三列，外加检查约束 `held + sold <= total` |

文档没写清、这里定下的：

1. **限量模式下没有设过的日子不可售。** 文档只说「有限时设每日可售单数」。没设就是没有库存，不当成不限量——否则供应商切到限量、只设了旺季几天，别的日子反而变成敞开卖。代价是忘了设的日子卖不出去，所以上架校验会提醒（见下），库存日历上「没设」和「停售」是两种不同的状态。
2. **设成 0 = 这一天停售**；清除 = 回到没设过。两者在限量模式下效果一样（都不可售），区别只在日历上怎么显示、以后切换逻辑时好不好区分。
3. **不分时段。** 文档写的是「每日可售单数」。一天一个数。
4. **按星期批量设置**是在文档的「日期范围 + 数量」上加的可选条件（空 = 每天），供「周末多放几单」这类设置用。
5. **只能改城市当地的今天和以后**，最远 730 天；一次最多 366 天。过去的日子只能看。
6. **已经有订单占着的库存不能被改没**：可售总数不能小于 `held + sold`，有占用的日子不能清除——409 `INVENTORY_BELOW_OCCUPIED`，`details.days` 列出是哪几天、各占用了多少，整批不写。可以改到正好等于占用数（这一天就售罄了）。
7. **不限量模式下也可以先把每天的数设好**，切到限量时生效。
8. **库存的修改用商品的版本号**（`If-Match`），成功后商品的版本号加一（ADR 0016「一个版本号」）。以后下单的预占不动商品的版本号。
9. **加急库存**（服务规则里的「每日加急库存」）是另一个数，属于服务规则，扣减同样在下单时做，不在这张表里。

### 并发预占（给 M3-01）

下单时预占用**一条条件更新**：

```sql
update inventory_days set held = held + $n
 where tenant_id = $1 and product_id = $2 and day = $3 and vehicle_group_id is null
   and total - held - sold >= $n
```

改到 1 行 = 占到了；0 行 = 没有库存（包括这一天根本没设）。判断和扣减在同一条语句里，数据库对这一行加行锁，并发的下单排队执行、后到的看到的是前一个提交后的数，不会超卖；不需要先 `select … for update` 再判断。支付确认是 `held = held - n, sold = sold + n`，释放是 `held = held - n`。检查约束 `held + sold <= total`、`held >= 0`、`sold >= 0` 是最后一道防线。集成测试里用 20 个并发的这条语句抢 5 单，验证了正好 5 个成功。供应商改库存（批量设置、导入）先锁住这些行再判断占用，和预占互斥。

报价时判断「有没有库存」用 domain 的纯函数 `hasInventory(mode, day, quantity)`（报价引擎第 9 步：有限库存时当日剩余 > 0）；报价只读不占。

### 上架校验的「库存」一项

不是必须项（需求文档第 7 节）。不限量 → 通过。限量、而从城市当地的今天起没有一天还有可售库存（没设、都停售、都占满）→ 不通过，原因 `NO_INVENTORY_AHEAD`——这样的商品上了架也报不出价。不通过不拦上架，列表上的概况也不受它影响。

### 批量导入导出

需求文档：下载 Excel 模版 → 填好上传 → 先显示校验结果和新增 / 修改 / 冲突条数 → 确认后写入。价格和库存各一套，流程相同：

1. **下载**：`GET …/price-rules/export`（`rows=none` 是只有表头的空白模版，不预置任何价格；默认带现有的价格）、`GET …/inventory/export`（一段日期每天一行，没设的那格空着，所以它本身就是模版）。第二张表是填写说明，列出这个商品可以填的区域（名称）、车型组（编码）。
2. **预览**：`POST …/import/preview`，请求体就是 .xlsx 文件本身。**只校验不写入**，逐行返回新增 / 修改 / 没变 / 出错 / 冲突，出错的指到单元格（`F7`）和原因；另返回文件的指纹（SHA-256）和商品现在的版本号。
3. **确认**：`POST …/import?file_sha256=…`，再上传一次同一个文件，带 `If-Match`（商品的版本号）和 `Idempotency-Key`。指纹和预览时的不一样 → 409 `IMPORT_FILE_CHANGED`；商品被别人改过 → 409 `VERSION_CONFLICT`；整份重新校验，有出错或冲突的行、或者没有要改的内容 → 409 `IMPORT_NOT_CLEAN`；全部通过才写入，**全部成功或全部失败**。

落地时定下的：

- **服务器不保存上传的文件**，所以确认时要再传一次。这样没有「待确认的导入」这种要清理的中间状态，也不存在预览和写入之间文件被换掉的问题（指纹核对）。
- **同步完成，不做异步任务。** 上限定在同步能完成的范围：文件最大 1 MB，价格一次最多 500 行（需求文档 batch-upsert 的上限），库存最多 366 行。校验和写入都在一次请求、一个事务里。
- **写入用的是和页面保存同一段代码**：价格是 M1-04 的批量保存（`applyPriceChanges`），库存是批量设置（`applyInventoryChanges`），规则完全一样（唯一性、已上架商品改完仍要满足上架条件、占用保护）。预览用的也是同一套检查。
- **价格表里怎么认行**：「价格编号」一列有值 = 修改那一条（导出的行带着它），空着 = 新增。导入不能删除价格。区域按名称认（任何一种语言的名称，同一个供应商同一个城市里区域不重名，ADR 0015），车型组按编码认。
- **金额填主单位**（日元整数、美元两位小数），按字符换成最小货币单位的整数，全程不经过浮点数；小数位超过币种精度的报 `PRECISION` 到那个单元格，不四舍五入。Excel 存成科学计数的数字、带千分位的文字都认。导出的金额同样是主单位。
- **日期**可以写 `2026-10-01` / `2026/10/1`，也认 Excel 把日期存成的序号。
- **带公式的单元格**报错（`FORMULA`），不取它缓存的值——缓存值可能是旧的，也避免「看起来是数、其实引用了别的表」。
- **审计**：价格导入逐条记（每条变了的价格一条，带前后值，和页面批量保存一样）；库存导入和批量设置各记一条汇总，里面有变了的每一天的前后值（库存导入另带文件指纹）。两种做法都能从日志追到每一处改动；库存一次可以改几百天，逐天各记一条没有必要。
- 权限：导出要 `product.read`，预览和导入要 `product.manage`（需求文档第 11 节：商品价格角色管价格和库存）。

### Excel 文件：自己读写，不引入第三方库

调查过的做法：引入 `exceljs`（体积大、依赖多，近年维护放缓）、SheetJS `xlsx`（npm 上的版本停在有已知漏洞的旧版，新版要从它自己的地址装）、或自己实现。.xlsx 是 zip 里的几份 XML；我们只需要「一张表、文字和数字单元格」这一小部分，项目里已经有只读的 zip 实现（ADR 0001、ADR 0014）。所以在 `apps/api/src/integrations/xlsx.ts` 自己实现了最小的读和写（约 300 行），不引入依赖。和 openpyxl 互相读写核对过（它读得出我们写的，我们读得出它写的）；**没有在真实的 Excel / WPS / Numbers 上验证过**，部署后要用真实软件走一遍。

上传的文件是不可信的输入，防护：

| 风险 | 做法 |
| --- | --- |
| 超大文件 | 请求体上限 1 MB（超过是 413，读之前就拒绝） |
| zip 炸弹 | 每份 XML 解压时限制输出最多 16 MB（解压过程中就截断，不看压缩包自报的大小）；最多 5000 行、60 列，单元格最多 2000 字，共享字符串最多 20 万条 |
| 路径穿越 | 压缩包里的文件名只用来在包内查找，从不当作磁盘路径；全程不写磁盘。工作表的位置如果指向 `xl/` 之外（`../`、绝对地址）直接拒绝 |
| XML 实体（XXE、实体炸弹） | 不解析 DTD；文件里出现 `<!DOCTYPE` / `<!ENTITY` 直接拒绝；只认五个预定义实体和数字字符引用 |
| 解析卡死 | 扫描 XML 的正则写成每个位置只有一种匹配方式，用时和长度成正比（有针对性的测试） |
| 公式注入（导出的文件被 Excel 打开） | 以 `=` `+` `-` `@`、制表符、回车开头的文字前面加单引号；读回来时去掉。导出从不写公式 |
| 读到公式 | 标成公式，由导入报到那个单元格，不取值 |

### 兼容别的软件存盘的文件（补充）

供应商拿到模版后会用 Excel、WPS、LibreOffice 填了再存，文件的写法和我们导出的不一样。读取时：

| 写法 | 做法 |
| --- | --- |
| 数据不在第一张表、有隐藏的表 | 先找叫「价格」/「库存」的那张（导出时就叫这个名字），没有才读排第一的那张 |
| 工作簿、工作表、共享字符串不在惯用的位置 | 按包里的关系文件去找（`_rels/.rels` → 工作簿 → 它的关系文件），相对和 `/xl/…` 的绝对写法都认；指到 `xl/` 之外的拒绝，指向外部的关系忽略 |
| 日期存成序号 | 1900 纪元（默认）和 1904 纪元（工作簿声明了 `date1904`）都认；写成文字的 `2026-10-01`、`2026/10/1`、`2026.10.1`、带零点时间的也认 |
| 富文本、注音、行内字符串、公式的文字结果 | 取文字；富文本各段拼起来，注音不取 |
| 数字存成文本、带千分位显示格式的数字 | 按单元格里的字符认，不经过浮点数 |
| 合并单元格、隐藏的行列、只有样式的空行 | 合并的只有左上角有值，其余当作空；隐藏的行照样读（藏起来不等于删掉）；行尾的空行忽略 |
| 样式、列宽、冻结、数据验证、打印设置、`docProps`、主题、`calcChain` | 不读，不妨碍 |
| 压缩包带数据描述符、ZIP64、任意压缩级别或不压缩、带注释 | 大小和位置一律以目录为准 |

怎么验证的：开发时用 Python 的 openpyxl 生成了带以上各种特征的文件（含 1904 纪元、只写模式的行内字符串、ZIP64、数据描述符），全部能读对；我们导出的文件 openpyxl 能读回。这一步是一次性核对，不在仓库里留 Python 依赖和二进制样本；仓库里的测试（`integrations/xlsx-compat.test.ts`）按 Excel 存盘的样子在测试代码里现场拼出同样特征的包来读，并逐项核对导出的文件具备 Excel 要求的部件（`[Content_Types].xml` 的声明、根关系、工作簿和它的关系文件、样式表里的内置样式和计数、工作表各部分的先后）。

**没有验证的**：本机拿不到 LibreOffice，也没有真实的 Excel 和 WPS。「导出的文件在这三个软件里能直接打开、不提示修复」和「它们另存后的文件能导入」仍要部署后人工走一遍。

### 导入结果里带的内容（补充）

- 预览的每一行带读到的内容（价格：区域、车型组、方向 / 套餐、主要价格、生效起止、状态；库存：日期、单数），新增的行也有——页面不用再去解析文件。
- 冲突的行在 `conflicts_with[]` 里写明和谁冲突：同一个文件的第几行，或已有的哪条价格，都带区域、车型组、方向 / 套餐、生效起止。已有的价格只在这个商品之内找。
- 库存里已经过去的日子：和现在的值一样算「没变」（导出一整个月、只改后半个月，不会被前半个月挡住）；改了才报错。
- 确认导入被拒（`IMPORT_NOT_CLEAN`）时，`details.preview` 就是完整的检查结果，和预览接口的返回一样。
- 单元格问题的 `reason` 是固定的一组（写在 openapi 的 `ImportCellIssue` 里），`message` 是给供应商看的中文，说明怎么改。

## 本期不做

| 内容 | 去向 |
| --- | --- |
| 下单预占、支付扣减、取消 / 超时释放、`SOLD_OUT` | M3-01（做法见「并发预占」） |
| 报价时校验库存 | M2-01（用 `hasInventory`） |
| 按车型组的库存 | 二期（需求文档）；字段已预留 |
| 加急库存的扣减 | M3-01 |
| 区域的批量导入（`/areas:import`，异步任务） | 需要新任务（ADR 0015 的「本期不做」） |
| 调价规则的导入导出 | 需求文档没有要求 |
| 导入时删除价格 | 不做：在页面上删 |
| 在真实的 Excel / WPS / LibreOffice 上验证导出的文件和各软件存盘的文件 | 部署后人工走一遍（见「兼容别的软件存盘的文件」）；发现读不了的写法再补 |
