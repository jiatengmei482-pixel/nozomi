# ADR 0066：整站美化（M6）的视觉规范

- 状态：已采纳（2026-11-08，M6-01）。业主指示新建 M6「整站美化」；按「只改视觉和排版，不改业务逻辑、接口和文案意思」执行。
- 补充 ADR 0011（前端）和 `docs/design/`：令牌体系、亮暗两套主题、对比度校验、360px 不横向滚动、键盘可用这些规则全部保留，本篇只调整取值、加几个令牌和两种共用样式。
- 编号：写这篇时 main 上最大是 ADR 0065，这里用 0066。

## 背景

M0–M5 的界面按「稳重的工具感」做：冷灰加一个亮蓝主色，不用阴影、不用品牌图形。功能齐了以后，业主要整站统一美化：

- NOZOMI 品牌要看得出来；
- 官网面向日本客人：简洁清楚、价格醒目、步骤简单、看着可信；
- 亮色、暗色两套都要好看；
- 无障碍和手机可用不能退步，所有测试照常通过。

## 决定

### 1. 品牌

- **标志**：圆角方块里一条「N」形路线，起点、终点各一个圆点，意思是「从这里到那里」。用内联 SVG 画（`apps/web/src/components/Brand.tsx`），只用令牌上色，不用外部图片和字体。标志是装饰（`aria-hidden`），旁边的字标「NOZOMI」才是可读的名字。
- **字标**：「NOZOMI」，`font-weight-heavy`、字距 0.14em，系统字体。
- **品牌色带**（新令牌 `color-brand` / `color-on-brand` / `color-on-brand-muted`）：深靛色，只用在登录页顶部、官网页眉、邮件页眉。色带上只放品牌和页面名称，不放按钮、输入框、其他链接（品牌本身做成的回首页链接除外，聚焦环用 `color-on-brand`，M6-05）；必须放控件时（如登录页的主题切换）给控件垫一块 `bg-surface` 的小底板。这是 README「层次靠背景色差」的一个有限例外，不是渐变，也不是插图。

### 2. 颜色

- 主色从亮蓝 `#1B4FD0` 换成偏靛的「藍色」：亮色 `#2A45B0`，暗色 `#4466E0`；链接和聚焦环跟着换（暗色 `#A9BBFF`）。理由：靛蓝在日本是常见的「可靠、正式」的颜色，比亮蓝更沉稳；两套主题的对比度都比原来高（主按钮文字亮色 6.83 → 8.15）。
- 红、绿、橙、浅蓝四种状态色不变，仍然只表示状态。
- 页面底色、文字色、边框色不变，避免一次性改动太多，后台长时间使用的观感保持稳定。
- 所有搭配仍由 `docs/design/contrast-check.mjs` 校验（新增两组品牌色带的搭配），`01-tokens.md` 的对比度表由脚本结果生成，单元测试逐行比对。

### 3. 形状和层次

- 圆角放大一级：`radius-md` 6 → 8px（按钮、输入框），`radius-lg` 8 → 10px（卡片），`radius-xl` 12 → 16px（对话框、登录卡片）。显得柔和、亲切，不改变任何尺寸。
- 新增 `shadow-card`（很轻的两层阴影），只给官网报价卡片、后台首页入口卡片，并且同时保留 1px 描边（暗色下阴影几乎看不见，靠描边）。登录卡片压在品牌色带上，要更明显的层次，用 `shadow-md`。后台的表格和普通卡片仍然不用阴影。
- 阴影改成偏蓝的冷色调，和主色协调。

### 4. 价格

- 新增 `font-size-5xl`（36px）和 `font-weight-heavy`（700），只用于价格数字和品牌字标。
- 共用样式 `.price`（`apps/web/src/styles/brand.css`）：数字大、粗、等宽（`tabular-nums`）；币种小一号、次要文字色，跟在数字后面同一基线。三个尺寸：`.price--sm`（列表）、默认（卡片）、`.price--lg`（应付总额）。
- 金额的格式化和取整仍走 `packages/domain/src/money.ts` 和现有的显示函数，`.price` 只管样式。

### 5. 字体

不变：只用系统字体，不加载网络字体；日文内容标 `lang="ja"` 用 `font-family-sans-ja`（Hiragino、Yu Gothic、Meiryo、Noto Sans JP）。

### 6. 分批

| 任务 | 范围 |
| --- | --- |
| M6-01 | 本篇、令牌、共用样式（品牌、价格）、登录类页面（`/platform/login`、`/login`、两步验证、设置密码，共用 `AuthLayout`） |
| M6-02 | 后台框架（侧栏、顶栏带品牌）和通用组件（按钮、表单、表格、状态徽标、卡片、对话框） |
| M6-03 | 运营后台、供应商后台各页面的细节 |
| M6-04 | 司机页 |
| M6-05 | 官网预订页、查订单页 |
| M6-06 | 邮件模板 |
| M6-07 | M6 验收 |

每批一个 PR；每批都要：亮、暗两套看过；360px 不横向滚动；axe 无障碍检查通过；所有单元、集成、端到端测试通过；不改接口、业务逻辑和文案意思。

## 后果

- 因为令牌是全站共用的，M6-01 合并后后台各页的主色和圆角就会跟着变（只是颜色和圆角，排版不变）；各页面的细节在后续批次里调。
- 端到端测试里有读 `tokens.css` 页面底色做比对的，底色没改，不受影响。
- 如果以后要换回原来的主色，只改 `tokens.css` 和 `01-tokens.md` 两处，再跑一次 `contrast-check.mjs`。
