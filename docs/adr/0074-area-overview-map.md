# ADR 0074：区域地图（总览、重叠检查、导入导出）——继续用 Leaflet 和开源底图

- 状态：已采纳（2026-11-09；M8-18 实施）。
  - 业主 2026-11-09：供应商要在一张地图上看到自己全部的报价区域，检查覆盖范围和重叠，并能修改；参考另一个平台的「固定費率區域」页面（左边列表、右边大地图、上面搜地址、右上「添加区域」、下面「拖放 .geojson 或点击导入」）。
  - 业主 2026-11-09（同日改定）：**这一期只用现有的免费开源底图**（Leaflet + 配置的瓦片）；谷歌地图做底图推迟，以后是否另建一把限定域名的浏览器密钥由业主决定。
- 补充 ADR 0011（前端不加载站外资源）、ADR 0015（区域与底图）、ADR 0017（地图画布的分工）：**都不改**。内容安全策略不动。
- 编号：写这篇时 main 上最大是 ADR 0073（M8-11 / M8-15），这里用 0074。

## 决定

1. **新增「区域地图」页，不改编辑器。** 供应商后台 `/areas/map`、运营后台 `/platform/areas/map`（只读）。画图、拖点、加点删点、改名、启用停用、保存前的校验（自相交、少于 3 个点）、离开前提醒、草稿，全部沿用现有的区域编辑页（`AreaEditorPage`）——总览页上的「添加区域」「编辑」直接进编辑页，保存或取消后回到区域地图。停用 / 启用 / 删除用区域列表同一套确认（`useAreaActions`）。
2. **接口**：
   - `GET /tenant/v1/area-map`（`area.read`）：令牌所属供应商的区域连同全部图形，每一项 = 区域详情 + `last_editor`（最近一次是谁、什么时候改的，取自审计日志里这个区域的最后一条；只给账号现在的名字，不给邮箱）。不认识的查询参数一律 400（尤其是 `tenant_id`）。
   - `GET /platform/v1/area-map`（`product.read`，和看供应商商品同一个权限）：全部供应商，按供应商、城市、状态筛，只读；`GET /platform/v1/map/config`（任何平台员工）：和供应商后台同一份底图配置。
   - 一次最多 300 个区域（按最近修改从新到旧），超过时 `truncated: true`，页面提示按城市 / 供应商筛。不分页：重叠要在同一批区域之间算。
3. **重叠的定义**（写进 `@nozomi/domain` 的 `findAreaOverlaps` 和 `tenant-areas.md` 第 19 节，页面文案按它）：
   - 一个区域「真正报价的范围」= 它的营运区合起来，减去**它自己的**禁行区（禁行区只管所在的区域，`tenant-areas.md` 第 17 节第 2 条）。所以区域甲的禁行区压在区域乙上，**不是**重叠（M8-36 起报价口径改了：点落在商品任何一个报价区域的禁行区里，整个商品不报，见 ADR 0085）；
   - 两个区域重叠 = 两者真正报价的范围有公共部分，且面积不小于 100 平方米（手画相邻区域时边上难免的细缝不提示）；只是边挨着边不算；
   - 只看**启用中**的区域（停用的不参与报价）；只看**可能被同一个商品同时选上**的两个区域：业务类型相同，或其中一个是「通用」；
   - 运营后台一次看几家时，只在同一个供应商的区域之间算（报价取最低是在一个供应商里比）。
   - **重叠只是提醒，不拦保存**：今天的规则是一个位置落在同一供应商的几个区域里时，每个区域各算一遍价，取最低。
4. **重叠在浏览器里算，用纯函数。** `packages/domain/src/area-overlap.ts`：竖条分解（slab decomposition）——把相关的边的端点、两两交点的经度排序，相邻两个经度之间的竖条里边互不相交，按中线处的纬度排好，自下而上数每块图形的进出，得到一串梯形，每个梯形属于哪几个区域是确定的。结果精确（误差只来自浮点数），给出每对区域的重叠面积和重叠部分的形状（梯形，同一竖条里同一组区域的相邻梯形合成一块，地图上画成一条路径，没有接缝）。圆早已存成 64 边形（ADR 0015），和多边形一样处理。单元测试 18 条，含凹多边形、斜边相交、圆与圆和解析值的对比、禁行区挖掉一部分、业务类型、停用、细缝。
   - **限制**：经纬度当平面（和现有的「点在不在区域里」一致），面积按竖条中线的纬度换算，几十公里的区域误差在千分之几；不支持跨 180° 经线（区域本来就不允许）；找交点是「按最小经度排序 + 扫描」，最坏情况是边数的平方——几十个区域、几千个点在毫秒级，几百个区域、每个几千点且彼此大面积交错时会到秒级，所以只在取回数据时算一次，不在拖动中重算。真要更大规模时改到后端算并缓存（不影响页面）。
5. **底图仍是 Leaflet + 配置的瓦片**（ADR 0015、0017），理由不变：打包进产物、不要密钥、内容安全策略只多一个瓦片图片来源、图形是 SVG 能直接用设计令牌和亮暗主题。区域地图的图形层只通过一个「地图底」的接口（`apps/web/src/lib/map-surface.ts` 的 `MapSurface`：坐标换像素、点击换坐标、移动视野、底图出没出问题）和底图打交道，现在只有 Leaflet 一个实现；测试用一个假的实现。编辑器（`AreaMap`）这次不动。
6. **按地址搜索这一期不做**，地图上方的定位框能搜平台录入的机场、车站、地标（`/tenant/v1/master/places`、运营后台 `/platform/v1/master/places`），或输入「纬度, 经度」。原因：现有的谷歌地址代查（ADR 0044、0069 B1）是给官网客人用的，它的每日上限（`GOOGLE_PLACES_DAILY_LIMIT`）全站共用，按 IP 限速；让后台也用，供应商画区域时的搜索会吃掉客人下单的额度，需要先定一份单独的预算和限速（按账号），这是业主的费用决定。到时加一个 `/tenant/v1/places/search`，复用同一个服务、另起一组按账号的限速，接进同一个定位框，页面别的部分不改。
7. **导入、导出**：
   - 导出：当前列表里的区域（或选中的一个）存成 GeoJSON `FeatureCollection`，一块图形一个要素，`properties` 带区域编号、名称、城市编码、业务类型、状态，和图形的 `kind`、`name`、`label`——和编辑器「复制坐标」同一个写法，所以导出的文件能原样导入，营运区 / 禁行区和备注名都带回来。只在浏览器里生成，不经服务器。
   - 导入：区域地图下方「拖放 .geojson 文件到这里，或点击导入」，文件只在浏览器里读（≤ 2 MB，只认 .geojson / .json）。一次导入成**一个新区域**：带着文件内容进新增区域页，内容已经放在「粘贴坐标」里，由同一套解析（`parseShapeText`）、同一套出错说法识别；用户选城市、起名字、核对后保存，校验和平时新增完全一样。一个文件里有几个区域（我们自己导出的带 `area_id`）时就地说明「一次只能导入一个区域」。需求文档里的 `/areas:import` 接口至今没有做，这次也不用它。
8. **「在地图上查看」对话框**（`apps/web/src/pages/areas/AreaMapDialog.tsx` 的 `AreaMapDialog` / `AreaMapButton`）：给一组区域编号，画出这几个区域和它们之间的重叠，只看不改；打开时才取数据。已接到商品第 ① 步的「服务区域」；价格页的区域选择（M8-12）照同样的方式接。
9. **颜色**：每个区域一种颜色，按列表顺序轮流用 5 个现有令牌（`primary`、`success-text`、`info-text`、`text-secondary`、`border-strong`）；红色留给禁行区，警告色留给重叠。设计规范没有成组的「分类色」，**建议美工补一组 8 色的分类色令牌**（亮暗两套、和 `bg-surface` 的对比度达标），补了以后只改 `areas.css` 的 `area-color--N` 几行。颜色之外，每个区域在地图上有名字标签、在列表里有文字，不靠颜色区分。

## 以后换成谷歌地图做底图要做什么（这次不做）

业主选了开源底图。以后要换成谷歌地图，至少要：

1. **另一把浏览器用的密钥**：在谷歌云控制台新建，只启用 Maps JavaScript API，按 HTTP 来源（referrer）限定为 `nozomi.moveglobal.io`（测试环境另加测试域名）。它是「发给浏览器、靠域名限制保护」的密钥。
2. **单独的设置卡片**：运营后台「系统设置 → 系统状态 → 第三方密钥」里另加一项，和现有的 `google_maps` 分开存（同样加密存库、页面只显示有没有填和末 4 位、填写更换清空都记审计且不记原文，ADR 0041）；只发给登录后要画地图的后台页面（经已登录才能调的配置接口），不进日志、代码、测试和提交记录。
3. **现有的服务器密钥 `google_maps` 永远不能到浏览器**：它没有域名限制，到了浏览器等于公开；浏览器密钥没填时不能拿它顶替。
4. **自动退回开源底图**：没有浏览器密钥、脚本加载失败、超时、密钥被拒（`gm_authFailure`）时，退回现在的 Leaflet 底图，只给一句不打扰的说明。图形层通过 `MapSurface` 接口工作，只要再写一个谷歌的实现（用 `OverlayView` 的投影换算像素），重叠、选中、编辑的逻辑都不用改。
5. **内容安全策略要改**（是对 ADR 0011 的有意改动，要另写一篇 ADR）：后台页面的 `script-src`、`img-src`、`connect-src` 要放行谷歌的来源（`maps.googleapis.com`、`maps.gstatic.com` 等）；谷歌的脚本会插入内联样式，`style-src 'self'` 下要么接受它显示不全，要么改成按次生成的 nonce（反向代理要配合）。官网页面不放行。
6. **费用**：Maps JavaScript API 按地图加载次数计费，要定预算和告警。

## 后果

- 好处：供应商一眼看到全部区域和重叠；重叠的定义和报价规则一致（禁行区只管自己、停用的不算、业务类型不相容的不算）；没有新增第三方依赖、没有改内容安全策略；以后换底图只换 `MapSurface` 的实现。
- 代价：重叠在浏览器里算，区域很多很复杂时会慢（见第 4 条的限制）；每个区域的颜色只有 5 种，区域多时会重复（靠名字标签和列表区分）；不能按地址搜。
