# ADR 0079：新预订页改成四步、右侧栏逐步累积；官网页面宽度三档

- 状态：前端已实施（2026-11-11；M8-27、M8-28，同一分支 `m8-27-book-new-four-steps`，负责人要求一起合并）。第 5 节后端、第 6 节令牌、第 7 节规范由对应角色补上后才能合并。
- 补充 ADR 0069（预订页重新设计）的「修正版 v2」页面结构、ADR 0072（路线静态图）、ADR 0073（区域价显示）、ADR 0076（人工报价）。**都不改**：报价规则、按两个坐标报价和包车询价接口、下单和付款接口、人工报价、验收通道（官网请求仍带同源凭据）。

## 背景

负责人要求 `/book/new` 改成分步填写（他说「三步」，列出来是四步，按四步做），右边一个从头到尾都在的侧栏，逐步放上客人已经确认的内容；另外要在运营后台能调官网的页面宽度（标准 / 较宽 / 最宽），平板和手机不受影响。
原来的页面是电脑单页（行程、车型、联系方式三块在左，右侧栏有附加服务、合计、去付款）、手机三步。

## 决定

### 1. 四步，每步一个网址

| 步骤 | 内容 | 「下一步」前检查 |
| --- | --- | --- |
| 1 行程 | 顶部「接送机 / 点对点 / 包车」标签；出发地、目的地（包车：上车地点、下车地点、套餐时长）；日期、时间（接机是航班落地时间）；乘客 / 行李 | 两端、日期、时间、包车时长（同原来手机第 1 步） |
| 2 车型和价格 | 现有车型列表、车内示意图、附加服务（从右侧栏移到这里，选了车型才出现）、「一口价包含」；报不出价时只有人工报价那一块（M8-21b） | 选了车型 |
| 3 乘客信息 | 乘车人、邮箱、手机、接机的航班号（必填）和举牌姓名（选填）、即时通讯、给司机的备注 | 同旧下单页的校验（`validateOrderForm`），不含「同意保存银行卡」 |
| 4 核对并付款 | 行程、车型和价格（车费、附加服务差额、合计、参考价）、乘客信息三块各带「修改」回到那一步；取消规则；同意保存银行卡；去付款 | 下单时再查一遍第 3 步的字段，有问题回第 3 步标红 |

- 网址 `?step=2`…`?step=4`（第 1 步不写），换步加一条历史记录，浏览器后退 / 前进就是上一步 / 下一步；其余链接参数（from、to、date…）原样保留。
- 从网址、前进键打开还到不了的步骤（行程没填好、没选车型、乘客信息没确认），页面用「替换」把网址改成能到的最后一步，不自己往后跳。链接参数还在读地点时不改。
- 链接给齐了两端和时间时打开就是第 2 步（原来只有手机这样）。
- 所有填过的内容都在页面状态里，换步不丢。换步时焦点移到那一步的标题。
- 步骤条在最上面：已完成的步骤是按钮（读屏名「第 N 步：名称（已完成，回到这一步）」），当前步骤 `aria-current="step"`。
- 填齐行程就在后台报价（沿用原来的停顿后报价），到第 2 步时价格多半已经出来了。

### 2. 标签和两端对不上：只提示，不挡

接送机、点对点都按两个坐标报价，服务端认机场、接机 / 送机 / 点对点（ADR 0069 A1）。标签只决定说法和提示：
选了「接送机」但两端都不是机场 →「出发地和目的地都不是机场，这是点对点行程。」+「改选「点对点」」；选了「点对点」但有一端是机场 →「有一端是机场，这是接送机行程。」+「改选「接送机」」。
有没有机场先看报价认出来的行程类型，没有报价时看地址搜索给的类型。不挡「下一步」，报价照常。没有给 `mode` 的链接按两端有没有机场选标签；`mode=airport|p2p|charter` 直接选。
只有可订城市里有的品类才出现对应标签，少于两个时不出现标签条。

### 3. 右侧栏（≥ 1024px）和手机、平板的摘要条

- 右侧栏四步都在：最上面是路线图（M8-10 静态图，Leaflet 兜底，包车和取不到路线时没有），下面按步骤追加：到第 2 步起有「行程」，选了车型有「车型和价格」（一个价：合计；含公里数那一句、「含区域加价，已算在这个价格里」），到第 4 步有「乘客信息」。第 1 步只有一句「每确认一步，这里会加上那一步的内容。」
- 车费 / 附加服务差额 / 参考价 / 取消规则 / 去付款从右侧栏移到第 4 步正文（右侧栏只放一个价格，不放操作）。
- < 1024px：单栏，右侧栏变成步骤条下面吸顶的「行程摘要」条（按钮 `aria-expanded`），收起时一行写「行程 · 两端 · 价格」，展开是同样的内容。第 2 步选了车型后底部固定条「车型 · 一口价 [下一步]」照旧。

### 4. 举牌姓名（暂行做法）

订单接口没有举牌姓名这一栏，本任务不改接口：前端把它写在给司机的备注最前面「举牌姓名：XXX」（换行后是客人写的备注），两者加起来不超过备注的上限，超了在备注栏提示。
**提议**（另立后端任务）：订单加 `sign_name`（接机才有），司机页和供应商订单详情单独显示；有了以后前端改成单独的字段，不再拼进备注。

### 5. 页面宽度：接口约定（后端按这个做）

- `GET/PUT /platform/v1/site-settings` 加 `page_width`：`"standard" | "wide" | "full"`，没设过是 `standard`。`PUT` 里**可选**，不给是不改（只改号码的老请求不受影响）；别的值 400 `VALIDATION_FAILED`（路径 `/page_width`）。权限不变：看 `site_settings.read`，改 `site_settings.manage`（只归超级管理员）。版本号、If-Match 同现在。审计 `site_settings` / `update` 带前后的 `page_width`。
- `GET /site/v1/config` 加 `page_width`（同样三个值）。
- OpenAPI：两处 schema 加这一项；前端对账表（`MANUAL_QUOTE_SCHEMA_FIELDS.SiteSettings`、`SITE_SCHEMA_FIELDS.SiteConfig`）随后加上，类型里的 `page_width?` 改成必有。
- 前端已按这个约定写好：运营后台「系统设置 → 官网设置」多一张「页面宽度」卡片（三个单选 + 保存，保存时号码原样带回）；官网外壳 `.site` 上写 `data-width`，所有官网页面（首页、`/book/new`、下单页、订单页）跟着变。自己不读配置的页面（下单页）直接打开时，外壳补读一次配置。

### 6. 页面宽度：设计令牌（设计角色按这个加）

样式只引用令牌（`styles.test.ts`），前端已经按下面的名字引用，需要在 `docs/design/tokens.css` 的布局令牌里加四个：

| 令牌 | 值 | 用在 |
| --- | --- | --- |
| `--layout-site-max-width` | 1200px | 官网正文、顶栏、页脚的最宽（标准档） |
| `--layout-site-max-width-wide` | 1440px（可以写成 `var(--layout-content-max-width)`） | 较宽档 |
| `--layout-site-max-width-full` | 1920px | 最宽档（两侧仍留 `space-6`） |
| `--layout-site-aside-width` | 380px | 预订页右侧栏宽度：页面变宽时只有左边变宽 |

`site.css` 在 `.site[data-width="wide|full"]` 上把 `--layout-site-max-width` 换成对应档（同现有的在 `.site` 上改 `--control-font-size` 的做法）。原来官网用的 `layout-reading-max-width`（960px）只在后台的阅读页继续用。
平板、手机不受影响：三档都比 1024px 宽，窄屏本来就是 100% 宽、单栏。

### 7. 规范要跟着改的地方（设计角色）

`docs/design/pages/site-booking-v2.md` 第 3.1 节（布局）、3.2 节（「接送 | 按小时包车」两段改三个标签；航班号移到第 3 步）、4.5 节、第 7、8 节（「怎么联系你」改名「乘客信息」、右侧栏内容）按本 ADR 第 1–4 节更新；`03-layout.md`「官网下单页」的最宽写成 `layout-site-max-width`；`platform-settings.md` 第 9 节加「页面宽度」卡片（本 ADR 第 5 节的文字）。

## 后果

- 电脑上从「一页看完」变成「一步一屏」，多点几次「下一步」；换来每一步内容少、能用网址回到某一步、右侧栏始终看得到确认过的内容。
- 第 4 步才勾「同意保存银行卡」，离付款最近。
- 页面宽度是全站一个值，不能按页面分别设置。
