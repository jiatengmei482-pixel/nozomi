# ADR 0017：前端的地图——用 Leaflet 管底图，图形自己画

- 状态：已采纳（2026-10-08，M1-02）
- 补充 ADR 0011（前端）和 ADR 0015「地图底图」一节：那边定了底图配置从哪来、内容安全策略怎么放行；这里定前端怎么用它。

## 背景

区域页面（`docs/design/pages/tenant-areas.md`）要在地图上看、画、改营运区和禁行区。前端此前没有任何地图相关的代码，也没有运行时依赖之外的第三方库。页面规范第 13 节推荐 Leaflet，并要求：不从 CDN 加载、颜色只用设计令牌、底图出不来时页面照常能完成全部操作。

## 决定

### 依赖

- 新增运行时依赖 `leaflet@1.9.4`（BSD-2-Clause，无子依赖），开发依赖 `@types/leaflet`。版本写死，升级单独做。
- **打包进产物**，不从 CDN 加载；产物仍然只有一个 JS 和一个 CSS（`e2e/build-output.spec.ts` 检查）。地图只有供应商后台的区域页用，现在不拆包：拆了就多出一个文件，要同时改产物检查和缓存规则，等体积成为问题时再做。
- **不引入 Leaflet 自带的样式文件**（`leaflet/dist/leaflet.css`）：里面有写死的颜色，还带图层控件、标记图标的图片（会变成 `data:` 地址，被内容安全策略的 `img-src` 拦掉）。我们只用到它的瓦片层，需要的几条定位规则（瓦片和各层绝对定位、瓦片加载完才显示、触屏的 `touch-action`）抄在 `apps/web/src/styles/areas.css` 里，没有颜色。
- Leaflet 的代码里有它自己的官网地址 `https://leafletjs.com`（署名控件的前缀链接）。我们不用它的署名控件，这个地址不会出现在页面上、也不会被请求；`build-output.spec.ts` 的「库自带的网址」名单里加了这一条。

### 分工：Leaflet 只管底图，图形是我们自己的 SVG

| 谁 | 管什么 |
| --- | --- |
| Leaflet | 加载瓦片、平移、缩放、把屏幕位置换算成经纬度 |
| `lib/area-editor.ts`（纯函数 + reducer） | 图形的全部状态和操作：加、删、挪点、插点、圆、撤销重做、校验、本地自测。不依赖地图库，不依赖浏览器 |
| `pages/areas/AreaMap.tsx` | 一层盖在地图上的 SVG：按 Leaflet 给的换算把图形画出来；把指针事件翻译成上面那套操作 |
| `pages/areas/ShapeList.tsx` | 图形列表和坐标表：同一套操作的另一种入口，不需要地图 |

这样分的原因：

- **颜色跟着令牌走**。图形、控制点、图例都是普通的 SVG 元素加类名，颜色写在样式文件里（`stroke: var(--color-…)`），主题切换自动跟着变。用 Leaflet 自己的矢量图层就得在脚本里给颜色值。
- **没有地图也能用**。图形的状态不在地图库里，所以底图没配、加载失败、地图库初始化出错，坐标表、粘贴、自测、保存都不受影响。没有配置底图时根本不创建地图。
- **好测**。reducer 和校验是纯函数，用单元测试覆盖；组件测试里底图配置是「没有」，不需要在模拟的 DOM 里跑地图库；地图上的鼠标操作由端到端测试在真实浏览器里做。
- 不用 Leaflet 的绘图插件（Leaflet.draw、Geoman）：它们各带一套样式和图标，颜色、文案、无障碍都不归我们管。

SVG 层是地图容器的兄弟节点，默认不接指针事件（点击落到地图上，由 Leaflet 换算位置后交给我们判断点中了哪块）；只有控制点接指针事件，拖动时用指针捕获，不会带着地图一起动。缩放动画关掉了（`zoomAnimation: false`）：否则动画期间 SVG 和底图对不齐。

禁行区的斜纹：页面规范写的是 `fill: url(#图样)`。样式检查（`styles.edge.test.ts`）规定 `fill` / `stroke` 只能是颜色令牌，所以改成等效的画法——一组铺满画布的斜线（颜色用令牌），用 `clip-path` 裁到图形内部。画出来一样，规则不用开口子。

### 底图

- 瓦片地址、暗色地址、缩放范围、瓦片边长、署名、来源页策略全部来自 `GET /tenant/v1/map/config`（ADR 0015），前端不写任何底图地址。
- `tiles` 是 `null`：不创建地图，原位置一句说明；画图工具禁用，其余照常。
- 瓦片取不到（连续失败且一张都没成功）：地图上一条提示，图形、控制点照常显示、照常能改。
- 暗色主题：有暗色地址就用它；没有就只给底图那一层加滤镜压暗（页面规范第 20 节的写法），图形和控件不加。
- 署名显示在地图右下角，内容来自配置；和图例放不下一行时署名折到图例下面，不互相盖住。
- 请求瓦片时带的来源页按配置的 `referrer_policy` 设在瓦片图片上（Leaflet 的 `referrerPolicy` 选项）；全站的 `no-referrer` 不变。
- 触屏（`pointer: coarse`）上关掉单指拖动地图：一根手指滑动是滚动页面，两根手指缩放地图。

### 内容安全策略

不变：`style-src 'self'`、`script-src 'self'`（加内联脚本的哈希）。Leaflet 定位瓦片用的是脚本设置元素的样式属性（CSSOM），不受 `style-src` 限制；它不往页面里插 `<style>`。`img-src` 只多放行瓦片的来源（ADR 0015）。

`vite preview`（端到端测试用）读环境变量 `NOZOMI_MAP_TILE_CSP_SOURCES`，把里面的来源交给同一个 `contentSecurityPolicy()`；正式环境走 ADR 0015 的 `MAP_TILE_CSP_SOURCES`。

### 测试

- 端到端测试从不请求真实的底图服务。`e2e/global-setup.ts` 在本机起一个假瓦片服务（对任何瓦片地址回一张 1×1 的图，并记下收到的请求数和来源页），API 的底图配置指向它，预览服务器的内容安全策略放行它——所以「策略会不会把底图拦掉」「来源页带得对不对」都是真的在测。
- 「没有配置底图」的用例：另起一个不配底图的 API 进程（同一个库、同一把签名密钥），那个页面的 `map/config` 取它的真实应答。
- 「底图取不到」的用例：在浏览器里把去假瓦片服务的请求掐断。

## 已知限制

- 地图库在首屏的 JS 里（压缩前约 148 KB，gzip 后约 43 KB），登录页也会下载它。见上面「不拆包」。
- 图形很多、点很多时（上限 50 块 × 1000 点）SVG 每次平移都重画全部路径。上限附近的流畅程度还没有测过；遇到卡再做视野裁剪。
- 没有做：在地图上整体拖动一块图形、触屏全屏绘制、参考点（机场、车站、地标）和搜索框、城市边界、键盘用准星画图。见 M1-02 的任务日志。
