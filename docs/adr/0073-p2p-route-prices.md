# ADR 0073：点对点线路价（有方向的跨区域一口价）、返程价格、含公里数

- 状态：已采纳（2026-11-09，M8-11 起实施）。业主 2026-11-09 对点对点 B 类的答复：① 做有方向的跨区域线路价，表单加「返程价格」，规则可设「含 X 公里 + 超出每公里 Y」；② 附加费全局生效（保持按商品统一定价）；③ 新车附加费、金牌司机不做。
- 补充 ADR 0018（价格规则）：价格规则多一个可空的「下车区域」；固定一口价多一组可选的「含公里数 + 超出每公里单价」。
- 补充 ADR 0020（报价引擎）第 4～7 步：点对点先找线路价，没有再用现在的区域价。
- 落实 ADR 0063 第 1 项（当时只是方案、默认双向同价），改为单向。
- 编号：写这篇时 main 上最大是 ADR 0070；0071 由 M4-34、0072 由 M8-10 占用，这里用 0073。

## 不变的（硬约束）

- **已有的价格规则含义不变**：新列可空、新参数可缺省；没填下车区域、没填含公里数的规则，报价结果和今天逐分一致（单元测试用现有报价样例对比）。
- **已下的订单不改、不重算**：订单和报价快照已经存的东西不动；新字段只出现在新报价、新订单上。
- 附加服务、司机语言仍按商品统一定价（ADR 0069 B15），不做按线路 × 车型定价；不做新车附加费、金牌司机。
- 一口价仍然包含所有费用（ADR 0069 B12、ADR 0070）：超出公里的钱是**报价时就算进一口价**的，不是服务后加收；车开绕路不加钱。
- 只对点对点品类开放。接送机、包车的价格规则不认识下车区域和含公里数（接口拒绝，400）。
- 对外价、加价比例仍然不出现在 `/tenant/v1`（规则 4）。

## 决定

### 1. 价格规则加「下车区域」

`price_rules` 加 `to_area_id uuid null`（外键到同一租户的区域，带 `tenant_id`，RLS 照旧）：

| 下车区域 | 含义 | 命中条件 |
| --- | --- | --- |
| 不填（null） | **区域价**，和今天一样 | 两端都落在商品的区域里；起终点落在不同区域时这些区域的价都算、取最低（ADR 0020 第 4 步，不变） |
| 填了 | **线路价，单向** | 上车点落在「区域」（`area_id`，页面叫上车区域）、下车点落在「下车区域」；反方向不命中 |

- 下车区域必须是这个商品的区域，且不能等于上车区域（同区域就是不填）。
- 冲突检查（409 `PRICE_RULE_CONFLICT`）的组合键加上下车区域：同一条线路（上车区域、下车区域）× 车型组 × 生效日期重叠，只能有一条；线路价和区域价互不冲突。

### 2. 报价时怎么选

点对点在第 4～7 步：

1. 先找**线路价**：上车点所在的每个区域 × 下车点所在的每个区域，有启用、覆盖用车日期、车型组对得上的线路价就用；命中几条取结算价最低的（一样低取商品里排在前面的区域，和现在的规则一致）。
2. 某个车型组没有命中的线路价时，退回**区域价**（今天的做法，不变）。
3. 线路价优先，**不和区域价比低**：供应商专门为这条线路定的价就是这条线路的价。

两端仍然都要在营运区里、不在禁行区里（第 4 步不变）。跨城市（广州 → 香港）仍是 ADR 0069 的 B8，这次不做。

### 3. 返程价格

供应商价格页新增线路价时，表单里有一个可选的「返程价格」：

- 填了：**同一个请求里**建两条规则——A → B 用「价格」，B → A 用「返程价格」；车型组、生效日期、含公里数、超出单价、状态相同。两条要么都建成，要么都不建（同一事务；任一条冲突整体 409，列出冲突）。
- 建好以后是两条独立的规则，各自编辑、启停、删除，改一条不会改另一条（页面提示写明）。
- 没填：只建 A → B。
- 区域价（不填下车区域）没有返程价格这一项。

接口：沿用批量新增（`POST …/price-rules/batch`），前端把一条带返程价的表单展开成两条；不新增专门的接口，避免两套校验。

### 4. 含公里数（可选）

固定一口价的参数多两个**可选、要么都填要么都不填**的字段：

| 字段 | 含义 | 范围 |
| --- | --- | --- |
| `includedKm` | 一口价含多少公里 | 整数，1～2000 |
| `overKmPerKmMinor` | 超出后每公里多少钱（最小货币单位） | 整数，0～单价上限（沿用 `PRICE_LIMITS`） |

区域价、线路价都能用；里程 + 时长、包车套餐不用这组字段（它们本来就按公里算）。

**计价**：

- 距离 = 报价时谷歌路线的距离（ADR 0042 路线预估，米），**报价时锁定**，存进报价快照和订单；之后车开绕路、改走别的路都不加钱。
- 超出公里数 Z = 向上取整到 1 公里：`Z = max(0, ⌈(路线米数 − X × 1000) ÷ 1000⌉)`。
  - 例：含 30 公里，路线 30.0 公里 → Z = 0，就是一口价；30.2 公里 → Z = 1；31.0 公里 → Z = 1；31.4 公里 → Z = 2。
  - **取整方式（向上取整到 1 公里）先按此实施，业主如有异议另行通知后再改**（改动只在 domain 的一个函数里）。
- 结算价 = 一口价 + Z × Y（整数，最小货币单位，不经过浮点）；之后的调价规则、加价、取整、附加服务完全照现在的流程，和今天的一口价一样。
- 规则设了含公里数，但这次报价**拿不到路线距离**（谷歌没配置、超出每日上限、超时等）：这条规则这次不报价（和「里程 + 时长」拿不到路线时的降级一样，ADR 0042），不按「没超」处理——避免少收供应商的钱。没设含公里数的规则不受影响。

### 5. 页面上的「服务线路」

供应商价格页的点对点规则：

- 「服务线路」下拉由商品的区域自动生成：每个区域一项「区域内（同区域一口价）」，再加上所有有序的两两组合「上车区域 → 下车区域」。区域增删后下拉跟着变；被停用或移出商品的区域上的规则照现在的「缺价 / 不能售卖」逻辑处理。
- 列表多一列「线路」（「东京市区 → 迪士尼」或「东京市区（区域内）」）和「含公里数」（「含 30 公里，超出每公里 ¥200」）。
- 「复制」按钮：用这条规则的内容预填新增表单（生效日期可改），保存时照常查冲突。

### 6. 显示「含 X 公里，超出 Z 公里 × Y」

规则设了含公里数时，这几处显示：

| 位置 | 显示 | 用哪个价 |
| --- | --- | --- |
| 供应商价格页（列表、详情） | 含 X 公里，超出每公里 Y | 结算价（供应商自己的价） |
| 官网报价卡片、新预订页右侧栏、订单页 | 含 X 公里，本次路线约 D 公里，超出 Z 公里 × Y（已含在一口价里） | 对外价：Y 按同一套加价和取整算出的每公里对外价 |
| 运营后台订单详情 | 同上，两种价都显示 | 结算价、对外价 |
| 供应商后台订单详情 | 同上 | 只用结算价（规则 4） |
| 订单确认邮件 | 同官网 | 对外价 |

- 没超（Z = 0）时写「含 X 公里，本次路线约 D 公里」。
- 一口价仍然显示为一个总价；这一行是说明，不是另一笔费用。客人看到的每公里对外价单独取整，和总价可能差在一个取整单位以内，所以不显示「基础价 + 超出 = 合计」的算式。
- 报价快照、订单上存：`included_km`、`route_meters`、`over_km`、`over_km_per_km_minor`（结算）和对外价的每公里单价；对外接口只给对外价。

### 7. 其他要认识线路和含公里数的地方

| 地方 | 做法 |
| --- | --- |
| 上架检查「该有价格的组合」 | 不变：仍然按区域价检查；线路价是可选的补充，没有线路价不算缺价 |
| 价格日历 | 线路价按线路分行显示 |
| 调价规则的适用区域 | 按规则的 `area_id`（上车区域）判断，和今天的数据含义一致 |
| 价格导入导出（`price-import`、`price-sheet`） | 加「下车区域」「含公里数」「超出每公里」三列；旧模板（没有这三列）照旧导入为区域价、无含公里数 |
| 销售接口 `/sales/v1`、官网接口 | 请求不变；应答多上面的说明字段（只加不改） |
| 租户隔离 | 下车区域必须是本租户、本商品的区域；跨租户的区域编号 404。新增或改动的 `/tenant/v1` 接口都有「租户 A 读不到、改不了租户 B」的集成测试 |

## 后果

- 供应商可以给有方向的跨区域线路定价，同区域一口价不变；已有规则、已下订单不受影响。
- 含公里数让一口价能覆盖长短不一的行程；距离以报价时的谷歌路线为准，客人和司机都不会因绕路多付。
- 设了含公里数的规则依赖路线预估：谷歌不可用时这些规则不报价（宁可报不出，不少收）。
- 业主若对取整方式有异议，只改 domain 里的一个函数和对应测试。
