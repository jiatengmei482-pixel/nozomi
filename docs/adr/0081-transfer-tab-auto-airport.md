# ADR 0081：客人预订页只剩「区间 / 包车」，系统按有没有机场自动判断；接送机报不出改用点对点商品

- 状态：已采纳（业主 2026-11-11 定，M8-33 实施）。
- **部分取代 ADR 0079 第 1 节**（M8-27 的「接送机 / 点对点 / 包车」三个标签和「标签不符一键切换」提示）。0079 的四步、右侧栏、页面宽度等其余部分继续有效。
- 补充 ADR 0069 A1（按两个坐标报价、认机场）、ADR 0080（报价优先级）。
- 编号：写这篇时 main 上最大是 ADR 0080（M8-30），这里用 0081。

## 业主定的规则（roadmap M8-33 为准）

1. 客人预订页第 1 步只有两个标签：**区间**（日文「区間」、英文 Transfer）、**包车**。客人页面上不出现「接送机还是点对点」的选择，也去掉 M8-27 的「标签不符一键切换」提示。
2. 系统按上下车点有没有机场自动判断：有机场 → 按接送机处理（航班号、免费等待、举牌）；没有 → 按点对点。认机场的规则不变（ADR 0069 A1：3 公里，或地址搜索说是机场且 10 公里以内）。
3. 报价：有机场先用**接送机商品**；接送机商品**一个都报不出**时，再用**点对点商品**（按出发地所在、官网能订点对点的城市；出发地不在任何城市时按目的地，见 ADR 0084），两者都走 ADR 0080 的规则。
4. 免费等待：显示所选商品自己设的时长；还没有报价（没设）时用平台默认：国际线机场 90 分钟，国内线、都有或没标明 60 分钟（和供应商后台最少值同一规则，`minimumFreeWaitMinutes`）。
5. 不改供应商后台的商品类型和数据。
6. 旧链接 `/book/new?mode=airport`、`mode=p2p` 继续能用，落到「区间」；`mode=charter` 仍是包车；新增 `mode=transfer`。
7. 现有报价一分不变。

## 实施

### 后端（`POST /site/v1/quotes/by-points`）

- 认出机场后照旧用接送机商品报（`siteQuotes`，同一个询价）。**只有结果一个报价都没有时**才运行第二步：用出发地坐标在官网能订点对点的城市里找服务城市（`serviceCityOf`，和点对点同一规则），用点对点商品再报一次；第二步报出来才采用，否则保留接送机的结果和原因。
- 应答新增两个字段（只增不改）：
  - `fallback_category`：采用了点对点商品时为 `point_to_point`，其余 `null`。`trip_type` 仍是 `pickup` / `dropoff`，客人页照样要航班号、显示免费等待和举牌。
  - `airport.flight_scope`：`international` / `domestic` / `mixed` / `null`，客人页还没有报价时按它显示默认免费等待。
- 第二步的询价日志在 `request` 里多记 `fallback_from: "airport_transfer"`，和第一步各记一条。未覆盖需求只在第一步按原规则记（第二步不再记，免得一次询价两条）；第二步报出来时，第一步记下的那条接送机未覆盖需求保留——它如实说明「接送机商品没覆盖」。
- 为什么是「一个都报不出才改用」而不是按车型组补齐：接送机报得出时完全不运行第二步，现有报价、排序、报价快照都不受影响（规则 7）；按车型组混合两种商品会让同一页上的取消政策、免费等待来源不一致，留待业主需要时再议。

### 前端（`/book/new`）

- `BookTab` 改为 `transfer | charter`，名称「区间 / 包车」；多语言的说法放在 `BOOK_TAB_I18N`（中「区间」、日「区間」、英 Transfer；包车日文暂写「貸切」、英文 Charter，多语言上线时由业主确认，M7-07）。
- 去掉 `tabMismatch` 和「改选「…」」按钮及其样式。
- 区间标签：城市能订接送机或点对点就出现。
- 接机提示的免费等待：有报价用报价里的 `free_wait_minutes`；还没有报价时按 `airport.flight_scope`（国际 90，其余 60）。

## 不做的

- 不改供应商后台、商品类型、价格和区域数据；不改 `POST /site/v1/quotes`（包车和渠道直接询价）。
- 不改订单的品类和下单校验：采用点对点商品时订单就是点对点品类的订单（报价快照决定）。点对点订单不收 `flight_no`、两端地址都必填，所以客人页在这种情况下照样让客人填航班号（接机必填），但下单时把航班号写进给司机的备注最前面（「航班号：…」，和举牌姓名同一处），两端地址都提交。航班号、举牌、乘车人的正式字段在 M8-32 一并处理。
