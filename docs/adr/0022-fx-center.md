# ADR 0022：汇率中心——免费源、精确的十进制汇率、定时拉取、挂起与确认、过期告警

- 状态：已采纳（2026-10-15，M2-03）
- 实现 ADR 0020 留下的 `FxRates.quote(from, to, at)`；按 ADR 0020 的说明删掉 `packages/domain/src/fx.ts` 里 M0 的浮点汇率代码。
- 补充 ADR 0004「汇率」一条：汇率怎么取、怎么存、怎么换算成报价用的那个数。
- 补充 ADR 0010 / 0012：两张新的平台表的授权；审计日志多一种入口 `job`（服务进程里的定时任务）。
- 编号说明：0021 留给同时在开发的另一个分支。

## 背景

需求：《用车报价服务平台》「汇率中心」（免费源、按 USD 基准存、任意两种币种走交叉汇率、按数据源频率拉取、不可用时用最近一次有效汇率、超过 48 小时暂停跨币种报价并告警、快照记汇率和取数时间、`fx_rate` 保留全部历史、租户只读）；
《平台运营端与渠道对接》「汇率中心运维」（看板：当前汇率、更新时间、数据源状态、近 30 天曲线；单次变动超过 3% 先挂起并告警人工确认；人工锁定要双人复核）、「汇率缓冲与加价下限」。
roadmap 的验收标准：汇率过期告警；快照写入报价。

## 决定

### 数据源

- ExchangeRate-API 的免费地址 `https://open.er-api.com/v6/latest/USD`（配置 `FX_SOURCE_URL`，M0-02 起就是默认值）：免费、免密钥、USD 基准、每天更新一次，响应里有更新时间和下次更新时间。对方要求展示署名链接——汇率只在运营后台内部使用，不对外展示，届时对外展示汇率的页面要带上。
- 付费档（v6 的 `conversion_rates`）是同一种格式，换源只改 `FX_SOURCE_URL`，接口不变。换成欧洲央行这类别的格式时，在 `packages/domain/src/fx-source.ts` 加一个解析函数。
- 付费档的地址里带密钥，所以**完整地址只在下载模块里用**：库里（`fx_fetches.source`、`fx_rates.source`）、日志、接口里一律只有主机名。
- 只存平台支持的币种（`money.ts` 的 `CURRENCIES`，现在 7 种）。数据源里其余 150 多种不存：报价用不到，还会让「变动超过 3%」被无关的币种触发。以后 `CURRENCIES` 加了币种，下一次拉取起自动开始存。
- 下载模块 `apps/api/src/integrations/fx-source.ts`：定时拉取每次最多等 10 秒、最多试 3 次（5xx、429 重试，4xx 不重试）；后台「立即拉取」只试 1 次、最多 8 秒（前端的请求时限是 10 秒）；超过 1MB 中止；严格按 UTF-8 解码。错误码 `FX_SOURCE_TIMEOUT` / `FX_SOURCE_UNAVAILABLE` / `FX_SOURCE_BAD_RESPONSE`。

### 汇率全程不经过浮点数

- **解析**：用 `JSON.parse` 的第三个参数 `context.source`（「JSON.parse source text access」，Node 22 起可用）把每个 JSON 数字按原文取出来，再在字符串上规范成十进制写法（`151.210` → `151.21`，`1e-5` → `0.00001`）。
  不能先 `JSON.parse` 成 number 再转字符串：`0.1000000000000000055` 这类写法转一圈就变了，指数写法会被改写。数字写成 JSON 字符串（`"7.1"`）的不认——它不是数据源约定的格式。
  不自己写 JSON 解析器：语法检查、转义、嵌套都交给运行环境，只在「数字」这一处拿原文。
- **存储**：`fx_rates.rate` 是不限精度的 `numeric`，存的就是规范后的十进制字符串，取出来用 `rate::text`，原样还原。
- **交叉汇率**：1 个 A = (1 USD 的 B 数) ÷ (1 USD 的 A 数) 个 B，先用精确分数算，再**四舍五入到 12 位小数**写成十进制字符串（`FxQuote.rate`）。
  报价快照里记的就是这个字符串，对外价、之后的订单和结算都按它算，可以原样复算。12 位是报价引擎 `rateFraction` 认的上限（ADR 0020 没改）；对平台的币种至少留 9 位有效数字（最小的韩元 → 美元约 0.0007），比数据源本身（约 6 位有效数字）精细三个数量级。
- 只有运营后台的曲线把汇率换成数字（定点的位置），那不是算钱。
- M0 的 `snapshotRate` / `convertMinor`（浮点汇率、浮点四舍五入）删掉了，没有别的调用方；`money.ts` 的 `roundHalfAwayFromZero` 留着，但现在业务代码里已经没有浮点输入用它。

### 表

迁移 `0018_fx_rates.sql`，两张平台表（不带 `tenant_id`，不开行级安全）：

| 表 | 内容 | 平台 | 租户 |
| --- | --- | --- | --- |
| `fx_fetches` | 每次拉取：开始 / 结束时间、定时还是手动（谁）、数据源主机名、结果、原因、数据源说的这批时间和下次更新时间、挂起的那批汇率和超限的币种、确认 / 放弃的人和时间 | 读、写、改（结束、确认、放弃） | 无 |
| `fx_rates` | 1 USD = rate 个 quote；`as_of`（这批的时间）、`fetched_at`（我们拉到的时间）、`source`、`fetch_id`；同一批同一个 `as_of`；保留全部历史 | 读、追加 | 只读 |

都没有 `delete`。`fx_rates` 只追加；`(base, quote, as_of)` 唯一。

**「取数时间」用数据源的更新时间（`as_of`）**，不是我们拉到的时间：数据源停在某一天不更新、我们却每小时拉到同一份时，48 小时的钟应当从数据的时间算起。快照里的 `as_of`、看板的「这批汇率的时间」、过期的判断都是它；「拉到的时间」另有一列。

### 拉取、校验、挂起

一次拉取分三步：① 短事务里拿排他锁、看要不要拉、登记一行「正在拉」；② **事务之外**下载（不占着数据库连接等外部服务）；③ 短事务里拿排他锁、校验、写结果。

结果（`fx_fetches.status`）：

| 结果 | 什么情况 | 汇率 |
| --- | --- | --- |
| `accepted` | 新的一批，校验通过 | 写入，立即生效 |
| `unchanged` | 和现在用的（或挂起待确认的）是同一批（`as_of` 一样）：数据源还没更新 | 不写 |
| `held` | 有币种和现在用的相比变动**严格大于** 3%（精确分数比较，正好 3% 不算） | 不写，整批存在这一行里等人确认 |
| `rejected` | 内容不对：不是 JSON / 对方说出错 / 基准不是 USD 或 USD 不是 1 / 更新时间缺失或比现在晚 5 分钟以上 / 缺平台币种 / 汇率不是正的十进制数或位数大得不正常 / 比现在用的那批还旧 | 不写，记错误码和说明 |
| `failed` | 连不上、超时、对方出错 | 不写 |
| `confirmed` / `dismissed` | 挂起的那批被人确认 / 放弃；有了更新的一批之后，旧的挂起批次自动作废（`dismissed`，没有确认人） | 确认时写入 |

内容不对时**整批拒收**，不挑能用的币种入库：缺一个币种多半是数据源出了问题，一半新一半旧的表比整张旧表更难排查。不论哪种失败，都继续用最近一次有效汇率（需求原话），直到 48 小时。

挂起之后，之后的每次拉取仍和**现在用的**那批比：行情真的变了，就一直挂起，直到有人确认；48 小时后跨币种报价停掉、告警——这正是「人工确认」要的效果，不会因为没人处理就自动生效。

### 定时任务和多实例

项目里原来没有定时任务。做法：**在 API 进程里**，`FxCenter.start()` 启动后 5 秒第一次检查，之后每 60 秒一次（`setTimeout` 链，上一轮结束才排下一轮，`unref` 不拖住进程退出；关闭时停掉并最多等 3 秒）。只有 `server.ts` 启动它（`buildApp({ jobs: true })`）；测试直接调 `tick()`。配置 `FX_AUTO_FETCH`（默认 true）关掉时只做过期检查，汇率只能在后台手动拉。

每一轮：到时间就拉，然后检查过期。「到时间」按数据源的频率（`nextFxFetchAt`，纯函数）：

- 从没拉过：马上；
- 上次拉到了：数据源说的下次更新时间之后 5 分钟；没说就 1 小时后；但不早于上次结束后 15 分钟（数据源迟迟不更新时不会每分钟去问）、不晚于 12 小时（数据源给的时间不对也能自愈）；
- 上次失败或内容不对：15 分钟后重试。

**多个 API 实例**（以后横向扩容）：每个实例都跑这个检查，靠数据库保证只有一个在拉——

- 「看要不要拉 + 登记正在拉」和「写结果」都在事务级咨询锁 `pg_advisory_xact_lock(hashtext(current_schema() || ':nozomi.fx_fetch'))` 里（锁名带 schema，集成测试各用各的 schema，互不排队），这两个事务都很短；
- 有一行「正在拉」时别的实例什么都不做，后台的「立即拉取」返回 409 `FX_FETCH_IN_PROGRESS`；
- 进程在拉的过程中退出，那一行停在「正在拉」：开始超过 5 分钟算中断，下一次拉取把它改成失败（`FX_FETCH_ABANDONED`）再拉；
- 写结果时只改还在「正在拉」的那一行，被判定为中断的不会被晚到的结果覆盖。

集成测试里两个实例共用一个库同时跑一轮，数据源只被请求一次。

没有引入任务队列或外部调度：一天一次的拉取不值得多一个组件；以后有了更多定时任务（订单超时、账单）再统一考虑，届时新增 ADR。

### 给报价引擎的汇率（`FxRates`）

`FxCenter.rates.quote(from, to, at)`：取现在用的那批（进程内缓存 30 秒；本进程里拉到新的、确认了挂起的立即作废），超过 48 小时（或取数时间比 `at` 晚 5 分钟以上）返回 null，否则返回交叉汇率。报价引擎自己还会再查一遍（ADR 0020 的 `fxQuoteUsable`）。多个实例各有各的缓存，别的实例最晚 30 秒后用上新汇率。
同币种的不调它（汇率 1、没有缓冲，ADR 0020）。

报价快照（`QuoteSnapshot`）里每个候选、中标的 `sell.fx` 就是这个 `{ from, to, rate, asOf }`：所用汇率和取数时间（验收标准「快照写入报价」）。平台试算接口的每个候选都带 `fx`。

### 过期告警

现在用的那批超过 48 小时没更新：

- 报价：跨币种的报不出（`FX_RATE_UNAVAILABLE`），同币种照常；
- 运营后台首页：页面顶部一条危险提示条（「汇率超过 48 小时没有更新，跨币种报价已暂停」+ 去汇率页）；汇率页顶部同样一条；
- `GET /platform/v1/dashboard/summary` 的 `fx.state`、`GET /platform/v1/integrations` 的 `fx_center.state` 是 `stale`；
- 审计日志一条（`resource = fx_rate`，`action = stale`，`resource_id` = 那批的 `as_of`，操作者「系统」，入口 `job`）和服务日志一条 error（`event: fx.stale`）。**每一批只记一次**：检查时先看审计日志里这批记过没有，和拉取用同一把锁，几个实例同时检查也只记一次。
- 挂起（变动超过 3%）同样记审计（`action = hold`）和服务日志（`event: fx.held`），首页卡片上一条提醒。

没有邮件、短信渠道（需求第三轮决策），告警只到后台、审计和服务日志。通知中心做出来以后，`fx.stale` / `fx.held` 接到通知中心（需求里的 `fx.stale` 事件）。

`/health` 没有加汇率：它是公开的、不登录就能调，按 ADR 0010 登录前角色不给新表权限；而且部署脚本以它判断部署成功，新装的环境本来就还没有汇率。汇率状态放在需要平台登录的集成状态里。

### 接口和权限

| 接口 | 权限 | 内容 |
| --- | --- | --- |
| `GET /platform/v1/fx-rates?base=` | `master_data.read`（每个平台角色） | 状态、这批的时间、过期时间、相对基准的汇率、平台币种两两互换、数据源状态（最近一次拉取、最近成功、下次拉取）、挂起的一批 |
| `GET /platform/v1/fx-rates/history?base=&days=` | `master_data.read` | 近 N 天（默认 30）的曲线 |
| `GET /platform/v1/fx-rates/fetches?limit=` | `master_data.read` | 拉取记录 |
| `POST /platform/v1/fx-rates/fetch` | `fx.manage` | 立即拉取（写审计） |
| `POST /platform/v1/fx-rates/fetches/{id}/confirm`、`/dismiss` | `fx.manage` | 确认 / 放弃挂起的一批（写审计） |
| `GET /tenant/v1/fx-rates?base=` | 租户 `master_data.read`（每个角色） | 状态、时间、相对基准的汇率。没有缓冲、加价、对外价（规则 4） |

新操作 `fx.manage` 只给**主数据运营和超级管理员**：汇率中心在「主数据」菜单下（需求的菜单表）。看板人人能看：汇率是公共资料，和看城市、机场一样。
路径用斜线（`/fetch`、`/confirm`），不用需求里的 `:lock` 写法，和本项目已有接口一致（ADR 0020 待定事项 19）。需求写的租户接口是 `GET /master/fx-rates`，这里是 `/tenant/v1/fx-rates`：`/tenant/v1/master/` 下是四类主数据（城市、地点、车型组、附加服务）同一套形状的列表接口，汇率不是那种形状。

运营后台「主数据 → 汇率」页（`/platform/master/fx-rates`）：数据源状态、当前汇率（可换基准）、常用币种互换表、近 30 天曲线（简单 SVG，没有引入图表库）、拉取记录、立即拉取和确认 / 放弃（有 `fx.manage` 的才有按钮）；首页「主数据」分区多一张「汇率」卡片。

## 没有做的

| 内容 | 原因 / 去向 |
| --- | --- |
| **人工锁定某个汇率（双人复核）** | 双人复核的审批机制（`approval` 表、`/approvals`）还不存在，按 roadmap 在 M2-04 和渠道加价规则一起做。锁定要用到同一套「一人提交、另一人批准」，现在单独做一个最小版本，M2-04 又要换掉。**建议新开任务「汇率人工锁定」排在 M2-04 之后**，锁定期间报价用锁定值（快照里标明是锁定的），锁定带到期时间、到期自动解除 |
| 欧洲央行等别的数据源格式 | 现在的源够用；换源时加一个解析函数 |
| 告警发到人（邮件、短信、通知中心） | 没有渠道（第三轮决策）；通知中心做出来后接上 `fx.stale` / `fx.held` |
| 报表的任意展示币种 | 报表任务用这里的 `fxQuoteFromTable` 换算 |
| 汇兑损益 | 结算任务（M5） |

## 待定事项（先按推荐做了）

| # | 问题 | 选的方案 | 理由 |
| --- | --- | --- | --- |
| 1 | 48 小时从什么时候算 | 数据源的更新时间 | 数据源停更、我们照样拉到同一份时也能发现 |
| 2 | 单次变动超过 3% 和谁比 | 和现在生效的那批比，按币种（相对 USD） | 需求「单次变动」；交叉汇率的变动由两个币种各自的变动决定，逐币种比已经覆盖 |
| 3 | 挂起时报价用什么 | 继续用旧的那批，直到确认或 48 小时过期 | 没确认的数不能进报价；过期后停掉跨币种报价，逼着有人处理 |
| 4 | 确认挂起的一批要不要双人复核 | 一人确认（`fx.manage`） | 需求只对「人工锁定」写了双人复核；确认的是数据源给的数，不是人填的数 |
| 5 | 数据源缺一个币种 | 整批拒收 | 见「拉取、校验、挂起」 |
