# ADR 0068：车型标识（代表车型、同级车型说明、最多乘客、最多行李）

- 状态：已采纳（2026-11-09，M7-01）。业主指示新建 M7「车型标识」：每个车型都要有 4 项标识，并在后台、官网、订单、邮件里显示。
- 补充 ADR 0012（主数据）：车型组**不加新字段**，4 项全部由现有的 `sample_models`（代表车型列表）和 `combos`（人数 / 行李数组合）得出。
- 补充 ADR 0020（报价引擎）：选车校验仍然只看组合，这里只增加显示。
- 编号：写这篇时 main 上最大是 ADR 0067，这里用 0068。

## 背景

业主要求每个车型都有 4 项：① 代表车型；② 同级车型说明（格式「X, Y or similar」，要符合当地实际车型）；③ 最多乘客数；④ 最多行李数。参考数据是 2.0 后台 settings/vehicle-types 的 57 个车型（只读抄录，不进仓库）。

核对现状（2026-11-09）：

| 要求 | 车型组现有字段 | 现在哪里用到 |
| --- | --- | --- |
| ① 代表车型 | `sample_models`：字符串列表，最多 10 个、每个最多 100 字 | 后台车型组可编辑；官网报价卡片显示「XX 或同级」 |
| ② 同级车型说明 | 同上 | 同上 |
| ③④ 最多乘客 / 行李 | `combos`：`[{ passengers, luggage }]`，至少一个 | **报价引擎按它选车**；供应商给商品选组合；官网报价卡片列出全部组合 |
| （座位数） | `seats` | 编码的一部分，创建后不能改 |

## 决定

### 1. 4 项怎么得出（不加字段）

`@nozomi/domain` 的 `vehicleLabel` / `vehicleLabelLines` 是唯一的定义，页面、接口、邮件都用它：

- ① **代表车型** = `sample_models` 的第一个。
- ② **同级车型说明** = `sample_models` 全部用「, 」连起来，后面加「or similar」：`Toyota Noah / Voxy, Nissan Serena or similar`。只有一个时是 `Toyota Camry or similar`。按业主给的格式，「or similar」不随界面语言翻译（车型名本来就是英文写法，整句保持一致）。
- ③ **最多乘客** = 组合里人数的最大值；④ **最多行李** = 组合里行李数的最大值。两者是各自的最大值，不一定能同时达到（「6 人 + 4 件 或 5 人 + 5 件」→ 最多 6 人、最多 5 件），所以官网报价卡片保留完整的组合说明。
- 代表车型没填时 ①② 不显示，不编造。

为什么不另存 ② 或 ③④：
- ② 另存会和 ① 的列表不一致（改了代表车型忘了改说明）。
- ③④ 另存会出现「标识说最多 6 人、组合里却只有 5 人」——报价按组合挑车，客人看到的必须和挑车的依据一致。

### 2. 后台怎么编辑

平台后台「主数据 → 车型组」原来就能编辑代表车型列表和组合（等级、座位数、编码创建后不能改）。M7-01 加：
- 表单里「客人看到的车型标识」预览：按正在填的值实时显示 4 项；
- 代表车型的提示写明「第一个是代表车型、全部连起来就是同级说明，写当地实际在跑的车型」；
- 列表多一列「同级车型」。

组合的校验（人数 ≤ 座位数、不重复、至少一个）不变。

### 3. 在哪里显示（M7-02～M7-04）

| 位置 | 内容 |
| --- | --- |
| 官网报价卡片（选车） | 4 项 + 原有的座位和组合说明 |
| 官网填写订单页、订单页（查订单） | 4 项 |
| 运营后台、供应商后台的订单详情 | 4 项（供应商后台不涉及对外价，规则 4 不受影响） |
| 订单相关邮件 | 「车型」下面加代表车型说明和最多乘客 / 行李 |

接口：报价（`SiteQuote.vehicle_group`）已经带 `sample_models`、`combos`；官网订单、运营和供应商的订单详情里的车型组补上这两个字段（只读、加字段，不改已有字段）。显示的是车型组**当前**的说明（见改进方案 3）。

### 4. 标签的语言

现在官网、后台、邮件只有中文界面。`VEHICLE_LABEL_TEXTS` 同时备好中文、日文、英文三套标签：

| | 中文 | 日文 | 英文 |
| --- | --- | --- | --- |
| ① | 代表车型 | 代表車種 | Representative model |
| ② | 同级车型 | 同等クラスの車種 | Similar models |
| ③ | 最多乘客 / N 人 | 最大乗車人数 / N名 | Max passengers |
| ④ | 最多行李 / N 件 | 最大荷物数 / N個 | Max luggage |

界面切到日文时直接换用日文一套（改进方案 2）。

### 5. 测试环境的数据（M7-05）

用抄录数据按**名称**对应现有车型组，日本 / 通用（抄录第 1 页）优先；只填代表车型列表。组合已经和抄录数据一致的不动；不一致的不改（改组合会改变选车结果），列出来。名称对不上、或现有值和抄录不同的，列出来不硬套。

## 超出现有框架的地方（改进方案，这次不做）

1. **按国家 / 地区的代表车型**。车型组是全球共用的（`VG-BIZ-7` 在日本和中国是同一条），抄录数据却是按地区分的（日本 7 座 Alphard、中国 GL8、泰国 Innova）。「符合当地实际车型」做不到每个国家不同。方案：加 `vehicle_group_regional_models(vehicle_group_id, country_code, sample_models)`，显示时按商品所在城市的国家取，取不到用车型组上的通用列表；后台车型组页面加「按国家覆盖」。影响主数据接口、报价、订单、邮件，单独排期。在那之前，车型组上的代表车型按**日本**写（现有商品都在日本）。
2. **日文界面**。官网和邮件现在只有中文。日文界面要做整套文案的翻译和语言切换（官网、订单页、邮件模板），不是只换车型标签。标签已备好，等日文界面任务。
3. **下单时的快照**。订单只记车型组编号，显示的是当前的代表车型和组合。以后改了车型组，旧订单也跟着变。若要「下单时看到什么就一直是什么」，要在订单上存一份快照（迁移 + 下单流程），单独排期。
4. **抄录数据里组合和现有不同的车型**：改组合会改变哪些商品能报价，要业主确认后由平台按现有流程在后台改，不在这次的数据填写里做。

## 后果

- 不加字段、不加迁移、选车逻辑不变；只增加显示和后台预览。
- 车型组的代表车型现在有两个用途（代表车型、同级说明），后台提示里写清楚了。
