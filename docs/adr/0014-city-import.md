# ADR 0014：城市从 GeoNames 导入、导入城市的编码、机场的城市建议

- 状态：已采纳（2026-10-07，M1-09）
- 补充 ADR 0012（主数据）。不改变其中的决定；城市导入的做法与机场导入一致，下面只写不同的地方。

## 背景

M1-01 之后机场可以从 OurAirports 导入，但城市只能逐个手工建（编码、各语言名称、时区、中心坐标）。测试环境有 97 个导入的日韩机场等着指定城市。需要：主要城市也能从公开数据导入；处理机场时系统能建议最近的城市。

## 决定

### 数据来源：GeoNames

- 来源：GeoNames，<https://www.geonames.org/>。
- 许可：知识共享 署名 4.0（CC BY 4.0，<https://creativecommons.org/licenses/by/4.0/>）。可以商用、可以修改，条件是**注明来源**。数据「按原样」提供，对方不保证准确、及时、完整（下载目录的 readme 原文，2026-10-07 核对）。
- 用到两种文件（制表符分隔的 UTF-8 文本，以 zip 提供）：
  - `https://download.geonames.org/export/dump/cities15000.zip`：人口 1.5 万以上的城市和各级首府，带中心坐标、IANA 时区、人口、英文名；
  - `https://download.geonames.org/export/dump/alternatenames/<国家码>.zip`：各语言的名称，日文、中文、韩文从这里取。
- 仓库里不提交数据文件；测试用测试代码里现场构造的小样本，不联网。

### 署名怎么满足

CC BY 要求在使用处注明来源。我们在这些地方注明：

1. 每条导入的城市记录带 `source = geonames` 和 `source_ref`（GeoNames 的编号），审计日志里也记；
2. 导入命令的输出第一行写明来源和许可；
3. 代码（`packages/domain/src/geonames.ts`）、本 ADR、根 `README.md`、`openapi.yaml` 的说明；
4. **面向用户的产品里**：运营后台的主数据页面和将来对客的官网，凡是展示这些城市数据的地方，在页脚或「关于 / 数据来源」处写一行「城市数据来自 GeoNames（geonames.org），CC BY 4.0」并链到 GeoNames。运营后台这一行由前端在 M1-09 的页面里加；官网上线时（M3-05）同样要有——这一条是许可的硬性条件，不是可选项。

平台改过的城市仍然保留 `source` 标记（改过不等于不再来自 GeoNames）。

### 导入范围

- 默认：所选国家里**人口不少于 30 万**的城市，外加首都和一级行政区（日本的都道府县、韩国的道 / 广域市）的首府，不论人口。
  按 2026-10-07 的文件：日本 92 个、韩国 35 个。`--min-population` 可以调（如 10 万：日本 277 个、韩国 60 个）。
- 只取「城市」类型（一般聚居地和各级首府）；城市里的区、已废弃的、历史上的聚居地不取。
- 人口门槛挑的是大城市，不是「有接送需求的地方」：箱根、轻井泽、日光这类人口少的目的地不在里面，仍然要手工建。
- 数据源的归类不完美：个别东京的区（如大田区）被归成了城市而被导入。导入的城市默认停用，复核时不启用即可。

### 导入城市的编码

城市编码的格式是 `CTY-国家码-序号`，序号 2 到 8 位大写字母或数字（ADR 0012）。导入的城市：

> `CTY-<国家码>-G<GeoNames 编号的 36 进制写法>`，例如东京（1850147）是 `CTY-JP-G13NKZ`。

- 编码只由数据源编号决定。同一个城市在任何环境、任何一次导入里都是同一个编码，和导入范围、导入顺序、库里已有多少城市都无关——重复导入、以后放宽范围、测试环境和正式环境之间，都不会出现「同一个城市两个编码」或「同一个编码两个城市」。
- 以 `G` 开头，不会和人起的助记码（`CTY-JP-TYO`）撞。万一手工建的城市正好用了同一个编码，导入不覆盖，列为需要人工处理。
- GeoNames 的编号目前最大约 1370 万（36 进制 5 位），加上 `G` 远小于 8 位的上限。
- 没有采用「按人口排名编流水号」：流水号取决于导入时库里已经有什么，不同环境、不同导入顺序会得到不同的编码，而编码创建后不能改。
- 代价是编码不好记。编码主要给系统之间对接用，人看的是名称；觉得某个城市需要好记的编码，可以先手工建（用助记码），导入会认出「看起来是同一个」而不重复创建。

### 名称

- 日、中、英、韩四种，数据源里有的才填，没有的不编。英文名取城市文件自带的名称；其余三种取各语言名称文件里的。
- 同一种语言有多个名称时：标了「简称」的优先于标了「首选」的（「東京」优先于「東京都」），历史名称和俗称不取。数据源只有全称时就是全称（首尔的韩文名是「서울특별시」），平台可以在后台改。
- 中文只取明确标为简体的（`zh-CN`、`zh-Hans`、`zh-SG`），其次才是只标了 `zh` 的——后者有时是繁体。
- 全部国家一起导入（`--all-countries`）时不自动下载各国的名称文件（两百多个文件），只有英文名。

### 和已有城市的关系

- 按数据源编号认「同一个城市」。数据源管的是：它提供的那几种语言的名称、时区、中心坐标。平台另外补的语言、边界、启用状态，导入不碰。
- 平台在后台改过导入城市的名称、时区或中心坐标 → 标记「平台改过」（`source_overridden`），再导入不覆盖。
- 手工建的城市和数据源里的某个城市「看起来是同一个」——同一个国家，并且有任意一种语言的名称相同，或中心坐标相距不到 5 公里——**不自动合并，也不重复创建**，在命令输出里列为需要人工处理。
- 事务、咨询锁（同一时间只允许一次城市导入）、更新时核对版本号、严格 UTF-8、带 NUL 的文件整份拒绝、每条新增和更新写审计日志：都和机场导入相同，代码共用（`import-common.ts`、`import-errors.ts`、`public-file.ts`、`updateMasterRowAtVersion`）。
- 时区除了应用里的规则，还要和数据库的时区名单逐字核对（和后台新增城市同一条规则）；数据库不认识的，这个城市不导入并在输出里说明。

### 默认停用，`--activate` 直接启用

- 不带 `--activate`：新导入的城市是停用的，等平台复核后在后台启用（和机场导入一致）。
- 带 `--activate`：这次**新增**的城市直接启用，审计日志的 `after` 里记 `activated_on_import: true`。
- `--activate` 不会去启用以前导入的、现在是停用的城市——那可能是有人特意停用的。

### 机场的城市建议

- 平台的地点列表按 `city_id=none`（还没有所属城市）筛选时，应答多一个顶层字段 `city_suggestions`：按 `items` 的顺序，每个地点一项 `{ place_id, suggested_city, nearby_cities }`——`suggested_city` 是最近的一个，`nearby_cities` 是由近到远最多 3 个。这正是「处理导入的机场」页面用的那个查询，所以不另设参数；租户的列表不带这个字段。
- 没有把建议放进每个地点对象里、也没有在城市的应答里加 `source`：前端有一组「接口约定」测试把 `City`、`Place` 两个应答结构的字段逐个钉住了，后端单方面加字段会让它失败。建议放在列表的顶层可选字段里不受影响；城市的 `source`（来源、是否被平台改过）目前只在数据库和审计日志里，等前端做 M1-09 的页面时两边一起加进接口。
- 候选：和地点同一个国家、启用中的城市；按地点坐标到城市中心坐标的球面距离排序；只要 **80 公里以内**的。
  大机场离它服务的城市中心一般在 60 公里以内（成田 → 东京约 58 公里，仁川 → 首尔约 48 公里）；80 公里留了余量，又不至于把隔着一个县的城市也建议出来。
- **最近的不一定对**：羽田离川崎市中心约 7 公里、离东京（新宿）约 17 公里，成田离千叶比离东京近。所以同时给出最多 3 个候选，由人确认；系统不自动指定。
- 距离在应用层用 `packages/domain/src/geo.ts` 的球面距离算（ADR 0002），不引入 PostGIS：一个国家启用中的城市是几十到几百个，逐个算是微秒级。
- 因为只在启用中的城市里找，流程是：导入城市 → 复核并启用城市（或导入时 `--activate`）→ 处理机场时才有建议。

### 压缩包

GeoNames 的文件是 zip。Node 没有内置的 zip 读取，我们也不为此引入第三方库（ADR 0001）：`apps/api/src/integrations/zip.ts` 用内置的 `zlib` 实现了只读、只取一个文件的最小解压（不加密、不分卷、小于 4GB，核对 CRC，解压后的大小有上限）。`--file` 也可以直接给解压好的 `.txt`。

## 没有做的

- 城市边界（多边形）：GeoNames 的这两个文件里没有，仍然由平台录入。
- 导入后自动给机场指定城市：只建议，不自动写。
- 「数据源里已经删除 / 降级的城市」的提示：机场导入有（数据源文件里有「已关闭」的记录可以对照），城市文件里没有对应的信息。
- 数据源里城市之间的合并、改名带来的重复：按编号认，编号变了就是另一个城市，由「看起来是同一个」的检查兜住手工建的那部分。
