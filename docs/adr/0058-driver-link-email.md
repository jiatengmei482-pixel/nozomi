# ADR 0058：司机链接系统自动发邮件

- 状态：已采纳（2026-11-02，M4-27）。
- 补充 ADR 0027「司机链接」：一张单可以同时有两种有效链接；本文其余未提到的规则（令牌格式、只存哈希、有效期、改派作废、司机请求的核对）不变。
- 补充 ADR 0049「不做」里的「司机通知」：负责人 2026-11-02 决定改为系统可以自动发邮件。接收方多一种 `driver`。
- 不改 ADR 0057：司机邮箱不是乘客信息，发送记录不加密（`recipient_enc` 为空）；乘客字段的读写路径不动。
- 迁移 0210、0225（和 M4-29 共用同一个文件，代码注释里的「ADR 0060」是 M4-29 的那篇，合并前以本文「链接跟着订单走」一节为准）、0226。

## 背景

以前调度员要手动把司机链接转发给司机。负责人决定（2026-11-02）：

1. 司机档案加「邮箱（选填）」。
2. 供应商设置加开关「司机链接发送方式：系统自动发送（默认）/ 调度员手动发送」。
3. 自动模式下，派车或改派后司机有邮箱就自动发；没邮箱就提示调度员手动发。
4. 复制链接始终保留作兜底，调度员能看到发送状态并重发。LINE 暂不做。

司机链接打开后能看到乘客姓名和电话，所以这个功能最大的风险是**把能看到客人信息的链接发给不该收的人**。下面的取舍都偏向这一边。

## 决定

### 两种链接：`driver_links.purpose`

| 取值 | 谁生成 | 原文在哪 | 什么时候作废 |
| --- | --- | --- | --- |
| `dispatcher`（旧数据都是） | 派车、改派、重新生成 | 只在那一次应答里 | 改派、救援、手动吊销、重新生成 |
| `email` | 后台任务发信前的那一刻 | 只在要发出去的邮件内容里（内存） | 上面四种，加上司机改邮箱 |

- **ADR 0027 的「一单一条有效链接」改成：一单最多一条有效的 `dispatcher` 链接 + 若干条 `email` 链接，全部属于这一单现在的司机。** 这条约束本来就只在代码里（库里没有唯一索引），现在也一样：`dispatcher` 只有派车和重新生成两处写，写之前都已吊销全单的链接。
- `currentDriverLink` 只认 `dispatcher`：它是调度员手里那一条，重新生成、吊销、订单详情都看它。「司机最近打开」取这一单所有有效链接里最晚的一次（司机从邮件打开时，不能还显示「司机还没打开过」）。
- 吊销语句（`revokeDriverLinks`、`revokeDriverLinksForRescue`）本来就按订单一次吊销所有未吊销的行，**不带 `purpose` 条件**：改派、救援、吊销、重新生成时两种一起作废。
- **不变式**：有效的 `email` 链接存在，有效的 `dispatcher` 链接就一定存在（`email` 链接只在锚点有效时才生成，见下一节；全单吊销不分种类）。所以 `currentDriverLink` 为空时，吊销接口返回 404 不会漏掉邮件链接。
- **司机请求的核对不变**：`withDriver` 不看 `purpose`，照旧按令牌找、锁订单、再读一次、核对现在的司机和有效期。生成邮件链接也在订单锁之内。
- 令牌生成器、格式、哈希都和以前一样（`newDriverToken`）。邮件链接的有效期同样是 `driverLinkExpiry`（用车结束后 24 小时）。
- 库里只有哈希。原文不进发件箱、发送记录、日志、审计；每次尝试发送时新生成（和官网查看链接同一种做法，ADR 0049「不存正文」）。失败的尝试留下的行立即吊销（见「发信失败」）。

### 发送请求：`driver_link_emails`

每次「要发一封」写一行（租户表，只能追加），和发件箱事件在同一个事务里，主键就是事件编号：

`tenant_id, id（= notification_events.id）, seq, order_id, assignment_id, driver_id, link_id（锚点）, trigger（auto / resend）, requested_by, requested_at`

`closed_code`、`closed_at`（迁移 0226）：这次发起**没有发送记录就结束了**。展开时司机已经没有邮箱记 `DRIVER_EMAIL_MISSING`，补回邮箱也不会补发，状态是「还没发」；事件展开出错到上限记错误码（解不开记 `PASSENGER_DECRYPT_FAILED`），状态马上是失败。这两列由后台任务（平台角色）写，触发器只放行这两列，租户仍然只能追加。15 分钟的兜底只留给后台任务根本没在跑的情况。

**为什么要这张表**：租户读不了发件箱（ADR 0049，有意的）。事件还没展开时发送记录也还没有，只靠 `notifications` 分不清「正在等」和「从来没发过」，也做不了可靠的限速；从 `notification_events` 开放读取会削弱 ADR 0049 的约束，所以不选。表里没有邮箱、令牌。

**锚点 `link_id`** 是发起时调度员手里那条 `dispatcher` 链接。一封等着的信只有锚点还有效才发，于是：

- 改派、救援、吊销、重新生成之后，之前排着的信全部作废（锚点都被吊销了）；
- A → B → A 改回去，旧信也不会发（锚点是旧的那条）。

### 发送时复查（都在租户事务里，先锁订单）

`services/driver-link-email.ts`：后台任务发信前开一个**租户事务**（租户编号来自事件），`select … for update` 锁订单，再读锚点、最新请求、供应商设置、司机当前资料，用 `driverLinkSendBlock`（domain 纯函数）判断，都过了才生成 `email` 链接。任何一条不满足都不发，记 `expired`，不能手动重试（`notificationRetryable` 只放行 `EXPIRED`）：

| 情况 | 代码 |
| --- | --- |
| 订单状态不在下面这些之内（已取消、救援中、已转出）；这张单现在的司机不是请求里那一位 | `ORDER_STATE_CHANGED` |
| 锚点链接已吊销或已过期 | `DRIVER_LINK_REVOKED` |
| 这张单后面又发起了一次（只发最新的那次） | `DRIVER_LINK_SUPERSEDED` |
| 供应商改成了手动发送 | `DRIVER_LINK_MANUAL` |
| 司机删了邮箱 | `DRIVER_EMAIL_MISSING` |
| 司机已停用 | `DRIVER_DISABLED` |

能发的订单状态和能重新生成链接的一样：已派车、已出发、已到达、服务中、已完成、客人未出现待审核（司机结束后还可能要传票据、证据）。

**收件人**永远是发送时司机资料里的邮箱，记录的收件人跟着改。

**为什么用租户事务而不是平台事务**：平台角色对 `driver_links` 只能改吊销的两列，给它插入权限等于扩大平台角色的能力；租户事务全程在行级安全之内，也和司机请求同一种锁。

**复查和发信之间的窗口**：生成链接后事务提交，再连邮件服务器（ADR 0049，发信不在事务里）。这几秒里改派或吊销，这条新链接已被一起吊销，信即使发出也是死链接；这几秒里司机改邮箱，下一节的吊销同样让那条链接作废。所以旧地址最多收到一条打不开的链接。

读司机资料时带共享锁（`for share`），和生成链接在同一个事务里：改邮箱锁不到「开始之后才派给他的单」，但它要等这把共享锁，等到时那条链接已提交，它的吊销看得到。少了这把锁，旧地址可能收到一条还能打开的链接（测试用锁固定过这个时序）。

### 司机改邮箱

- 改了地址：这位司机名下还有效的 `email` 链接**全部吊销**（原因 `email_changed`），`dispatcher` 链接不动。场景是地址填错、把链接发给了陌生人，调度员改对之后，发错的那封必须立刻失效，而调度员未必想到去吊销。
- 判断「已发送」时还看这一单有没有有效的邮件链接：改走再改回原地址，地址对得上，但信里的链接已作废，页面提示重发，不说已发送。
- **不自动重发**：一位司机可能有多张单，改一次邮箱不应该连发一串；订单详情提示「司机邮箱改过了，之前那封里的链接已作废」，调度员点「重发邮件」。还在等的信发到新地址。
- 锁顺序：先按编号锁这位司机在途的订单，再锁司机行。派车和后台任务都是先锁订单、写外键时才碰司机行（`for key share`），顺序相反会死锁。

### 链接跟着订单走（负责人决定，2026-11-02）

- **取消即失效**：所有取消路径（付过款的、没付款的）和取消同一个事务把这一单的链接全部吊销（原因 `cancelled`）；`withDriver` 再挡一道，迁移 0225 把之前已取消的单一起作废。
- **有效期跟随当前用车时间**：改期**生效**时，没吊销、没过期的链接（调度员的和邮件的）按新用车时间重算，延后和提前都一样；待确认、被拒都按原时间。已吊销的、已过期的不复活。
- 链接过期之后才改到更晚：重发返回 409 `DRIVER_LINK_NOT_ACTIVE`（请重新生成），不说「用车结束已超过 24 小时」；只有按现在的用车时间确实过了才是 `DRIVER_LINK_EXPIRED`。
- 实现和测试（`driver-links-lifecycle.itest.ts`、迁移 0225）从 M4-29 取，只留链接相关的部分，文件名和编号不变。这份测试的 `requestReschedule` 改过一处：M4-27 上只有离用车不到 24 小时的改期才要确认，所以把时钟拨近，两边都走确认这条路。

### 发信失败（测试发现的风险）

- **任何一次发信失败都吊销这次生成的邮件链接**（原因 `send_failed`），重试时另生成。理由：正文发完之后才被拒、或超时，令牌可能已经到了对方服务器，链接不能继续有效。代价：极少数「服务器其实收了、应答丢了」的信里是死链接，但重试会再发一封能用的；重试用完是失败，页面看得到。
- **吊销是尽力而为**：吊销出错只记日志（`notification.driver_link_revoke_failed`），链接到期才失效。
- **剩下的缺口**：发送途中进程退出（`OUTCOME_UNKNOWN`）时没有人执行吊销，这条链接还有效，到期或被改派、吊销时才失效。发件方不知道那封发出去了没有，记录是最终失败、页面说明可能已发出，调度员可以点吊销。不加启动时清理：要把链接和发送记录关联起来，为这个极少见的情况不值得。

### 限速的范围（测试发现的风险，结论是不改）

限速只挡重发，**不挡派车和改派自动发的信**（它们仍然计入次数）。原因：负责人要求不能阻塞派车，也不应该出现「派了车但因为限速没发信」这种要调度员自己发现的情况。滥用方面：改派要带订单版本号、走完派车校验、写审计日志，每次都作废上一条链接，发出去的也只是这家自己司机的邮箱。账号被盗时的上限因此不严格等于 200 封/小时，审计能查到。

一家的总量在订单锁之外另有一把这一家的咨询锁（事务结束释放）：订单锁只挡同一张单，几张单同时重发不能都读到「还差一次」。这把锁在订单锁之后拿，拿到后不再等别的锁，不会死锁。

### 手动模式、没邮箱

都不写请求、不生成邮件链接。页面提示调度员手动发。手动模式下「重发邮件」也不可用（409 `DRIVER_LINK_EMAIL_MANUAL`）：管理员选了手动，可能就是不想让系统给司机发信，调度员不能绕过这个设置。

**重新生成不自动发信**：调度员重新生成多半是因为怀疑链接泄露（包括邮箱）。旧的邮件链接一起作废，页面提示可以点「重发邮件」。

### 重发

`POST /tenant/v1/orders/{id}/driver-link/email`，`order.dispatch`，写审计（资源 `driver_link`，动作 `retry`，只有订单编号和打码地址）。**只是发邮件，不动现有链接**。

- 没有有效链接：409 `DRIVER_LINK_NOT_ACTIVE`（吊销之后不能靠重发绕过去，要先重新生成）。过期：409 `DRIVER_LINK_EXPIRED`。没邮箱：409 `DRIVER_EMAIL_MISSING`。司机已停用：409 `DRIVER_DISABLED`，不写请求、不占限速，发送状态的 `can_resend` 也是 false（排着的信发送时才发现停用的，仍记 `DRIVER_DISABLED`）。
- **连点保护和限速**（`DRIVER_LINK_EMAIL_LIMITS`）：同一张单 60 秒内只能发起一次（含自动发的那次）、一小时最多 5 次；同一家供应商一小时最多 200 次（账号被盗时不能拿它当群发工具）。超了 429 `RATE_LIMITED` + `retry_after_seconds`。判断在订单锁之内，同时点两下只有一下成功。
- 只发最新的一次，前面还在等重试的作废（`DRIVER_LINK_SUPERSEDED`）：不会排了几封一起到。

### 司机邮箱的隐私

- 列 `drivers.email`，可空。校验用现有的 `emailSchema`（trim、小写、长度、格式），拒绝控制字符；库里另有检查约束，防头注入。
- `PUT /drivers/{id}` 不带 `email` 表示不改（老的 API 调用方不会把邮箱清掉）；带 `null` 才是清空。
- **谁能看全**：`GET /drivers…` 只有有 `fleet.manage` 的（管理员、调度，他们要能改）；只读角色只有 `email_masked`。`/assignable`、订单详情、派车应答一律只有打码后的。
- 平台接口没有司机邮箱字段；发送记录打码（`maskEmail`，ADR 0049）。
- 审计里存打码后的地址，另加 `email_changed`（两个不同地址可能打码后一样）。
- 日志不写地址。发件箱 `data` 只有编号。
- 幂等记录（`idempotency_keys`）里存着新增司机时的应答，含完整邮箱，和电话同等保护（行级安全，只有这家读得到）。这是现有机制，不单独处理。

### 邮件内容

事件 `order.driver_link`，接收方 `driver`，变量白名单 `DRIVER_VARIABLES`：`driver_name, order_no, service_time, trip_summary, vehicle_group, driver_link_url, link_expires_at`。

- **没有**客人姓名、电话、邮箱、对外价、加价比例、结算价（规则 4；单元测试扫模板，集成测试扫真实邮件）。
- `trip_summary` 只有城市、方向、机场或车站：**不写客人填的详细地址**。ADR 0049 给供应商的邮件有地址，但司机的个人邮箱不在我们控制范围内，邮件会长期留存；详细地址打开链接能看到。
- 写明「不要转发，链接能看到客人信息」。

### 免打扰：不适用

免打扰是**供应商员工**的设置（ADR 0049），司机不是员工，也没有地方设。这封信是调度员刚做的派车操作的直接结果，晚发可能误事：**一律马上发**，不进 `notificationQuietUntil`。代价是司机半夜可能收到邮件；邮件本身不响铃，比「临近用车被压到用车之后」的后果轻。

### 有效期

用 ADR 0049 的默认（事件后 7 天），不用用车时间：用车之后重发（司机要传票据）也必须能发。值不值得发由发送时的复查决定；邮件长期没配置时，配好后已结束超过 24 小时的单因为锚点过期不会发。

### 不阻塞派车

业务事务只写请求和发件箱。发信失败、邮件没配置都走通知中心的重试和最终失败（ADR 0049）。派车应答里的发送状态在事务内算好；判断「邮件有没有配置」放在事务之后，出错只影响这一个提示，不影响派车结果。

### 发送状态

`driverLinkEmailView`（domain 纯函数），派车应答、重新生成应答、订单详情和 `GET /tenant/v1/orders/{id}/driver-link/email` 同一份：

| `state` | 含义 | 页面 |
| --- | --- | --- |
| `pending` | 等待中（含等重试；`error_code = NOT_CONFIGURED` 时提示手动发） | 正在发到 `x***@…` |
| `sent` | **邮件服务器已接收**，不代表司机已收到 | 已发送（邮件服务器已接收） |
| `failed` | 最终失败、作废，事件展开出错到上限，或超过 15 分钟没结果（后台任务没在跑） | 发送失败 + 中文原因 |
| `manual` | 手动模式 | 当前设置是手动发送 |
| `no_email` | 自动模式，司机没邮箱 | 这位司机没有邮箱，请手动发 |
| `not_sent` | 这条链接还没发过（重新生成之后；改过邮箱之后 `address_changed = true`） | 可以点重发 |
| `no_link` | 没有有效链接 | 不显示重发 |

失败原因只给我们写的中文（`driverLinkEmailErrorText`），不把 SMTP 配置类的提示给供应商。

### 设置

`tenant_notification_settings.driver_link_delivery`（`auto` / `manual`，默认 `auto`，没有这一行也算 `auto`），经现有的 `GET/PUT /tenant/v1/notification-settings`：看 `notification.read`，改 `notification.manage`（管理员），有版本号和审计。`PUT` 不带这一项表示不改。

### 租户读发送记录

`notifications_tenant_audience_only` 放宽为 `audience in ('tenant', 'driver')`：订单详情要读这一单发给司机的状态。发给客人、发给员工的仍然读不到。`GET /tenant/v1/notifications` 显式只列 `audience = 'tenant'`，含义不变（发给自己这家的）。

### 供应商 API 和 Webhook

- `POST /assign`、`POST /driver-link` 的应答多 `driver_link_email`（状态，没有令牌）；`GET /orders/{id}` 多 `driver_link_email`。
- **Webhook 不带发送状态**：`order.assigned` 推送时信还没发，带了也是「等待中」，反而让人以为可靠；要状态调上面的接口。推送里从来没有令牌，这点不变。

### 没有新增权限和菜单

权限沿用 `order.read`、`order.dispatch`、`fleet.manage`、`notification.manage`，菜单不变。

## 回退

- 关掉功能：把供应商设置改成手动，或不填司机邮箱。复制链接一直在。
- 代码回退：新列和新表都是加法，老代码不读它们。残留的 `email` 链接老代码按令牌也能用，到期失效；老代码的 `currentDriverLink` 可能把它当成当前链接，只影响显示，全单吊销仍然作废它们。

## 不做

| 内容 | 为什么 |
| --- | --- |
| LINE、短信 | 负责人决定暂不做 |
| 「司机已收到」 | SMTP 做不到（ADR 0049），文案只写邮件服务器已接收 |
| 其他语言的司机邮件 | 模板只有中文，和 ADR 0049 一样；司机有语言字段，要多语言时按它选 |
| 邮件里放详细地址、客人姓名 | 见「邮件内容」 |
