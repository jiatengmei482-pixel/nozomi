# ADR 0089：包车按行程计价——最终报价公式

- 状态：已采纳（业主 2026-11-13 定，经监工转达；M9W-01 实施）
- **部分被 ADR 0093 取代**（2026-11-14）：第 1 节公式里的「超时费」（新询价下单时不再收，超时由供应商服务后提交）、第 3 节「选套餐（服务层）」（改为各商品在引擎里按「套餐价 + 超公里费」取最低自选套餐后再比价）。第 2、4、5 节不变；部署前的订单改期照旧。
- 修改 ADR 0088：取代 0088「范围」里「不预收超公里」的那一句；0088 的途经加价规则、经停点、价格明细、页面等其余决定全部不变。
- 业主原话：上车地点加价 + 经停区域加价 + 下车地点加价 + 总公里数限制加价 + 时间限制加价 + 车型加价 = 最终报价。

本篇取代 ADR 0088「不做：预收超公里、按时长自动选套餐」：包车可以**按行程计价**，超公里、超时在报价时就算进一口价。不按行程计价的包车询价（不给 `itinerary_pricing`）和上文完全一样。

### 1. 公式

```
最终价 = 车型套餐价（按「行驶 + 各点停留」总时长选的套餐）
       + 上车区域加价 + 经停区域加价（按第 3 节去重） + 下车区域加价
       + 超公里费 = max(0, 全程公里 − 套餐含公里) × 超公里单价
       + 超时费   = max(0, 总时长 − 套餐时长) × 超时单价（每小时，按分钟比例）
       → 再过调价规则（作用在以上合计上）→ 平台加价
```

单价、含公里、套餐时长取自现有包车套餐规则（`charter_package` 的 `packageKm`、`overtimePerHourMinor`、`overKmPerKmMinor`），询价时锁定。公式就是 `basePrice` 里原有的包车公式，只是报价时第一次把用量传进去（以前包车报价时用量为空、超出部分全部服务后加收）。客人按最终价付款；只有当天超出预计的部分走现有的服务后加收。

### 2. 引擎

- `QuoteRequest` 加可选 `routeUsage: { meters, minutes }`（只有包车能给，非负整数，上限 5000 公里、7 天）；给了就作为包车的用量传给 `basePrice`，超时、超公里和套餐价、区域加价一起过调价。不给时用量仍为空，报价逐分不变（golden、`area-surcharge.test.ts` 原样通过）。
- 结算价明细加 `itinerary`（全程米数、总时长、套餐含公里、套餐分钟、超出米数、超出分钟、两个单价、超公里费、超时费），只在按行程计价时写；`areaSurcharge.packageMinor` 只是套餐价（扣掉超公里、超时）。拆分用和 `basePrice` 同一个函数 `charterOverage`。
- 对外价明细 `price_breakdown` 按顺序：套餐（`base`，倒算吸收尾差）、上车加价、经停加价（逐区域）、下车加价、超公里、超时、调价、其他费用；各项之和等于对外价。

### 3. 选套餐（服务层）

每个车型组选**能覆盖总时长的最小套餐**；所有套餐都覆盖不了时用最大套餐 + 超时费。做法：取这个城市官网能选的套餐时长（同 `GET /site/v1/cities/{id}/charter-packages`），先按「能覆盖的」从短到长、再按「覆盖不了的」从长到短逐个询价（带同一份 `routeUsage`），每个车型组取第一个报得出价的那一档。这样不改比价和快照的结构；代价是一次询价会生成几档的报价和询价日志（只有选中的报价返回给客人，其余 30 分钟后过期）。

### 4. 路线

服务器逐段估路线：上车点 → 经停点 1…N → 下车点，每段用现有路线估算（ADR 0042，同一对坐标有缓存、受每日上限，限时同报价的外部调用）；全程米数 = 各段之和，总时长 = 各段行驶分钟 + 各经停点停留分钟。**全程和时长只由服务器算，不接受客户端传的数字。** 某一段取不到 → 422 `ITINERARY_ROUTE_UNAVAILABLE`（`details.leg` 第几段，从 1 起），页面提示联系客服。

接口：`POST /site/v1/quotes` 包车给 `itinerary_pricing: true` + `pickup` + `dropoff` + 可选 `waypoints`（含 `stay_minutes`），不给 `package_hours`（给了 400 `NOT_APPLICABLE`）；应答多 `itinerary_route { legs[{minutes, meters}], drive_minutes, stay_minutes, total_minutes, total_meters }`（不叫 `route`：按两个坐标报价的应答里 `route` 已是路线预览），每个报价的 `package.hours` 是选中的套餐，`price_breakdown` 含 `over_km`、`overtime`。快照的 `request` 锁定 `waypoints`、`routeUsage`（含逐段 `legs`、停留合计）和选中的 `packageHours`。

### 5. 订单

订单的 `package_hours` 是选中的套餐；路线合计、套餐含量、超出量随结算价明细（`settlement.itinerary`）锁定。订单详情（渠道、官网、供应商、运营）和司机页给 `itinerary`（只有量，没有金额）；供应商、运营的结算价明细另有超公里费、超时费。改期按快照的 `request`（含 `routeUsage`）重算；救援改派显式传 `routeUsage`。事后补收照现有流程。
