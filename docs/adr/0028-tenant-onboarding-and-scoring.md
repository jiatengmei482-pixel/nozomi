# ADR 0028：供应商入驻、资质审核、合同、状态机、履约评分

- 状态：已采纳（2026-10-25，M4-01）
- 实现 ADR 0020 留给 M4-01 的 `TenantStandings`（评分、已完成订单数、观察期）和待定事项 17（准入过滤：试运营每日订单上限、资质有效）。
- 补充 ADR 0008：租户状态从「启用 / 暂停」两种扩成完整的入驻状态机；「暂停不影响登录」不变。
- 补充 ADR 0023：双人复核新登记三类——人工暂停供应商（`tenant.suspend`）、清退（`tenant.terminate`）、合同版本（`tenant.contract`，「修改租户结算条款」）。
- 补充 ADR 0010：迁移 0030 新增九张租户表的授权。
- 编号说明：ADR 0027、迁移 0025–0029 留给 M3-02（派车、司机 H5、租户 Webhook），合并时按实际顺序调整。

## 背景

需求：《平台运营端与渠道对接》「租户管理」（状态表及进入条件、资质审核、营运资质为必审项、合同与结算条款、履约评分、租户详情页）、
「履约保障与服务标准」（救援计 1 次履约失败；30 天内司机未到 2 次观察、3 次暂停；中标排序的准入过滤）、「敏感操作双人复核」（停用租户、修改租户结算条款）、数据模型 `tenant_contract`、`tenant_score_daily`；
《用车报价服务平台》「12. 资质认证」「评分与中标分析」（租户看到自己的履约评分各项）、数据模型 `company_document`、API 表「资质：`GET/PUT /company`，`POST /company/documents`」。
文末决策：第三轮（评分低于 4.0 观察、低于 3.5 暂停；试运营 10 单 / 30 天 / 20 单）、第四轮（租户端不返回对外价和加价比例）、第五轮 ②（价差 3% 内评分高者中标、观察期 +5%、90 天滚动）。
roadmap 的验收标准：90 天滚动评分；观察 / 暂停自动触发。

### 状态和转换

| 状态 | 能做什么 | 怎么进来 | 谁 |
| --- | --- | --- | --- |
| `applying` 申请中 | 填企业信息、上传资质；建区域、商品（不能上架） | 招商在后台建（新建的供应商都从这里开始）；审核中被驳回 / 要求补充一项必交资质 | 平台 / 系统 |
| `reviewing` 审核中 | 等审核（可以继续交资质） | 「提交审核」：企业信息填齐 + 每项必交资质都有一份审核中或已通过、没过期的 | 供应商管理员 |
| `signed` 已签约 | 建区域、商品，**不能上架** | 「签约」：必交资质全部审核通过且有效 + 有一份已生效的合同 | 运营 |
| `trial` 试运营 | 上架、参与比价，每日订单上限 10 单 | 「开始试运营」：至少 1 个商品通过上架校验 + 完成一次测试单（运营写测试单的说明）+ 资质有效 | 运营 |
| `active` 正式 | 无上限 | 每日检查：试运营满 30 天、试运营以来完成 ≥ 20 单、没有成立的重大投诉 | 系统 |
| `suspended` 暂停 | 商品不参与比价、不能下单；已有订单继续履约；照常登录、维护商品（可以上架，恢复后马上能卖） | 系统：必交资质过期、评分跌破 3.5、30 天内司机未到达到 3 次；运营：人工暂停（双人复核） | 系统 / 运营 |
| `terminated` 已清退 | 只能查看；所有修改 409 `TENANT_TERMINATED` | 清退（双人复核），要求没有未履约完的订单 | 运营 |

- 只有试运营、正式参与比价（`tenantBids`）。报价引擎找商品时，不参与比价的给出原因：`TENANT_SUSPENDED`（暂停）或新的 `TENANT_NOT_ONBOARDED`（还在入驻中、已清退）。下单时同样核对（409 `QUOTE_NO_LONGER_AVAILABLE`）。
- **观察期不是一个状态**，是试运营 / 正式（以及暂停中的）供应商身上的标记：`observation_reasons`（评分低于 4.0、近 30 天司机未到 2 次）。原因每天按最新数据重算，都没有了自动退出。排序价 ×1.05（ADR 0020 已实现），只用于比较。暂停中照样重算，恢复后马上生效。
- **暂停可以有几个原因**（`suspension_reasons`：`manual`、`document_expired`、`score_below_red_line`、`driver_no_show`），全部消除才恢复；恢复回到暂停之前的状态（`suspended_from`，试运营或正式）。
  - 运营**人工恢复**清掉全部原因（「需运营人工恢复」），直接生效（和启用渠道一样，需求只要求停用复核）；**还有过期的必交资质时不能人工恢复**（409 `DOCUMENTS_INVALID`）。
  - 只因资质过期而暂停的：供应商换上新证件、审核通过的那一刻自动恢复（每日检查也会补做）。
- 每次状态、暂停原因、观察期变化都经同一个函数 `applyTenantChange`，在同一个事务里：改主体（`version` 加一）、写一行状态记录 `tenant_status_events`（动作、前后状态、前后的暂停和观察原因、操作者、说明、复核编号）、写一条审计、需要时给供应商一条提醒。
- **租户角色不能改 `tenants`**：供应商点「提交审核」也在平台事务里做（租户编号只来自令牌）。否则供应商的代码出错时能把自己改成「正式」。

### 自动触发的口径（每日检查）

- **「跌破」而不是「低于」**：评分自动暂停要求「上一次不低于 3.5、这一次低于 3.5」（第一次算就低于也算）；司机未到要求「上一次不到 3 次、这一次 ≥ 3 次」。
  评分的「上一次」是**上一次按数据算出的分**：今天以前最近一天不是默认分（完成满 20 单）的那天的分（`tenant_score_daily` 里 `is_default = false` 的最近一行），默认分的日子跳过；从来没有按数据算过的，算「第一次」。
  默认 4.5 不是「回升」：人工恢复后单数短暂掉到 20 单以下（比价用默认分）、再回到 20 单而分数仍低于 3.5 的，不会再被自动暂停；新供应商第一次满 20 单就低于 3.5 的照常暂停。
  运营人工恢复以后分数还没回升，第二天不会马上又被暂停（否则「人工恢复」没有意义）；回升到 3.5 以上再跌破会再暂停。观察期没有这个问题（不需要人工恢复），按「低于」每天判断。
- **默认分不触发**：完成不足 20 单时比价用默认 4.5，也不据此进观察、暂停。
- **资质「过期」只算审核通过过、到了到期日、还没换上新的**。从没交过不算过期：M4-01 之前就在运营的供应商（迁移把它们原样保留为「正式」）没有资质记录，不会因此被自动暂停；运营在详情页能看到它们缺哪些资质（见「待定事项」1）。
- 到期日当天起不算有效（需求「到期当天租户自动转暂停」）。
- 试运营转正式先于暂停判断：同一天既满足转正式又要暂停的，记下「暂停之前是正式」。

### 每日检查（`TenantJobs`）

- 跑在 API 进程里（ADR 0022 的做法）：启动后 10 秒第一次，之后每小时一轮；只有服务进程启动，测试直接调 `tick()`。
- 「今天」按 `Asia/Tokyo`（`TENANT_RULES.timeZone`）：资质到期、合同生效、每日评分、试运营每日上限都按它。东京午夜后的第一轮就把「到期当天」的暂停做掉。
- 每个供应商每天只做一次（`tenants.evaluated_on`）：每一家在自己的平台事务里 `for update skip locked` 锁住、确认今天还没做，再做。一天跑几轮、几个实例同时跑都只做一次；一家出错不影响别的，下一轮再做。已清退的不做。
- 做的事：到期提醒（30、7 天各一次；7 天内只发 7 天那档）和到期通知 → 评分 → 转正式 → 观察 / 暂停 / 资质恢复 → 记下评分结果。

### 资质

- **按国家的必交清单**（domain 的常量，改要改代码）：日本——登记簿謄本、一般乘用旅客自动车运送事业许可（绿牌）、旅客赔偿责任保险、营运车辆商业保险（「营运资质为必审项」）、结算账户证明；
  其他国家——《用车报价服务平台》「12. 资质认证」的营业执照、旅客运输许可、保险证明（营运车辆商业保险）、结算账户。国家在企业信息里填，提交前没填按通用清单显示。
- 营运许可、保险**必须**有到期日（不能已到期）；营业执照可填；登记簿、结算账户证明没有到期日。
- 每次提交一行（`tenant_documents`，按序号排先后）：新交的一份审核中时，同类型已经通过的那份照常有效；新的一份通过时，同类型更早的全部变成「被取代」。只能审每个类型最新提交的那份（409 `DOCUMENT_SUPERSEDED`）。
- 审核：通过（可以照证件改正到期日）/ 驳回（必填原因）/ 要求补充（必填原因）。审核中被驳回或要求补充一项必交资质：退回申请中。每次都给供应商一条提醒（带原因）。
- 「到期后商品自动下架」（《用车报价服务平台》12）和「到期当天租户自动转暂停」（《平台运营端》，更新、更具体）效果一样：商品不参与比价。这里按后者做，商品自己的上下架状态不动——恢复以后不用供应商重新上架。
- 「过期自动下架相关车辆」要等车辆（M3-02）：车辆证件到期由派车那边的「证件过期的不能派」处理。

### 文件存在哪里

和 M3-02（ADR 0027 的照片）同一个做法：存在 PostgreSQL（`tenant_files.data`，`bytea`），不存本机文件、不接对象存储——单机 Docker Compose、以后可能多实例，库里的文件随每日数据库备份一起备份和恢复，和资质记录在同一个事务里写入。
任务说明里提到「最小的本机存储接口」；考虑到 M3-02 已经定了库内存储、本机文件要另外挂卷和备份，这里没有另起一套，合并 M3-02 时两边的格式判断可以合成一个函数。

- 只收 PDF、JPEG、PNG，按文件开头的字节判断，和请求头声明的 `Content-Type` 不一致（`application/octet-stream` 除外）415；空文件 400；超过 10 MB 413。请求体就是文件本身（不引入 multipart 依赖），文件名放在查询参数（去掉路径、控制字符、引号，最长 200 字）。
- 下载原样返回：`Content-Disposition: attachment`（UTF-8 文件名）、`X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; sandbox`、`Cache-Control: no-store`。
- 访问控制：供应商只读得到自己的（行级安全 + 每条 SQL 带 `tenant_id`，别人的文件 404）；平台只有 `tenant.review`（超级管理员、运营、招商）能下载——资质里有结算账户证明。
- 「结算账户（账户号加密存储）」：本期只收证明文件，不单独存账户号；账户号和付款一起在财务任务做（要一把单独的加密密钥）。

### 合同

- 每个供应商可以有多个版本（`tenant_contracts`）：版本号、生效日期、结算币种（平台支持的任一币种）、合同扫描件（可选）、说明；固定条款按已确认的写死——月结、次月 20 日付款、平台不收服务费、不收保证金。
- 新版本「修改租户结算条款」走双人复核（`tenant.contract`）：发起（`tenant.review`）→ 另一位 `tenant.approve` 批准后写入。生效日期不早于今天（不追溯）、晚于已有的最后一个版本；批准时核对发起之后没有别的版本插进来（`APPROVAL_STALE`）。
  「不追溯」在批准时再按批准当天（东京日期）核对一次：发起时生效日期是今天、过了午夜才批准的，生效日期已在过去，批准返回 409 `CONTRACT_VALID_FROM_PASSED`，什么都不写，复核仍是待审核（ADR 0023「任何一步失败整个回滚」）；审核人驳回或发起人撤回后按新的生效日期重新发起。不在批准时自动把生效日期改成当天——双人复核批的是发起时写明的条款，审核人没看过的日期不应生效。
- 某一天生效的是生效日期不晚于它的最后一个版本。电子签不做；违约金阶梯在「履约保障」和账单任务里用，不在合同表里重复。供应商能看自己的合同版本。

### 履约评分

**输入**（近 90 天，`[今天往前 89 天的 0 点, 现在)`）：

| 指标 | 来源 | 谁写 |
| --- | --- | --- |
| 完成订单数 | 订单状态流水里变成「已完成」、现在仍是已完成的单 | 订单（M3-02 履约回传） |
| 按时派车率 | `tenant_performance_events`，`kind = dispatch`，`on_time` = 截止时间前派车 | 派车（M3-02） |
| 准时到达率 | `kind = arrival`，`on_time` = 用车时间前到达上车点 | 司机 H5 / 履约回传（M3-02） |
| 客人评价均分 | `order_reviews`（1–5 分，一单一条） | 客人订单页（M3-05） |
| 投诉率 | `kind = complaint`（成立的投诉；`major` = 重大投诉，影响转正式） | 工单判定（M3-06） |
| 履约失败率 | `kind = failure`，`failure_type` = 救援改派 / 司机未到 / 重大迟到 | 救援（M3-04）、工单 |

两张输入表已经建好、接进了计算，写入口（`recordPerformanceEvent`、`recordOrderReview`）也在；**现在还没有任何代码调它们**——派车、履约、救援、工单、评价都在后续任务。在那之前所有供应商都按默认 4.5，和 ADR 0020 一样；比价按已完成订单数、排序价（第二轮决策「一期可先用已完成订单数排序」）。同一单同一类只记一次（唯一约束）。

**公式**（满分 5 分）：按时派车率、准时到达率 × 5；评价均分；投诉 = 5 × (1 − 成立的投诉 / 完成订单)；失败 = 5 × (1 − 失败次数 / (完成订单 + 失败次数))；按 25 / 25 / 20 / 20 / 10 加权（第三轮决策「五项权重沿用」）。
某一项没有数据就不算这一项，其余权重按比例放大；一项都没有为空。全程整数分数，最后四舍五入到百分之一分一次。**完成不足 20 单用默认 4.5**（按数据算出的分照样记下给人看）。

- 每天每个供应商一行 `tenant_score_daily`（输入的各个数、按数据的分、比价用的分、是不是默认分）：评分趋势；主体上另存最新一次的结果（比价每次询价都要读，一条按主键的查询）。
- **供应商能看到自己的评分**：需求「租户可在自己后台看到各项指标」「评分与中标分析：租户看到自己的履约评分各项」。`GET /tenant/v1/performance`（每个角色都能看）给最新一次的各项指标、权重、得分、近 90 天趋势和观察 / 暂停的规则；看不到别的供应商的分、对外价、加价比例。

### 接进报价引擎和下单

- `TenantStandings`（ADR 0020）的实现：按数据的分（为空 → 默认）、近 90 天完成订单数、观察原因是否为空。每次询价现查，不进商品目录的缓存。
- 准入过滤：只有试运营、正式参与比价；**试运营当天（东京时间 0 点起）接的、没取消的单达到 10 单**的不参与比价（新原因 `TRIAL_DAILY_LIMIT`，渠道看到的是 `NOT_AVAILABLE`），每次询价现数。
- 下单时再核对一次：先拿「这个供应商的试运营上限」的事务级咨询锁，数完再建单，并发也不会超过 10 单；超了 409 `QUOTE_NO_LONGER_AVAILABLE`（`reason: TRIAL_DAILY_LIMIT`）。待支付的单也算（不然并发能同时占住第 11 单）；超时取消的不算。
- 供应商状态在商品目录的缓存里（30 秒，ADR 0020），所以暂停、清退在询价里最迟 30 秒后生效；下单那一步现查，不会卖给已暂停的供应商。

### 权限

| 操作 | 角色 |
| --- | --- |
| `tenant.read`：看企业信息、资质（不能下载文件）、合同、状态记录、评分、审核队列 | 原有：超级管理员、运营、招商、渠道经理、只读 |
| `tenant.review`（新）：审核资质、上传 / 下载文件、发起合同版本 | 超级管理员、运营、招商 |
| `tenant.change_status`：签约、开始试运营、恢复、**发起**人工暂停和清退 | 原有：超级管理员、运营、招商 |

## 待定事项（需求文档没写清；先按推荐做了）

| # | 问题 | 选的方案 | 理由 |
| --- | --- | --- | --- |
| 1 | M4-01 之前已经在运营（「正式」）的供应商没有资质记录 | 原样保留为正式，不自动暂停；详情页显示缺哪些资质，由运营通知补交 | 一上线就把全部现有供应商暂停会断掉所有报价；「资质过期」按字面只管到期的 |
| 2 | 「完成一次测试单」怎么证明 | 运营开始试运营时写测试单的说明（必填，进状态记录） | 现在还没有「测试单」这种订单类型（不付款、不派给客人）；做成订单类型需要和下单、派车一起定 |
| 3 | 评分自动暂停后人工恢复，分数没回升时 | 不会第二天又被暂停；回升到 3.5 以上再跌破才再暂停（「跌破」口径）；中间不足 20 单用默认分的日子不算回升 | 否则人工恢复只能维持到下一次每日检查 |
| 4 | 「无重大投诉」的范围 | 试运营以来没有成立的重大投诉（投诉事件 `major`） | 重大与否由工单判定时标记（M3-06） |
| 5 | 资质到期是暂停供应商还是下架商品 | 暂停供应商（商品状态不动） | 两份文档写法不同，以更新、更具体的《平台运营端》为准；恢复后不用重新上架 |
| 6 | 新供应商的入口 | 只有招商在后台代建；没有公开的「入驻申请」页 | 公开页要防刷、验证邮箱，没有邮件服务时做不完整；需要时单独做 |
| 7 | 「今天」用哪个时区 | 东京时间 | 平台和首批供应商在日本、韩国（同一时差）；有别的时区的供应商时按国家分开 |
| 8 | 试运营的「每日订单」按下单日还是用车日 | 按下单时刻（东京时间的这一天） | 上限是控制新供应商一天接多少单的风险；按用车日会让一天里接下几十张未来的单 |
| 9 | 人工暂停、清退、合同都走双人复核；恢复直接生效 | 同左 | 需求「停用租户」「修改租户结算条款」要复核；启用不会让客人多付钱（ADR 0023 同样的取舍） |
| 10 | 已清退要求「账单结清」 | 现在只核对订单都履约完（没有未完成的单） | 账单在财务结算任务；到时在发起和批准时加上 |
