# ADR 0024：机场的中文名、日文名从 GeoNames 导入

- 状态：已采纳（2026-10-18，M1-15）
- 补充 ADR 0012（主数据、机场从 OurAirports 导入）和 ADR 0014（城市从 GeoNames 导入）。不改变其中的决定；数据来源、署名、下载、事务、咨询锁、版本核对、严格 UTF-8 的做法和城市导入相同，下面只写不同的地方。

## 背景

OurAirports 只有英文名，导入的机场要由平台逐个补上中文名、日文名，供应商在接送点里输入「成田」才找得到成田机场。GeoNames 里有机场的多语言名称，城市导入已经在用它（CC BY 4.0）。

## 决定

### 数据来源：同一个国家的两个文件

- `https://download.geonames.org/export/dump/<国家码>.zip`：这个国家的全部地理名称记录（19 列，和城市文件同一种格式；日本约 5MB）。
- `https://download.geonames.org/export/dump/alternatenames/<国家码>.zip`：各语言的名称（城市导入用的同一个文件）。语言一栏是 `iata` 的行就是机场的三字码，`ja`、`zh…` 是日文、中文名。
- 只用名称文件不够：同一个三字码也挂在城市、街区上（2026-10-18 的日本文件里，NRT 同时挂在成田机场和成田市上，HND 同时挂在羽田机场和「羽田」这个街区上，TYO、OSA 挂在东京、大阪上）。所以先用国家文件认出类型是机场（`S` / `AIRP`）的记录，只看这些记录的三字码和名称。
- 没有用全世界的文件（allCountries，压缩后约 400MB）：命令只支持 `--country`，按国家下载。
- 按 2026-10-18 的文件：日本有 133 条机场记录，其中 96 条有三字码，没有一个三字码挂在两条机场记录上。

### 按三字码对应

- 库里类型是机场、编码就是三字码的地点（从 OurAirports 导入的和平台手工建的都算），只看 `--country` 所选国家的。
- 下面这些不填，在命令输出里列为「需要人工处理」：
  - 同一个三字码挂在数据源里好几条机场记录上（分不清是哪一个）；
  - 数据源里这个机场在另一个国家；
  - 两边的坐标相差超过 **10 公里**（两个数据源给同一个机场的坐标一般相差不到 3 公里，10 公里以上多半是三字码挂错了记录）。
- 库里有、数据源里找不到三字码的，单独列出来。

### 选哪个名称

同一种语言有多个名称时的取舍（`packages/domain/src/geonames-airports.ts`）：

1. 历史名称、俗称不取；空白、只有不可见字符、超过 200 字的不取。
2. **日文**：只取标签是 `ja` 的，而且必须有汉字或假名——数据源里标成 `ja` 的有不少是罗马字（「Kansai Kokusai Kūkō」「Tōkyō Kokusai Kūkō」）。中文名同样必须有汉字。名称里夹着字母、数字的（「JR…」）照样取。
3. **中文只要简体**：
   - 标签优先级：`zh-CN` > `zh-Hans` > `zh-SG` > `zh`（和城市导入同一个顺序）；
   - `zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO`（繁体）、`yue`（粤语）、`wuu`（吴语）不取；
   - 只标了 `zh` 的在日本的机场里大多是繁体（「松本機場」「東京國際機場」），所以任何一条中文名里出现繁体专用字（機、場、國、際、東、島……，只收了地名里常见的、在简体里一定写成另一个字的约一百个字）就不要它；
   - 只有繁体的，中文名**留空**，在输出里列出「数据源里只有繁体中文名」，由平台在后台填简体。不做繁简转换（没有可靠又不引入第三方库的转换表）。
4. 剩下的里面：「首选的简称」>「简称」>「首选」> 其余；还一样就取数据源里编号最小的那条（最早录入的，一般是正式名称）。
   不用「最短的」：关西机场的候选里有「関空」，比正式名称短，但不适合做名称。

由此羽田的日文名是「東京国際空港」而不是「羽田空港」（两个都没有标首选，前者编号小）；中文名只有繁体，留空。

### 只填空着的，不覆盖人工修改

- 只填空着的语言（没有这种语言，或者只有空白）。已经有名称的，不管是平台填的还是以前导入的，一律不改；数据源后来改了名，也不更新——要更新请平台在后台改。
- 「人工改过」的判断和城市导入是同一个思路：**记下导入写进去的是什么，以后拿它和现在的值比**。城市用的是一个 `source_overridden` 标记，机场不能直接用它：地点上原有的 `source` / `source_overridden` 记的是 OurAirports 管的英文名和坐标，平台改中文名不会、也不应该把它标成「改过」（否则以后 OurAirports 的坐标更新也被挡住）。所以新增一列 `places.name_sources`（迁移 `0022_place_name_sources.sql`），按语言记下数据源、数据源编号和当时填的文字：
  - 以前由导入填过、现在空了 → 平台在后台删掉了，**不再补回去**；
  - 现在的值和导入写的不一样 → 平台改过，不覆盖；
  - 平台在后台改名称时不需要动这一列，比较就能认出来。
- 这一列只在数据库和审计日志里，不出现在接口的应答里（前端的接口约定测试钉住了 `Place` 的字段）。
- 填名称是一次真正的修改：版本号加一、更新时间改为现在、写审计日志（操作者「系统」、入口「命令行」，`after` 里记 `name_source`：数据源、编号、填了哪几种语言）。不改启用状态、所属城市、英文名和坐标。
- 每次写入核对版本号：导入运行期间平台在后台改过的机场不填，列为需要人工处理。同一时间只允许一次机场名称导入（咨询锁）；整次导入在一个事务里。

### 命令

```
pnpm masterdata:import-airport-names --country JP,KR [--dry-run]
pnpm masterdata:import-airport-names --country JP --file JP.zip --names-file alternatenames/JP.zip   # 不联网
```

- `--file`（国家文件）和 `--names-file`（名称文件）要一起给，都可以给多次（每个国家一个），`.zip` 或解压好的 `.txt` 都行。zip 里取和文件名同名的 `.txt`（两个下载下来都叫 `JP.zip`，放在不同目录即可）。
- 要先有机场：先运行 `pnpm masterdata:import-airports`。可以反复运行。

### 署名

和城市导入相同的位置：每个填进去的名称在 `places.name_sources` 里记着来源和编号，审计日志里也记；命令输出的第一行写明来源和许可；代码、本 ADR、根 `README.md`、`openapi.yaml` 的说明。

**面向用户的页面**：凡是展示机场名称的页面（运营后台的地点页、供应商后台的接送点选项、以后的官网），署名那一行要包含机场名称——例如「城市数据和机场的中文、日文名称来自 GeoNames（geonames.org），CC BY 4.0」。这一条是许可的条件，由前端在下一个涉及这些页面的任务里改（M1-15 只做了后端）。

### 在真实文件上试跑（2026-10-18，日本，`--dry-run`）

在临时的测试 schema 里先导入 OurAirports 的 82 个日本机场，再试运行：82 个全部对上，没有需要人工处理的；将给 71 个机场填名称（日文 70 个、中文 41 个），另外 11 个数据源里没有这两种语言；20 个只有繁体中文名、中文名留空（含羽田、中部、神户、松山、新潟）。成田：日文「成田国際空港」、中文「成田国际机场」；羽田：日文「東京国際空港」，中文留空。

## 没有做的

- 韩文名：`MASTER_DATA_LANGUAGES` 里有 `ko`，但这个任务只要求中文、日文；要导入只需把 `ko` 加进 `AIRPORT_NAME_LANGUAGES`。
- 繁简转换、给繁体名单独存一种语言。
- 航站楼的名称：数据源里没有。
- 数据源后来改名时提示「可以更新」：现在只在输出里列出「以前导入的，数据源后来改了」，不自动更新。
