# ADR 0073：下车区域价——点对点线路价（含返程价格、含公里数）和包车下车区域加价

- 状态：已采纳（2026-11-09；M8-11 起实施）。
  - 业主 2026-11-09 对点对点 B 类的答复：① 做有方向的跨区域线路价，表单加「返程价格」，规则可设「含 X 公里 + 超出每公里 Y」；② 附加费全局生效（保持按商品统一定价）；③ 新车附加费、金牌司机不做。
  - 业主 2026-11-09 对包车结束地点的答复：包车**必须**选下车地点；下车和上车不在同一区域时加钱；包车商品可添加多个「下车区域」，像点对点一样每个下车区域填自己的价格；下车地点不在任何已设区域 = 不报价，转人工。
  - 「没有可订包车时」继续隐藏「按小时包车」标签（M8-03 的做法不变）。
- 补充 ADR 0018（价格规则）：价格规则多一个可空的「下车区域」；固定一口价多一组可选的「含公里数 + 超出每公里单价」；包车多一种「下车区域加价」。
- 补充 ADR 0020（报价引擎）第 4～7 步：点对点先找线路价；包车要看下车点。
- 落实 ADR 0063 第 1 项（当时只是方案、默认双向同价），改为单向。
- 编号：写这篇时 main 上最大是 ADR 0071（M4-34）；0072 由 M8-10 占用，这里用 0073。

## 不变的（硬约束）

- **已有价格规则的含义不变**：新列可空、新参数可缺省。没填下车区域、没填含公里数的点对点、接送机规则，报价结果和今天逐分一致（用现有报价样例做对比测试）。包车现有的套餐价仍然是「同一区域内」的价（见第 2 节「对现有包车商品的影响」）。
- **已下的订单不改、不重算**：新字段只出现在新报价、新订单上。
- 附加服务、司机语言仍按商品统一定价（ADR 0069 B15）；不做新车附加费、金牌司机。
- 一口价仍然包含所有费用（ADR 0069 B12、ADR 0070）：线路价、超出公里、下车区域加价都是**报价时就算进一口价**的，不是服务后加收；车开绕路不加钱。包车原有的服务后加收（超时、超公里等，ADR 0029、0070）不变。
- 区域就是主站现有的报价区域（营运区 + 禁行区，ADR 0015）；不另造区域。
- 对外价、加价比例仍然不出现在 `/tenant/v1`（规则 4）。

## 一、公共底层：价格规则的「下车区域」

`price_rules` 加 `to_area_id uuid null`（外键到同一租户的区域，带 `tenant_id`，RLS 照旧）。现有的 `area_id` 在页面上叫「上车区域」。

| 品类 | 不填下车区域 | 填了下车区域 |
| --- | --- | --- |
| 点对点 | 区域价（今天的做法） | 单向线路价（第二部分） |
| 包车 | 套餐价 = 下车在**同一区域**的价（第三部分） | 下车区域加价（第三部分） |
| 接送机 | 今天的做法 | 不允许（400） |

公共规则（点对点和包车都用，一处实现）：

- 下车区域不能等于上车区域（同区域就是不填）。
- 下车区域必须是本租户的区域；跨租户的区域编号按 404 处理，和不存在一样。
- 冲突检查（409 `PRICE_RULE_CONFLICT`）的组合键加上下车区域：同一（上车区域、下车区域）× 车型组 ×（包车：套餐时长）× 生效日期重叠，只能有一条。
- 报价时判断「点落在哪些区域」沿用第 4 步现有的函数（营运区内、不在那个区域的禁行区里）；上车点、下车点各判一次，再按「上车区域 × 下车区域」找规则。
- 价格页的「下车区域」选择、列表的「线路」一列、导入导出的「下车区域」一列，点对点和包车用同一套组件和同一套导入列。
- 每个新增或改动的 `/tenant/v1` 接口都有「租户 A 读不到、改不了租户 B」的集成测试（含用别人的区域做下车区域）。

## 二、点对点线路价

### 1. 含义

| 下车区域 | 含义 | 命中条件 |
| --- | --- | --- |
| 不填 | **区域价**，和今天一样 | 两端都落在商品的区域里；起终点落在不同区域时这些区域的价都算、取最低（ADR 0020 第 4 步，不变） |
| 填了 | **线路价，单向** | 上车点落在上车区域、下车点落在下车区域；反方向不命中 |

点对点的下车区域还必须是这个商品的区域（两端都要在商品区域里，这一条今天就有）。

### 2. 报价时怎么选

1. 先找**线路价**：上车点所在的每个区域 × 下车点所在的每个区域，有启用、覆盖用车日期、车型组对得上的线路价就用；命中几条取结算价最低的（一样低取商品里排在前面的区域）。
2. 某个车型组没有命中的线路价时，退回**区域价**（今天的做法）。
3. 线路价优先，**不和区域价比低**：供应商专门为这条线路定的价就是这条线路的价。

跨城市（广州 → 香港）仍是 ADR 0069 的 B8，这次不做。

### 3. 返程价格

新增线路价时，表单有一个可选的「返程价格」：

- 填了：**同一个请求里**建两条规则——A → B 用「价格」，B → A 用「返程价格」；车型组、生效日期、含公里数、超出单价、状态相同。两条要么都建成，要么都不建（同一事务；任一条冲突整体 409，列出冲突）。
- 建好以后是两条独立的规则，各自编辑、启停、删除（页面提示写明）。
- 区域价没有返程价格这一项。
- 接口沿用批量新增（`POST …/price-rules/batch`），前端把一条带返程价的表单展开成两条；不另开接口，避免两套校验。

### 4. 含公里数（可选）

固定一口价的参数多两个**可选、要么都填要么都不填**的字段：

| 字段 | 含义 | 范围 |
| --- | --- | --- |
| `includedKm` | 一口价含多少公里 | 整数，1～2000 |
| `overKmPerKmMinor` | 超出后每公里多少钱（最小货币单位） | 整数，0～单价上限（沿用 `PRICE_LIMITS`） |

点对点的区域价、线路价都能用；接送机、包车不用这组字段。

- 距离 = 报价时谷歌路线的距离（ADR 0042，米），**报价时锁定**，存进报价快照和订单。
- 超出公里数 Z = 向上取整到 1 公里：`Z = max(0, ⌈(路线米数 − X × 1000) ÷ 1000⌉)`。例：含 30 公里，30.0 公里 → Z = 0；30.2 公里 → 1；31.0 公里 → 1；31.4 公里 → 2。**取整方式先按此实施，业主如有异议再改**（只改 domain 的一个函数）。
- 结算价 = 一口价 + Z × Y（整数运算）；之后的调价规则、加价、取整、附加服务照现在的流程。
- 设了含公里数的规则，这次报价**拿不到路线距离**时，这条规则不报价（宁可报不出，不少收供应商的钱）；没设的规则不受影响。

## 三、包车下车区域加价

### 1. 含义

包车商品的区域就是「上车区域」（今天的做法：包车只看上车点）。新增「下车区域」：

| 下车地点落在 | 价格 |
| --- | --- |
| 上车点所在的同一区域 | 现在的包车套餐价（车型组 × 套餐时长），**不变** |
| 某个已设的下车区域 | 包车套餐价 + 这个下车区域的加价（按下面业主选定的方式） |
| 不在任何一种 | **不报价**；客人看到「这个下车地点暂时没有在线报价，请联系客服」（沿用现有的人工报价说法） |

- 下车区域可以是本租户的任何区域（不要求是这个商品的上车区域）：比如上车区域「东京 23 区」，下车区域「箱根」「富士山」。
- 下车点也要在那个区域的营运区里、不在它的禁行区里。
- 下车点同时落在几个下车区域：取总价最低的。
- 一口价含所有费用：加价包含在报价里；包车原有的服务后加收（超时、超公里）不变。

### 2. 加价怎么填（**请业主二选一**）

| 选项 | 供应商填什么 | 数据 |
| --- | --- | --- |
| **A（建议）** | 每个下车区域 × 车型组填一个**加价**，不分套餐时长；最终价 = 套餐价 + 加价 | 新的价格方式「下车区域加价」（`charter_dropoff`，参数 `surchargeMinor`），规则的套餐时长为空 |
| B | 每个下车区域 × 车型组 × 套餐时长直接填**全价**；最终价 = 这个全价（不再加套餐价） | 沿用包车套餐价的格式（套餐公里、套餐价、超时、超公里），规则带下车区域 |

建议 A：填的数少（区域 × 车型，而不是区域 × 车型 × 时长），跨区域多出来的主要是单程距离，和包几个小时关系不大；供应商改套餐价时不用逐个区域重填。B 适合各时长差别很大的情况。业主选定之前按 A 设计接口；两种都能放进上面的公共底层，改选项只影响第 2 节和价格页表单。

调价规则（节假日、夜间等）：按 A 时作用于「套餐价 + 加价」的合计，和今天作用于套餐价一样；调价规则的「区域」按上车区域判断。

### 3. 下车地点必填

- 官网 `/site/v1` 的包车询价和下单：**下车地点必填**（坐标 + 地址），订单上存下车点和地址，以后运营、供应商订单详情、司机页、确认邮件都显示。
- 旧预订页 `/book` 的包车：改成跳到新预订页的包车（M8-05 会整体切换）。
- 渠道接口 `/sales/v1`：为了不打断已接入的渠道，下车地点暂时可不填；**不填时只报「没有设下车区域」的包车商品**（这时只有同区域价，没有少收的风险），设了下车区域的商品不报价并给出原因。渠道文档写明以后会改为必填。

### 4. 对现有包车商品的影响（请业主知悉）

今天包车不看下车点。上线以后，**下车地点不在上车区域、也没设下车区域的包车，会从「能报价」变成「转人工」**。现在测试环境只有一个上架的包车商品（东京）。建议：上线前通知有包车商品的供应商先补下车区域；正式环境切换前我列出受影响的商品。

## 四、显示

| 位置 | 点对点含公里数 | 包车下车区域 |
| --- | --- | --- |
| 供应商价格页 | 列表「含 X 公里，超出每公里 Y」（结算价） | 列表「下车区域」和加价（结算价） |
| 官网报价卡片、新预订页、订单页、确认邮件 | 「含 X 公里，本次路线约 D 公里，超出 Z 公里 × Y（已含在一口价里）」，Y 用对外价 | 下车地点；跨区域时写「下车在 XX 区域，已含在一口价里」，不单列加价 |
| 运营订单详情 | 同上，结算价和对外价都显示 | 下车地点、下车区域、加价（结算价和对外价） |
| 供应商订单详情 | 只用结算价（规则 4） | 下车地点、下车区域、加价（结算价） |

- 一口价仍显示为一个总价；这些行是说明，不是另一笔费用。客人看到的每公里对外价单独取整，和总价可能差一个取整单位以内，所以不写「基础价 + 超出 = 合计」的算式。
- 报价快照、订单上存：`to_area_id`、`included_km`、`route_meters`、`over_km`、`over_km_per_km_minor`、`dropoff_surcharge_minor`（结算）和对应的对外价；对外接口只给对外价。

## 五、其他要认识下车区域的地方

| 地方 | 做法 |
| --- | --- |
| 上架检查「该有价格的组合」 | 不变：按上车区域检查；线路价、下车区域加价是可选的补充，不算缺价 |
| 价格日历 | 按线路 / 下车区域分行显示 |
| 价格导入导出 | 加「下车区域」「含公里数」「超出每公里」「下车区域加价」列；旧模板（没有这几列）照旧导入 |
| 销售接口、官网接口的应答 | 只加字段，不改已有字段 |

## 后果

- 点对点和包车共用一套「下车区域」数据、校验和界面，不重复造。
- 已有规则、已下订单不受影响；但包车开始看下车点，没设下车区域的包车商品对跨区域下车不再自动报价（第三部分第 4 节）。
- 设了含公里数的规则依赖路线预估：谷歌不可用时这些规则不报价。
