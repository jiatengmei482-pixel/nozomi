# ADR 0073：区域价——点对点线路价（含返程价格、含公里数）和包车区域加价

- 状态：已采纳（2026-11-09；M8-11 起实施）。
  - 业主 2026-11-09 对点对点 B 类的答复：① 做有方向的跨区域线路价，表单加「返程价格」，规则可设「含 X 公里 + 超出每公里 Y」；② 附加费全局生效（保持按商品统一定价）；③ 新车附加费、金牌司机不做。
  - 业主 2026-11-09 对包车结束地点的答复：包车**必须**选下车地点；上车、下车不在商品本身的区域时加钱；不在任何已设区域 = 不报价，转人工。
  - 业主 2026-11-09 给了参考（另一个平台商家后台的「区域加价」）：包车用**加价模式**，不填全价——商品挂多个加价区域，每个区域分别设「上车加价」和「下车加价」；报价 = 包车基础价 + 上车点所在区域的上车加价 + 下车点所在区域的下车加价；加价按「车型组 × 套餐时长」填，用商品币种。
  - 「没有可订包车时」继续隐藏「按小时包车」标签（M8-03 的做法不变）。
- 补充 ADR 0018（价格规则）：点对点价格规则多一个可空的「下车区域」；固定一口价多一组可选的「含公里数 + 超出每公里单价」；包车多一种价格方式「区域加价」。
- 补充 ADR 0020（报价引擎）第 4～7 步：点对点先找线路价；包车上车点可以在加价区域里，并且要看下车点。
- 落实 ADR 0063 第 1 项（当时只是方案、默认双向同价），改为单向。
- 编号：写这篇时 main 上最大是 ADR 0071（M4-34）；0072 由 M8-10 占用，这里用 0073。

## 不变的（硬约束）

- **已有价格规则的含义不变**：新列可空、新参数可缺省。没填下车区域、没填含公里数的点对点、接送机规则，报价结果和今天逐分一致（用现有报价样例做对比测试）。包车现有的套餐价就是「基础定价」，含义不变（对现有包车商品的影响见第三部分第 5 节）。
- **已下的订单不改、不重算**：新字段只出现在新报价、新订单上。
- 附加服务、司机语言仍按商品统一定价（ADR 0069 B15）；不做新车附加费、金牌司机。
- 一口价仍然包含所有费用（ADR 0069 B12、ADR 0070）：线路价、超出公里、区域加价都是**报价时就算进一口价**的，不是服务后加收；车开绕路不加钱。包车原有的服务后加收（超时、超公里等，ADR 0029、0070）不变。
- 区域就是主站现有的报价区域（营运区 + 禁行区，ADR 0015）；不另造区域。
- 对外价、加价比例仍然不出现在 `/tenant/v1`（规则 4）。

## 一、点对点和包车共用的部分（不重复造）

参考截图里的包车「区域加价」是**按单个区域**分别设上车、下车加价，不是「上车区域 → 下车区域」的线路，所以包车**不用**点对点的「下车区域」这一列。两者共用的是：

| 共用的 | 说明 |
| --- | --- |
| 区域 | 都是主站现有的报价区域（营运区 + 禁行区，ADR 0015）；价格页的区域下拉同一个组件，旁边「新增自定义区域」跳到现有的区域页面 |
| 「点落在哪些区域」 | 报价第 4 步现有的函数（营运区内、不在那个区域的禁行区里），上车点、下车点各判一次 |
| 价格规则的整套设施 | 都存成价格规则（`price_rules`）：生效日期、启停、版本号、批量新增、冲突检查、价格日历、导入导出、权限、审计、规则 4 都沿用 |
| 租户隔离 | 区域必须是本租户的；用别人的区域按 404 处理。每个新增或改动的 `/tenant/v1` 接口都有「租户 A 读不到、改不了租户 B」的集成测试 |

## 二、点对点线路价

### 1. 含义

| 下车区域 | 含义 | 命中条件 |
| --- | --- | --- |
| 不填 | **区域价**，和今天一样 | 两端都落在商品的区域里；起终点落在不同区域时这些区域的价都算、取最低（ADR 0020 第 4 步，不变） |
| 填了 | **线路价，单向** | 上车点落在上车区域、下车点落在下车区域；反方向不命中 |

数据：`price_rules` 加 `to_area_id uuid null`（外键到同一租户的区域，带 `tenant_id`，RLS 照旧），只对点对点开放（接送机、包车填了 400）。

- 下车区域必须是这个商品的区域（两端都要在商品区域里，这一条今天就有），且不能等于上车区域（同区域就是不填）。
- 冲突检查（409 `PRICE_RULE_CONFLICT`）的组合键加上下车区域：同一线路（上车区域、下车区域）× 车型组 × 生效日期重叠只能有一条；线路价和区域价互不冲突。

### 2. 报价时怎么选

1. 先找**线路价**：上车点所在的每个区域 × 下车点所在的每个区域，有启用、覆盖用车日期、车型组对得上的线路价就用；命中几条取结算价最低的（一样低取商品里排在前面的区域）。
2. 某个车型组没有命中的线路价时，退回**区域价**（今天的做法）。
3. 线路价优先，**不和区域价比低**：供应商专门为这条线路定的价就是这条线路的价。

跨城市（广州 → 香港）仍是 ADR 0069 的 B8，这次不做。

### 3. 返程价格

新增线路价时，表单有一个可选的「返程价格」：

- 填了：**同一个请求里**建两条规则——A → B 用「价格」，B → A 用「返程价格」；车型组、生效日期、含公里数、超出单价、状态相同。两条要么都建成，要么都不建（同一事务；任一条冲突整体 409，列出冲突）。
- 建好以后是两条独立的规则，各自编辑、启停、删除（页面提示写明）。
- 区域价没有返程价格这一项。
- 接口沿用批量新增（`POST …/price-rules/batch`），前端把一条带返程价的表单展开成两条；不另开接口，避免两套校验。

### 4. 含公里数（可选）

固定一口价的参数多两个**可选、要么都填要么都不填**的字段：

| 字段 | 含义 | 范围 |
| --- | --- | --- |
| `includedKm` | 一口价含多少公里 | 整数，1～2000 |
| `overKmPerKmMinor` | 超出后每公里多少钱（最小货币单位） | 整数，0～单价上限（沿用 `PRICE_LIMITS`） |

点对点的区域价、线路价都能用；接送机、包车不用这组字段。

- 距离 = 报价时谷歌路线的距离（ADR 0042，米），**报价时锁定**，存进报价快照和订单。
- 超出公里数 Z = 向上取整到 1 公里：`Z = max(0, ⌈(路线米数 − X × 1000) ÷ 1000⌉)`。例：含 30 公里，30.0 公里 → Z = 0；30.2 公里 → 1；31.0 公里 → 1；31.4 公里 → 2。**取整方式先按此实施，业主如有异议再改**（只改 domain 的一个函数）。
- 结算价 = 一口价 + Z × Y（整数运算）；之后的调价规则、加价、取整、附加服务照现在的流程。
- 设了含公里数的规则，这次报价**拿不到路线距离**时，这条规则不报价（宁可报不出，不少收供应商的钱）；没设的规则不受影响。

## 三、包车区域加价

### 1. 含义

| 名称 | 是什么 |
| --- | --- |
| 基础定价 | 现在的包车套餐价（车型组 × 套餐时长 × 商品区域），不变 |
| 商品本身的区域 | 商品现在选的报价区域（今天包车上车点必须在这里） |
| 加价区域 | 新增：商品可以挂多个区域（主站现有区域），每个区域对每个车型组 × 套餐时长填「上车加价」「下车加价」（≥ 0，可以是 0） |

报价：

```
包车价 = 基础定价 + 上车加价（上车点所在的加价区域） + 下车加价（下车点所在的加价区域）
```

- 上车点或下车点在**商品本身的区域**里：这一端加价为 0。
- 在某个**加价区域**里：这一端加那个区域的加价。
- 落在几个区域里：这一端取最小的加价（商品本身的区域算 0）。
- 上车点或下车点**哪里都不在**：不报价，客人看到「这个地址暂时没有在线报价，请联系客服」（沿用现有的人工报价说法）。
- 参考截图的例子（东京 0/0、富士山 1000/1000、千叶 500/500、八王子 800/800）：东京上车、富士山下车 = 基础价 + 0 + 1000；千叶上车、八王子下车 = 基础价 + 500 + 800。
- 金额用商品币种（跟子品牌，ADR 0018），整数最小货币单位。
- 一口价含所有费用：加价包含在报价里；包车原有的服务后加收（超时、超公里）不变。
- 调价规则（节假日、急单、夜间等）作用于「基础定价 + 加价」的合计，和今天作用于套餐价的方式一样；参考截图里的日期溢价、急单、夜间加价主站已有，这次不动。

### 2. 数据

存成价格规则，新的价格方式 `charter_area_surcharge`（参数 `pickupSurchargeMinor`、`dropoffSurchargeMinor`）：

- `area_id` = 加价区域，`vehicle_group_id`、`package_hours` = 对应的车型组和套餐时长，生效日期、启停照旧。
- 冲突检查的组合键加上价格方式：同一区域可以同时有基础定价和加价，不算冲突；同一区域 × 车型组 × 套餐时长 × 生效日期重叠的加价只能有一条。
- 加价区域**不加进**商品的区域列表（商品区域仍然只表示「基础定价的范围」），所以上架检查「该有价格的组合」不受影响。
- 价格页可以「一次给所有车型组和套餐时长填同一个加价」（展开成多条，批量新增，同一事务），再按需单独改。

### 3. 页面（对照参考截图）

供应商商品的「价格」页，包车多一个「区域加价」块：

- 「选择区域」下拉（本租户的报价区域）+「确认添加」；旁边「新增自定义区域」跳到区域页面。
- 列表：加价区域 / 上车加价 / 下车加价 / 操作（编辑、删除）；按车型组和套餐时长切换或展开。
- 删除 = 停用（只停用不删数据，和价格规则一致）。

### 4. 下车地点必填

- 官网 `/site/v1` 的包车询价和下单：**下车地点必填**（坐标 + 地址）；订单存下车点和地址，运营、供应商订单详情、司机页、确认邮件都显示。
- 旧预订页 `/book` 的包车：改成跳到新预订页的包车（M8-05 会整体切换）。
- 渠道接口 `/sales/v1`：为了不打断已接入的渠道，下车地点暂时可不填；**不填时只报没有设加价区域的包车商品**（不会少收），设了加价区域的商品不报价并给出原因。渠道文档写明以后改为必填。

### 5. 对现有包车商品的影响（请业主知悉）

今天包车只看上车点。上线以后多了一个条件：**下车点也要在商品本身的区域或某个加价区域里**，否则转人工。现有包车商品没有加价区域，下车点出了商品区域的包车会从「能报价」变成「转人工」。测试环境现在只有一个上架的包车商品（东京）。建议上线前通知有包车商品的供应商补好加价区域；正式环境切换前我列出受影响的商品。

| 位置 | 点对点含公里数 | 包车区域加价 |
| --- | --- | --- |
| 供应商价格页 | 列表「含 X 公里，超出每公里 Y」（结算价） | 「区域加价」列表（结算价） |
| 官网报价卡片、新预订页、订单页、确认邮件 | 「含 X 公里，本次路线约 D 公里，超出 Z 公里 × Y（已含在一口价里）」，Y 用对外价 | 下车地点；有加价时写「含区域加价」，不单列金额 |
| 运营订单详情 | 同上，结算价和对外价都显示 | 上车、下车所在的加价区域和加价（结算价和对外价） |
| 供应商订单详情 | 只用结算价（规则 4） | 上车、下车所在的加价区域和加价（结算价） |

- 一口价仍显示为一个总价；这些行是说明，不是另一笔费用。客人看到的每公里对外价单独取整，和总价可能差一个取整单位以内，所以不写「基础价 + 超出 = 合计」的算式。
- 报价快照、订单上存：`to_area_id`、`included_km`、`route_meters`、`over_km`、`over_km_per_km_minor`、包车的上车 / 下车加价区域和加价（结算）和对应的对外价；对外接口只给对外价。

## M8-15 落地时定下的细节（不改上面的决定）

- **冲突键里的「价格方式」按「基础定价 / 加价」两类分**：同一区域的套餐价和区域加价不冲突；基础定价的几种计价方式之间照旧冲突（点对点同一组合不能同时有一口价和里程 + 时长，和今天一样）。
- **上车点只在加价区域里时，基础定价用哪个区域的**：上车点在商品区域里 → 用上车点所在的商品区域（和今天一模一样）；否则用下车点所在的商品区域；两端都只在加价区域里 → 商品的每个区域都算、取最低（和第 4 步「几个区域都算、取最低」同一个口径）。
- **加价区域**：本租户的报价区域，业务类型是包车或通用（和商品选区域同一条规则），新选的不能是停用的；**不能是商品本身的区域**（在那里加价不会起作用，400 `AREA_IS_PRODUCT_AREA`）；不限城市（东京出发去富士山这类跨城市的加价区域可以用）。不存在或别的租户的区域 404。
- **某一端的加价区域里没有这个车型组 × 套餐时长的区域加价**：只这个车型组不报（原因同缺价：`NO_PRICE_RULE` / `PRICE_NOT_IN_EFFECT` / `PRICE_RULE_DISABLED`）；「这一端在不在任何区域里」只看有启用的区域加价的区域。
- **明细**：结算价明细的 `base` 含区域加价（调价作用在合计上，各项之和仍等于总价），另有 `areaSurcharge`（基础定价、上车 / 下车各用哪个区域的哪条规则、加多少）。对外价参考按这一单的汇率、缓冲、加价比例单独换算、单独四舍五入（不含最低毛利、渠道取整），存在报价快照的中标对外价里，只给运营看。
- **加价区域算「被商品用着」**：已上架的包车商品有启用的区域加价挂在某个区域上时，这个区域不能停用、删除（409 `AREA_IN_USE`），和商品区域一样。
- **渠道接口没给下车点、商品设了区域加价**：商品层面的原因 `DROPOFF_REQUIRED`，给渠道的也是 `DROPOFF_REQUIRED`（渠道补上下车点就能报）。
- **旧 `/book` 的包车**：选了包车（或城市只有包车）直接跳到 `/book/new?mode=charter`。
- **官网 `/site/v1` 的包车下车地点暂为可选**（协调决定，保守做法，让 M8-15 能单独合并、不打断现在的新预订页包车）：规则同渠道接口——不给时只报没设区域加价的包车商品（和以前一样只看上车点），设了的不报（`DROPOFF_REQUIRED`）；给了下车点时按上面的完整逻辑。第三部分第 4 节「官网下车地点必填」由 M8-13 落实（新预订页加下车地点输入框的同时把 `/site/v1` 改为必填）。
  - **M8-19 已落实**（2026-11-10，从 M8-13 拆出）：新预订页包车加了必填的下车地点输入框，`/site/v1` 包车询价的 `dropoff` 改回必填（不给 400 `REQUIRED`），下单的 `dropoff_address` 随之必填；`/sales/v1` 仍可选，规则不变。

## M8-11 落地时定下的细节（不改上面的决定）

- **数据**：迁移 0270 给 `price_rules` 加 `to_area_id`（外键到同一租户的区域，删区域时跟着删；检查约束兜底：只能是点对点、不能等于 `area_id`）。含公里数存在一口价的参数里（`includedKm`、`overKmPerKmMinor`）；没设的一口价参数和以前一模一样（只有基础价），已有规则不变。
- **「命中」线路价的口径**：启用、覆盖用车日期、车型组对得上的线路价就算命中（同 `selectPriceRule`）。命中了但这一条报不出（设了含公里数而拿不到路线、调价后不大于 0、超上限）时，这个车型组**不退回区域价**、按那个原因不报——「线路价不和区域价比低」，退回去可能比供应商给这条线路定的价低（保守做法）。停用的、不在生效期的线路价不算命中，照常用区域价。
- **线路两端用哪些区域**：只在第 4 步「能接这一单的区域」里找（点落在某个区域的禁行区里时，这个区域照旧整个不参与；M8-36 起整个商品不报，见 ADR 0085），上车点、下车点各自所在的区域两两组合、两端不同。
- **缺价、上架、概况**：线路价和区域加价一样不算「该有的价格」（`sellablePriceRules`、`priceCoverage`、价格概况的条数都不算它）；只有线路价、没有区域价的商品不能上架。改取整单位的检查**算**线路价（它们同样会被取整成 0）。
- **含公里数的距离锁定**：报价快照和订单的结算价明细里有 `toAreaId`、`distance`（含公里数、路线米数、超出公里数、超出每公里结算价），`usage` 也记下这段路线；改期重算用订单上的这段路线，不按现在的路线重算。中标对外价里另有超出每公里的对外价参考（同区域加价的口径：单独换算、单独四舍五入，只给运营看）。
- **对外的样子**：`/site/v1`、`/sales/v1` 的报价多 `distance { included_km, route_meters, over_km, over_km_per_km }`，`over_km_per_km` 是对外价，格式同 `price.total`（`{ amount, currency }`，不是设计稿 10.7 写的最小单位整数），没设含公里数为 `null`；只加字段，不改已有字段。线路价本身（下车区域）对外不出现。
- **价格日历**：`to_area_id` 参数（只有点对点）；每天多 `route_rule`（用的是线路价 true / 这个车型组没有能用的线路价、退回区域价 false / 没给下车区域 null），`price_rule` 多 `to_area_id`。
- **导入**：「下车区域」按商品选的区域的名称认（认不出 `AREA_NOT_IN_PRODUCT`，和「区域」相同 `SAME_AREA`）；接口里别的租户的区域按 404，导入里按名称认不出（同「区域」列）。
- **M8-13 再做的**：官网订单页（`/site/v1/order`）、确认邮件的 `distance_note`、domain 里生成「含 X 公里，本次路线约 D 公里……」那句话和 D 的格式化函数。

## M8-13 落地时定下的细节（不改上面的决定）

- **说法只在 domain 里拼**（`packages/domain/src/included-km.ts`）：客人那句「含 X 公里，本次路线约 D 公里，超出 Z 公里 × Y（已含在一口价里）」（没超出「在含的公里数以内」，单价是 0「超出的公里不另收」）、后台的「含 X 公里 · 路线约 D 公里（报价时）· 超出 Z 公里」、「含区域加价」。官网报价卡片、新预订页、订单页、确认邮件、运营 / 供应商订单详情都调这里。D = 路线米数**向上取整到 0.1 公里**（规范 10.8 第 1 条），Z 用报价 / 订单上存的数，不重算。新预订页右侧栏的「约 X 分钟 · Y 公里」在选了含公里数的车型时用同一个 D。
- **官网 / 渠道订单应答**（`SalesOrder`、`SiteOrder`，只加字段）：`includes_area_surcharge`（订单上锁定的两端加价之和大于 0）、`distance`（同报价的格式，对外价）。每公里的对外价 = 订单上锁定的超出每公里结算单价，按这一单对外价用的汇率、缓冲、加价比例单独换算、单独取整（`sellEquivalentMinor`，和报价时同一个口径）——改期重算后跟着订单走，不读报价快照。运营订单详情的 `over_km_per_km_sell` 改用同一个算法（同一单和官网订单页、确认邮件同一个数；没改期的单和快照里的数一样）。
- **确认邮件**：客人白名单加 `distance_note`（可省略的整行，「公里数：…」）和 `area_surcharge_note`（新的一类「可为空的后缀」变量：为空时替换成空字符串、那一行照常，接在「已付金额」后面写「（含区域加价）」）。只在客人的 `order.confirmed` 用；供应商邮件不加（规则 4、ADR 0049）。已付金额本身的写法不变。
- **订单详情的「用的价格」**：`GET /tenant/v1/orders/{id}` 和 `GET /platform/v1/orders/{id}` 多 `pricing_route { kind: route | area, area, to_area }`（区域编号和现在的名称，没有金额）。上车区域取下单用的报价快照里中标的区域；救援转给了别的供应商、或订单上的线路和快照对不上时不猜（`area` 为 null）。只有用了线路价或设了含公里数的点对点单才有，别的单为 null（显示不变）。供应商看到的公里数和区域加价沿用已有字段（`order.settlement.distance`、`area_surcharge`，只有结算价）。
- **司机页**：包车单有下车点时「下车：地址」+ 文字链接「导航到下车点」和坐标；M8-15 之前的包车单写「下车：没有指定（包车，按客人安排）」；接送机、点对点照旧。没有任何价格。

## 后果

- 点对点和包车共用区域、区域判断、价格规则设施和区域下拉组件；包车不用点对点的「下车区域」列（加价是按单个区域，不是线路）。
- 已有规则、已下订单不受影响；但包车开始看下车点，没设加价区域的包车商品对出了商品区域的下车不再自动报价（第三部分第 5 节）。
- 设了含公里数的规则依赖路线预估：谷歌不可用时这些规则不报价。
