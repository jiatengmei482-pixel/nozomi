# ADR 0084：点对点出发地不在任何城市时按目的地的城市报价（往返对称）

- 状态：已采纳（业主 2026-11-12 提出 M8-35「往返都应约 49,500」，按最低风险、可撤回的做法实施）。
- **补充 ADR 0069 第 4 条**（点对点按出发地落在哪个城市报价）和 ADR 0081 第 3 条（接送机报不出改用点对点商品时的城市）。B8「跨城市行程」其余部分仍等业主。
- 编号：写这篇时 main 上最大是 ADR 0081；0082（M8-32）、0083（M8-31）在未合并的分支上，这里用 0084。

## 问题

业主在测试环境发现：商品 PRD202611110153080140（轻井泽 ↔ 东京）「银座 → 轻井泽」报得出 ¥49,500（45,000 × 1.1），「轻井泽 → 银座」报不出。
用官网匿名询价（`POST /site/v1/quotes/by-points`）复现：

| 方向 | city | 结果 |
| --- | --- | --- |
| 银座 → 轻井泽王子大饭店西馆 | 东京（CTY-JP-G13NKZ） | VG-ECO-4 ¥49,500，`pricing_basis: one_price`，路线约 175.9 公里 |
| 轻井泽王子大饭店西馆 → 银座 | null | `OUT_OF_SERVICE_AREA`，没算路线 |

原因不在区域匹配：点对点先按**出发地**选城市（城市中心周围 80 公里内最近的，ADR 0069 第 4 条），轻井泽离东京中心约 146 公里，
哪个城市都不在，请求在选城市这一步就被拒了，根本没走到商品的区域判断。区域判断本身两端对称：一个点落在几个区域里时每个区域都算，
点对点线路价试所有「上车区域 × 下车区域」组合，命中几条取最低（ADR 0073 第二部分；`route-prices.test.ts` 已有用例，这次补了轻井泽的例子）。

## 决定

1. 点对点选城市：出发地落在某个能订点对点的城市里时**照旧按出发地**；出发地哪个城市都不在、目的地在时，**按目的地的城市**（`pointToPointCityOf`）。两端都不在仍是 `city: null`、`OUT_OF_SERVICE_AREA`。
2. 接送机报不出改用点对点商品（ADR 0081）时用同一个函数选城市。
3. 选到城市以后的报价规则不变：两端都要落在商品的区域里（或按 ADR 0080 的一口价 + 区域外里程、计程价），线路价仍是单向的。

## 影响

- 以前报得出的询价走的是同一条路（出发地在城市里），**价格一分不变**；只有以前 `city: null` 的询价现在会按目的地的城市试一次。
- 两端在不同城市（例如东京 → 大阪）仍按出发地，跨城市的其余问题仍是 B8。
- 后台「报价试算」（供应商对一个商品试算）本来就不选城市，不受影响。

## 撤回

把 `site.ts` 里的 `pointToPointCityOf` 换回 `serviceCityOf(出发地)` 即可，没有数据变化。
