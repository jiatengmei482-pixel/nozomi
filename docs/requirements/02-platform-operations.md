# 平台运营端与渠道对接 · 开发需求

Oct 6, 2026 · @LUCAS

## 文档说明

平台运营端是整个多租户用车平台的「统筹系统」：管租户、管渠道、管钱、管规则；渠道对接层把平台的报价和下单能力，转换成各家 OTA 要求的接口格式。本文档与《用车报价服务平台 · 开发需求》配套使用：那份写租户端和报价引擎，这份写上一级的运营和销售对接。

**四类使用者**

| 使用者 | 是谁 | 入口 |
| --- | --- | --- |
| 平台运营 | 你方公司：运营、招商、客服、财务、风控、技术 | 平台运营后台 + `/platform/v1` |
| 租户（供应商） | 车队，包括你自己的 NOZOMI 车队 | 租户后台 + `/tenant/v1` |
| 销售渠道 | 自有官网、OTA、分销平台、旅行社、企业客户 | 标准接口 `/sales/v1`，或经连接器接入 |
| 终端客人与司机 | 乘客、司机 | 渠道的页面、司机 H5 |

**本文档覆盖**

- 运营后台的全部模块：租户、渠道、连接器、订单中心、工单、比价监控、财务、风控、主数据、通知、报表、账号安全。
- 渠道对接层的通用框架。各家 OTA 的具体字段等拿到对方接口文档后逐家补充。
- 平台运营 API、数据模型、上线路线。

**不在本文档**：客人支付收银（由渠道自己收款，平台只和渠道结算）、司机考勤与工资、车队内部财务。自有官网的前台页面另行设计，它在平台里只是一个渠道。

**已确认的业务规则**：租户报结算价，平台按百分比加价赚差价，不向租户收任何费用；加价比例可以按渠道、租户、城市、品类、车型组分别设置；同车型取对外价最低者中标（与最低价相差 3% 以内时评分高者中标，观察期租户排序时加 5%）；支付后自动确认、租户不能拒单；只有租户声明无法履约、超时未派车、司机未到、租户被暂停这 4 种情形由平台救援改派，费用由原租户承担；付款前不显示中标租户；多币种由中央换算中心换算，租户和客人都可以用任意币种。第一个渠道是自有官网，暂无 OTA。

## 整体架构

平台分四层：销售渠道、渠道对接层、平台核心、租户；平台运营后台从侧面管理核心的全部规则和数据。

&#91;embedded content: 整体架构 · 4 层 + 运营后台\]

- 自有官网和 API 分销商直接用标准接口；OTA 由我们开发连接器去适配对方的规范。
- 比价、中标、加价、建单只在平台核心做一次，所有渠道得到的规则一致。
- 连接器独立部署，一家 OTA 出问题可单独暂停，不影响其他渠道。

## 运营后台菜单与角色

运营后台共 13 个一级菜单，每个平台员工按角色只看到自己负责的部分。运营后台可以「以某租户身份查看」租户后台做问题排查，但只读，并留审计日志。

| 菜单 | 主要功能 | 主要使用角色 |
| --- | --- | --- |
| 总览 | 今日订单、GMV、毛利、异常待办、连接器健康度 | 全部 |
| 租户管理 | 入驻申请、资质审核、合同、结算条款、评分、停用 | 招商、运营 |
| 渠道管理 | 渠道账户、授权租户、加价规则、额度、密钥 | 渠道经理 |
| 连接器 | 各 OTA 适配器的配置、编码映射、推送任务、调用日志、告警 | 技术、渠道经理 |
| 订单中心 | 全局订单查询、异常队列、人工介入 | 客服、运营 |
| 工单 | 投诉、no-show 审核、修改单、退款 | 客服 |
| 比价监控 | 中标分布、无人报价的缺口、价格带 | 运营、招商 |
| 财务结算 | 应收应付、账单、发票、付款、对账差异 | 财务 |
| 风控 | 价格异常、异常下单、资质到期、黑名单 | 风控 |
| 主数据 | 城市、机场、车站、POI、车型组、附加服务、模版、汇率中心、节假日 | 主数据运营 |
| 通知中心 | 消息模版、发送记录 | 运营 |
| 报表 | 经营、渠道、租户、履约、财务报表 | 管理层、运营 |
| 系统设置 | 平台账号、角色、审计日志、全局参数 | 超级管理员 |

**平台角色**：超级管理员、运营、招商（租户入驻）、渠道经理、客服、财务、风控、主数据运营、技术（连接器和日志）、只读。权限按「菜单 × 操作（查看 / 编辑 / 审核 / 导出）」配置，可自建角色。

**敏感操作双人复核**：修改渠道加价比例、修改租户结算条款、付款给租户、人工退款超过阈值、停用租户或渠道。发起人和审核人不能是同一人。

## 租户管理

租户从「申请 → 资质审核 → 签约 → 试运营 → 正式」入驻，只有「试运营」和「正式」状态的租户参与比价。

**租户状态**

| 状态 | 可以做什么 | 进入条件 |
| --- | --- | --- |
| 申请中 | 填企业信息、上传资质 | 在入驻页提交申请，或招商代建 |
| 审核中 | 等待 | 资质齐全 |
| 已签约 | 建区域、商品、司机、车辆，不能上架 | 资质审核通过 + 合同生效 |
| 试运营 | 上架、参与比价，每日订单上限（默认 10 单） | 至少 1 个商品通过上架校验、完成一次测试单 |
| 正式 | 无上限 | 试运营满 30 天且完成 ≥ 20 单、无重大投诉 |
| 暂停 | 商品不参与比价，已有订单继续履约 | 资质过期、评分低于红线、欠款、人工暂停 |
| 已清退 | 只能查看历史和账单 | 合同解除，已有订单全部履约完毕并结清 |

**资质审核**

- 按国家配置必交资料清单。日本：登记簿谊本、一般乘用旅客自动车运送事业许可、旅客赔偿责任保险、结算账户证明。其他国家按当地法规增补。
- 审核动作：通过 / 驳回（必填原因）/ 要求补充。每份证件记录到期日，到期前 30 天、 7 天各提醒一次，到期当天租户自动转「暂停」。
- 抽查：每季度随机抽查租户的司机和车辆证件，要求上传原件照片。

**营运资质为必审项**：租户必须提供当地合法的客运营运许可（日本为一般乘用旅客汽车运送事业许可，即绿牌）和营运车辆商业保险，到期前 30 天提醒续期，过期自动下架相关车辆。平台自身是否需要旅行业登记，确定服务器和公司主体后再确认。

**合同与结算条款**（每个租户一份，可有生效日期的多个版本）

| 条款 | 已确认 |
| --- | --- |
| 结算币种 | 租户自选，任何币种均可（由中央换算中心换算） |
| 结算周期 | 月结，次月 20 日付款 |
| 平台服务费 | 无。平台只赚加价差价 |
| 保证金 | 无。次月 20 日的账期本身起到押金作用；租户退出时最后一期账单延后一个周期付款，用于扣除尾单投诉和拒付 |
| 违约金 | 按「履约保障与服务标准」的违约金阶梯和客人赔付表扣除；从当期或下一期账单中扣除 |
| 专属加价比例 | 可选。针对该租户单独设定加价比例，在渠道加价规则里配置 |

**履约评分**（满分 5 分，每日按近 90 天数据重算；建议权重，待确认）

| 指标 | 权重 |
| --- | --- |
| 按时派车率（截止时间前派车） | 25% |
| 准时到达率（用车时间前到达上车点） | 25% |
| 客人评价均分 | 20% |
| 投诉率（成立的投诉 / 完成订单） | 20% |
| 履约失败率（司机未到、重大迟到） | 10% |

- 新租户前 20 单使用平台默认分 4.5。
- 评分低于 4.0 进入观察期（通知租户整改）；低于 3.5 自动暂停，需运营人工恢复。
- 评分按最近 90 天滚动计算，用于价差 3% 以内的中标排序；租户可在自己后台看到各项指标。

**租户详情页**：基本信息、资质、合同版本、商品和价格概览、近 90 天订单和中标率、评分趋势、工单、账单、操作日志；可「以租户身份只读查看」。

## 渠道管理

每个销售渠道是一个独立账户：它能卖哪些租户、哪些城市和品类、加价多少、用什么币种结算、最多欠多少钱，都在这里设置。

**渠道类型**

| 类型 | 接入方式 | 例子 |
| --- | --- | --- |
| 自营 | 直接调用 `/sales/v1` | NOZOMI 官网、自有 App |
| API 分销商 | 对方按我们的 `/sales/v1` 对接 | 旅行社、企业差旅平台 |
| OTA（连接器） | 我们按对方规范开发适配器 | Klook、Trip.com、道旅、KKday 等，具体由连接器实现 |
| 线下代理 | 在平台后台手工下单 | 实体旅行社、酒店前台 |

**渠道配置项**

| 配置 | 说明 |
| --- | --- |
| 基本信息 | 名称、公司、联系人、合同、状态（测试 / 启用 / 暂停） |
| 结算币种 | 渠道与平台的对账币种；客人下单币种不受限，每次询价都可指定币种，由中央换算中心换算 |
| 授权范围 | 可卖的租户（全部 / 白名单 / 黑名单）、城市、品类 |
| 加价规则 | 默认加价比例 + 细分规则（见下表）；还可设最低毛利金额和对外价取整规则 |
| 付款方式 | 预付款（下单扣余额）/ 信用额度（月结）；余额或额度不足时拒绝下单并告警 |
| 取消规则策略 | 沿用租户商品规则，或强制使用渠道统一规则（有些 OTA 只支持固定几种取消政策） |
| API 凭证 | client\_id / secret、IP 白名单、限流、Webhook 地址 |
| 展示设置 | 是否在付款后展示中标租户名（默认是）、商品详情语言 |

**加价规则（从具体到通用匹配，命中第一条即停）**

| 优先级 | 维度 | 例子 |
| --- | --- | --- |
| 1 | 渠道 × 租户 × 城市 × 品类 × 车型组 | 官网 · Relaxcar · 东京 · 包车 · 商务 7 座 = 12% |
| 2 | 渠道 × 租户 | 官网 · Relaxcar = 15% |
| 3 | 渠道 × 城市 × 品类 × 车型组 | 官网 · 东京 · 包车 · 商务 7 座 = 12% |
| 4 | 渠道 × 城市 × 品类 | 官网 · 东京 · 接送机 = 8% |
| 5 | 渠道默认 | 官网 = 10% |

- 加价按租户报价的百分比计算，平台毛利永远是正数；调整各租户的比例就是调节利润的手段。
- 因为不同租户的加价比例可以不同，比价按「对外价 = 结算价 × (1 + 该租户适用的加价比例)」取最低，保证客人拿到的是最低价。所有租户比例相同时，等同于比结算价。
- 可叠加「日期范围」，用于促销期临时降低加价。
- 修改加价规则需双人复核，生效前可用「试算」看对近 30 天订单的毛利影响。

**渠道与自营的关系**：NOZOMI 官网是一个普通的自营渠道，NOZOMI 车队是一个普通租户，都走同样的比价和结算规则，账务上分开核算。

**自营中立**：NOZOMI 车队作为普通租户（TNT-NOZOMI）参与比价，和其他租户用同一套规则；系统不提供人工指定中标的功能。每次报价快照保存全部候选租户的排序依据，租户对某单有异议时可申请查看匿名化的排序记录。

## 渠道对接层（OTA 连接器）

每家 OTA 对应一个连接器，连接器只做「翻译」：把对方的请求和编码转成平台标准的报价、下单接口，再把结果转回对方格式。比价、中标、定价、派单全部在平台核心完成，连接器不写业务规则。

&#91;embedded content: 两种对接模式 · 各 4 步，最后都到中标租户\]

实时询价在客人搜索时就锁定了价格；推送模式在下单时重新比价，所以多了一个价格倒挂的异常分支。

**两种对接模式**

|  | 实时询价（pull） | 推送商品（push） |
| --- | --- | --- |
| 谁先动 | OTA 在客人搜索时调用我们 | 我们提前把商品、价格、库存推给 OTA |
| 价格怎么来 | 每次实时跑比价 | 定时跑比价，把「未来 N 天 × 车型 × 套餐」的最低对外价推过去，同时记下每个价格对应的中标租户和结算价 |
| 下单时 | 带 quote\_id，价格已锁定 | 按推送时的快照把订单交给当时的中标租户，结算价也按快照 |
| 租户改价 | 下一次询价即生效 | 触发立即重推。重推前已下的单仍按旧快照，对外价和结算价来自同一快照，平台不会亏钱 |
| 库存 | 实时校验 | 推送「可售 / 停售」，比如某天所有租户都满了就推停售 |
| 适合 | 接送机、点对点 | 包车、一日游类商品 |

**推送模式的「平台商品」**

OTA 上展示的商品不属于任何一个租户，而是平台商品：如「东京出发 富士山一日包车」。它的内容由平台运营编辑，绑定「城市 + 品类 + 路线」，每个 SKU 是「车型组 × 套餐」。所有满足条件的租户商品都参与它的比价。

**连接器要实现的能力（每家 OTA 都按这张清单验收）**

| 能力 | 说明 |
| --- | --- |
| 鉴权 | 对方调用我们时的验签；我们调用对方时的凭证管理和自动续期 |
| 编码映射 | 地点（对方机场、城市编码 ↔ 平台主数据）、车型（对方车型 ↔ 车型组）、商品和 SKU、附加服务、语言、币种 |
| 实时询价 | 对方询价 → `/sales/v1/quotes` → 按对方格式返回；超时上限按对方要求（通常 2–3 秒） |
| 推送商品 | 商品内容、SKU、价格日历、库存状态；全量 + 增量；对方限流时排队 |
| 下单 | 对方订单 → 平台订单；保存对方订单号，用它做幂等；重复推送不重复建单 |
| 取消与修改 | 对方发起的取消和修改；平台侧取消时主动通知对方 |
| 状态回传 | 确认、派车（司机、车牌）、完成、no-show、附加费用，按对方状态码和时限要求 |
| 取消规则转换 | 平台取消阶梯 → 对方支持的政策；转不了时取更严的一档，平台不吃亏 |
| 对账 | 拉取或接收对方对账单，逐单比对金额和状态，差异进财务待办 |
| 监控 | 成功率、耗时、错误码分布；连续失败自动告警，可一键暂停该渠道 |

**编码映射管理**

- 运营后台提供映射表：左边对方编码，右边平台主数据，支持批量导入。
- 自动匹配：机场按 IATA 三字码、坐标按距离小于 200 米自动建议，人工确认。
- 未映射的编码进「待映射」队列，并统计因此漏掉的询价次数。

**可靠性要求**

- 所有发往 OTA 的请求走消息队列，失败按「1 分钟、5 分钟、30 分钟、2 小时」重试，超过后进人工队列。
- 每次请求和返回完整留存 90 天，可按对方订单号查。
- 每个连接器有独立的沙箱配置和自动化回归用例（询价、下单、取消、派车回传、对账）。
- 连接器独立部署，一个 OTA 出问题不影响其他渠道。

## 订单中心与异常处理

订单中心跨租户、跨渠道查看全部订单；运营每天从「异常队列」开始工作，而不是翻订单列表。

**全局订单列表**

- 筛选：用车日期、下单日期、渠道、租户、城市、品类、状态、是否异常、渠道订单号、乘客姓名或电话。
- 列：平台订单号、渠道订单号、渠道、中标租户、用车时间、路线、车型组、对外价、结算价、毛利、状态。
- 订单详情一页看全：报价快照（含全部参与比价的租户和价格、汇率）、状态时间线、派车和改派记录、司机定位轨迹、航班号和司机填写的实际落地时间、发给渠道和租户的全部推送、工单、账务分录。

**异常队列**（系统自动生成，处理完标记关闭）

| 异常 | 触发条件 | 处理方式 | 时限 |
| --- | --- | --- | --- |
| 超时未派车 | 过派车截止时间 | 电话催租户；用车前 6 小时仍未派车，自动进入救援改派 | 立即 |
| 司机未出发 | 用车前 1 小时仍未「已出发」 | 联系租户和司机 | 15 分钟 |
| 司机未到达 | 用车时间已到仍未「已到达」 | 联系司机，并主动联系客人；到点 15 分钟仍未到达且联系不上，启动救援改派或请客人自行打车凭票报销 | 5 分钟 |
| 渠道状态回传失败 | 重试耗尽 | 技术排查后手工重发 | 2 小时 |
| no-show 待审核 | 租户提交 no-show | 转工单审核 | 24 小时 |
| 附加费用待审核 | 单笔超过阈值或无凭证 | 审核通过后推送渠道 | 24 小时 |
| 履约未结束 | 服务结束 24 小时后仍未「已完成」 | 催租户提交 | 24 小时 |
| 支付异常 | Stripe 扣款失败、拒付、退款失败 | 财务核实，必要时取消订单 | 当天 |

**人工介入能力**（全部留审计日志）

- 代客人修改订单、代取消（可选「免收取消费」，需填原因）。
- 代租户回传履约状态（租户系统故障时）。
- 手工重发渠道和租户推送。
- 手工调账：给渠道退款、给租户加扣款，必须绑定工单。
- 救援改派：只在「履约保障与服务标准」一节列出的 4 种情形下可用。运营一键按原报价条件重新比价，选出救援租户；客人价格不变，差价和违约金从原租户账单扣除。其他情况一律不改派。

**航班信息**（不接航班数据服务）

- 订单只记录航班号，司机和调度自行查看航班动态。
- 实际落地时间按优先级取：客人在订单页点「我已落地」的时间 → 司机在 H5 填写并拍到达屏照片的时间 → 预订时填写的计划到达时间；客人和司机都有记录且不一致时取较晚者。时间由系统记录，提交后不能改，有争议走工单。

## 履约保障与服务标准

原则不变：支付后自动确认、租户不能拒单、平时不改派。新增「救援改派」兜底：只在下表 4 种情形启动，客人价格不变，所有额外成本由原租户承担。做法参考 [Kiwitaxi 服务标准](https://kiwitaxi.com/en/agency/docs/level_of_services_agency)（供应商未履约扣订单全额）和 [Kiwitaxi 客户条款](https://kiwitaxi.com/en/docs/individual-customer-offer/old5)（司机未到时退款并补偿客人另找车的差价）。

**触发情形与违约金阶梯**

| 情形 | 触发方式 | 客人端 | 原租户承担 |
| --- | --- | --- | --- |
| 租户在用车前 ≥ 24 小时声明无法履约 | 租户点「声明无法履约」或调用接口 | 无感，换租户服务 | 救援差价 |
| 租户在用车前 2–24 小时声明 | 同上 | 无感 | 救援差价 + 原结算价 30% |
| 用车前 < 2 小时声明，或用车前 6 小时仍未派车 | 租户声明或系统自动 | 无感；无人可接时全额退款 | 救援差价 + 原结算价 100% |
| 司机未到：到点 15 分钟仍未「已到达」且联系不上 | 客人投诉或系统告警 | 全额退款 + 凭票报销替代交通（上限为订单对外价的 1.5 倍） | 原结算价 100% + 报销金额 |
| 租户被暂停或解约，名下还有未来订单 | 运营批量发起 | 无感 | 按距用车时间套用前 3 行 |

救援差价 = 救援租户结算价 − 原结算价（按快照汇率换算，为负时记 0）。不可抗力（大雪封路、机场关闭、政府管制）经运营确认后免违约金，客人全额退款。

**救援流程**

1. 触发后订单进入 `rescue_pending`，原租户不能再操作该单（可查看）。
2. 引擎按原报价条件重新比价，排除原租户和已拒绝的租户，按中标排序依次向候选租户发「救援单」。
3. 救援单是唯一需要租户主动接单的订单：15 分钟内不接就顺延下一家（用车前 2 小时内缩短为 5 分钟）；接单后按普通订单履约，结算价为其当前报价。
4. 全部候选都不接，运营可人工指定租户（双人复核）；仍无结果则客人全额退款，并告知可自行打车凭票报销。
5. 客人和销售端收到新的司机信息，价格不变；差价、违约金、报销由平台先垫付，记入原租户下一期账单。

**计入评分**：每次救援计 1 次履约失败；30 天内司机未到 2 次自动进入观察期，3 次自动暂停待复核。

**中标排序（修正版）**

客人支付的仍是中标租户自己的对外价；只是「谁中标」不再只看最低价，避免低价低质租户抢单（[Transferz](https://www.transferz.com/news/ensuring-a-sustainable-value-chain-in-ground-transportation) 称之为 race to the bottom）。

1. **准入过滤**：状态为试运营或正式；试运营当日未达 10 单上限；库存、提前预订时长、资质都有效。
2. **排序价**：观察期租户的排序价 = 对外价 × 1.05，其他租户 = 对外价。排序价只用于比较，不影响客人支付金额。
3. **价格带**：排序价不超过最低排序价 × (1 + δ) 的租户进入「同价区间」；δ 由渠道配置，范围 0–5%，默认 3%。
4. **区间内排序**：评分高者 → 已完成订单数多者 → 排序价低者。
5. **评分口径**：最近 90 天滚动；完成不足 20 单的租户用默认 4.5。

```latex
winner = \arg\max_{t:\ R_t \le (1+\delta)\min R}\ (score_t,\ completed_t,\ -R_t),\quad R_t = P_{sell,t}\cdot(1 + 0.05\cdot[observation_t])
```

例：A 对外价 ¥30,000、评分 4.9；B ¥29,500、评分 4.3。价差 1.7% < 3%，A 中标，客人付 ¥30,000。

**免费等待与 no-show**

| 场景 | 免费等待 | 起算时间 |
| --- | --- | --- |
| 接机 · 国际线 | 90 分钟 | 实际落地时间 |
| 接机 · 国内线 | 60 分钟 | 实际落地时间 |
| 接站 | 30 分钟 | 列车计划到达时间 |
| 送机、点对点 | 15 分钟 | 约定上车时间 |
| 包车 | 0（从约定开始时间计入套餐时长） | 约定开始时间 |

实际落地时间取值：客人点「我已落地」→ 司机填写 + 到达屏照片（必传）→ 计划到达时间；两边不一致取较晚者。免费等待结束后的付费等待按租户价格规则的超时单价，只在客人最终上车时收。开始时间参考 [Transfeero](https://partner-help.transfeero.com/before-service/how-long-is-the-complimentary-waiting-ti)（从实际落地起算）。

no-show 成立必须同时满足（证据标准参考 [Jayride](https://jayride.helpscoutdocs.com/article/137-my-passenger-didn-t-show-up-what-do-i-do-now-will-i-still-get-paid)）：

1. 司机在免费等待开始前点「已到达」，定位距主数据里的上车点坐标 ≤ 300 米。
2. 免费等待内至少 3 次联系记录（电话或即时通讯截图）。
3. 在上车点举牌的照片，带系统时间水印。
4. 司机在 H5 点「申请离开」，客服 10 分钟内尝试联系客人；超时未处理视为同意。
5. 用车后 24 小时内提交。

成立：客人不退款，租户拿 100% 结算价。证据不全：客人全额退款，租户拿 0；若证据显示司机未到场，按「司机未到」处理。

**航班延误与取消**：延误在计划到达后 6 小时内，租户必须顺延接机且不加收费用；超过 6 小时或航班取消，客人可免费改期或全额退款，租户不收费也不计履约失败。

**平台统一取消政策**

付款前客人不知道是哪家租户，所以取消政策按品类和车型级别由平台统一，租户商品里的取消规则改为只读。分级思路参考 [Kiwitaxi](https://kiwitaxi.com/en/docs/individual-customer-offer/old5)（经济车型与商务车型的免费取消时限不同）。

| 适用 | 免费取消 | 扣 50% | 扣 100% |
| --- | --- | --- | --- |
| 接送机、点对点 · 经济 / 舒适 | 用车前 ≥ 24 小时 | 6–24 小时 | < 6 小时或 no-show |
| 接送机、点对点 · 商务 / 豪华 / 中巴 | ≥ 48 小时 | 24–48 小时 | < 24 小时或 no-show |
| 包车（全部车型） | ≥ 48 小时 | 24–48 小时 | < 24 小时或 no-show |

- 扣款按同一比例拆：租户得结算价 × 扣款比例，平台得加价 × 扣款比例。
- 平台或租户原因、航班取消（有证明）、不可抗力导致的取消一律免费。
- 渠道只支持固定几种政策时，连接器按「更严的一档」映射，平台不吃亏。

**改单补充**：原「客人修改订单规则」不变。新增一条：用车前 24 小时内改日期或时间，需租户在 30 分钟内确认；不确认或拒绝时，客人可免费取消后重新下单，这不计入租户履约失败。

**服务后加收费用**

1. 客人付款时用 Stripe 保存支付方式（下单页明确告知并勾选同意），用于事后扣款。
2. 可加收的只有：包车超时 / 超公里、付费等待、客人现场加的停靠点或附加服务、包车的高速费和停车费（商品设为「不含」时，凭票实报）。接送机和点对点为一口价，含高速和停车费。
3. 租户在服务结束 24 小时内提交金额和凭证 → 邮件通知客人，48 小时内可提异议 → 无异议自动扣款。
4. 单笔超过订单对外价 50%、无凭证或客人有异议时，转工单人工审核。
5. 平台订单不允许司机现场收现金，避免争议。

**客人赔付表**（投诉成立时自动带出金额；参考 [Kiwitaxi 服务标准](https://kiwitaxi.com/en/agency/docs/level_of_services_agency)）

| 问题 | 赔客人（按对外价） |
| --- | --- |
| 司机迟到 15–29 分钟 | 10% |
| 司机迟到 ≥ 30 分钟 | 50% |
| 司机未到 | 100% 退款 + 替代交通报销（上限 1.5 倍对外价） |
| 车型降级 | 差价 + 订单 20% |
| 未举牌（商品含举牌） | 10% |
| 没送到目的地 | 25% |
| 车况、司机态度投诉成立 | 10% |

- 每笔赔付至少等值 ¥500，由平台先付给客人。
- 租户按同一比例乘以结算价承担，加价部分由平台承担；司机未到的报销金额全部由租户承担。
- 租户免费升级车型不算违规。
- 投诉时限：服务后 14 天内；租户 24 小时内回复，平台 3 个工作日内判定。

**客人通知（不接短信）**

- 渠道：邮件 + 订单页（免登录链接）；下单时可选填 WhatsApp / LINE / 微信 / KakaoTalk，司机和客服用它联系客人。
- 时间点：支付后发确认邮件；派车后发司机姓名、车牌、联系方式；用车前 24 小时发提醒（含集合点说明和照片）；司机点「已到达」时发邮件并更新订单页。
- 集合点说明、照片由主数据里的地点统一维护，每个机场航站楼一份。
- 用车当天客服热线覆盖全部服务时段，订单页始终显示。

## 客服与工单

所有需要人来判断的事都走工单，工单绑定订单，处理结果自动影响账务和租户评分。

**工单类型**

| 类型 | 发起方 | 处理结果 | 影响 |
| --- | --- | --- | --- |
| 客人投诉 | 渠道、客人、客服 | 成立 / 不成立；成立时选赔付方式（部分退款、全额退款、优惠券） | 成立计入租户投诉率；赔付按责任方扣款 |
| no-show 审核 | 租户 | 通过（客人全额付费）/ 驳回（按未履约处理） | 驳回计入履约失败率 |
| 附加费用审核 | 租户 | 通过 / 部分通过 / 驳回 | 通过后推送渠道向客人收取 |
| 修改订单 | 渠道、客人 | 自动重算差价，超出自助范围的转人工 | 差价多退少补 |
| 履约失败 | 客服、系统 | 先救援改派；无法救援时客人全额退款并报销替代交通；按违约金阶梯向原租户扣款 | 计入履约失败率 |
| 失物招领 | 客人 | 联系租户、记录归还方式 | 无 |
| 租户申诉 | 租户 | 对投诉或扣款的申诉，由另一人复核 | 可撤销处罚 |

**客人修改订单规则**

| 修改内容 | 处理 |
| --- | --- |
| 航班号、乘客信息、备注 | 直接修改，通知租户 |
| 日期或时间（同一租户仍可服务） | 按新时间重算该租户的结算价，对外价按原加价比例；差价多退少补；不重新比价 |
| 人数、行李（仍在车型容量内） | 直接修改 |
| 车型、品类、城市、超出容量 | 按「取消重下」处理，取消部分按取消规则 |
| 已进入免费取消期以外 | 只能改航班号和乘客信息 |

**工单流转**

1. 创建：渠道 API、客服手工、租户后台、系统自动。
2. 分派：按类型和语言自动分给客服组。
3. 征求租户意见：租户须在 24 小时内回复并上传证据，超时视为认可。
4. 判定：客服给出结论和赔付方案；金额超过阈值需主管复核。
5. 执行：自动生成退款、扣款分录，并通过渠道通知客人。
6. 关闭：租户可在 7 天内申诉一次。

**时效目标**：首次响应 ≤ 2 小时；用车当天的紧急工单 ≤ 15 分钟；一般工单 3 个工作日内结案。

**客服工作台**：左侧工单队列，右侧订单全景（同订单中心详情）；快捷回复模版（中、日、英、韩）；一键联系租户调度人和司机。

## 比价监控与运力缺口

比价监控回答两个问题：哪里没人报价（该去招哪里的租户），哪里价格没竞争力（渠道卖不动）。所有询价都记录，包括没有结果的。

**询价日志**：每次询价记录渠道、城市、品类、起终点、用车时间、人数、参与比价的租户及其结算价、未报价原因（错误码）、中标租户、最终是否下单。保留 180 天，用于分析。

**看板指标**

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 有价率 | 返回至少 1 个报价的询价 / 全部询价 | 运力覆盖是否足够 |
| 转化率 | 下单数 / 有价询价数 | 价格是否有竞争力 |
| 平均参与租户数 | 每次有价询价里的租户数 | 比价是否充分 |
| 中标集中度 | 某城市里第一名租户的中标占比 | 是否过度依赖一家 |
| 价格带 | 同城市 × 品类 × 车型组的结算价最低 / 中位 / 最高 | 风控和招商谈判的参考 |

**运力缺口报告**（每周自动生成）

- 按「城市 × 品类 × 车型组」列出无人报价的询价次数，按次数排序；例如「札幌 · 接送机 · 13 座：本周 46 次无报价」。
- 拆分原因：没有租户、不在区域内、无价格规则、服务时间不覆盖、提前预订时长不够、库存售罄、容量不足。
- 从报告一键创建「招商任务」，分配给招商人员跟进。

**租户端「线路最低价查询」**（已确认）：租户选择城市、品类、车型组、套餐和日期，看到自己在该线路的排名，以及「结算价降到多少（−X%）即可成为最低价」的提示。不显示对外价和加价比例，避免租户反推出自己的专属加价，帮助租户自己调价拿更多订单。不显示是哪家租户的价格。平台也会在租户连续未中标时主动推送这条提示。

**防刺探**：查询结果用每日 0 点的快照，不是实时数据；每个租户每天最多查询 20 次。这样租户反复调价也摸不到对手的实时价格。

## 财务结算

平台向渠道收「对外价」，向租户付「结算价」，两者之差就是平台毛利；每一笔金额变动都生成一条「账务分录」，账单和报表都从分录汇总，不直接改金额。

**一单的账务分录**

| 事件 | 应收渠道 / 客人 | 应付租户 | 平台毛利 |
| --- | --- | --- | --- |
| 支付确认 | + 对外价 | + 结算价 | + 加价 |
| 客人免费取消 | − 对外价 | − 结算价 | − 加价 |
| 客人有偿取消（扣 M%） | 只收 M% × 对外价 | 只付 M% × 结算价 | M% × 加价 |
| no-show 审核通过 | 全额 | 全额 | 全额 |
| 附加费用（超时、超公里、停车） | + 金额 × (1 + 加价比例)，或现场付司机则不进平台 | + 金额 | + 加价部分 |
| 投诉赔付（责任在租户） | − 赔付额 | − 赔付额（从账单扣） | 0 |
| 投诉赔付（责任在平台） | − 赔付额 | 0 | − 赔付额 |
| 履约失败 | − 全额 | − 结算价 − 违约金 | − 加价 + 违约金 |

**汇率与币种**

- 平台不设单一本位币：应收按客人支付币种记，应付按租户结算币种记，都保留原币金额。
- 每笔分录同时保存报价快照里的汇率；报表可选任意展示币种（JPY、CNY、USD 等），由中央换算中心换算。
- 毛利 = 应收 − 应付，按快照汇率换算到同一币种后计算；实际收付款时的汇率差单独记「汇兑损益」。

**汇率缓冲与加价下限**：客人支付币种与租户结算币种不同时，换算汇率在中央汇率上加 1.5% 缓冲，覆盖 Stripe 实际换汇和次月付款前的汇率波动。每个渠道设最低加价比例（默认 10%），覆盖支付手续费、汇率缓冲、拒付和赔付准备金；加价规则低于下限时系统拦截。汇率在报价快照里锁定，之后的波动记入汇兑损益。

**拒付**：Stripe 拒付成立且原因是服务问题时，从责任租户账单扣回；盗刷类拒付由平台承担。

**账单**

| 账单 | 周期 | 流程 |
| --- | --- | --- |
| 渠道应收账单 | 按渠道合同；预付款渠道每单实时扣余额 | 生成 → 发渠道确认 → 开票 → 收款核销 |
| 租户应付账单 | 按租户合同（默认月结） | 生成 → 租户确认（可提异议）→ 租户开票 → 双人复核 → 付款 |
| OTA 对账 | 每日 | 连接器拉取对方账单 → 自动比对 → 差异进财务待办 |

- 只有「已完成」「no-show 已审核」「有偿取消」的订单进入账单；服务日期在周期内且已结案。
- 未结案的工单对应金额暂扣，结案后在下一期补发。
- 账单导出 Excel / PDF；发票按各国要求配置（日本需支持适格请求书登记号）。

**收款与付款**：自有官网的客人付款用 Stripe（支持多币种），支付成功的回调触发「支付确认 → 自动确认 → 推单给中标租户」；取消和赔付的退款也走 Stripe。给租户付款：月结，次月 20 日付上月已结案订单；生成付款批次 → 双人复核 → 银行转账（导出批量付款文件，付款后回填银行流水号）。结算账户变更需租户管理员两步验证 + 平台审核。

**财务报表**：毛利报表（按渠道 / 城市 / 品类 / 租户）、应收账龄、应付账龄、渠道余额和额度使用、退款与赔付明细、汇兑损益。

## 风控与价格监控

风控规则全部可配置（阈值、开关、动作），命中后进风控队列；下表是上线时的默认规则。

| 风险 | 规则 | 动作 |
| --- | --- | --- |
| 租户录错价（过低） | 新价格低于同城同品类同车型中位数的 50% | 保存时弹提示；上线后暂不参与比价，等租户确认 |
| 租户录错价（过高） | 高于中位数 300% | 提示，不拦截 |
| 调价规则异常 | 单条调价超过 +300% 或低于 −50% | 保存时二次确认 |
| 中标价突变 | 同一组合的最低结算价 24 小时内下降超过 30% | 告警运营 |
| 异常下单 | 同一乘客电话或邮箱 24 小时内 > 5 单；同一航班同一乘客重复下单 | 人工核实后放行 |
| 恶意取消 | 同一渠道账户取消率连续 7 天 > 40% | 告警渠道经理 |
| 假履约 | 完成订单无任何定位记录；实际公里与路线估算差异 > 50% | 转工单核查，暂缓结算 |
| 附加费用异常 | 单笔附加费用 > 结算价 50%，或某租户附加费用占比显著高于同行 | 人工审核 |
| 资质风险 | 租户、司机、车辆证件到期 | 到期前提醒，到期自动暂停或禁止派单 |
| 账户安全 | 租户结算账户变更；异地登录；API 密钥大量失败 | 二次验证、延迟付款、自动封密钥 |
| 渠道信用 | 信用额度使用超过 80% / 100% | 告警 / 拒绝下单 |

- **黑名单**：乘客电话、邮箱、司机、车牌，全平台共享；租户可申请拉黑乘客，平台审核。
- **风控队列**：命中规则、相关订单或价格、处理结论（放行 / 拦截 / 转工单），作为后续调整阈值的依据。

## 主数据与内容运营

主数据的变更会同时影响所有租户和渠道，所以走「草稿 → 复核 → 发布」流程，发布后推 `master.changed` 事件。

| 对象 | 运营动作 | 注意 |
| --- | --- | --- |
| 国家、城市 | 新增、停用、多语言名、时区、边界 | 新开城市前先建主数据，再招租户 |
| 机场 | IATA 码、航站楼、每个航站楼的坐标和接机点、国际 / 国内属性 | 你覆盖的约 100 个机场是一期主数据的重点；国际线和国内线的默认免等（90 / 60 分钟）挂在这里 |
| 车站 | 站点、出口、坐标 | 与机场同一套「接送点」逻辑 |
| POI | 新增、合并重复点、纠正坐标 | 可从询价日志里的高频地址自动推荐新 POI |
| 车型组 | 等级、座位、人数和行李组合、代表车型、升级关系 | 升级关系用于派车校验（只允许同级或升级） |
| 附加服务目录 | 新增、适用品类、计费单位 | 包车目录不含「车辆超时费」 |
| 详情模版 | 按品类 × 语言维护固定文字和变量 | 改模版前可预览对所有商品的影响 |
| 平台商品（推送模式） | 标题、图片、路线、亮点、SKU（车型组 × 套餐）、各 OTA 的商品编码 | 内容合规：不写无法保证的评价、排名 |
| 节假日日历 | 各国法定假日、客源国长假（中国国庆、春节等） | 供调价规则直接引用 |
| 多语言 | 日、中、英、韩，可扩展 | 机器翻译初稿 + 人工校对；未校对的语言不对外展示 |

**汇率中心运维**

- 数据源：先用免费汇率源（如欧洲央行每日参考汇率，或免费档的汇率 API）。免费源一般每日或每小时更新，刷新频率跟随数据源；以后可换付费实时源，接口不变。
- 任意两种币种都用交叉汇率换算，租户报价币种和客人支付币种都不受限。
- 看板：当前汇率、更新时间、数据源状态、近 30 天曲线。
- 异常：单次变动超过 3% 先挂起并告警人工确认；超过 48 小时未更新则暂停跨币种报价。
- 人工锁定：极端行情时可临时锁定某个汇率（双人复核）。

## 平台账号、安全与审计

平台员工能看到所有租户和乘客的数据，所以账号安全按最严格的标准做。

- **登录**：公司 SSO（Google Workspace 或 Microsoft）优先；必须两步验证；会话 8 小时过期；可设 IP 白名单。
- **权限**：角色 × 菜单 × 操作；可加数据范围（如只看某几个城市、某几个渠道）。
- **个人信息保护**：乘客姓名、电话、邮箱加密存储，列表里默认打码；点「查看」才显示全文并记日志；订单完成 180 天后自动脱敏。按日本个人信息保护法、各客源国法规评估跨境传输（待法务确认）。
- **审计日志**：谁、什么时间、从哪个 IP、通过后台还是 API、对什么对象做了什么、前后值。保存 3 年，不可修改。可按人、对象、时间查询。
- **全局参数**：派车截止时间、报价有效期、风控阈值、试运营上限、评分权重等都在系统设置里配置，修改需双人复核并有版本记录。
- **密钥管理**：OTA 和渠道的凭证存在密钥管理服务里，后台只显示后 4 位，定期轮换。
- **备份与恢复**：数据库每日全量备份 + 实时日志，可恢复到任意时间点；每季度演练一次恢复。
