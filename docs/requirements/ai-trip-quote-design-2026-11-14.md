# NOZOMI AI 行程报价 · 设计方案（草案 v1，2026-11-14）

## 0. 原则
- **现有程序不变**：接送机、点对点、包车的报价引擎原样保留。新功能是在上面加一层「行程编排」，只做加法。
- **AI 只负责听懂，不负责定价**：AI 把客人的一句话或上传的行程转成「标准行程单」；价格全部由规则引擎计算，AI 不能编价格。
- **同一个入口**：表单、AI、嵌入组件、客服录单，最后都提交同一份「标准行程单」，走同一个编排接口。没有 AI 也能测试和使用。
- **客人先确认再付款**：AI 解析出的行程用地图和时间表展示，客人改完、确认后才锁价下单；AI 做了的假设（例如停留时长取默认）要标出来。

## 1. 整体流程
1. **输入**：一句话 / 上传行程（PDF、图片、Excel、旅行社行程单、酒店和航班确认单）/ 表单。
2. **AI 解析** → 标准行程单（JSON）：天数、每天的分段、时间、地点、经停和停留时长、人数行李、航班号（只用于接机段）、车型偏好、语言等附加。缺少关键信息（日期、人数）时只追问这几项。
3. **行程编排**（新）：把行程单拆成「服务段」，判断每段用什么产品；再叠加跨段规则（住宿、返程、多日、工时）。
4. **分段报价**：每段调用现有引擎（接送机引擎、点对点引擎、包车三层区域引擎），得到各段价格。
5. **综合报价**：各段价格 + 跨段规则费用 + 附加 = 总价；给出 1–2 个方案对比（例如「一车到底」和「分城市本地用车」）。
6. **展示**：地图 + 每日时间表 + 价格明细，三者联动。
7. **确认下单**：生成 1 个行程订单，下挂多个子订单（每段一个，可分给不同供应商），一次付款。

## 2. 服务段类型与判定规则
| 段类型 | 判定 | 用哪个引擎 |
|---|---|---|
| 接机 | 起点是机场、有到达航班、当天之后只去一个目的地 | 现有接送机（含免费等待 90/60 分钟） |
| 送机 | 终点是机场、只从一个地点出发 | 现有接送机 |
| 点对点 | 非机场 A→B、中间不停留 | 现有点对点 |
| 包车 | 当天有经停或停留 | 现有包车（三层区域 + 套餐选择） |
| 接机 + 包车 | 机场上车，之后有经停 | 需求一「机场开始套餐」，与「接机 + 单独包车」比价取低 |
| 包车 + 送机 | 包车，最后在机场下车 | 需求一「机场结束套餐」，同样比价取低 |
| 多日包车 | 连续多天、同一辆车 | 每天按包车计算 + 跨段规则（住宿、停驻、工时） |

编排器对同一天的几段要做**合并比价**：例如「接机 → 酒店放行李 → 下午游览」，比较「接机 + 下午包车」和「接机开始包车」两种拆法，取总价低的。

## 3. 底层需要新增的规则（规则引擎，商品级可配置，命中才加入报价）
### 3.1 司机住宿费
- **触发**：多日用车，当天结束点到次日开始点都不在车辆基地附近（不在①基础价区域内），且次日继续用同一辆车。
- **计费**：每车每晚一笔；按过夜地区可设不同金额（箱根、轻井泽等旺季可更高）；可选「客人提供住宿」抵免。
- **明细显示**：司机住宿费（第 N 晚，地区名）。

### 3.2 长途返程费（单程远距离）
- **现状**：③上下车加价只覆盖关东一类的近郊空驶。东京→大阪这种单程，车要空车回去，现在没有规则。
- **触发**：下车点不在任何①③区域内，但在商品允许的「长途单程范围」内（例如 ≤ 600 km）。
- **计费**：二选一取低——返程公里 × 返程单价，或固定返程交通费（司机坐新干线回）+ 车辆回送费；也可以按目的地城市设固定表。
- 超出长途范围的，转人工。

### 3.3 多日连续用车
- 每天按当天行程选包车套餐；不用车的空闲日，车留在当地的按「车辆停驻费 / 最低日费」计算，车回基地再来的按两段返程计算，取低。
- 同一辆车贯穿全程优先；行李只在接送机那几天多的，允许各段用不同车型（按段选车）。

### 3.4 司机工时合规（日本 改善基准告示，2024 年 4 月起）
- 每天拘束时间 ≤ 13 小时（上限 15 小时），两天之间休息 ≥ 11 小时（至少 9 小时）；多日连续用车要检查。
- 超过时：建议换司机（加换班费或第二位司机），或提示客人调整行程；超过上限的不能在线下单。

### 3.5 时间类加价（先查现有系统是否已有）
- 深夜早朝（例如 22:00–5:00）加价：接送机多半已有，包车也要能用。
- 节假日、旺季（年末年初、黄金周、盂兰盆节、樱花季）加价：按日期表配置。

### 3.6 其他
- **跨城市方案对比**：例如东京 3 天 + 京都 2 天，AI 同时给两个方案：「一车到底（含住宿和返程）」和「东京、京都各用本地车，中间建议坐新干线」，标出价格差。
- **附加项沿用现有**：司机语言、儿童座椅、举牌等。
- **组合优惠（可选，后期）**：多段打包折扣，按规则配置，默认关闭。
- **取消规则按段**：每个子订单按它自己的产品规则；整单取消时逐段计算。
- **报价有效期与锁价**：综合报价给一个报价编号，付款前过期就自动重新报价。

### 3.7 城市间长途移动（≥300 km）：新干线方案 vs 一包到底
**场景**：东京玩几天，再去大阪玩几天，中间要移动 400 多公里。

**判断条件**：两天之间的移动距离 ≥ 300 km（可配置）时，编排器自动算两个方案，并排给客人比较；不满足条件的只出一包到底方案。

**方案 A：新干线 + 两边配车**（行程拆成两段）
- 出发城市：送站点对点（酒店 → 东京站/品川站），用出发城市的商品。
- 中间：客人坐新干线。车票不由我们销售，只显示参考时长和参考票价（或以后作为附加项代订）。
- 到达城市：接站点对点（新大阪站 → 酒店），用到达城市本地的商品或供应商。
- 之后几天在大阪用大阪本地包车。
- **成立条件**：两端都有新干线站，而且都在各自城市商品的服务区域内；铁路门到门时间比开车少 60 分钟以上（可配置）；不需要多次换乘（最多 1 次，可配置）。
- **提醒**：大件行李（三边之和超过 160 cm）坐新干线要预订「特大行李放置处座位」；也可以建议用行李宅急便寄送。人多、行李多、有老人小孩时，在方案对比里加提示。

**方案 B：一包到底**（同一辆车开过去）
- **成立条件**：没有新干线，或者铁路比开车慢、换乘多（例如没有直达的景区路线）。这种情况只出方案 B。
- **移动日计费**（两种算法取低）：
  1. 套餐算法：当天包车套餐价 + 超公里费 = 套餐价 + (当天总公里 − 含公里) × 超公里单价。
  2. 长途档位算法（新增）：按当天移动距离查长途档位价，例如 300–400 km、400–500 km、500–600 km 各一个价，含司机工时。
  - 原因：超公里单价是按市内用车定的，长距离直接乘会偏高；档位价让长途报价合理、可预期。
- **高速费**：包车价已含高速费，但长途高速费很高（例如东京到大阪单程约 1 万日元）。需要确认现有超公里单价是否覆盖；不覆盖的话，长途移动日按「预估高速费」单独计入（用路线接口的收费估算或固定表）。
- **后续费用**：
  - 到达城市继续用同一辆车：每晚加司机住宿费（3.1）。
  - 行程在到达城市结束：加返程费（3.2）。返程按返程公里 × 返程单价计算，返程单价通常低于超公里单价，例如超公里单价的 50%（可配置）；也可以按司机坐新干线回来 + 车辆回送计算，两者取低。
- **对比方案**：到达城市有本地供应商时，同时算「移动日一包到底 + 到达后改用本地车」，看是否更便宜。

**有没有上限**
- 超公里费本身不封顶，用上面的长途档位价避免价格离谱。
- 设三条运营上限，都是商品级配置：
  - 单日最大行驶距离，默认 600 km。
  - 单日驾驶时间，默认 9 小时。
  - 拘束时间：13 小时（3.4）。
- 超出上限时，系统按顺序给出可选方案：
  1. 双司机（加第二司机费）。
  2. 拆成两天开（中途加一晚住宿）。
  3. 改走新干线方案。
  4. 都不行就转人工。

**展示**：方案对比卡片，并排显示两个方案的总价、门到门时间、换乘次数、行李提示和地图路线；有一方明显更划算或更省时，就标「推荐」。

**需要的新数据**：新干线站点表（每个站属于哪个城市商品的服务区域）；主要线路的铁路时长和票价，用路线接口的公共交通模式，或维护主要线路固定表；长途档位价表；返程单价；长途高速费表。

## 4. 转人工的情况（不报价，留下需求）
区域外地点、超过工时上限、超出长途范围、AI 解析置信度低（客人不确认），或者需要特殊车辆（大巴、无障碍车）。转人工后记录进「未覆盖需求」，方便后续补规则。

## 5. 地图可视化（包车搜索与报价页）
- 地图上画出全部路线：每天一种颜色，经停点按顺序编号，机场和酒店用专用图标，显示每段的时长和公里数。
- 显示区域图层：基础价区域、行程区域、上下车加价区域淡色铺底，客人能看出为什么加价。
- 联动：点价格明细里的某一项（例如「富士山行程加价」），地图高亮对应的点和区域；拖动经停点或调整顺序，价格立即重算。
- 多日行程：按日切换，再加一个「全部天数」总览。
- 手机：地图在上、时间表在下；嵌入组件只放缩略地图，点开才进完整地图。
- 成本：用现有 Google 地图 key；大量列表缩略图用静态地图，减少计费。

## 6. 数据模型（新增，不改现有表）
- **行程单（trip）**：客人、来源（AI 句子 / 上传文件 / 表单 / 嵌入组件）、原始输入、标准行程 JSON、确认状态、报价编号、有效期。
- **服务段（trip_segment）**：段类型、日期、起止时间、地点列表（含经停和停留）、对应商品、段报价明细、子订单 ID。
- **跨段费用（trip_fee）**：费用类型（住宿 / 返程 / 停驻 / 换班 / 时间加价）、触发规则 ID、金额、说明。
- **规则配置**：商品级的住宿费表、返程规则、长途范围、停驻费、工时阈值、时间加价表。

## 7. 分期（每期都走 ADR → 独立审查 → PR → 测试站验收）
1. **P1 底层**：行程单与服务段数据模型、编排接口（先只接收结构化输入）、住宿 / 返程 / 多日 / 工时四类规则、方案对比。用 30 条真实客人需求做成固定测试集。
2. **P2 地图**：包车页和行程报价页加完整路线地图和区域图层，与明细联动。
3. **P3 AI 一句话**：一句话 → 标准行程单 → 编排；带确认页，标出假设。
4. **P4 上传行程**：PDF、图片、Excel 识别。
5. **P5 入口铺开**：嵌入组件加「一句话报价」输入框，客服后台可以粘贴客人消息直接出报价。

## 8. 待业主确认（先按建议默认值开发，都可在后台改）
| 项 | 建议默认 |
|---|---|
| 司机住宿费 | 每车每晚 ¥15,000（含餐），旺季地区可单独设 |
| 长途返程费 | 返程公里 × 超公里单价 与 ¥(新干线票价 + 2 小时工时) 取低 |
| 长途单程范围 | 600 km 以内在线报价，超过转人工 |
| 空闲日停驻费 | 每天 ¥10,000 或按 4 小时套餐价，取低 |
| 换司机 | 超 13 小时自动报两名司机方案（第二位司机按半日费） |
| 节假日加价 | 先确认现有系统是否已有，没有则做成日期表，默认 0 |
| 长途判断距离 | ≥ 300 km 同时算新干线方案和一包到底方案 |
| 新干线方案成立 | 两端有站且在服务区、比开车快 60 分钟以上、最多换乘 1 次 |
| 长途档位价 | 每 100 km 一档，与「套餐 + 超公里」取低（金额待定） |
| 返程单价 | 超公里单价的 50%，与「司机新干线 + 车辆回送」取低 |
| 单日上限 | 行驶 600 km、驾驶 9 小时、拘束 13 小时；超出时依次给双司机、分两天、新干线方案 |
