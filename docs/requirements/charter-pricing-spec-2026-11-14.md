# NOZOMI 包车报价逻辑规格（开发版）2026-11-14（业主提供 PDF 转录）

## 一、总价公式与三层区域
总价 = 套餐价 + Σ(经停涉及的每个行程区域的行程加价) + 上车加价 + 下车加价 + 超公里费 + 司机语言等附加。四部分各算各的，互不抵消。车辆一律东京市区出库/归库：上车加价=出库空驶费，下车加价=归库空驶费。以上都是结算价；前台售价=结算价×1.1。超时费不在下单时收，由供应商服务后提交。
- ①基础价区域：东京市内、羽田机场等按套餐价就能接的范围；用上车点、下车点判断；在这里上下车不加钱；套餐价整单只算一次（东京市内价）。
- ②行程区域：富士山、箱根、镰仓等景区；用经停点判断；每个区域一单只收一次；不同区域叠加；上车或下车在同一区域也照收，不抵消。
- ③上下车加价区域：离东京市区远需空驶的范围；用上车点、下车点判断；上车点在区域内收一次上车加价，下车点在区域内再收一次下车加价；上下车在同一区域也各收一次。
当前东京金额（结算价，行程/上车/下车）：东京市内 0/0/0；富士山 10,000×3；箱根 10,000×3；镰仓 8,000×3；日光 15,000×3；轻井泽 15,000×3；伊豆 15,000×3。
四个标准场景（10h）：东京往返富士山=10h套餐+富士山行程（加价 10,000）；东京上车→富士山下车=套餐+富士山行程+富士山下车（20,000）；富士山上车→富士山游玩→富士山下车=套餐+富士山行程+上车+下车（30,000）；富士山上车→箱根游玩→富士山下车=套餐+箱根行程+富士山上车+富士山下车（30,000，不收富士山行程：行程加价只看经停点）。

## 二/三、报价流程 6 步
商品匹配只看上车点和下车点；行程加价只看经停点；三层加价各自算完后相加，互不抵消。
步骤1 匹配商品：上车点和下车点都落在该商品①或③区域内才参与报价；不再用“上车点所属城市”筛商品（例：河口湖在东京包车的富士山③内，就由东京包车报价，套餐按东京市内价）。经停点不影响匹配，只影响行程加价；经停点不在任何①②③区域内时该商品不报价（转人工）。多个商品都能报时，展示同一车型下总价最低的一个。
步骤2 算 T 和 D：路线 上车→各经停（按客人顺序）→下车，用路径接口算每段时间和公里，不含出库/归库空驶。T=行驶时间+各经停停留+经停数×每站默认占用(建议15分)+整单缓冲(建议60分)，商品级配置。经停数量不设业务上限，只受路径接口技术上限约束。
步骤3 选套餐：候选=该商品时长≥T 的所有套餐（T 超过最大套餐时只有最大套餐）。每个候选算 套餐价+max(0,D−含公里)×超公里单价，取最低。客人可手动改更长套餐，不能短于 T。不同商品各自选套餐、各自算总价再比价（现在平台先统一定套餐时长，只有含这一档的商品才比价，需要改）。
步骤4 三层加价（每个点同一层只落在一个区域，后台保证同层不重叠）：
- 上下车加价(点,方向)：点在任一①→0（基础价优先）；否则取点所在③；③不存在→商品不报价；返回 区.加价[方向]。
- 行程加价：已收区域=空；对每个经停：在任一①→跳过（市内经停不加价）；取所在②；不存在→商品不报价；不在已收区域则加价并记入。注意：不要因为上车点或下车点也在这个区域就跳过。
- 总加价=上车加价+下车加价+行程加价。
- 没有经停的单（待业务确认）：建议把下车点所在②当作一个经停计入行程加价，否则客人不填经停就能少付。
- 明细逐项列出：套餐/上车加价(区域名)/下车加价(区域名)/行程加价(区域名，第几个经停)/超公里费。
步骤5 超限提醒：T>12h 或 D>360km 提醒缩减行程、仍可下单；T>13h 不允许在线下单转客服；两个阈值商品级配置；文案见《NOZOMI 包车开发需求》需求四。
不变规则：从预约上车时间开始计时占用全部时长、无免费等待；不设航班号字段、不校验航班；报价含高速费、停车费，服务后不再另收。

## 四、区域数据模型与后台校验
区域角色由两种（服务区域/区域加价）改为三种：①基础价区域=基础信息→服务区域（现有），不填加价；②行程区域=价格规则→行程加价（新），可按车型组，空=经停在此不报价；③上下车加价区域=价格规则→上下车加价（现有“区域加价”改名），上车/下车加价可按车型组，空=在此上下车不报价。②③是两张独立表，同一地理区域可同时加入两张表、金额各填；也允许②③用不同地理区域（②小范围景区如华严瀑布、河口湖，③按距离大范围）。当前“区域加价”里的“途经加价”列迁移到②行程加价表。套餐价不再按“服务区域×车型组×套餐”填，改为按“车型组×套餐”填一次（处处是东京市内价）。
保存/上架校验：1) 同商品同层区域不能重叠（①①、②②、③③），重叠时拦下并提示重叠区域名和面积；2) ①与③不能重叠，①②、②③可以重叠；3) 同一区域不能既是①又是③（东京包车出过这种配置导致“有 N 条未保存”）；4) 上架“覆盖检查”：可配置城市热门景点坐标清单，上架前列出不在任何区域的景点；5) 加价表空格提示：空格=不报价，容易漏填。
区域编辑器建议：“从本区域减去另一个区域”操作切掉重叠；“在地图上看全部”按商品和层筛选并标红重叠；区域详情显示在哪些商品里当①/②/③。

## 五、与现平台差异（2026-11-14 实测，前台价）
1 P0 经停加价被上下车抵消：东京上车→河口湖经停→河口湖下车只收下车 11,000；应 行程 11,000+下车 11,000=22,000。
2 P0 加价区域内上车不匹配商品：河口湖上车“暂时没有在线报价”；应由东京包车报价并收富士山上车加价。
3 P1 基础价区域与加价区域重叠照收：羽田∩横滨、东京市∩千叶市重叠处上车或经停收 3,300；应基础价优先收 0，并后台禁止重叠。
4 P1 两加价区域重叠取高价：八王子(3,000)∩富士山(15,000)经停收 16,500，后台说明写取最低；应同层不允许重叠。
5 P1 套餐先统一定时长再比价：特殊商品只有 8/10/12h 时，5h48m 日光行程定为 6h，特殊商品不参与；应各商品自己选套餐算总价再比。
6 P1 只按时长选套餐：132km 选 4h+超公里=47,259，5h 只要 46,200；应含超公里取最低。
7 P1 服务区域没填套餐价：上车报不出价、经停收 0；应套餐价商品统一填一次或上架拦下。
8 P2 区域加价上下车必填：建不了只管经停的区域；应②③分表。
9 P1 自动选套餐没缓冲：短线 5h 变 4h 实际超时；应每站默认占用+整单缓冲。
10 P2 经停上限 10：应不设业务上限。
11 P2 无超限提醒：454km 正常下单；应超 12h/360km 提醒、超 13h 拦。
已确认正常：经停命中加价区域加价；同一区域多个经停只收一次；不同区域各收一次；明细逐项；多商品同时报价展示最低价。
