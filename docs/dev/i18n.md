# 前端固定文案：i18n key 怎么用（M11-01、M11-02）

业主 2026-11-15：多语言放到系统做完以后再统一做。**开发期间新功能只做中文，但新的固定文案一律走 i18n key，不在组件里写死**；文案清单要能从代码导出，交业主定稿。

## 规则

- 新页面、新提示、新按钮、新错误提示的中文写进文案本，组件里用 `t("模块名.key")`。
- 只写中文。日文、英文以后统一补；缺的语言自动退回中文。
- 主站已有的日文、英文文案（如 `BOOK_TAB_I18N`、嵌入组件 `embed/widget-core.ts` 的 `TEXTS`、主数据的 `LocalizedText`）**原样保留，不删、不改、不搬**。
- 已有的写死中文**不批量搬**：改到哪一块、顺手把那一块的新文案放进文案本就行（避免和别的开发线冲突）。
- 邮件 / 通知模板仍写在 `packages/domain/src/notifications.ts`（它本身就是按事件分好的模板表），导出清单会一起列出来。

## 怎么加文案

1. 每个功能模块一本文案：`apps/web/src/i18n/messages/<模块>.ts`

   ```ts
   import { defineMessages } from "../i18n.ts";

   export const freeWait = defineMessages("freeWait", {
     flightKindLegend: "航班类型",
     previewChange: "同意后免费等待 {from} → {to}",
   });
   ```

   - 模块名和 key 用小驼峰，只含字母和数字；`defineMessages` 的第一个参数和登记名一致（有测试检查）。
   - 参数写成 `{name}`。数字、拼好的短句都当参数传，不要在文案里拼接中文。
2. 在 `apps/web/src/i18n/messages/index.ts` 的 `MESSAGE_BOOKS` 里登记一行。
3. 页面里取：

   ```ts
   import { t } from "../../i18n/index.ts";

   t("freeWait.flightKindLegend");
   t("freeWait.previewChange", { from: 60, to: "90 分钟" });
   ```

   key 写错，类型检查就报错。以后补日文、英文：在同一本里写 `defineMessages("freeWait", { ... }, { ja: { ... }, en: { ... } })`，切换语言用 `setLang`。

第一本示例：`apps/web/src/i18n/messages/free-wait.ts`（M9E-28 接机免费等待的文案，原来的 `FREE_WAIT_TEXTS`）。

## 导出文案清单（M11-02）

```bash
pnpm copy:export                 # 写到 copy-export/（不提交）
pnpm copy:export --out <目录>
```

生成三个文件：

- `keys.md`、`keys.csv`：每条文案的 key、中文、用在哪些页面、出现位置（文件:行），按页面分组；后面附邮件 / 通知模板（`mail.<事件>.<收件人>`）。给业主定稿就用这两个。
- `hardcoded.csv`：组件里还写死的中文（去掉注释后含中文的行），只报告、不拦；审查时看新代码有没有新增。

页面分组按文件所在目录（`pages/book/new` 是官网预订页，`pages/orders` 是供应商后台订单，等等，见 `scripts/copy-export.ts` 的 `PAGE_GROUPS`）；`lib/` 里的文案按引用它的页面算。

## 审查时

- 新代码里的中文固定文案是不是都在文案本里（`pnpm copy:export` 后看 `hardcoded.csv` 里有没有本 PR 新增的行）。
- 新文案本有没有在 `MESSAGE_BOOKS` 登记。
